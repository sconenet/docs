# خادم DNS عبر UDP + TCP (M6 + M7b) — `scone dns`

> مواصفة معيارية لسطح DNS الخاص بـ Scone.
> أي تباعد وثائق/كود = خطأ برمجي (صحّح مصدر الحقيقة).

## نظرة عامة

**خادم DNS** سطح اختياري من المُرحّل: يجيب على استعلامات DNS
عبر **UDP وTCP** (RFC 7766، نفس المنفذ) لأسماء Scone **فقط من
بيانات متحقَّق منها مقابل السلسلة**، ويقدم **تراجعًا تكراريًا
اختياريًا** (`addr:port`) لكل ما عدا ذلك. لا يملك سلسلة ولا
مخزن ولا DHT: قرارات الوجود/الانتهاء تمر عبر **لقطة DNS
المرجعية** (رؤية RAM تُنشر بعد كل كتلة مطبَّقة — انظر أدناه)،
وجلب السجلات يمر عبر المُرحّل (العملية)، عبر القناة الداخلية
`RelayCommand`/`ResolveLocal` (داخل العملية، ذهاب-إياب واحد) —
نفس المسار المتحقَّق منه كالـ CLI.

```text
              UDP+TCP :5353 (default 127.0.0.1)
                    │
             scone relay --dns 127.0.0.1:5353
                    │  ┌────────────────────────────────┐
                    ├──┤ Sharded cache, 16 ways (qname)  │
                    │  └────────────────────────────────┘
                    │  Scone-shaped name?
                    │  ├─ YES → authoritative DNS snapshot:
                    │  │        unknown/expired → NXDOMAIN (RAM,
                    │  │        zero round trips into the core)
                    │  │        → apex search by suffix
                    │  │        → internal `resolve_local` (relay)
                    │  │           chain + verified record (hash,
                    │  │           owner, sequence) → answers
                    │  │        apex without a published record → NODATA
                    │  └─ NO → upstream fallback (if configured)
                    │           otherwise REFUSED
                    │
                    │  response budget:
                    │    UDP → 512 bytes (no EDNS); overflow =
                    │          cut at the last fitting record + TC=1 →
                    │          the client retries over TCP
                    │    TCP → 64 KiB (2-byte length prefix,
                    │          RFC 1035 §4.2.2): full set
```

## الإقلاع

```bash
scone relay --dns 127.0.0.1:5353            # DNS surface only
scone relay --dns 0.0.0.0:53 \
            --dns-upstream 1.1.1.1:53 \
            --dns-upstream 8.8.8.8:53       # + recursive fallback
```

يعلن المُرحّل العنوان الفعلي على stdout (عقد قابل للقراءة
آليًا، مثل `p2p:`): سطر `dns: <addr>` فور ربط الـ socket.

عميل التحقق: `dig <name> --dns 127.0.0.1:5353
--qtype A` (A, AAAA, TXT, MX, NS, CNAME, ANY).

## مسار الحلّ (السلطة = السلسلة، دائمًا)

0. **لقطة DNS المرجعية**: رؤية غير قابلة للتعديل
   (`Arc<HashMap<DomainId, {valid_until, has_record}>>`،
   تغذية `tokio::sync::watch`) ينشرها جوهر المُرحّل **بعد كل
   كتلة مطبَّقة** (push، لا poll) وعند الإقلاع. قرارات
   الوجود/الانتهاء — NXDOMAIN، نطاق منتهٍ — تُقدَّم من RAM عبر
   هذه اللقطة: استنساخ `Arc` واحد + بحث خريطة واحد، **دون دخول
   حلقة التشغيل أحادية المالك للمُرحّل أبدًا**. يبقى المسار
   الكامل (`RelayCommand`/`ResolveLocal`) محجوزًا لجلب السجلات
   الفعلي (سحوبات DHT)، وهي نادرة بفضل الذاكرة المؤقتة. لا
   تحمل اللقطة بيانات السجلات **أبدًا**: الوجود والانتهاء
   فقط.
   - **دلتا copy-on-write بتعقيد O(الممسوس)**: الخريطة
     `Arc<HashMap>`؛ نشر امتداد القمة ينشر دلتا الكتلة
     (معاملات الكتلة نفسها تسمّي كل نطاق يمكنها تغييره —
     Register/Assign/Update/Renew/TransferDomain — زائد إزالات
     GC-الانتهاء الحتمية المقيَّمة وقت الدفع) عبر
     `Arc::make_mut`: تُستنسخ الخريطة فقط إذا كان قارئ لا يزال
     يحمل الرؤية السابقة. الإقلاع وإعادات التنظيم تعيدان بناء
     اللقطة الكاملة (جولة خلفية مرقّمة واحدة).
   - الطزاجة: قد يرى قارئ لقطة عمرها بضع مئات من ms خلال تطبيق
     كتلة — نفس التقادم الذي كان سيكون لـ RPC حالة؛ TTLs ذاكرة
     DNS المؤقتة غير متأثرة (الأجوبة تبقى مرجعية وفق أصلها).
1. **الذاكرة المؤقتة المُقسَّمة**: [`ShardedCache`] — 16 shard
   مستقلًا من `Cache` مفهرسة بـ `hash(qname)` (الـ qtype يتشارك
   الـ shard: محلية لكل اسم). الاسم الساخن يتنافس مع 1/16 من
   الترافيق بدل الانتظار خلف mutex واحد عند آلاف الاستعلامات
   في الثانية. حدود شاملة (100,000 مدخل / 64 MiB افتراضيًا،
   `--dns-cache-limit` / `--dns-cache-max-mem`) مقسّمة على
   الـ shards (أسوأ حالة موثّقة: معامل 1 + N/shards). يُحاسب
   الحجم الحقيقي للـ rdata لكل مدخل (~128 بايت حملًا لكل
   مدخل) ويُطلق الإخلاء FIFO عند أول الحدّين المُصابين — سقف
   الذاكرة يصمد حتى أمام مداخل بالحجم الكامل
   (`MAX_DHT_RECORD_LEN`). TTL بقيمة 60 ث
   (مرجعي) / مصدود عند 600 ث (تراجع). تتبع الذاكرة السلبية
   (NXDOMAIN/NODATA) نفس القواعد؛ يحمل كل مدخل أصله (مرجعي أو
   تراجع) ليبقى بت AA صادقًا عند الإصابة. **لا تخزين مؤقت
   أبدًا لـ SERVFAIL** (فشل محلي عابر) **ولا REFUSED** (حالة
   إعداد): كلاهما يعاد حسابه عند كل استعلام. إخلاء FIFO عند
   السعة. **المسار الساخن (مستوحى من Cloudflare/1.1.1.1)**:
   - مداخل `Arc<CacheEntry>` مشتركة: الإصابة رفع عدّاد مرجعية،
     وليست **أبدًا** نسخة عميقة للـ rdata (يستبدل `put`
     الـ Arc — لا تعديل مشترك؛ ما يزال الـ TTL يُفحص تحت قفل
     الـ shard)؛
   - **بحث دون تخصيص ذاكرة**: خريطة ثنائية المستوى
     (`Box<str>` qname ← qtype ← مدخل)، يستقصي `&str`
     المستعار للاستعلام مباشرة (`Borrow<str>`) — مفتاح الـ
     tuple القديم `(String, u16)` كان يخصص `String` جديدة عند
     **كل** بحث؛
   - **سجلات متجاورة مضغوطة**: عازلة `Box<[u8]>` واحدة لكل
     مدخل (`u16 rdlen ‖ u16 rtype ‖ u32 ttl ‖ rdata` لكل سجل)
     بدل `Vec` واحدة لكل سجل — ميزانية الذاكرة تتعقب بالضبط
     ما هو مخصص؛
   - **ضغط أسماء RFC 1035 عند الإخراج**: مالك الأجوبة المرجعية
     مؤشر ضغط من 2 بايت (`0xC00C`) إلى السؤال المُردَّد — لا
     يعاد ترميز السؤال كاملًا لكل سجل.
2. **شكل Scone؟** مرشِّح مسبق صارم: علامات `[a-z0-9-_]`
   (1..63)، ≥ 2 علامة، TLD بطول 1..63 بايت `[a-z0-9-]` (انظر
   `TldName::MAX_LEN`)، طول إجمالي ≤ 253 — **والـ TLD خارج جذر
   ICANN** (`is_icann_tld`، قائمة IANA المجمدة + RFC 2606:
   `com`، `fr`، `org`… لا تنتمي إلى Scone أبدًا). الاسم الذي
   **لا يمكن** أن يكون اسم Scone (مثل `www.foo_bar`، شرطة
   سفلية في الـ TLD) يذهب إلى التراجع؛ واسم Scone ممكن
   (`absent.uip`) شأن سلسلة: غير مسجل ← NXDOMAIN مرجعي، حتى
   دون upstream. والـ TLD التابع لـ ICANN (`example.com`)
   يُمرَّر إلى الـ upstreams إن هُيّئوا، وREFUSED وإلا — لا
   يُحلّ مرجعيًا بواسطة Scone أبدًا.
3. **بحث القمة (apex)**: اللواحق من الأطول إلى الأقصر (على
   الأقل علامتان). أول لاحقة حالتها على السلسلة معروفة
   للمُرحّل = القمة؛ مجموعة السجلات تخدم الاسم كاملًا (الأسماء
   الفرعية مشمولة — سلوك wildcard ضمني، قرار مفتوح).
4. **`resolve_local` (قناة داخلية)**: ذهاب-إياب واحد، وليس
   منتظر DHT أبدًا. حالة على السلسلة (`registered`، مالك،
   تسلسل) + سجل ذاكرة DHT المحلية **يعاد التحقق منه** (مالك،
   تسلسل، record_hash == التزام على السلسلة). السجل غير
   المطابق لا يجيب أبدًا — التوفر ≠ السلطة.
   - غير مسجل ← NXDOMAIN؛
   - مسجل بلا سجل صالح ← NODATA (NOERROR، 0 جواب)؛
   - سجل متحقَّق ← أجوبة مرشَّحة حسب qtype.

## المرمّز (RFC 1035، مجموعة فرعية صارمة)

- الاستعلام: ترويسة 12 بايت، سؤال **واحد**، QCLASS = IN،
  **بلا ضغط** (مؤشر = رفض). العلامات تُحوَّل صغيرة ويُتحقق
  منها. QR=1، QDCOUNT≠1، علامات غير صالحة ← **صمت**
  (القمامة لا تكلّف شيئًا).
- الاستجابة: QR|RD(صدى)|RA، **AA فقط على الأجوبة المرجعية**
  (السلسلة، طازجة أو مؤقتة — أبدًا على التراجع أو أكواد
  RCODE للخطأ)، السؤال منسوخ حرفيًا، والأجوبة المرجعية
  **بمالك مضغوط RFC 1035** (مؤشر 2 بايت `0xC00C` إلى السؤال
  المُردَّد)؛ ردود الـ upstream للتراجع تُقدَّم كما هي (لا
  يعاد ترميزها أبدًا).
- الأنواع المخدومة: A، AAAA، CNAME، NS، MX، TXT، **PTR، SRV،
  CAA** (+ Unknown يعاد ترميزه حرفيًا؛ 9 أنواع أصلية
  إجمالًا، rdata مرمَّز وفق RFC — 1035/2782/8659؛ CAA صارم:
  البت الحرج 0x80 فقط، وسوم صغيرة). استعلام A/AAAA يشمل
  CNAMEs المجموعة (تتبع الأسماء المستعارة). استعلام ANY
  (255): المجموعة كاملة مرشَّحة بالمرمّز.
- الحدود (M7b): **ميزانية الاستجابة تعتمد على النقل** —
  512 بايت عبر UDP (حمولة RFC 1035 §2.3.4 الكلاسيكية، بلا
  EDNS)، و65,535 عبر TCP. المجموعة التي تتجاوز الميزانية
  تُقطع عند آخر سجل يسع، مع **TC=1** (اقتطاع صادق، RFC 1035
  §4.2.1): يعيد العميل المحاولة عبر TCP (RFC 7766)، حيث
  تُقدَّم المجموعة الكاملة. رد upstream أكبر من ميزانية UDP
  يعاد ترميزه مقتطعًا (TC=1) بدل تقديمه كما هو؛ وعبر TCP
  يمر بايتًا ببايت. يطبَّق الاقتطاع أيضًا على إصابات الذاكرة
  المؤقتة (الميزانية تُطبَّق وقت الاستجابة، لا وقت ملء
  الذاكرة).
- أكواد RCODE: 0 NOERROR (بأجوبة أو بدون)، 2 SERVFAIL (فشل
  محلي)، 3 NXDOMAIN (مرجعي)، 5 REFUSED (غير Scone دون
  upstream).

## التراجع التكراري

- الـ upstreams بصيغة `addr:port` (UDP)، تُجرَّب بالترتيب،
  مهلة 2 ث لكل upstream، وsocket **متصل** بالـ upstream
  (ترشيح نواة: حزمة من أي مصدر آخر لا تُقبل أبدًا). لا تُقبل
  استجابة الـ upstream إلا إذا **طابقت الاستعلام**: نفس
  TXID، QR=1، السؤال (QNAME+QTYPE+QCLASS) منسوخ بايتًا
  ببايت. استجابة غير مطابقة ← SERVFAIL، ولا يُخزَّن شيء.
- استجابة الـ upstream المتحقَّح منها تُمرَّر كما هي؛
  أجوبتها تُخزَّن بأصل `fallback` (AA لا يُضبط أبدًا، حتى
  عند إصابة ذاكرة) وTTL مصدود عند 600 ث. أكواد RCODE لخطأ
  الـ upstream (غير NOERROR/NXDOMAIN) لا تُخزَّن.
- **خاص افتراضيًا**: لا upstream = REFUSED للأسماء خارج شكل
  Scone.

## الذاكرة السلبية للـ DHT (مضاد التضخيم)

**سحبة DHT بلا جواب** (سجل متوقع على السلسلة — `record_hash`
ملتزَم — لكنه غائب عن الذاكرة المحلية والأقران المُستعلامين)
تُركن الاسم لمدة `DHT_NEGATIVE_TTL_SECS` (30 ث) في ذاكرة
سلبية محدودة (FIFO، سقف `DHT_NEGATIVE_CAP` بقيمة 4,096
اسمًا): إعادة حلّ نفس الاسم ضمن الـ TTL **مكبوتة** (تُعدّ،
ولا يعاد السحب أبدًا). لم يعد الماسح — أو اسم ساخن لم ينشر
مالكه قط — يستطيع تضخيم استعلام DNS واحد إلى `GetRecord` لكل
قرين في الشبكة لكل استعلام. يموت المدخل السلبي عند الـ TTL،
أو عند وصول السجل (السحبة الناجحة تكتب في الذاكرة الحقيقية)،
أو بدفعه خارج سقف الـ FIFO.

عدادات مكشوفة (`scone_dht_negative_hits_total`،
`_expired_total`، `_capped_total` — انظر "المقاييس" في
`relay.md`).

## TCP (M7b، RFC 7766)

نفس منفذ UDP (ربط TCP ثانٍ على عنوان `--dns`). يتبع النقل
RFC 1035 §4.2.2: كل رسالة مسبوقة بطولها على **2 بايت**
big-endian.

- **الاستعلام**: طول البادئة ≥ 1 و≤ 512 بايت (استعلام DNS
  يسع الحمولة الكلاسيكية — RFC 7766 §6؛ لا يُخدَم EDNS). خارج
  الحدود ← إغلاق اتصال فوري.
- **الاستجابة**: ميزانية 65,535 بايت (حد أقصى بادئة الـ
  2 بايت) — المجموعة الكبيرة جدًا على UDP تُقدَّم هنا
  **كاملة**، TC=0.
- **Pipelining**: استعلامات متعددة لكل اتصال تُخدَم تسلسليًا،
  بالترتيب (كتابة واحدة = استجابة مسبوقة واحدة).
- **مهلة القراءة**: 5 ث لكل قراءة (بادئة أو جسم) — العميل
  الصامت يُفصل، وتُحرَّر خانته.
- **الاتصالات المتزامنة**: 64 كحد أقصى (semaphore)؛ والـ 65
  يُرفض فورًا (إغلاق الاتصال)، ولا يُصفّ أبدًا — لا نمو غير
  محدود للمهام أو الذاكرة.
- أخطاء قراءة/كتابة/مهلة: سجل debug + إغلاق نظيف. **لا panic
  أبدًا على مُدخل شبكي.**
- القمامة (استعلام غير مفهوم) تنال الصمت لكنها لا تغلق
  الاتصال: يُخدَم الاستعلام التالي (الصالح).

```text
client                     server
  │ [len u16][query]         │
  │ ─────────────────────►   │ cache → authoritative → fallback
  │ ◄─────────────────────   │ [len u16][response ≤ 64 KiB]
  │ (UDP had answered TC=1 → the client retries here)
```

## الحدود والحواجز

| الحاجز | القيمة |
|---|---|
| مخطوطة UDP (استعلام/استجابة) | 4096 بايت (تُرفض بعده) |
| ميزانية استجابة UDP (TC=1 بعدها) | 512 بايت (بلا EDNS) |
| أقصى استعلام TCP | 512 بايت (يُغلق بعده) |
| أقصى استجابة TCP | 65,535 بايت |
| اتصالات TCP متزامنة | 64 (semaphore، رفض فوري) |
| مهلة قراءة TCP | 5 ث |
| الذاكرة المؤقتة | حدود شاملة 100,000 مدخل / 64 MiB افتراضيًا، مقسّمة على 16 shard (`--dns-cache-limit` / `--dns-cache-max-mem`) |
| TTL مرجعي | **لكل سجل** (`record.ttl`، حدود 1..=2,592,000 ث؛ الثابت التاريخي 60 ث يبقى فقط لاستجابات الخدمة) |
| TTL التراجع (صادّ) | 600 ث |
| استعلامات UDP المتوازية | 4,096 (`MAX_INFLIGHT_UDP`، semaphore؛ بعدها: إسقاط، يعيد العميل المحاولة) — قابل للضبط `--dns-max-inflight` (أدنى 1) |
| الذاكرة السلبية DHT | 30 ث (`DHT_NEGATIVE_TTL_SECS`)، سقف FIFO بقيمة 4,096 اسمًا |
| المهلة لكل upstream | 2 ث |

قواعد المشروع محترمة: لا panic أبدًا على بيانات الشبكة؛ فك
ترميز صارم في كل مكان؛ الخادم لا يلمس سلسلة ولا مخزن ولا DHT
(يبقى المُرحّل سلطة التحقق الوحيدة).

## الاختبارات

- وحدات (`scone-network::dns`): مرمّز صارم (QR، ضغط، رفض
  العلامات)، أجوبة مرجعية، NODATA، NXDOMAIN، REFUSED دون
  upstream، تراجع إلى mock UDP، ذاكرة محدودة، تقسيم TXT، تحليل
  upstream؛ إصلاح M6: صدق بت-AA (مرجعي مقابل تراجع مقابل
  أخطاء، بما فيها إصابات الذاكرة)، اقتطاع TC=1 لمجموعة
  متضخمة، رفض استجابة upstream (عدم تطابق TXID أو السؤال)، لا
  تخزين SERVFAIL/REFUSED؛ الذاكرة المُقسَّمة: انتشار
  الـ shards، تقسيم الحدود الشاملة، 4 عمال متزامنين على اسم
  ساخن؛ المسار الساخن: بحث دون تخصيص، مداخل مضغوطة، ضغط
  المالك.
- M7b: ميزانية لكل نقل (UDP بقيمة 512 بايت ← TC=1، TCP ←
  المجموعة الكاملة)، اقتطاط إصابة ذاكرة، `run_tcp` حقيقي
  (مجموعة > 512 تُقدَّم كاملة، pipelining لاستعلامين، استعلام
  متضخم ← إغلاق، عميل صامت ← مهلة 5 ث، قمامة ثم استعلام صالح
  على نفس الاتصال)، رد upstream > 512 يعاد ترميزه TC=1 على
  UDP / بايتًا ببايت على TCP.
- تكامل حقيقي (`tests/dns_server.rs`): مُرحّل كامل (بما فيه
  إنتاج devnet) + تسجيل + UpdateDomain + PutRecord، ثم
  استعلامات UDP حقيقية: A متحقَّق منه (بت AA)، TXT، NODATA
  AAAA، NXDOMAIN، تراجع عبر mock، إعادة استعلام، اسم فرعي عبر
  القمة.
- E2E ثنائي (`crates/scone/tests/dns_cli.rs`): الملف التنفيذي
  `scone` الحقيقي — `relay --dns`، `identity generate`،
  `domain register`، `domain update --file`، ثم `dig`
  (dnsutils) (A متحقَّق منه، TXT، NXDOMAIN، REFUSED) على منفذ
  UDP حقيقي.

## قرارات مفتوحة

- لا EDNS (تبقى ميزانية UDP بقيمة 512 بايت؛ الاقتطاع TC=1 +
  TCP يغطيان حاجة devnet).
- لا تحمل مجموعة السجلات اسمًا لكل سجل: المجموعة كاملة تخدم
  كل اسم فرعي للقمة (wildcard ضمني). العنونة لكل سجل كانت
  ستتطلب توسيع `DnsRecord` (بروتوكول).
- يمرر التراجع الاستعلام الخام: يستطيع upstream خبيث الإجابة
  بأي شيء (استجابة غير متحقَّح منها — هذا نموذج التكرار
  القياسي؛ أسماء Scone لا تمر عبره **أبدًا**).

## GeoDNS (توجيه جغرافي)

> مواصفة معيارية. أي تباعد وثائق/كود = خطأ برمجي.

### جدول GeoIP مدمج (تلقائي)

يضمّن كل ملف تنفيذي **جدول تحويل IP ← بلد** مجمَّعًا داخل
المُرحّل: **لا يحتاج إعدادًا**، التوجيه الجغرافي نشط في كل
مكان، تلقائيًا.

- **مصدر البيانات**: **ملفات تفويض الـ RIR** (RIPE NCC، ARIN،
  APNIC، LACNIC، AFRINIC)، حرة التنزيل وإعادة التوزيع:
  `https://ftp.ripe.net/pub/stats/<rir>/delegated-<rir>-extended-latest`
  (بلد تسجيل كل كتلة IPv4/IPv6 مفوَّضة). تاريخ التوليد في
  ترويسة الجدول
  (`assets/embedded-geo.table`).
- **إعادة التوليد**: `scripts/gen-geo-table.py` (ينزّل الملفات
  الـ 5، يحوّل، يوحّد البادئات — ~176,000 قاعدة).
- **الدقة**: بلد (ISO 3166-1 رقمي) + قارة (UN M49) مشتقة. لا
  ASN ولا منطقة (غائبان عن التفويضات).
- **الأداء**: بحث ثنائي فوق نطاقات مرتّبة (فهرس يُبنى مرة
  عند أول استخدام، لكل عائلة v4/v6) — مقيس ~95 ns/بحث ساخن،
  ~50 µs وصول عشوائي على الجدول الكامل (قياس: `cargo test -p
  scone-network --release --test geo_bench -- --ignored`).
- **تحديد موقع المُرحّل ذاتيًا**: يتبع التوجيه **IP المصدر
  لكل استعلام** — مُرحّل شبكة محلية يوجّه عملاءه المحليين إلى
  المنطقة الصحيحة تلقائيًا.
- **الأسبقية**: جدول مشغّل صريح
  (`--geo-ip-table`/geo-config) **يتجاوز** المدمج.

### نظرة عامة

يستطيع نطاق نشر قواعد **توجيه جغرافي** في مجموعة سجلاته
الموقّعة: سجلات `GEOROUTE` (نوع خاص بـ Scone بقيمة `32,768`،
خارج نطاق IANA). يجيب المحلّل أسئلة A/AAAA لهذه النطاقات
**بعنوان نقطة النهاية التي اختارتها القاعدة** (النطاق الأقرب
لموقع **العميل**، المشتق من IP مصدره عبر الجدول)، بدل سجل
A/AAAA ثابت. كل ما عدا ذلك (نطاقات بلا GEOROUTE، qtypes أخرى)
يتبع مسار DNS الكلاسيكي، **بايتًا ببايت**.

### مقاييس GeoDNS

يكشف نقطة Prometheus تقسيم الأجوبة الجغرافية:

- `scone_dns_geo_answers_total` — إجمالي أجوبة GEOROUTE
  المقدَّمة؛
- `scone_dns_geo_by_continent_total{continent="<M49>"}` — حسب
  القارة؛
- `scone_dns_geo_by_country_total{country="<ISO>"}` — حسب البلد
  (محدود بالمعايير نفسها: ≤ 9 قارات، ≤ 250 بلدًا).

### سجل GEOROUTE (الـ wire)

الـ GEOROUTE = **نطاق (scope)** + ≤ 32 **نقطة نهاية** (ترتيب
قانوني عند فك الترميز: أولوية تصاعدية، وزن تنازلي، هدف
تصاعدي؛ تكرار = رفض):

```text
GeoScope   = 0x00 (world)
           | 0x01 continent.v (UN M49 code: AF=2, AS=142, EU=150,
                                NA=3, SA=5, OC=9, AN=999)
           | 0x02 country.v   (ISO 3166-1 numeric code: US=840,
                                TW=158, FR=250…)
           | 0x03 region.v    (OPAQUE ISO 3166-2 subdivision, u32:
                                publisher-defined number, compared
                                as is — no local table)
           | 0x04 asn.v       (AS number, u32)
           | 0x05 prefix.addr[16] || prefix.len u8
             (normalized 16-byte IP prefix: IPv4 = address in the
              first 4 bytes + ZERO tail, len ≤ 32;
              IPv6 = 16 free bytes, len ≤ 128; host bits ALWAYS
              zero — a non-normalized prefix is rejected)
GeoTarget  = 0x00 octets[4]  (binary IPv4 address)
           | 0x01 octets[16] (binary IPv6 address)
GeoEndpoint = target || priority.v || weight.v
GEOROUTE    = scope || count.v(≤32) || endpoints…
```

حدود التحقق (فك الترميز): `priority > 0`، `weight ≤ 100`
(`weight = 0` = نقطة نهاية غير نشطة، لا تُنتخب أبدًا)، TTL
ضمن 1..=2,592,000 ث كأي سجل. البلد/القارة غير المعروفين
للجداول المحلية **مسموحان** على الـ wire: يتراجع التوجيه ببساطة
إلى نطاق أعلى.

**توافقية الـ wire الرجعية (v1 ← v2)**: بايتات v1 دون تغيير —
نطاقات v1 (عالم/قارة/بلد) تحتفظ بـ discriminants الخاصة بها
`0x00..=0x02` وترميزها الدقيق؛ النطاقات الثلاثة الجديدة تأخذ
الـ discriminants التالية (`0x03..=0x05`) بترتيب كلي متسق مع
الترتيب القانوني
(`World < Continent < Country < Region < Asn < IpPrefix`). فاكّ
ترميز v1 يقابل discriminant ≥ `0x03` كان يفشل صرامةً سلفًا
(سجل مرفوض)؛ وبايتات v1 المنتجة تظل تُفك بشكل مطابق (انظر
اختبار `geo_known_bytes`، مجمَّد).

### الانتقاء (الحلّ)

1. **النطاق** — خصوصية تنازلية، **6 مستويات**: **أطول بادئة
   IP مطابقة ← AS الدقيق ← البلد الدقيق ← المنطقة الدقيقة ←
   القارة ← العالم**.
   - *IpPrefix*: بين المسارات التي تطابق بادئتها IP العميل
     (كما يعرفه المحدِّد: `client_ip`، وإلا بادئات الأصل
     المعروفة)، تفوز **الأطول** (`len` أقصى)؛ عند تساوي
     `len`، الأول بالترتيب القانوني (ترتيب slice الـ
     `routes`، مرتّب عند الترميز). التقسيم الفرعي أقل خصوصية
     من بادئة/AS (اللتين تحددان الشبكة الدقيقة) وأقل من البلد
     (ترقيم معتم، موثوق فقط إذا تشارك الناشر والمحدِّد نفسه)،
     لكن أكثر من القارة (إنه محتوى في بلده، ومن ثم بالأولى في
     قارته).
   - *Asn*: رقم AS الدقيق للعميل.
   - *Country*: البلد الدقيق.
   - *Region*: التقسيم الدقيق (معرّف معتم).
   - *Continent*: يوفره المحدِّد **أو يُشتق من البلد** عبر
     الجدول المحلي (`continent_of_country`)؛ البلد غير المعروف
     للجدول يتراجع إلى القارة الصريحة أو العالم.
   - *World*.
   تنتج [`GeoLocation`] إصدار v1 (region/asn/prefixes/client_ip
   غير مضبوطة) سلوك v1 بالضبط: بلد ← قارة ← عالم. لا مسار
   مطابق (بما في ذلك دون نطاق عالمي) ← سلوك DNS كلاسيكي،
   كأن الـ GEOROUTE غير موجود.
2. **الأولوية** — دلالات شبيهة-SRV: فقط مجموعة **الأولوية
   الدنيا** مؤهلة؛ الأولويات الأعلى مستويات **failover**.
3. **الوزن** — داخل المجموعة المنتخبة، سحب **مرجّح حتمي**:
   hash مستقر (SplitMix64) لـ nonce (عدّاد استعلامات المحلّل)
   مقابل الأوزان التراكمية. بلا RNG: استعلامان بنفس الـ nonce
   يعطيان نفس النتيجة، والـ nonces المتزايدة توزّع تناسبيًا مع
   الأوزان. `weight = 0` = غير نشط، لا يُنتخب أبدًا (ولو وحده
   — انتقل إلى المستوى التالي).
4. **Failover الصحة** — نقطة النهاية **غير السليمة** تُوضع
   جانبًا؛ إن كان المستوى الأدنى كله غير متاح، انتقل إلى مستوى
   الأولوية التالي. **المجهول يُحتسب متاحًا** (المجهول لا
   يُعاقب). كل شيء غير متاح ← سلوك DNS كلاسيكي.

### الاستجابة

- عنوان واحد: **A إذا IPv4، وAAAA إذا IPv6** — ترشيح صارم
  حسب العائلة وفق qtype (سؤال A لا يجيب أبدًا بـ IPv6،
  والعكس).
- TTL = الخاص بسجل GEOROUTE المصدر (محدود عند فك الترميز
  بقواعد TTL العامة).
- AA مضبوط (استجابة مرجعية — الـ GEOROUTE سجل موقّع متحقَّق
  منه كأي سجل آخر).
- استجابة فارغة بعد الترشيح (لا مرشح من العائلة الصحيحة، كل
  شيء غير سليم، لا مسار مطابق) ← يواصل المحلّل مساره
  الكلاسيكي (نموذجيًا NODATA: NOERROR، 0 جواب)؛ أكواد rcode
  للخطأ تتبع القواعد العامة (لا تُخزَّن أبدًا).
- سجل A/AAAA كلاسيكي متشارك في المجموعة يأخذ **الأسبقية** على
  الجغرافي (الجغرافي يطبَّق فقط عند غياب جواب wire للـ
  qtype).

### الذاكرة المؤقتة: قرار صريح

قرار التوجيه الجغرافي **لا يُخزَّن أبدًا** تحت
`(qname, qtype)`: فهو يعتمد على نطاق عميل المحلّل، ومفتاح
كهذا كان سيقدّم مسار US لعميل TW. تعاد حساب الأجوبة الجغرافية
عند كل استعلام (الكلفة: select_scope واحد + سحب مرجّح،
ميكروثوانٍ) وتتجاوز الذاكرة المؤقتة. تبقى الذاكرة الكلاسيكية
(qname, qtype) دون تغيير لكل ما عدا ذلك — بما فيها NODATA
الناتج حين لا يقرر الجغرافي شيئًا. وتبقى أكواد rcode للخطأ
غير مخزَّنة أبدًا.

### فحوصات الصحة (`--health-check`)

- `HealthCache` لكل هدف (`GeoTarget`): `probe` = قراءة غير
  حاجبة (حالة طازجة، أو مجهول)، **أبدًا** لا يُطلق فحص من
  مسار الحلّ.
- التحديث: إن كان مرشح منتخب مجهولًا/غائبًا عن الذاكرة،
  يُجدول تحديث واحد كمهمة خلفية
  (`tokio::spawn_blocking`: اتصال TCP حاجب، ممنوع في حلقة
  UDP). مضاد سبام: تحديث واحد في كل مرة لكل هدف (HashSet)،
  قابل لإعادة التشغيل بعد انتهاء التحديث السابق.
- `TcpChecker`: اتصال TCP محدود (مهلة 2 ث) إلى
  `target:port`. **لا يمكن اشتقاق المنفذ من سجل DNS**:
  يضبطه `--health-port` (افتراضي 443). الفاحص **ساذج عمدًا**
  (اتصال ناجح ≠ خدمة سليمة) — قابل للتحسين (HTTP، TLS، مستوى
  التطبيق) دون تغيير الصيغة.
- TTL المدخل: `--health-ttl-secs` (افتراضي 5 ث)؛ مدخل منتهٍ =
  مجهول = متاح.

### الأمان

- سجلات GEOROUTE سجلات موقّعة كأي سجل آخر: يُتحقق منها مقابل
  السلسلة (مالك، تسلسل، record_hash) قبل أي استخدام. **لا ثقة
  شبكية دون تحقق** — GEOROUTE من DHT غير متحقَّح منه لا يجيب
  أبدًا.
- موقع العميل يأتي من **جدول GeoIP المدمج** (تفويضات RIR،
  انظر أعلاه) مشتقًا من IP مصدره — أو من الإعداد المحلي
  الصريح للمحلّل
  (`--geo-ip-table` أو
  `--geo-country`/`--geo-continent`/`--geo-asn`/`--geo-region`،
  الذي يأخذ الأسبقية)، أبدًا لا يأتي من GeoIP API شبكي (لا
  تسريب استعلامات، لا تبعية).
- السحب حتمي ومحلي: لا سر، لا إلغاز مطلوب (الأمان هو أمان
  توقيع السجل، لا أمان السحب).

### مثال كامل (مواصفة مرجعية)

ينشر `www.example.scone` (القمة `example.scone`، المجموعة كلها
تخدم كل اسم فرعي):

| النطاق | نقطة النهاية | الأولوية | الوزن |
|---|---|---|---|
| US (840) | 10.1.0.1 | 10 | 70 |
| US (840) | 10.1.0.2 | 10 | 30 |
| US (840) | 10.2.0.1 | 20 | 100 |
| TW (158) | 10.3.0.1 | 10 | 80 |
| TW (158) | 10.4.0.1 | 10 | 20 |
| TW (158) | 10.2.0.1 | 20 | 100 |
| WORLD | 10.0.0.1 | 100 | 100 |

السلوك المتوقع:

- عميل **US** ← 10.1.0.1 (≈70%) أو 10.1.0.2 (≈30%)؛ إن كان
  كلاهما غير سليم ← failover p20 ← **10.2.0.1**؛
- عميل **TW** ← 10.3.0.1 (≈80%) أو 10.4.0.1 (≈20%)؛
- عميل **FR** (250) ← لا مسار FR ولا EU في المجموعة ← WORLD
  ← **10.0.0.1**؛
- كل شيء غير سليم ← لا قرار جغرافي ← NODATA (NOERROR، 0
  جواب)؛
- سؤال **A** على مسار IPv6 فقط ← جواب فارغ (أبدًا IPv6 في
  A)؛
- نطاق بلا قاعدة منطبقة ← نفس السؤال، سلوك كلاسيكي (NODATA:
  الـ GEOROUTE لا يملك rdata بقيمة A على الـ wire).

### خيارات CLI (`scone relay`)

| الخيار | الافتراضي | الدور |
|---|---|---|
| (لا شيء — GeoDNS مفعّل دائمًا، جدول مدمج) | مفعل | توجيه تلقائي حسب IP المصدر |
| `--geo-ip-table <path>` | — | **جدول GeoIP محلي** (انظر أدناه). يأخذ **الأسبقية** على كل خيارات `--geo-*` الثابتة |
| `--geo-country <u16>` | — | بلد العميل، ISO 3166-1 رقمي (840=US…) — ثابت |
| `--geo-continent <u16>` | — | قارة العميل، UN M49 (150=EU…)؛ مشتقة من البلد إن أُغفلت — ثابتة |
| `--geo-asn <u32>` | — | AS العميل (64500…) — ثابت، جديد في v2 |
| `--geo-region <u32>` | — | تقسيم العميل (معرّف ناشر معتم) — ثابت، جديد في v2 |
| `--health-check` | مغلق | يفعّل الفحوصات (failover الصحة) |
| `--no-health-check` | مغلق | **يعطّل الفحوصات صراحةً** — **يتغلب** على `--health-check` (انظر الأسبقيات) |
| `--health-ttl-secs <u64>` | 5 | TTL مدخل صحة |
| `--health-port <u16>` | 443 | منفذ TCP للفحوصات (غير قابل للاشتقاق من سجل DNS) |

#### جدول GeoIP محلي (`--geo-ip-table`)

ملف نصي محلي للبادئات، يُقرأ **مرة** عند الإقلاع (100,000
قاعدة كحد أقصى، `MAX_GEOIP_RULES`). قاعدة واحدة لكل سطر،
`#` = تعليق، والأسطر الفارغة مهملة:

```text
# prefix/mask        country continent asn     region
10.0.0.0/8           840   3          .       .
2001:db8::/32        250   150        64500   11
192.0.2.0/24         158   9
```

- `prefix/mask`: IPv4 (`len ≤ 32`، يحوَّل إلى صيغة 16 بايت،
  ذيل صفري — نفس اصطلاح الـ wire) أو IPv6 (`len ≤ 128`).
  **يجب أن تكون بتات المضيف صفرًا** (`10.1.2.3/8` يُرفض)؛
- `country`: ISO 3166-1 **رقمي** `u16`، إلزامي؛
- `continent`: UN M49 `u16`، اختياري (`.` أو إغفال = غائب،
  يمكن حينها اشتقاق القارة من البلد)؛
- `asn`: `u32`، اختياري (`.` = غائب)؛
- `region`: `u32` معتم، اختياري (`.` = غائب).

الحلّ: **IP مصدر استعلام DNS** (لكل عميل: UDP `recv_from` /
TCP `peer_addr`؛ مجهول ← IP مرجع المحلّل) يقارن في 16 بايت؛
تفوز القاعدة **بأطول بادئة مطابقة** (عند التعادل، الأولى
بترتيب الملف)؛ لا تطابق ← موقع فارغ (عالمي).

**الصرامة**: الملف مُهيَّأ من المشغّل — السطر غير الصالح
(بادئة مشوهة، بلد غير رقمي، قارة مجهولة، حقل زائد…) **خطأ
إقلاع** يحمل **رقم السطر المخالف**؛ أبدًا لا سطر يُهمَل بصمت،
أبدًا لا جدول جزئي.

#### أسبقيات الخيارات

- **المحدِّد (Locator)**: يأخذ `--geo-ip-table` **الأسبقية**
  على الخيارات الثابتة
  (`--geo-country`/`--geo-continent`/`--geo-asn`/`--geo-region`)،
  فتُهمَل عند تقديم الجدول. دون جدول، تطبَّق الخيارات
  الثابتة.
- **الصحة**: `--no-health-check` **علم مخصص يتغلب** على
  `--health-check` — التوليفة `--health-check
  --no-health-check` تترك الفحوصات معطلة، دون غموض ترتيب
  المُدخل. دون `--health-check`، الفحوصات مغلقة افتراضيًا:
  **المجهول = متاح**، ويخرج الجواب الجغرافي حتى لو كان الهدف
  ميتًا. (يوجد أيضًا `NoopChecker` — سليم دائمًا — لتركيب
  بنية الصحة دون وضع أي نقطة نهاية جانبًا: اختبارات/حذر.)

مثال:

```bash
scone relay --dns 127.0.0.1:5353 \
            --geo-ip-table /etc/scone/geoip.txt \
            --no-health-check
```

مثال v2 ثابت:

```bash
scone relay --dns 127.0.0.1:5353 \
            --geo-country 250 --geo-asn 64500 --geo-region 11 \
            --health-check --health-port 443
```


## DoH / DoT (نقل مشفّر) — عبر واجهة أمامية خارجية

يتحدث خادم DNS الخاص بـ Scone **UDP وTCP خالصين** (RFC 1035 /
7766) — هذا هو النطاق الأصلي، كامل ومُختبَر. النقل المشفّر
نحو *العميل النهائي* (DoH — DNS-over-HTTPS، RFC 8484؛ DoT —
DNS-over-TLS، RFC 7858) **مفوَّض إلى واجهة أمامية قياسية**:
يقدّم Scone البيانات، وتقدّم الواجهة النقل.

لماذا هذا التصميم: خادم DoH أصلي كان سيتطلب كومة HTTPS كاملة
داخل العقدة (شهادات، تجديد، HTTP/2) — سطح تشغيلي كبير مقابل
صفر فائدة قبل وجود مستخدمين نهائيين على جانب المتصفح.
الواجهات القائمة تفعل ذلك أفضل وأمدًا أطول؛ وتبقى العقدة
دنيا.

### مثال: unbound يقوم بـ DoH أمام مُرحّل Scone

`/etc/unbound/unbound.conf`:

```
server:
    interface: 127.0.0.1
    port: 5354
    do-ip4: yes
    do-udp: no
    do-tcp: yes

    # DoH (RFC 8484) on 443
    https-port: 443
    tls-service-key: "/etc/unbound/scone.key"
    tls-service-pem: "/etc/unbound/scone.pem"

forward-zone:
    name: "."
    forward-addr: 127.0.0.1@5353   # the Scone relay (--dns 127.0.0.1:5353)
```

تُستخرج الشهادة (`scone.pem`/`scone.key`) كأي خدمة TLS — مثل
certbot/acme.sh على نطاق المحلّل. ثم يشير عملاء DoH إلى
`https://dns.example.tld/dns-query`.

### مثال: knot-resolver يقوم بـ DoT

`/etc/knot-resolver/kresd.conf`:

```
net.listen('127.0.0.1', 5353, { kind = 'dns' })
net.listen('0.0.0.0', 853, { kind = 'tls' })
tls.cert_file = '/etc/knot-resolver/scone.pem'
tls.key_file  = '/etc/knot-resolver/scone.key'
```

### ما تضيفه الواجهة الأمامية

- **تشفير قناة العميل ← الواجهة** (المقطع العدائي: شبكة
  المستخدم)؛ يبقى مقطع الواجهة ← المُرحّل محليًا (نفس الآلة
  أو شبكة موثوقة).
- **ذاكرة مؤقتة إضافية على جانب الواجهة** (ذاكرة
  unbound/knot أيضًا — غير ضارة، TTLs الخاصة بـ Scone تبقى
  الحد الأعلى).
- **نقطة نهاية مستقرة** (IPv4/IPv6، نطاق) بينما يتحرك
  المُرحّلون.

### ما لا تفعله الواجهة الأمامية

- لا *تتحقق* من شيء: كل جواب يقدمه المُرحّل متحقَّق منه مقابل
  السلسلة قبل تخزينه (انظر "مسار الحلّ"). الواجهة تُرحّل
  أجوبة مرجعية سلفًا.
- لا تستبدل اللامركزية: واجهة DoH خدمة *مُشغَّلة* — خيار
  مشغّل المحلّل، لا خيار البروتوكول. كل مُرحّل Scone يبقى
  قابلًا للاستخدام باستقلال عبر UDP/TCP الأصلي.

### تنفيذ أصلي مستقبلي (موثّق، غير مُلتزَم به)

يبقى نقل DoH أصليًا (`--doh ADDR`) ممكن التصوّر: صيغة الـ wire
متطابقة (RFC 8484 يعيد استخدام رسائل DNS الثنائية)، فسيكون
فك ترميز POST/GET + HTTP/2 خلف وكيل TLS (caddy/nginx يتولى
الشهادات)، والعقدة نفسها تبقى بلا TLS. لا عمل جارٍ — الطلب
سيأتي مع المستخدمين النهائيين.
