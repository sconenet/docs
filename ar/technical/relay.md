# مُرحّل الشبكة (M4) — الهندسة والتدفقات والتحكم عبر CLI

> مواصفة معيارية لمُرحّل شبكة Scone (`scone-network`).
> أي تباعد وثائق/كود = خطأ برمجي (صحّح مصدر الحقيقة).

## نظرة عامة

**المُرحّل** هو عقدة P2P الكاملة لـ Scone: يصون البلوكشين
القانوني (RAM + `NodeStore` بـ redb)، ويرحّل المعاملات
والكتل، وينتج الكتل (نمط devnet)، ويخدّم بروتوكول المزامنة،
وينشر ويحلّ `SignedDnsRecord` في DHT بـ Kademlia، ويكشف
**بروتوكول p2p** (`/scone/reqres/1`) الذي يستعلمه الـ CLI
مباشرة (توحيد RPC←p2p: قناة TCP بـ JSON اختفت).

```text
                    ┌────────────────────────────────────────┐
                    │              scone relay               │
  P2P (libp2p)      │                                        │
  QUIC (udp,        │  Swarm libp2p                          │
  ephemeral port    │  ├─ identify  (address discovery)      │
  by default) ◄─────┤  ├─ ping      (liveness)               │
                    │  ├─ kad       (record DHT)             │
                    │  └─ reqres    (scone-prot. messages)   │
                    │                                        │
                    │  Relay core (single task)              │
                    │  ├─ Blockchain (full validation)       │
                    │  ├─ Mempool (bounded, dedup by TxId)   │
                    │  ├─ BlockBuilder (devnet production)   │
                    │  ├─ Fork parking (bounded, 2048)       │
                    │  └─ Sync driver (batched catch-up)     │
                    │                                        │
  CLI ◄─────────────┤  reqres p2p (QUIC, same messages)      │
                    └────────────────────────┬───────────────┘
                                     │
                              NodeStore (redb)
```

الـ `crates/scone-network` هو **الـ crate غير المتزامن الوحيد**
في فضاء العمل: كل ما تحته (crypto ← core ← protocol ←
blockchain ← storage) يبقى متزامنًا ونقيًا.

## قبول الاتصالات (P1.5)

حدود صارمة على مستوى السرب (سلوك libp2p `connection_limits`،
المدخل الأول في `SconeBehaviour`):

- `MAX_TOTAL_CONNECTIONS = 128` — سقف الاتصالات المنشأة
  (واردة + صادرة) لكل مُرحّل؛ الفائض الوارد يُرفض REFUSED،
  ولا يُصفّ أبدًا؛
- `MAX_PER_PEER_CONNECTIONS = 4` — لا يستطيع قرين واحد احتكار
  الحصة الكلية بفتح اتصالات كثيرة؛
- `MAX_PENDING_INCOMING = 32` — حارس slowloris: أنصاف
  الاتصالات غير المصادَقة لا تنتظر إلى ما لا نهاية.

تكمل هذه الحدود حدود الرسائل القائمة
(`MAX_MESSAGE_LEN` بقيمة 1 MiB) وحدود الميزانيات (مزامنة
`max ≤ 128` كتلة، DNS عبر TCP بقيمة 64 اتصالًا/512 بايت/5 ث).
مهاجم فيض الاتصالات ينال رفضًا، لا نموًا في الذاكرة.

## اكتشاف الأقران

ثلاث آليات متكاملة، بهذا الترتيب من الأسبقية:

1. **بذور صريحة** (`--bootstrap`، multiaddrs كاملة) — تأخذ
   الأسبقية دائمًا؛ تقديم قائمة غير فارغة يستبدل كل ما
   عداها. يفرغ `--no-builtin-seeds` البذور المدمجة لنشرات
   خاصة 100%.
2. **بذور مدمجة** (`builtin_seeds(network)` في
   `scone-network/src/config.rs`) — مجمّدة عند كل إصدار رسمي
   للملف التنفيذي، لكل شبكة. المُرحّل غير المُهيَّأ ينضم إلى
   الشبكة وحده. (فارغة على testnet ما دامت الـ testnet العامة
   غير منشورة.)
3. **دليل متعلَّم** (`<data-dir>/peers.json`) — كل عنوان
   يُتعلَّم عبر `identify` يُحتفظ به (آخر رؤية؛ سقف **2000
   مدخل** — عناوين، لا اتصالات، ~400 KiB في RAM عند الحد
   الأقصى — و**قطع عمر 90 يومًا**: المدخل الذي رُئي آخر مرة
   قبل أكثر من 90 يومًا يُهمل عند الكتابة ويُتجاهل عند
   التحميل، فيبقى الـ 2000 خانة مليئة بأقران معقولين بدل
   أحافير ما قبل التقلب التي ما كانت ستسهم إلا بمهلة اتصال
   عند الإقلاع) ويُحفظ ~مرة/دقيقة عند نبضة الإنتاج. عند
   الإقلاع بلا بذرة وبلا bootstrap، يعاد تركيب الدليل: يجد
   المُرحّل أقرانه المعتادين دون إعداد. إنه ذاكرة مؤقتة:
   ملف غائب/تالف = دليل فارغ، وليس خطأً أبدًا.
4. **mDNS محلي** (`--mdns`) — اكتشاف بلا إعداد على الوصلة
   المحلية: المُرحّلات المجاورة على نفس مقطع الشبكة تجد
   بعضها بلا أي بذرة (مسار devnet بلا إعداد). **الافتراضي:
   مفعل على devnet، مغلق فيما عداها** (شبكة محلية قابلة
   للتصفير شبكة اكتشاف بالتصميم؛ ونشر عام لا يبث
   multicast). السلوك: ربط socket البث؛ فشل الربط (لا
   multicast على الواجهة، بيئة معزولة) **يعطّل** mDNS مع
   تحذير — ليس قاتلًا أبدًا (الاكتشاف رفاهية، وليس
   حبل نجاة). كل جار `Discovered` يغذّي جدول Kademlia
   (`kad.add_address`)، تمامًا كـ bootstrap صريح ناقص
   الإعداد؛ مداخل `Expired` يتتبعها libp2p نفسه (يغلق
   الاتصال بمهلة خاصة به). عضوا `mdns`/`upnp` في السلوك
   `Toggle`s (تفعيل/تعطيل عند البناء،
   `build_behaviour(key, enable_mdns, enable_upnp)`).
5. **UPnP** (`--upnp`، opt-in) — تخطيط منفذ استماع QUIC من قبل
   موجّه المنزل: تصبح العقدة قابلة للوصول من الخارج **دون**
   مُرحّل دائرة. عند `NewExternalAddr`، يُسجَّل العنوان
   الخارجي كعنوان خارجي حقيقي للسرب
   (`add_external_address` — يراه identify/autonat، مرشح
   transport-relay). لا بوابة IGD (`GatewayNotFound`) أو
   بوابة غير قابلة للتوجيه (`NonRoutableGateway`): سجل info
   بسيط، ويُتخطى التخطيط — حالات عادية على شبكة منزلية.
   التخطيط المنتهي (فشل التجديد) تحذير.

يتبع mDNS الشبكة (`--mdns`/`SCONE_MDNS` صريح يفوز دائمًا):
**مفعل افتراضيًا على devnet**، مغلق على testnet/mainnet؛
ويبقى UPnP **معطلًا افتراضيًا**
(`enable_mdns`/`enable_upnp` = `false` في `config.rs`، يفعّل
المُرحّل mDNS لـ devnet): نشر عام لا يبث شيئًا ولا يتحدث إلى
أي موجّه.

### تحسين الطوبولوجيا المحلية (مفعل دائمًا)

يحسّن المُرحّل جواره فعليًا باستخدام محرك `scone-topology`
النقي (انظر وثائق الـ crate). **مفعل دائمًا**؛ الضبط الوحيد
المكشوف هو **ملف تعريف** (`--topology-profile`، متغير البيئة
`SCONE_TOPOLOGY_PROFILE`، الافتراضي `default`):

| الملف | min / target / max | التقييم | لمن |
|---|---|---|---|
| `tiny` | 2 / 4 / 6 | 120 ث | Raspberry Pi، صندوق منزلي، VPS أحادي vCPU |
| `small` | 4 / 8 / 12 | 90 ث | خادم صغير، NAS منزلي |
| `default` | 8 / 16 / 32 | 60 ث | خادم قياسي (الافتراضي) |
| `high` | 16 / 32 / 64 | 45 ث | عقدة سيادية، عمود فقري |
| `very-high` | 32 / 64 / 128 | 30 ث | عقد المؤسسين |
| `devtest` | 2 / 4 / 6 | 5 ث | **مختبر/اختبار فقط** (غير مستقر بالتصميم) |

```
scone relay --topology-profile tiny
```

المعاملات الحامية (تخلف 0.15، تهدئة 600 ث، سماح 120 ث، قياس
15 ث) متطابقة في كل مكان: تحرس الاستقرار ولا سبب لتوسّعها مع
حجم العقدة. الاسم غير المعروف خطأ إقلاع مُصنَّف.

الإعداد غير المتسق (`min > target > max`، عتبة خارج
`[0,1]` — بما فيها `NaN` —، فاصل صفري) **خطأ إقلاع مُصنَّف**،
وليس سلوكًا صامتًا أبدًا.

**الرؤية (`TopologyView`)** — تُغذّى بأحداث السرب:

- نجاح `ping` ← ملاحظة RTT (نافذة وسيط من 8 عينات)؛
- فشل `ping` ← عقوبة موثوقية؛
- استلام `identify` ← العناوين (≤ 4/قرين) + البروتوكولات
  المعلنة (قناع بت: kad/reqres/identify/relay)؛
- اتصال منشأ ← حالة الاتصال، الاتجاه (وارد/صادر)، العمر،
  مُرحّل الدائرة المكتشف؛
- اتصال مغلق ← عقوبة + عدّاد تقلب فقط إن كان غير مُستدرَج
  (الإخلاء الطوعي لا يُحتسب)؛
- فشل اتصال صادر ← عقوبة موثوقية.

الرؤية محدودة (500 قرين؛ بعدها، لا تُحفظ إلا الأقران
المتصلون).

**`kad_required` من الـ kbuckets** — قبل كل تقييم، يمشي
المُرحّل على جدول توجيه Kademlia: يُحمى القرين إن كان
`Connected` في دلو، أو `Disconnected` في دلو **مشبع** (k
= 20). القرين المحمي لا يُختار للإخلاء **أبدًا**.

**حلقة التحسين** — عند فاصل تقييم الملف (60 ث تحت
`default`؛ انظر الجدول أعلاه):

1. إعادة حساب `kad_required` (الـ kbuckets)؛
2. تقييم المحرك (تخلف: فترة سماح 120 ث، تحسين نتيجة أدنى
   +15%، تهدئة إخلاء 600 ث)؛
3. تطبيق القرار: `AddCandidate` ← اتصال بالمرشح؛
   `Replace` ← إغلاق القرين المُخلى (مرة واحدة — تدريجي، بلا
   دوران) ثم اتصال بالبديل؛
4. تُسجَّل لقطة **مقاييس** (مستوى INFO):
   عدادات known/connected/incoming/outgoing/circuit/protected،
   متوسط/وسيط RTT، دوال IP المتمايزة، أقصى تركيز، تقلب
   (استبدالات/انفصالات).

نتيجة الجوار ليست مقياس ثقة **أبدًا** (انظر وثائق
`scone-topology`): لا قرار توافقي يُشتق منها.

### قابلية الوصول (AutoNAT) ومُرحّل النقل (circuit-relay v2)

يشغّل كل مُرحّل AutoNAT (عميل + خادم): تطلب العقدة من
أقرانها محاولة اتصال عائد إليها؛ الحكم (`reachable`: نعم =
قابل للوصول من الخارج، لا = خلف NAT، مجهول = لم يُختبر
بعد) يُحدَّث كل 5 دقائق ويُكشف في `NodeStatus` (الحقل
`nat_reachable`، varint على الـ wire بقيمة 0/1/2) — يعرضه
الـ CLI (`scone status`). العناوين الخاصة تُحتسب
(`only_global_ips = false`): شبكة LAN تختبر قابلية وصولها
المحلية.

المُرحّل القابل للوصول يفعّل circuit-relay v2 **hop** (يستطيع
ترحيل ترافيك لأقران خلف NAT) و**DCUtR** (خرق ثقب: عقدتان
متصلتان عبر دائرة تحاولان اتصالًا مباشرًا وتحرّران
المُرحّل). والمُرحّل المحكوم عليه خلف NAT يطلب تلقائيًا
حجزًا من أول قرين قابل للوصول معروف ويستمع عبره (العنوان
`/p2p/<relay>/p2p-circuit`).

قاعدة الإنتاج: العقدة المحرونة خلف NAT لا ينبغي أن تصبح
منتجة كتل (كمنس/توفر متدنيين) — قاعدة PoS (المقعد = نطاق
حيّ) لا تمنعها بعد؛ يوثَّق كمتطلب تشغيلي قبل الـ testnet
العامة.

## النقل وبروتوكولات libp2p

| البروتوكول | الاسم | الدور |
|---|---|---|
| QUIC (quic-v1) | — | النقل الرئيسي (udp) |
| identify | `/scone/id/1` | اكتشاف عناوين الأقران (يملأ جدول Kademlia) |
| ping | معيار libp2p | الحياة |
| Kademlia | `/scone/kad/1` | DHT: المفتاح = `DomainId` (32 بايت)، القيمة = الترميز القانوني للـ `SignedDnsRecord` |
| request-response | `/scone/reqres/1` | رسائل تطبيق scone-protocol |

### إطار التطبيق (`/scone/reqres/1`)

كل إطار بصيغة `len: u32 BE || bytes` حيث البايتات هي الترميز
القانوني لـ `Message` من `scone-protocol` (المرمّز القائم —
لا صيغة ثانية). الطول محدود بـ `limits::MAX_MESSAGE_LEN`
**قبل** أي قراءة أو تخصيص: القرين المعلن عن إطار أكبر يُرفض
بلا كلفة ذاكرة.

الرسائل المتبادلة (واحدة لكل ذهاب-إياب طلب/استجابة):

| الرسالة | الاتجاه | الرد |
|---|---|---|
| `Hello { version }` | مصافحة | `Hello` (الإصدار المحلي) |
| `Ping` / `Pong` | الحياة | `Pong` |
| `GetBlock { hash }` | استعلام | `Block` (نافذة RAM) أو `Pong` إن كان مجهولًا |
| `GetBlocks { start, max }` | مزامنة | كتلة **واحدة** (ارتفاع `start`)، أو `Pong` إن لا شيء |
| `Block (b)` | ترحيل كتل | `Pong` (إيصال) |
| `Transaction (tx)` | ترحيل معاملات | `Pong` (إيصال) |
| `GetRecord { domain_id }` | DHT محلي | `Record` (الذاكرة المحلية) أو `Pong` |
| `Record (r)` | نشر | `Pong` إن قُبل، وإلا خطأ |

قاعدة: **رد واحد بالضبط لكل طلب**؛ رسائل الإيصال هي
`Pong`. ردود المزامنة تحمل كتلة واحدة في كل مرة — اللحاق
يتكرر على جانب الطالب (انظر "المزامنة"). هذا محدود عمدًا:
لا أكثر من كتلة واحدة قيد الإرسال لكل قرين أبدًا.

## سلوك المُرحّل

### الإقلاع

0. حلّ الشبكة (`--network testnet|mainnet|devnet`، وtestnet
   افتراضي ما دام المشروع قيد التطوير — M8b). دليل البيانات
   **لكل شبكة** (`~/.scone/<network>/`): المخزن غير الفارغ
   الحامل لسلسلة من شبكة أخرى يُرفض (`Corrupted`)؛
1. فتح/إنشاء مخزن redb (`<data-dir>/chain.redb`)؛
2. `load_chain(store, network)`: قمة O(1) + حالات نطاقات
   مرقّمة (نافذة RAM: التكوين + القمة)؛
3. بناء السرب (هوية Ed25519 سريعة لكل جلسة — استمرار هوية
   الشبكة قرار مفتوح)؛
4. تركيب قائمة الإقلاع (انظر
   [اكتشاف الأقران](#اكتشاف-الأقران)): `--bootstrap` صريح
   (ينتهي بـ `/p2p/<peer-id>`) وإلا البذور المدمجة للشبكة
   وإلا الدليل المتعلَّم (`peers.json`)؛
5. اتصال بكل multiaddr وتسجيله في جدول Kademlia (الاتصال
   الميت يُتجاهل — البقية تكوّن الشبكة).

### استلام معاملة (إرسال P2P أو `submit tx` من الـ CLI)

1. فك ترميز محدود صارم (`MAX_MESSAGE_LEN`)؛
2. تحقق تشفيري كامل (`validate_transaction`: ربط owner/key،
   `verify_strict` فوق الحمولة القانونية)؛
3. **منع إعادة التشغيل أولًا** (رخيص، مستقل عن الحالة،
   نهائي)، ثم فحص مسبق للحالة (مرآة رخيصة لقواعد
   `push_block` — الـ PoW، وهو مكلف، لا يُتحقق منه إلا وقت
   الدفع): إعادة تشغيل `RenewDomain` تجيب بـ `TxReplay`، لا
   بخطأ PoW كاذب (إثباتها مرتبط بالانتهاء الذي تجاوزه
   التطبيق الأول). فصل الشبكات مفروض عند الخطوة 2: حمولة
   التوقيع تحقن شبكة **المُرحّل**، فالمعاملة الموقّعة في
   مكان آخر تفشل بـ `InvalidSignature` (wire 2026-09: لا
   حقل `network` بعد الآن)؛
   `RegisterDomain` ← TLD الاسم المسجَّل
   (وإلا `UnknownTld`، D1/M7c) **ومفتوح** (وإلا `TldClosed`،
   M8b) ثم الاسم حر؛ `UpdateDomain` ← نطاق معروف، تسلسل
   دقيق `current + 1`، المالك؛ `RegisterTld` ← TLD حر؛
   `TransferTld`/`RevokeTld`/`SetTldOpen` ← TLD معروف +
   موقّع المالك؛ `AssignDomain` ← مالك الـ TLD + اسم حر؛
   `RenewTld` ← TLD خاص معروف + مالك، مدة ثابتة يعاد اشتقاقها،
   فحص مسبق لنافذة المهلة؛ `RenewDomain` ← نطاق معروف + مالك،
   فحص مسبق لـ PoW التجديد (مرتبط بالانتهاء الحالي) عند
   الارتفاع التالي؛
4. إدراج في الـ mempool (سعة ثابتة، تنقية بالـ `TxId` —
   إعادة إرسال معاملة موجودة في الحوض no-op)؛
5. بث إلى الأقران (عدا المرسل).

### استلام كتلة (P2P، مزامنة، أو ذاتية الإنتاج)

1. `push_block`: التحقق الكامل القائم (الأب = القمة
   القانونية، الارتفاع، جذر Merkle معاد حسابه، كل معاملة
   متحقَّق منها ثم مطبَّقة — ذري لكل كتلة)؛
2. إن قُبلت: يقرأ المُرحّل نتيجة التطبيق
   (`push_block_with_gc` ← hash + النطاقات التي أزالها
   الـ GC الحتمي) ويثبّت عبر `store_block_with_removals`
   (إلحاق دلتا ذري: الكتلة + القمة + الحالات المعدَّلة —
   upserts **وإزالات**: النطاقات المنتهية، الـ TLD الملغاة).
   لذا لا تستطيع إعادة تشغيل أبدًا بعث تسجيل منتهٍ؛
3. تسوية الـ mempool (تُزال المعاملات المضمَّنة)؛
4. بث إلى الأقران (عدا المرسل).

الكتلة غير الصالحة تُرفض بخطأ مُصنَّف؛ ويواصل المُرحّل
العمل. لا panic على بيانات الشبكة. التطبيقات الثقيلة (Argon2
+ التزام redb) تمر عبر `tokio::task::block_in_place` (محرك
مزامنة، قبول p2p، إنتاج): ينقل الـ runtime المهام الجاهزة
إلى عمال آخرين — تطبيق كتلة لم يعد يوقف خدمة DNS أو
المقاييس.

### لقطة DNS (النشر)

بعد كل كتلة مطبَّقة (قبول p2p — إعادة تنظيم مشمولة —، محرك
مزامنة، إنتاج) **وعند الإقلاع** (يجب ألا تعيد إعادةُ تشغيل
NXDOMAIN أسماء حية حتى الكتلة التالية)، ينشر المُرحّل
**لقطة DNS المرجعية** على تغذية `watch` التي يقرؤها سطح DNS
(المواصفة الكاملة في `dns.md`):

- امتداد القمة (المسار الغالب): **دلتا O(الممسوس)**،
  copy-on-write — معاملات الكتلة تسمّي النطاقات الممسوسة،
  زائد إزالات الـ GC الحتمية
  (`AppliedBlock.gc_removed_domains`، المقيَّمة وقت الدفع)؛
- إعادة تنظيم / إقلاع: **إعادة بناء كاملة** (جولة
  `ChainState::dns_facts` مرقّمة واحدة).

### إنتاج الكتل (M5: منتج موقّع)

كل `produce_interval` ثانية (2 ث افتراضيًا): إن كان الـ
mempool غير فارغ، تُجمَّع كتلة بـ `BlockBuilder`
(`timestamp = now`) **موقّعة من منتج مرخّص** (حمولة
`SCONE-BLOCK-V1` في `header.consensus`، انظر
`/docs/en/technical/blockchain.md`) وتتبع بالضبط مسار قبول
كتلة مستقبَلة. المُرحّل بلا معاملات لا ينتج شيئًا.

مفتاح الإنتاج: مفتاح الـ anchor (`--anchor-key`) حين يكون
المُرحّل مسلّحًا بواحد — الـ anchor منتج مرخّص — وإلا مفتاح
devnet الثابت، صالح ما دام مجموع المنتجين فارغًا (إقلاع
مفتوح: التكوين). فور وجود نطاق/TLD حيّ، الكتلة الموقّعة
بمفتاح devnet تُرفض (`InvalidProducer`).

### حلقة الـ anchor (النهائية، M5)

مع `--anchor-key` (ملف مفاتيح `.sconekey`، عبارة المرور عبر
`--anchor-passphrase-env`، الافتراضي `SCONE_ANCHOR_PASS` —
افتراض مكتبة `scone-network` بقيمة
`SCONE_ANCHOR_PASSPHRASE` لا يُبلَغ أبدًا عبر الملف التنفيذي،
clap يتجاوزه دائمًا):

- بعد كل كتلة مقبولة/منتجة، إن كانت هذه العقدة عضوًا في
  اللجنة الحالية **و**تصل اللجنة إلى
  `MIN_FINALITY_COMMITTEE_SIZE`، يوقّع المُرحّل نقطة التفتيش
  المقترحة عبر `SignerGuard` الخاص به
  (`signer-state.dat` في دليل البيانات — مفتاح واحد =
  صوت/epoch، آمن ضد التحطم fail-closed) وينشرها؛
- التوقيعات المستقبلة (`Message::Checkpoint`) تتراكم بـ hash
  `CheckpointData` (محدودة بـ 256 مدخلًا)؛ عند تواقيع
  `quorum_for(حجم اللجنة)` عضوًا على نفس البيانات ←
  `accept_checkpoint` + بث نقطة التفتيش النهائية؛
- المُرحّل بلا مفتاح anchor يبقى **سلبيًا**: يراكم، يُنهي،
  ويرحّل، لكنه لا يوقّع أبدًا؛
- `GetCheckpoints` ← تُقدَّم نافذة `checkpoint_window()`؛
- أي خطأ في الحلقة يُسجَّل ويُبتلع — ليس قاتلًا أبدًا؛
- الحالة (`GetStatus`) تكشف `checkpoints` و`finalized_epoch`.

### توقيف التشعب وإعادات التنظيم (إصلاح الأقلية اللاصقة)

الكتلة الأخت عند نفس الارتفاع، أو الكتلة التي أبوها ليس
القمة الحالية (`ParentNotTip`/`UnknownParent`)، لا تُفقد
**أبدًا**: تُوقَّف (خريطة محدودة، `PARKED_CAP = 2048` كتلة،
~KiB لكل منها — أسوأ حالة RAM محدودة؛ التوقيف الممتلئ يتجاهل
الوافدين الجدد بصمت). الـ hashes المعروضة سلفًا على
`accept_block` تُنقّى (`seen_blocks`): الكتلة الخاسرة المعاد
نشرها لا يعاد تقييمها.

عند كل نبضة `Produce`، يعيد `reconsider_parked` النظر:

1. تفريغ خطي للكتل المتوقفة التي أصبح أبوها القمة؛
2. إن كان فرع متوقف أقوى من القمة الحالية (قواعد اختيار
   الفرع **دون تغيير**: أرضية النهائية، أطول سلسلة، أدنى
   hash)، تبنٍّ — اللاحقة المزاحة تُوقَّف هي أيضًا (طرفا
   التشعب يبقيان قابلين للتقييم).

هذا يفكّ عقدة تبنّت الجانب الخاسر لتشعب متساوي الارتفاع:
الكتلة الفائزة، المعروضة مرة ثم المرفوضة، يعاد تقييمها
دوريًا بدل نسيانها للأبد (اكتشاف chaos-30: كتلتان أختان
بفارق 15 ms).

**ثبات إعادة التنظيم**: تبنّي فرع آخر لا يمر بالإلحاق الرتيب
(`NonMonotonicHeight`). يطبّق المُرحّل `rewind_to_height(نقطة
التشعب)` ثم `persist_state_snapshot` (إعادة كتابة الحالة
الحية من تصدير السلسلة) ثم إعادة إلحاق رتيبة للاحقة الفائزة
(انظر `storage.md`). فشل الثبات يُسجَّل ويُخفَّض (يُشفى عند
الإقلاع عبر إعادة التشغيل) — ليس قاتلًا أبدًا.

## المزامنة (اللحاق)

عند كل اتصال بقرين، يطلب المُرحّل
`GetBlocks(start = local_height + 1)`. كل `Block` مستقبَلة
تُكمل الارتفاع المتوقع بالضبط تُطلق طلب الارتفاع التالي، حتى
النفاد (`Pong` = لا مزيد) أو `MAX_SYNC_ROUNDS` (10,000) دفعة —
حدّ مطلق حتى ضد قرين كاذب. الكتل المستقبلة تمر بتحقق كامل:
لا يستطيع قرين خبيث تمرير أي شيء غير صالح.

### سجلات DHT

- **put** (تدفق API/ويب — أُزيلت قناة الـ CLI السداسية): فك
  ترميز محدود صارم
  (`MAX_DHT_CACHE_ENTRY`)، تحقق مقابل الحالة على السلسلة
  (مالك، تسلسل، `record_hash` معاد حسابه — انظر "تحقق
  السجلات")، ثم `kad.put_record` (تخزين محلي +
  نسخ إلى الأقران الأقربين، `Quorum::Majority` من معامل
  النسخ) وذاكرة redb مستمرة.
- **get** (`domain resolve`): `kad.get_record`؛ المنتظر مرتبط
  بـ `QueryId` الخاص به و`DomainId` المطلوب — الرد لا يحلّ
  إلا الاستعلام المطابق، ومفتاح السجل يجب أن يكون النطاق
  المطلوب بالضبط (يُفحص **قبل** التحقق على السلسلة). ثم
  يُتحقق من النتيجة مقابل السلسلة قبل إعادتها. سقف الطلبات
  المتزامنة: `MAX_DHT_WAITERS` (256)؛ بعده، خطأ فوري. الحلّ
  المتحقَّح منه بنجاح يُكتب في الذاكرة المستمرة (M5):
  القراءات المحلية (`domain_info`) تقدّمه بعدها دون استعلام
  DHT جديد.
- يعمل Kademlia في نمط خادم، بلا TTL للسجلات (السلسلة تحكم
  الصلاحية، لا الزمن).

### تحقق السجلات (قاعدة "السلسلة هي السلطة")

الـ `SignedDnsRecord` المحلول أو المستقبَل لا يُقبل/يُعاد
إلا إذا:

1. كان النطاق مسجّلًا على السلسلة؛
2. `record.owner` = المالك الحالي على السلسلة؛
3. `record.sequence` = التسلسل الحالي على السلسلة؛
4. `record_hash(record.record)` (BLAKE3 معاد حسابه) =
   `record_hash` الملتزَم على السلسلة.

وإلا: رفض صامت على جانب P2P، وخطأ صريح على جانب الـ CLI.
يُتحقق من توقيع Ed25519 للسجل **عند الاستلام** من قبل
المُرحّل (`ResolveLocal`: المفتاح العام للمالك معروف على
السلسلة، والتوقيع يجب أن يفتح — سجل موقّع بمفتاح آخر يُرفض،
`record rejected`)؛ ويُنقل أيضًا للمتحققين المستقبليين — يبقى
الالتزام على السلسلة ضبط السلامة الأولي.

## مقاييس Prometheus

نقطة HTTP (صيغة نص Prometheus 0.0.4، عرض مكتوب يدويًا — لا
تبعية جديدة) تخدمها مهمة مخصصة:

- **معطّل افتراضيًا**: لا يعمل أي خادم HTTP بدون `--metrics-addr` (القياسات اختيارية).
- `--metrics-addr ADDR:PORT`：يربط نقطة النهاية على هذا العنوان (مثل `127.0.0.1:9101` محليًا، `0.0.0.0:9101` للخارج).
- `--metrics-token TOKEN`: ينتقل إلى نمط **خاص** —
  `Authorization: Bearer *** مطلوب (مقارنة زمن-ثابت،
  `401` وإلا؛ التوكن لا يظهر في السجلات ولا في العرض).
- فشل الربط **يعطّل النقطة** (تحذير غير قاتل) — وليس العقدة
  أبدًا.

يُعلن الربط الفعلي على stdout (عقد قابل للقراءة آليًا، مثل
`p2p:`): سطر `metrics: <addr>` فور الاستماع.

**19 عدادًا** (`counter`، رتيبة — المسارات الساخنة:
`fetch_add(Relaxed)` على `Arc<Metrics>` مشترك، وليس أبدًا
مُدخل توافق):

| المجموعة | السلاسل |
|---|---|
| السلسلة | `scone_blocks_applied_total`, `scone_blocks_rejected_total`, `scone_checkpoints_signed_total`, `scone_checkpoint_sigs_received_total` |
| Mempool | `scone_txs_admitted_total`, `scone_txs_rejected_total`, `scone_txs_evicted_grace_total`, `scone_txs_included_total` |
| DNS | `scone_dns_queries_total`, `scone_dns_cache_hits_total`, `scone_dns_cache_misses_total`, `scone_dns_local_chain_total`, `scone_dns_dht_answers_total`, `scone_dns_rejected_unverified_total` |
| DHT | `scone_dht_pulls_issued_total`, `scone_dht_negative_hits_total`, `scone_dht_negative_expired_total`, `scone_dht_negative_capped_total`, `scone_dht_cache_evictions_total` |
| شبكة الأقران | `scone_peer_connections_established_total`, `scone_peer_connections_closed_total`, `scone_peer_connections_incoming_total`, `scone_peer_dial_failures_total`, `scone_peer_blocks_received_total`, `scone_peer_transactions_received_total` |

**6 مقاييس gauge** (`scone_height`، `scone_mempool`،
`scone_peers`، `scone_domains`، `scone_finalized_epoch`،
`scone_addr_book_entries`) — الخمسة الأولى تُحدَّث كل 15 ث عبر
قناة `RelayCommand` (نفس مسار `status` في الـ CLI — مصدر حقيقة
وحيد)؛ و`scone_addr_book_entries` يُصانه السجل مباشرة (يُحدَّث
عند كل إدراج في دفتر العناوين — مصدر الحقيقة).

اختبار E2E: `metrics_endpoint_public_and_private` (200 +
العرض، 401 دون توكن/بتوكن خاطئ، 200 مع Bearer).

## تحكم الـ CLI (توحيد RPC←p2p)

أُزيل خادم RPC بـ TCP JSON: يتحدث الـ CLI (وجسر axum الخاص
بالمسجّل) بروتوكول p2p **مباشرة** — نفس الـ wire
(`/scone/reqres/1`)، نفس المعالجات على جانب المُرحّل، صفر
قنوات متوازية. كل أمر يفتح اتصال QUIC إلى multiaddr العقدة
(`--peer`)، يتبادل `Message` واحدة، يغلق.

رسائل التحكم التي يخدمها المُرحّل:

- `GetStatus` ← `NodeStatus { network, nat_reachable, tip,
  height, domain_count, mempool, peers, finalized_epoch,
  checkpoints, fresh_operators }` (يعرضه `scone status` —
  `fresh_operators` = المشغّلون ذوو نبضة طازجة، RFC
  إثبات الخدمة)؛
- `LookupName { name }` ← `NameState` (الحالة على السلسلة،
  مثل `lookup`)؛
- `GetOwnedNames { owner }` ← `OwnedNames` (النطاقات الحية +
  TLD الخاص بـ `OwnerId`)؛
- `Transaction (tx)` ← إرسال مع بث حر (يعيد المُرحّل النشر
  إلى الأقران)؛
- `GetRecord { domain_id }` / `Record (r)` — حلّ ونشر DHT (مثل
  `scone domain resolve` على جانب الـ CLI)؛
- رفض التطبيق ← `Message::Error(msg)` (يصل العميل كرسالة
  مقروءة، لا EOF).

يرفع العميل سرب libp2p أدنى (request-response + identify)،
مهلة استدعاء 30 ث (ذهاب-إياب 20 ث). الافتراضي `--peer`:
`/ip4/127.0.0.1/udp/4001/quic-v1/p2p/12D3KooW…` (عقدة تطوير
محلية؛ الـ multiaddr الكامل بمعرّف القرين الحقيقي يعلنه
المُرحّل على stdout عبر سطر `p2p:`).

تبقى قناة `RelayCommand` الداخلية لسطح DNS المدمج
(`ResolveLocal`، ذهاب-إياب داخل العملية، وليس منتظر DHT
أبدًا — انظر `dns.md`).

unreachable — is a relay running?"، خروج غير صفري. يُحتفظ

سكربتات فقط).

### الإعداد عبر البيئة (`.env`)

عند الإقلاع، يحمّل `scone` (عبر `dotenvy`، قبل تحليل clap)
ملف `.env` من الدليل الحالي: الملف الغائب = no-op صامت، وليس
خطأً أبدًا. تصبح القيم المحمّلة **خط الأساس البيئي**
للخيارات التي تصرّح بمتغير (`env = "…"` في `cli.rs`)؛
**العلم الصريح في CLI يفوز دائمًا** على `.env`، و`.env` يفوز
على الافتراضيات المدمجة:

```text
علم CLI صريح  >  متغير .env  >  الافتراضي المدمج
```

يوثّق الملف `.env.example` في جذر المستودع كل متغير (انسخ إلى
`.env` وعدّل؛ الـ `.env` **في gitignore** — لا تدخل `.env`
حقيقيًا في commit أبدًا). المتغيرات:

| المتغير | العلم المرآة | الدلالة |
|---|---|---|
| `SCONE_NETWORK` | `--network` | `testnet` (الافتراضي)، `mainnet`، `devnet` |
| `SCONE_DATA_DIR` | `--data-dir` | دليل البيانات (الافتراضي `~/.scone/<network>/`) |
| `SCONE_LISTEN` | `--listen` | multiaddr استماع P2P (الافتراضي: كل الواجهات، منفذ سريع) |
| `SCONE_BOOTSTRAP` | `--bootstrap` | بذور bootstrap، **قابل للتكرار** (سطر لكل قيمة — dotenvy يراكم)؛ يستبدل البذور المدمجة |
| `SCONE_GENESIS` | `--genesis` | ملف التكوين (عقد المؤسسين) |
| `SCONE_MDNS` | `--mdns` | اكتشاف mDNS محلي (`true` = مفعل، `false` = مغلق؛ الافتراضي: مفعل على devnet، مغلق فيما عداها) |
| `SCONE_UPNP` | `--upnp` | تخطيط منافذ UPnP (`true` = مفعل) |
| `SCONE_DNS_ADDR` | `--dns` | عنوان ربط خادم DNS عبر UDP |
| `SCONE_DNS_UPSTREAM` | `--dns-upstream` | تراجعات تكرارية، **قابلة للتكرار** |
| `SCONE_DNS_CACHE_LIMIT` | `--dns-cache-limit` | سقف مداخل ذاكرة DNS |
| `SCONE_DNS_CACHE_MAX_MEM` | `--dns-cache-max-mem` | سقف ذاكرة ذاكرة DNS (مثل `64MB`) |
| `SCONE_DNS_MAX_INFLIGHT` | `--dns-max-inflight` | سقف استعلامات DNS المتزامنة |
| `SCONE_METRICS_ADDR` | `--metrics-addr` | metrics endpoint address (`ADDR:PORT`)|
| `SCONE_METRICS_TOKEN` | `--metrics-token` | توكن bearer لنقطة المقاييس |
| `SCONE_TOPOLOGY_PROFILE` | `--topology-profile` | ملف الطوبولوجيا (`tiny`/`small`/`default`/`high`/`very-high`/`devtest`؛ الافتراضي `default`) |
| `SCONE_ANCHOR_KEY` | `--anchor-key` | ملف مفاتيح الـ anchor (نقطة تفتيش + إنتاج) |

الـ `SCONE_ANCHOR_PASS` ليس خيار متغير: إنه الاسم الافتراضي
**للمتغير الحامل لعبارة مرور الـ anchor**
(`--anchor-passphrase-env`، الافتراضي `SCONE_ANCHOR_PASS` على
مستوى الـ CLI) — يقرأ المُرحّل عبارة المرور من المتغير الذي
يسمّيه هذا العلم.

**الـ anchor التلقائي (مفعل افتراضيًا)**: دون `--anchor-key`،
يُولَّد/يُثبَّت ملف مفاتيح anchor تلقائيًا في دليل البيانات
(`anchor.sconekey`، عبارة المرور `SCONE_ANCHOR_PASS` إن
عُرِّفت، وإلا تُولَّد عشوائيًا وتُكتب في `anchor.pass`) — يصبح
المُرحّل منتجًا فور امتلاك مفتاحه نطاقات/TLD حية (أهلية PoS
ليست مجانية أبدًا). يُبقي `--no-anchor-auto` المُرحّل سلبيًا
بصرامة. متغير البيئة الافتراضي لـ `--anchor-passphrase-env`
هو `SCONE_ANCHOR_PASS`.

الـ `--network`: يتبع الافتراضي **البنية** (mainnet على ملفات
مفعّلة بالـ mainnet، وtestnet خلاف ذلك)؛ و`devnet` هي الشبكة
المحلية القابلة للتصفير (تكوين `scone-devnet` خاص، PoW شبه
صفري 0..=2 بت — محو `~/.scone/devnet/` وإعادة الإطلاق يصفّر
السلسلة). يضبط التكوين، وصعوبات PoW، ودليل البيانات
الافتراضي (`~/.scone/<network>/`)؛ والمعاملة من شبكة أخرى
تُرفض بشكل مُصنَّف (`WrongNetwork`).

السطحية السداسية غير المتصلة (الأمران الفرعيان `tx` و
`submit`) اختفت (remove-tx-surface-v2). يغطي الـ CLI مسارات
المستخدم (`domain register`، `domain renew`، `domains`)
**و**عائلة M8b كأوامر من الدرجة الأولى: `tld open`،
`tld transfer`، `tld revoke`، `domain assign`،
`domain transfer`. مطالبات `register` تعدّن الـ PoW الخاص بها
عند صعوبة الشبكة (ميلي ثوانٍ على devnet).

تضبط الخيارات `--geo-*`/`--health-*` الـ GeoDNS وفحص الصحة
**لمحلّل DNS المدمج**: الدلالات الكاملة، ترتيب الأسبقية،
وجدول GeoIP المحلي موثّقة في
[`dns.md`](dns.md#geodns-geographic-routing) — التوجيه
الجغرافي **مفعل دائمًا** (جدول GeoIP مدمج، لا خيار مطلوب)؛
و`--health-check` مغلق افتراضيًا، والمسار الكلاسيكي دون
تغيير.

### `domain register|update` (M5) — معاملات موقّعة في أمر واحد

تسلسل هذه الأوامر بناء ← توقيع (مخزن المفاتيح) ← إرسال ←
(تأكيد) في استدعاء واحد.

- **register**: يبني `RegisterDomain` موقّعة (الطابع الزمني =
  الآن، إثبات فارغ في devnet)، يرسلها، ينتظر تأكيدًا على
  السلسلة (تسلسل ≥ 0، مهلة 30 ث). الاسم المسجَّل سلفًا
  يُرفض على جانب العميل **وعلى** جانب المُرحّل.
- **update**: ملف السجلات هو مصدر الحقيقة الوحيد. التسلسل
  (على السلسلة + 1) و`record_hash` (BLAKE3 القانوني لسجلات
  الملف) **مشتقان**، لا يُدخلان أبدًا: الموقّع والمتحققون لا
  يستطيعون التباعد. بعد تأكيد الـ UpdateDomain، يُنشر
  الـ `SignedDnsRecord` (سجلات الملف + المالك + توقيع Ed25519
  فوق الترميز القانوني) إلى الـ DHT عبر `put_record` (الذي
  يعيد التحقق مقابل السلسلة). النطاق غير المسجّل، أو هوية
  غير مالك، أو خطأ ملف، تفشل بنظافة، دون لمس السلسلة.

#### ملف السجلات

نص، سجل لكل سطر، `#` = تعليق، والأسطر الفارغة مهملة؛ الترميز
القانوني المرتّب يجعل ترتيب الملف بلا أثر على الـ hash
الملتزَم. الملف هو المجموعة **الكاملة** (التحديث يستبدل، لا
يدمج). الأنواع:

```text
A 192.0.2.1
AAAA 2001:db8::1
CNAME www.example.uip
NS ns1.example.uip
MX 10 mail.example.uip
TXT free text (spaces normalized)
```

أخطاء مُصنَّفة: نوع مجهول، IP/اسم غير صالح (مع رقم السطر)،
مجموعة فارغة، تكرار، > `MAX_RECORDS_PER_SET`.

## `--genesis` (المؤسسون)

`scone relay --genesis genesis.bin` — **عقد المؤسسين فقط**
(حملة kickstarter؛ ينتج الملفَ الملفُ التنفيذي
`scone-genesis`). القواعد المعيارية:

1. يُرفض الملف **قبل القراءة** إن تجاوز 1 MiB، ثم يُفك بصرامة
   (`decode_complete`: لا بايتات زائدة). hash الكتلة 0
   **يُعاد حسابه**، ولا يُقرأ من الملف أبدًا.
2. تحقق دلالي: ارتفاع 0، و`consensus` يبدأ بمعرّف الشبكة
   المطلوبة (`--network`)، بلا معاملات، وmanifest تخصيصات
   قانوني. أي خرق = خطأ مُصنَّف عند الإقلاع (لا panic أبدًا،
   الـ daemon لا ينطلق).
3. دليل بيانات **بِكر**: تولد السلسلة على التكوين المخصَّص —
   التخصيصات تطبَّق في RAM **قبل أي كتابة قرصية**، ثم تُثبَّت
   (حالات مزروعة + كتلة تكوين تحت مفتاح meta). لذا لا
   تستطيع أول كتلة منتجة إلا مدّ التكوين المخصَّص.
4. دليل بيانات **منتج سلفًا**: تكوين ولادة المخزن هو
   `prev_hash` للكتلة 1 (ذاتي الشهادة). تساوي hash الملف =
   OK صامت (الخيار **زائد عن الحاجة بعد الإقلاع الأول**)؛
   الاختلاف = رفض مُصنَّف — العقدة تنضم لشبكة عبر المزامنة،
   لا عبر `--genesis` أبدًا.
5. إعادة تشغيل **دون** الخيار: دليل بيانات مولود من مؤسس
   يستعيد تكوينه المخصَّص عبر مفتاح meta (إعادة ربط RAM عند
   كل إقلاع).

تثبيت hash التكوين الثابت (مضاد تباعد الشبكات) مسار عمل
منفصل.

### manifest الملف التنفيذي `scone-genesis` (kickstarter)

يحضّر الملف التنفيذي `scone-genesis` (الـ crate
`scone-genesis`) الـ manifest `genesis-manifest.json` (صيغة
`ALLOC-V1`) ثم ينتج `genesis.bin`. القواعد المعيارية:

- ينشئ `scone-genesis new --network <network>` manifest فارغًا؛
  وتدير `add`/`remove`/`list` التخصيصات، وتنتج `build` ملف
  `genesis.bin` (+ hash)، ويعيد `verify` التحقق منه.
- يتطلب `add domain <name>` أن يكون **TLD النطاق مخصصًا
  سلفًا في الـ manifest** (رفض فوري وإلا — كانت السلسلة
  سترفضه عند تطبيق التكوين)؛ و`valid_until` الخاص به
  **تلقائي**: `born_at + 1 سنة` (الـ default_validity للـ
  manifest)، لا يُدخل يدويًا أبدًا.
- `add tld <name>`: **مفتوح افتراضيًا** (لا أحد، خدمة ذاتية،
  أرضية سنة، مالك = صفر على الـ wire — النوع `0x03`)؛
  و`--private` = خاص (مالك، مدة تكوين `born_at +
  TLD_TERM_SECS` — 3 سنوات، دورة حياة قياسية: `RenewTld`،
  مهلة 60 يومًا).
- ترتيب قانوني بالاسم (محتويات متساوية ⇐ نفس الكتلة ⇐ نفس
  الـ hash، أيًّا كان ترتيب الإدراج)؛ التكرارات مرفوضة.

## الحدود وضمانات الذاكرة

| المورد | الحد |
|---|---|
| إطار P2P | `MAX_MESSAGE_LEN` (1 MiB) قبل التحليل |
| Mempool | 4096 معاملة (رفض مُصنَّف بعدها)؛ `MAX_PENDING_PER_DOMAIN = 4` معاملات معلقة لكل نطاق |
| سماح Mempool | `MAX_GRACE_ATTEMPTS = 10` إعادة إدراج لمعاملة مطراحة لسبب غير نهائي (≈ 7 دقائق عند 40 ث/دورة)، ثم إخلاء |
| توقيف التشعب | `PARKED_CAP = 2048` كتلة متنافسة |
| نقاط التفتيش المتراكمة | `MAX_PENDING_CHECKPOINTS = 256` (إخلاء: أدنى hash بيانات) |
| منتظرو DHT المتزامنون | `MAX_DHT_WAITERS` (256)؛ بحث DHT محدود بـ 30 ث (`DHT_LOOKUP_TIMEOUT`) |
| كتل لكل رد مزامنة | 1 لكل ذهاب-إياب؛ ≤ 10,000 دفعة لكل قرين (`MAX_SYNC_ROUNDS`)؛ حدّ بروتوكولي `MAX_BLOCKS_PER_REQUEST = 128` على الطلب |
| سجل DHT | `MAX_DHT_CACHE_ENTRY` (64 KiB) |
| ذاكرة DHT المستمرة (قرص) | حد LRU مزدوج: `DHT_CACHE_MAX_ENTRIES` (100,000 مدخل) و`DHT_CACHE_MAX_BYTES` (2 GiB) — أيهما أصاب أولًا يخلي بترتيب المفتاح؛ إخلاء الـ GC في نفس المعاملة كالكتلة (النطاق الذي تقتله GC السلسلة لا يخلف مدخلًا يتيمًا أبدًا) |
| الذاكرة السلبية DHT | `DHT_NEGATIVE_TTL_SECS` (30 ث)، سقف FIFO `DHT_NEGATIVE_CAP` (4,096) |
| السلسلة في RAM | التكوين + نافذة القمة (التاريخ يُقدَّم من المخزن) |

قاعدة مضادة للحلقات (H2): لا يعاد بث المعاملة إلا إذا أُدرجت
**فعلًا** في الـ mempool (الرؤية الأولى)؛ والتكرار (الموجود
في الحوض أو في السلسلة سلفًا) لا يعاد ترحيله أبدًا. الكتلة
القانونية سلفًا تُكتشف وتُهمَل قبل `push_block` (لا إعادة
تخزين، لا إعادة بث).

قرارات مفتوحة: استمرار هوية الشبكة للمُرحّل، بث gossip
(حاليًا: unicast طلب-استجابة لكل قرين معروف). محلولة منذ
الكتابة الأولى: اختيار فرع حقيقي (توقيف + reconsider_parked،
انظر أعلاه)، توافق PoW (منتج موقّع + لجنة anchor)، محلّل
DNS (السطح `--dns`، انظر dns.md)، قناة التحكم (توحيد
RPC←p2p: لا TCP JSON بعد الآن).

## الإغلاق الرشيق (SIGTERM / SIGINT)

يلتقط daemon الـ `scone relay` (في المقدمة) إشارتَي SIGTERM
وSIGINT عبر `tokio::signal`: عند الإشارة، يُلغى مستقبل
`Relay::run` (`tokio::select!` في الملف التنفيذي)، مما يُفلت
سرب libp2p ويغلق مقابس QUIC. ثم يوقف runtime توكيو (tokio) بإغلاق
محدود (≤ 2 ث) يُفلت مهام DNS المنفصلة (UDP/TCP) ويغلق
مقابسها — الهدف أن `kill` لا يخلف socket UDP يتيمًا (حالة
ملاحظة على testnet 60). الإغلاق المدفوع بإشارة يسجّل
`relay shutting down (signal)` (INFO، stderr) ويخرج بكود خروج
**0**: الإغلاق المطلوب ليس فشلًا. إن فشل تركيب المعالج، يطبَّق
السلوك الافتراضي للإشارة (تدهور، لا panic أبدًا).


## نقل Tor (قضية مفتوحة)

لا يعبر QUIC/UDP وسطاء SOCKS الخالصين، فلا يستطيع المُرحّلات
اليوم العمل عبر Tor ببساطة. نقل Tor أصلي لـ libp2p (مُرحّل
بعنوان onion) هو المسار المتتبَّع للأمام — انظر دليل مقاومة
الرقابة على الموقع للحالة الراهنة وجسر CNAME بقيمة `.tor`
(أسماء مقروءة للخدمات الخفية، مدعوم اليوم).
