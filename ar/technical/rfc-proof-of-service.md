# RFC — إثبات التشغيل ولجنة النهائية (proof-of-service)

> الحالة: معيارية — منفَّذة من البداية إلى النهاية (الخطوات 1
> إلى 5: core/protocol/blockchain/network/CLI؛ هذه الوثيقة هي
> الصيغة المُجمَّعة). كل قاعدة أدناه متحقَّق منها مقابل الكود؛
> الثوابت المذكورة هي القيم المُرمَّزة.
> التاريخ: أكتوبر 2026 (تجميع معياري). تمسّ:
> `scone-core`، `scone-protocol`، `scone-blockchain`،
> `scone-network`، `scone` (CLI).

## 1. الدافع

مجموع النهائية هو مجموع المالكين (مالكو النطاقات/TLD
الحية). الملكية تمنح مقعدًا — **التشغيل** لا يمنح شيئًا.
يربط هذا RFC حق توقيع نقاط التفتيش بإثبات تشغيل مُرحّل
متصل، دون تقييد الملكية أبدًا:

- **حرية مصانة**: يبقى الـ TLD الخاص قابلًا للإسناد دون شرط
  نشاط ما دامت مدته تُجدَّد (`RenewTld`، مدة 3 سنوات). فقط
  *توقيع نقاط التفتيش* يُكتسب بالحضور.
- **حافز على التشغيل**: تشغيل TLD خاص (أو أي مقعد) = الجلوس
  في اللجنة. يشارك المشغّل في إبقاء الشبكة قائمة والبروتوكول
  يعترف بذلك.
- **لامركزية قابلة للقياس**: تصبح اللجنة مجموعة المشغّلين
  *المتصلين فعلًا*، لا مفاتيح ساكنة.

## 2. نظرة عامة

معاملة `Heartbeat` خفيفة (discriminant بقيمة `0x71`)، موقّعة
من مفتاح **مشغّل**، تُصدر مرة في كل epoch. تحتفظ الحالة بنافذة
منزلقة من النبضات الحديثة. تُنتخب لجنة كل epoch **من المجموعة
الفرعية للمجموع التي لمشغّلها الفعلي نبضة طازجة**. دون نبضة:
لا توقيع، لكن لا فقدان لحقوق الملكية.

## 3. معاملة الـ Heartbeat

```
Heartbeat {
    operator: PublicKey,     // Ed25519 key of the operator (the signer)
    owner: OwnerId,          // identity RE-DERIVED from operator (never trusted)
    tip_seen: [u8; 32],      // last tip seen by the node
    height_seen: u64,        // corresponding height
    timestamp: u64,          // Unix seconds
} + Ed25519 signature over the canonical payload (network injected)
```

الجسم الموقّع (wire، `scone-protocol`):
`operator[32] ‖ owner[32] ‖ tip_seen[32] ‖ height_seen.v ‖
timestamp.v ‖ operator[32]` (يظهر مفتاح الموقّع في ذيل الجسم،
كما في كل معاملة) `‖ signature[64]`، أي ~230 بايتًا مرمَّزة —
**بلا PoW**: الكلفة هي الحضور المستمر (نبضة واحدة لكل epoch،
لأشهر).

الموقّع هو المشغّل نفسه: يُعاد اشتقاق `owner` دائمًا من
`operator` (لا يؤخذ من المُدخل أبدًا)، ويرفض فك الترميز بخطأ
مُصنَّف (`InvalidOwner`) مفتاحَ توقيع يختلف عن حقل
`operator` الترويسي.

- يخدم `tip_seen`/`height_seen` الرصد (كشف المشغّلين المعيبين
  أو المتأخرين)؛ ولا يؤثران في الصلاحية (عقدة متأخرة قليلًا
  تبقى عقدة حية).

### 3.1 تحقق نقي (scone-core)

1. توقيع Ed25519 صالح فوق الحمولة القانونية للشبكة.
2. `owner` == الهوية المشتقة من `operator` (وإلا
   `InvalidOwner`) — يُفحص عند الترميز وفك الترميز وبواسطة
   `validate()`.

### 3.2 قواعد الحالة (التطبيق، scone-blockchain)

عند تطبيق نبضة في كتلة ناقلة بارتفاع `block_height` (كل رفض
يسبق أي تعديل):

1. **منع إعادة التشغيل بين الـ epochs**: `timestamp` تصاعدي
   بصرامة لكل مشغّل — رفض مُصنَّف `StaleHeartbeat` إذا كان
   `timestamp <= operator_last_hb[operator]`.
2. **التفرد لكل epoch**: لا تُقبل إلا نبضة واحدة لكل
   (`operator`، epoch الكتلة الناقلة) — التكرار يُرفض بخطأ
   مُصنَّف (`HeartbeatDuplicate`). الـ epoch هو
   `block_height / epoch_min_blocks` (نفس تعريف النهائية، وليس
   ثابتًا جديدًا أبدًا).
3. إدراج مُسجَّل في اليوميات في النافذة + تحديث
   `operator_last_hb` (قابل للعكس عند إعادة التنظيم، تراجع
   مطابق بالبت).

### 3.3 مضاد السبام

- معاملة واحدة مقبولة لكل مشغّل لكل epoch — أقصى تدفق هو
  `pool_size / epoch_secs`، مهمل.
- بلا رسوم (قبل الطبقة الاقتصادية): المعدل محدود بنيويًا.

## 4. تفويض التشغيل

يمرّ رابط المقعد ← المشغّل عبر معاملتين مخصصتين:

- `SetTldOperator { tld_id, operator }` (discriminant بقيمة
  `0xA9`)، موقّعة من المالك **الحالي** للـ TLD **الخاص**
  (الـ TLD المفتوح لا أحد يوقّعه شرعيًا — رفض مُصنَّف
  `TldIsOpen`). `operator: None` = إلغاء، والعودة إلى
  التشغيل الذاتي بمفتاح المالك؛ قابل للإلغاء فورًا.
- `SetDomainOperator { domain_id, operator }` (discriminant
  بقيمة `0x5E`)، موقّعة من المالك الحالي للنطاق. نفس
  الدلالات.
- لا تحمل `RegisterTld` / `RegisterDomain` / `AssignDomain`
  أي حقل `operator`: رابط المقعد ← المشغّل دائمًا واقعة
  حديثة على السلسلة، تُحلّ عند القمة.

خيار المشغّل على الـ wire قانوني: `0x00` = `None` (تشغيل
ذاتي)، `0x01` = مفتاح خام 32 بايت؛ أي قيمة أخرى تُرفض عند فك
الترميز.

تحافظ الحالة على:

```
seat_operators: HashMap<OwnerId, OperatorKey>   // per seat
operator_seats: HashMap<OperatorKey, u64>       // bounded counter
operator_last_hb: HashMap<OperatorKey, u64>     // last accepted ts
```

قواعد التطبيق (`apply_seat_operator`، مُسجَّلة في اليوميات):

- **Idempotence**: إعادة التفويض لنفس المشغّل (أو إلغاء تفويض
  غير موجود) عملية no-op غير مُسجَّلة (التراجع المطابق بالبت
  يقتضيها).
- **حد ضد الإيجار**: لا يمكن تفويض مشغّل إلا من **مقعد واحد
  وحيد** في كل مرة (`MAX_SEATS_PER_OPERATOR = 1`). مقعد ثانٍ
  يفوّض مشغّلًا محجوزًا ← رفض مُصنَّف
  `OperatorAlreadyDelegated`. السبب: دون حد، يبيع مشغّل كبير
  التوقيع بالجملة ويعيد خلق المركزية — بالضبط ما تريد اللجنة
  المنتخبة تجنّبه.

## 5. نافذة الطزاجة

### 5.1 نافذة منزلقة

```
recent_heartbeats: BTreeMap<(epoch, OperatorKey), ()>
```

- يُدرج المدخل عند تطبيق نبضة صالحة (§3.2).
- تنقية حتمية عند كل تطبيق كتلة
  (`gc_heartbeats_journaled`): يُزال أي مدخل لـ epoch بقيمة
  `e` حيث `e + HEARTBEAT_WINDOW_EPOCHS <= epoch` (مُسجَّل — قابل
  للعكس عند إعادة التنظيم، كطوابير الانتهاء).
- `HEARTBEAT_WINDOW_EPOCHS = 2`: الـ epoch الحالي + السابق —
  يستطيع المشغّل تفويت epoch واحد دون فقدان الطزاجة، والثاني
  يُنهيها.
- **سقف ذاكرة بنيوي**: تحتفظ النافذة على الأكثر
  `HEARTBEAT_WINDOW_EPOCHS × operator_count` مدخلًا (واحد لكل
  مشغّل لكل epoch، مفتاح tuple)؛ و`operator_last_hb` محدود
  بعدد المشغّلين ولا يُنقَّى أبدًا (قاعدة منع إعادة التشغيل
  رتيبة).

### 5.2 الطزاجة

"طازج" = وجود مدخل `(e, operator)` لأجل `e` في
`[epoch − HEARTBEAT_WINDOW_EPOCHS + 1, epoch]`. بما أن الحالة
تنقّي عند كل كتلة، فالوجود في `recent_heartbeats` هو الطزاجة
نفسها (`operator_is_fresh`).

### 5.3 المشغّل الفعلي

**المشغّل الفعلي** للمقعد هو `seat_operators[seat]` إن وُجد
تفويض حيّ، وإلا فمفتاح المالك (`effective_operator`). يوقّع
المقعد بذلك المفتاح الفعلي — التفويض ينقل حق التوقيع، لا
الملكية أبدًا.

## 6. انتخاب اللجنة

```
eligible = { effective operators of the frozen pool's seats
             (banned key excluded) having a fresh heartbeat }

if |eligible| >= MIN_FINALITY_COMMITTEE_SIZE (= 4) :
    committee = select_committee(seed, eligible)   // existing draw
else :
    committee = select_committee(seed, pool)       // safe degradation
```

تفاصيل معيارية (متحقق منها في `finality.rs`، محدَّدة في
`/docs/en/technical/blockchain.md` § "المقاعد ولجنة النهائية"):

- المجموع `pool` هو المجموع **المجمّد عند آخر نقطة تفتيش
  نهائية** (`FinalizedBase.pool` — وليس الحالة الحية أبدًا):
  رؤية محلية ستتباعد بين العقد ولن يتشكل النصاب أبدًا؛
- تُشتق البذرة `seed` من hash محتوى نقطة التفتيش السابقة
  (`signing_hash`)؛
- يُحلّ كل مقعد من المجموع المجمّد إلى مشغّله الفعلي بواسطة
  الحالة عند القمة (التفويض والنبضات وقائع حديثة على السلسلة:
  عقدتان عند نفس القمة تحسبان نفس المجموعة)؛ المفاتيح المحظورة
  تبقى مستبعدة؛
- يجري السحب فوق مجموعة المفاتيح الفعلية المرتّبة/المنقّاة من
  التكرار (`select_committee` دون تغيير).

**تدهور صريح وآمن**: شبكة في طور الإقلاع (بلا نبضات)، أو
انقطاع عام للمشغّلين، تعود إلى المجموع كله — لا تُفقد النهائية
أبدًا بالبناء. هذه قاعدة "لا انسداد أبدًا" للمشروع مطبَّقة
هنا.

### 6.1 الإقلاع البارد

الـ epoch 0 (وما دام عدد المشغّلين الطازجين دون
`MIN_FINALITY_COMMITTEE_SIZE`): المجموع كله. يشتد القيد
طبيعيًا مع إصدار المشغّلين النبضات. لا فترة انتقالية خاصة
لتهيئتها.

## 7. الإصدار التلقائي (scone-network)

عند كل دورة إنتاج (`Wake::Produce` — لا مؤقّت جديد)، يفحص
المُرحّل إن عُبّر **حد epoch** (`height / epoch_min_blocks`،
نفس تعريف النهائية). عند الدورة الأولى لـ epoch جديد، يصدر
نبضة إذا:

1. مفتاح anchor مسلّح (`--anchor-key` أو تلقائي)، و
2. يحمل ذلك المفتاح نفسه مقعدًا حيًا (فحص محلي: المفتاح في
   مجموع الأهلية on-chain — مالكو النطاقات/TLD الحية،
   المفاتيح المحظورة مستبعدة).

مضاد سبام محلي: إصدار واحد على الأكثر لكل epoch لكل عقدة
(مذكرة `last_emitted_epoch`، ذاكرة محلية، وليست حالة سلسلة
أبدًا)؛ لا تُؤخذ المذكرة إلا بعد حقن ناجح في الـ mempool —
الفشل يعيد المحاولة عند الدورة التالية. لا شيء هنا قاتل: في
أسوأ الأحوال تنتظر النبضة الدورة التالية.

**المشغّل المفوَّض** (الذي ليس مالكًا بنفسه) لا يشمله الإصدار
التلقائي: يصدر عبر بانٍ في الـ CLI للـ §8 (تشغيل يدوي أو
معزول). النبضة ليست بالضرورة مُنتَجة في كتلة من المُصدِر
نفسه: إنها معاملة كأي معاملة (mempool، إنتاج من أي أحد).

## 8. CLI (`scone`)

بانى النبضة غير المتصل (الأداة التي أُزيلت مع سطح `tx`)
أُزيل مع سطح المعاملات غير المتصل (cli-simplify-v1). يصدر
المُرحّلون نبضتهم تلقائيًا (§7)؛ الإصدار اليدوي/المعزول، إن
لزم مجددًا يومًا، سيعود كأمر مخصص. كانت الافتراضات:
`tip_seen` = 32 بايت صفر (للرصد فقط)، `height_seen` = 0،
`timestamp` = الآن.
- كما في كل معاملة، يعيد `tx sign` **ربط** المشغّل والمالك
  بالمفتاح الموقِّع الحقيقي (قيم المُدخل لا تُوثق أبدًا)؛
  ويتحقق `tx verify` محليًا.

## 9. الرصد

- يحمل `NodeStatus` (رسالة p2p على الـ wire بقيمة `0x0d`)
  `fresh_operators: u32` (بصيغة varint): عدد المشغّلين ذوي
  نبضة طازجة — المجموعة الحية من المجموع المؤهلة للجنة
  (المشغّلون الفعليون لمقاعد المجموع، المفاتيح المحظورة
  مستبعدة، مرتّبة/منقّاة من التكرار). يملؤه المُرحّل من
  `state().fresh_operators(height)`؛ ويعرضه `scone status` كـ
  `fresh operators: N`.
- حجة حملة: "تشغيل TLD خاص = الجلوس في لجنة نهائية الـ DNS
  اللامركزي" — قابلة للتحقق على السلسلة.
- سطح مستقبلي (غير محدد): `operator_status` — لكل مقعد،
  المشغّل المفوَّض، الطزاجة (طازج / منتهي / لم يُرَ قط)، آخر
  `tip_seen`. أُزيل الـ RPC المحلي للتحكم (عقدة p2p فقط)؛
  السطح ما زال يُعرَّف.

## 10. ما لا يفعله هذا RFC

- **لا فقدان للحيازة** بسبب الخمول (الخيار A — اضمحلال الـ
  TLD غير المُشغَّل — مرفوض صراحةً).
- **لا مكافأة** (الخيار C ينتظر طبقة اقتصادية).
- لا تثبت النبضة *جودة* الخدمة (الكتل المنتجة، سجلات DHT
  المُقدَّمة) — فقط الحضور. عدّ المساهمة الحقيقية امتداد
  مستقبلي ممكن، أكثر قابلية للعبث.

## 11. ثوابت محمية

- حتمية مطابقة بالبت: النافذة والانتخاب دالتان نقيتان في
  الحالة المطبَّقة (مُسجَّلة في اليوميات، تراجع مطابق بالبت).
- لا panic أبدًا على بيانات الشبكة: نبضة أو تفويض مشوّه ←
  رفض مُصنَّف (`InvalidOwner`، `StaleHeartbeat`،
  `HeartbeatDuplicate`، `OperatorAlreadyDelegated`،
  `TldIsOpen`، `NotTldOwner`، `NotOwner`).
- الحيازة غير مشروطة؛ فقط توقيع نقاط التفتيش مشروط.

## 12. الثوابت والمعاملات (القيم المُرمَّزة)

| الاسم | القيمة | الموضع |
|---|---|---|
| `HEARTBEAT_WINDOW_EPOCHS` | 2 | `scone-blockchain/src/state.rs` |
| `MAX_SEATS_PER_OPERATOR` | 1 | `scone-blockchain/src/state.rs` |
| `MIN_FINALITY_COMMITTEE_SIZE` | 4 | `scone-core/src/consensus_params.rs` |
| discriminant الـ `Heartbeat` | `0x71` | `scone-protocol/src/transaction.rs` |
| discriminant الـ `SetTldOperator` | `0xA9` | نفسه |
| discriminant الـ `SetDomainOperator` | `0x5E` | نفسه |

هذه القيم جزء من التوافق: تغييرها يكسر قابلية إعادة تشغيل
السلسلة (النافذة/التنقية) أو الانتخاب (اللجنة).
