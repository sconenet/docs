# التخزين — الثبات المحلي للعقدة (redb)

> وثيقة معيارية. أي تباعد بين هذه الوثيقة و
> `crates/scone-storage/src/` يُعد خطأً برمجيًا (حدّد مصدر
> الحقيقة وصحّحه). مرجع التنفيذ: الـ crate `scone-storage`
> (الصيغة v1)، خلفية `redb` 4.2.

## الغرض

الثبات المحلي المدمج للعقدة: الكتل القانونية، حالات
النطاقات، ذاكرة DHT المؤقتة، البيانات الوصفية. المخزن
**ثبات (persistence)**، وليس سلطة أبدًا: حالة RAM
([`ChainState`]، مصدر التوافق) يُعاد بناؤها عند الإقلاع من
المخزن، وكل كتابة **دلتا** (النطاقات المعدَّلة بكتلة)، وليست
نسخة كاملة من الحالة أبدًا.

قيد عرضي (موجه للمستخدم، في كل milestone): **بصمة ذاكرة
دنيا**. الأحجام الكبيرة (الكتل، حالات النطاقات، ذاكرة DHT)
تعيش في redb ويُوصل إليها عبر مؤشرات/نطاقات — لا تُحمَّل
كاملة في RAM أبدًا، ولا تُكرَّر بلا فائدة أبدًا.

## الحدّ: الـ trait `NodeStore`

يعرّف `crates/scone-storage/src/lib.rs` وجهة التخزين الوحيدة
المرئية لبقية الكود (البلوكشين، مُرحّل M4 المستقبلي):

- `append_block(height, hash, bytes)` /
  `append_block_with_state(..., deltas)` — إلحاق ذري (انظر
  أدناه)؛
- `block_at_height(h)` / `block_by_hash(hash)` — قراءات
  نقطية؛
- `tip() -> (height, hash)` — بتعقيد O(1)، مقروء من `meta`؛
- `put_domain_state` / `domain_state` / `domain_count` — عداد
  **مُصان** (`meta["domain_count"]`)، وليس `COUNT(*)` أبدًا؛
- `iterate_domains(after, max) -> DomainPage` — ترقيم صفحات
  قائم على المؤشر (دفعات من 100 افتراضيًا)، بترتيب بايتات
  تصاعدي للـ `DomainId`؛
- `put_tld_state` / `tld_state` / `tld_count` / `iterate_tlds`
  — نفس العقود لسجل الـ TLD (`tld_count` مُصان، مؤشر محدود)
  (M7d)؛
- `put_dht_cache` / `dht_cache` — بايتات `SignedDnsRecord`
  معتمة؛
- `resolve_name(canonical)` / `resolve_tld(tld)` — فهرس
  دائم Name→Id (P0.2)، بحث نقطي O(1)، بلا تكرار على
  النطاقات (الافتراضي `None` = خلفية بلا فهرس، يتراجع
  المستدعي إلى `iterate_domains` أو حالة السلسلة)؛
- `tld_floors_all` / `snapshot_tld_floors_all` — قراءة أرضيات
  العمر للـ TLD المفتوحة (خيار المالك: جداول مخصصة،
  `tld_floors_v1` الحية و`snapshot_v1_floors` المجمّدة)؛
- `rewind_to_height(h)` — إعادة تنظيم: يزيل الكتل فوق `h`
  ويعيد `tip`/`tip_height` إلى `h` في معاملة واحدة
  (تمهيد لـ `persist_state_snapshot`، انظر أدناه)؛
- `meta_get` / `meta_set`؛
- `snapshot_meta` / `snapshot_domains` / `snapshot_tlds` — قراءة
  لقطة حالة الإقلاع (M6b؛ الافتراضات الفارغة = خلفية بلا
  لقطة، يتراجع `load_chain` حينها إلى التحميل الكامل).

القواعد:

- **لا أنواع redb في الـ API**: بايتات (`&[u8]`، `[u8; 32]`)
  وأنواع النواة فقط. الخلفية قابلة للاستبدال.
- **بلا async، بلا قابلية تعديل داخلية**: الكتابات تأخذ
  `&mut self` (يُسلسل redb الكُتّاب)، والقراءات تأخذ `&self`
  (معاملة قراءة قصيرة واحدة لكل استدعاء).
- لا يعيد الـ API التحقق من الكتل أبدًا: الـ hash المُمرَّر
  إلى `append_block*` هو الـ hash **المعاد حسابه** الذي يوفره
  المستدعي (`Blockchain::push_block`).

## مخطط جداول redb

| الجدول | المفتاح (الترتيب) | القيمة |
|---|---|---|
| `blocks_by_height` | ارتفاع `u64` (b-tree مرتّب) | `hash(32) ‖ height(8 BE) ‖ canonical block` |
| `blocks_by_hash` | hash الكتلة (32 بايت) | الترميز القانوني للكتلة |
| `domains` | `DomainId` (32 بايت، ترتيب البايتات) | `DomainStateBytes` (أدناه) |
| `tlds` | `TldId` (32 بايت، ترتيب البايتات) | `TldStateBytes` (أدناه، M7d) |
| `dht_cache` | `DomainId` (32 بايت) | بايتات `SignedDnsRecord` (معتمة) |
| `names_v3` (P0.2) | مفتاح الفهرس (32 بايت، ترتيب البايتات) | المعرّف الهدف (32 بايت) |
| `name_reverse_v3` (P0.2) | المعرّف الهدف (32 بايت، ترتيب البايتات) | `tag(1) ‖ canonical name` |
| `meta` | `&[u8]` | `&[u8]` |
| `snapshot_v1_meta` (M6b) | `u64` = 0 (خانة وحيدة) | `height(8 BE) ‖ tip_hash(32)` = 40 بايت بالضبط |
| `snapshot_v1_domains` (M6b) | `DomainId` (32 بايت، ترتيب البايتات) | `DomainStateBytes` (نفس صيغة `domains`) |
| `snapshot_v1_tlds` (M6b) | `TldId` (32 بايت، ترتيب البايتات) | `TldStateBytes` (نفس صيغة `tlds`) |
| `tld_floors_v1` (خيار المالك) | `TldId` (32 بايت، ترتيب البايتات) | `u64` (أرضية الانتهاء، BE الضمني في redb) |
| `snapshot_v1_floors` (M6b) | `TldId` (32 بايت، ترتيب البايتات) | `u64` — نسخة مجمدة من الأرضيات (الحالة عند اللقطة، لا القمة) |

مفتاح `meta` إضافي (P0.3/P0.4):

| المفتاح | القيمة |
|---|---|
| `verified_snapshot_v1` (P0.3) | `height(8 BE) ‖ tip_hash(32) ‖ manifest_hash(32)` = 72 بايت — علامة لقطة متحقق منها مستوردة (محجوز، مثل `tip`) |

مفاتيح `meta`:

| المفتاح | القيمة |
|---|---|
| `format_version` | `u64 BE` = `STORAGE_FORMAT_VERSION` (1) |
| `tip` | hash (32 بايت) لكتلة القمة |
| `tip_height` | `u64 BE` (يجعل `tip()` بتعقيد O(1)) |
| `domain_count` | `u64 BE` (عداد مُصان) |
| `tld_count` | `u64 BE` (عداد مُصان، M7d) |

ترويسة `hash ‖ height` في `blocks_by_height` تجعل كل فهرس
مكتفيًا بذاته (قابل للتحقق دون قراءة الكتلة)؛ ويُحدَّث
الفهرسان في نفس المعاملة.

### اصطلاح التكوين

كتلة التكوين حتمية (ثوابت البروتوكول) ولا تُخزَّن كبايتات
**أبدًا**. المخزن الجديد لديه `tip == (0, genesis_hash)`؛ وأول
كتلة ملحقة بارتفاع 1. يُعاد اشتقاق hash التكوين دائمًا
(`scone_blockchain::genesis_hash()`)، ولا يُقرأ أبدًا.

## صيغة ترميز `DomainStateBytes` (M8b)

57 أو 89 بايتًا حسب وسم الإصدار البادئ، أعداد صحيحة ثابتة
العرض big-endian (قانونية، قابلة للمقارنة بايتًا-ببايت):

```text
DomainStateBytes = tag ‖ owner(32) ‖ sequence(8 BE) ‖ registered_at(8 BE)
                   ‖ valid_until(8 BE) [‖ record_hash(32)]

tag = 0x01 : record_hash present → exactly 89 bytes
tag = 0x02 : record_hash absent  → exactly 57 bytes
```

- `registered_at` / `valid_until` (M8b): انتهاء التسجيل
  (سنة عند المطالبة، قابل للتجديد، انظر
  `/docs/en/technical/blockchain.md`).

ترميزات M7 (41/73 بايتًا، بلا انتهاء) **غير شرعية** منذ M8b:
فك ترميز صارم ← `Corrupted`. (مخزن M7 يتجدد عبر إعادة التشغيل:
`load_chain_replay`.)

- `owner`: الـ `OwnerId` (32 بايت)؛
- `sequence`: تسلسل آخر `UpdateDomain` مطبَّق (0 مباشرة بعد
  `RegisterDomain`)؛
- `record_hash`: الالتزام الحالي على السلسلة لمجموعة سجلات
  DNS (`None` ما دام لم يُطبَّق أي `UpdateDomain`).

فك ترميز **صارم** (`DomainStateBytes::decode`): وسم مجهول، أو
طول خاطئ، أو بايتات زائدة ← `StorageError::Corrupted`، وليس
panic أبدًا.

## صيغة ترميز `TldStateBytes` (خيار المالك)

طول متغير حسب الـ variant — 34 بايتًا لـ TLD **خاص**،
و2 لـ TLD **مفتوح** (لا تسلسل ولا hash سجل):

```text
TldStateBytes = tag(0x04) ‖ flag(0x00|0x01) ‖ owner(32)? ‖ until(8)
```

- `flag` (خيار المالك، تعداد `TldState`): `0x00` =
  `TldState::Open` (لا أحد — خدمة ذاتية + PoW، بلا بايتات
  مالك)، و`0x01` = `TldState::Private` (تتبعها 32 بايت مالك).
  قانوني بصرامة — أي بايت آخر ← `Corrupted`. الثابت "مفتوح
  ⟺ لا مالك" بنيوي: لا يمكن الخلط بين الحالتين.
- **`until` (8 بايت، BE64)**: ساعة الـ TLD الخاصة — نهاية
  المدة الخاصة (مطالبة/تجديد + 3 سنوات) أو جدول موت المفتوح
  (أرضية سنة عند الولادة، تدفعها كل نطاق حي). صارف خاصية
  للمدخل مجددًا (تغيير دورة حياة الـ TLD). لا يزال الجدول
  المشتق `tld_floors_v1` (+ نسخته المجمدة `snapshot_v1_floors`)
  يتتبع الأرضيات، يُعاد بناؤه عند إعادة التشغيل ويُستعاد عند
  الإقلاع — العقدة المعاد تشغيلها تقتل نفس الـ TLD التي
  تقتلها العقدة المتواصلة.

ترميزات M7d (33 بايت، وسم `0x01`)، وM8b (34 بايت، وسم `0x02`،
`open` منطقي)، والوسم القديم `0x03` (`until` مضمّن) **غير
شرعية**: فك ترميز صارم ← `Corrupted` (قبل الـ mainnet، إعادة
الجيل عبر إعادة التشغيل هي مسار الترحيل).

الوسم موجود فقط لتطور الصيغة: تخطيط مستقبلي يرفع الوسم
والقراء القدامى يفشلون بـ `Corrupted` بدل التخمين. فك ترميز
**صارم** (`TldStateBytes::decode`): وسم مجهول، أو طول خاطئ، أو
بايتات زائدة، أو flag غير قانوني ←
`StorageError::Corrupted`، وليس panic أبدًا.

## ضمانات الذرية

يكتب `append_block_with_state` في معاملة redb `WriteTransaction`
**واحدة**:

1. الكتلة في `blocks_by_height` (فحص مسبق: يجب ألا يوجد
   الارتفاع بمحتوى مختلف، وإلا
   `StorageError::Conflict`)؛
2. الكتلة في `blocks_by_hash`؛
3. كل دلتا حالة نطاق (`domains`)؛
4. عداد `domain_count` (يزيد بعدد النطاقات **الجديدة**
   فقط؛ `UpdateDomain` لنطاق قائم لا يزيده)؛
5. كل دلتا سجل الـ TLD (`tlds`، M8b: مطالبات، نقل،
   فتح/إغلاق) — **في نفس المعاملة**: كتلة مكتوبة دون تغييرات
   الـ TLD الخاصة بها مستحيلة بنيويًا؛
6. عداد `tld_count` (الـ TLD الجديدة فقط)؛
7. كل **إزالة** (M8b): النطاقات المنتهية بالـ GC الحتمي
   (`removed_domains`) والـ TLD الملغاة (`removed_tlds`)
   تغادر المخزن في نفس المعاملة، والعدادات تنقص — إعادة
   تشغيل لا تستطيع أبدًا بعث تسجيل منتهٍ؛
8. دلتا **فهرس الأسماء** الخاص بـ P0.2 (upserts وإزالات،
   انظر أدناه) — نفس الضمانات: تحطم لا يترك أبدًا مدخل فهرس
   يشير إلى نطاق غائب؛
9. `tip` و`tip_height`.

يلتزم redb بنمط WAL: تحطم في منتصف الكتابة يترك حالة
**سابقة** متسقة. لذا فـ **الكتلة المكتوبة دون حالتها مستحيلة
بنيويًا** — هذا هو الثابت المفتاحي للمilestone.

ضمانات إضافية:

- **الرتابة**: إلحاق عند ارتفاع ≠ `tip_height + 1` ←
  `StorageError::NonMonotonicHeight`، ولا يكتب شيء (يُفحص
  *قبل* فتح معاملة الكتابة)؛
- **Idempotence**: إعادة إلحاق كتلة القمة الحالية بنفس زوج
  `(height, hash)` عملية no-op (المسار السريع يقارن الارتفاع
  والـ hash؛ عند تساوي الارتفاع، بايتات كتلة متطابقة no-op
  صامت، وبايتات مختلفة `Conflict`)؛
- **قاعدة بيانات تالفة**: ملف مقتطع/ملوّث ← خطأ مُصنَّف
  (`StorageError::Database`/`Corrupted`) عند الفتح أو القراءة،
  وليس panic أبدًا (مُختبَر)؛
- **إصدار الصيغة**: `format_version` ≠ 1 ←
  `StorageError::UnsupportedFormat` (مسار ترحيل صريح مطلوب، لا
  تخمين أبدًا).

## تكامل البلوكشين (`integration.rs`)

فصل الأدوار: [`ChainState`] في RAM = سلطة التوافق؛
المخزن = الثبات. الاستراتيجية المختارة (الأبسط، كما هو موثّق):
**الثبات عند كل كتلة** — يكتب `store_block` الكتلة + حالات
النطاقات **التي مسّتها تلك الكتلة** (دلتا). تبقى إعادة
التشغيل الكاملة ممكنة وتخدم كمسار ضبط/إصلاح.

- `store_block(store, chain, block, hash)`: يرمّز الكتلة
  قانونيًا، ويقرأ الحالة النهائية للنطاقات الممسوسة والـ
  TLD المطالَب بها من حالة RAM (المحدَّثة سلفًا بـ
  `push_block`)، إلحاق ذري.
- `load_chain(store)`: **دون إعادة تشغيل** — يقرأ القمة +
  كتلة القمة (قراءات كتل O(1))، ويستعيد حالة النطاق في
  صفحات من 100 (`DOMAIN_PAGE`) **وسجل الـ TLD في صفحات من
  100** (`TLD_PAGE`، M7d — إغلاق نافذة إعادة التشغيل: بدونها،
  كانت العقدة المعاد تشغيلها تنسى كل TLD مطالَب به وترفض كل
  `RegisterDomain` تحت ذلك الـ TLD بـ `UnknownTld`، رغم أن
  قرصها يحمل الحالة الكاملة). تحتفظ سلسلة RAM بالتكوين +
  القمة فقط؛ الكتل التاريخية تبقى في المخزن وتُقدَّم منه. منذ
  M8، يعيد `load_chain` بعدها بناء **فهرس منع إعادة تشغيل
  الـ TXID** (انظر أدناه).
- `load_chain_replay(store)`: يعيد تشغيل كل الكتل المخزنة
  واحدة واحدة (ليس كلها في RAM أبدًا) بتحقق كامل؛ القمة
  الناتجة يجب أن تساوي القمة المخزنة، وإلا `Corrupted`.
- `rebuild_replay_index_from_store(store, chain, tip_height)`
  (M8): يعيد مسح آخر
  `min(REPLAY_WINDOW_BLOCKS, tip_height)` كتلة مستمرة (كتلة
  واحدة في RAM في كل مرة) ويعيد إدراج كل TxId في فهرس السلسلة
  **عند ارتفاع تضمينه الأصلي**، عبر الـ API العامة
  `Blockchain::rebuild_replay_index` (لا وصول للحقول الخاصة).
  كتلة غائبة تحت القمة أو غير قابلة لفك الترميز داخل النافذة
  ← `Corrupted` (تلك البايتات خدمت سلفًا لبناء السلسلة: فشل
  هنا يشير إلى مخزن متضرر).
- `touched_domains(block)`: معرّفات النطاقات المعدَّلة
  بمعاملات الكتلة، منقّاة من التكرار، بترتيب الكتلة.
- `touched_tlds(block)`: معرّفات الـ TLD المتغيرة بالكتلة
  (`RegisterTld`، `TransferTld`، `RevokeTld`، `SetTldOpen`)،
  منقّاة من التكرار، بترتيب الكتلة (M8b).
- `store_block_with_removals(...)`: variant لـ `store_block`
  يستقبل أيضًا النطاقات التي أزالتها الـ GC للكتلة (M8b)
  لأجل الكتابة الذرية الموصوفة أعلاه. يغذّي المُرحّل هذه
  القائمة من `Blockchain::push_block_with_gc` (نتيجة التطبيق
  تكشف `gc_removed_domains`). **إخلاء الـ GC لذاكرة DHT
  المؤقتة**: تُحذف مداخل `dht_cache` للنطاقات المزالة في نفس
  المعاملة كالكتلة (دلتا الإلحاق تحمل جدول `dht_cache`) — سجل
  DHT لا يبقى بعد النطاق الذي خدمه، والمداخل المنتهية لا
  تتراكم للأبد (اختبار:
  `gc_evicts_the_dht_cache_entry`).

سيستخدم المُرحّل (M4): `load_chain` عند الإقلاع، ثم لكل كتلة
مقبولة `push_block` (RAM) ثم `store_block` (قرص).

## ثبات إعادة التنظيم (`rewind_to_height` + `persist_state_snapshot`)

إعادة التنظيم (التحول إلى فرع أخت أقوى) لا تمر بالإلحاق
الرتيب — كتابة اللاحقة الفائزة ستفشل بـ
`NonMonotonicHeight`. المسار المخصص (إصلاح الأقلية اللاصقة،
مُرحّل + مخزن):

1. `rewind_to_height(fork_height)` — معاملة redb واحدة تزيل
   الكتل فوق نقطة التشعب وتعيد `tip`/`tip_height` (يُصلَح
   فهرس الأسماء والحالات الحية في الخطوة التالية)؛
2. `persist_state_snapshot(store, chain)` — يعيد كتابة الجداول
   الحية (`domains`، `tlds`، فهرس الأسماء، أرضيات الـ TLD)
   من تصدير حالة RAM بعد إعادة التنظيم: الجداول الحية لا
   تصف **أبدًا** الفرع الخاسر عند الإقلاع؛
3. إعادة إلحاق رتيبة للاحقة المتبنّاة (دلتا عادية).

فشل ثبات على هذا المسار يُسجَّل ويُخفَّض (يُشفى المخزن عند
الإقلاع عبر إعادة التشغيل) — ليس قاتلًا أبدًا.

## لقطة حالة الإقلاع (M6b)

يبقى `load_chain` كما وُصف أعلاه بتعقيد O(حجم الحالة): لا
تُعاد أي كتلة، لكن جدول `domains` كله يُعاد قراءته. إنه مسار
الثبات-لكل-كتلة الذي يجعل إعادة التشغيل غير ضرورية. تعالج
لقطة M6b كلفة مختلفة: حالة إعادة بناء حالة RAM **بإعادة
التشغيل** (إصلاح، ضبط، أو خلفية بلا حالة مستمرة لكل كتلة).
تقدم إقلاعًا بتعقيد **O(tip − H)** — بإعادة تشغيل اللاحقة فوق
اللقطة فقط.

### الكتابة

- **الفاصل**: `SNAPSHOT_INTERVAL = 64` (ثابت عام لـ
  `scone-storage`). المحفّز هو إلحاق الكتلة
  `k·SNAPSHOT_INTERVAL + 1`: تلك المعاملة تُجمّد حالة الجداول
  الحية **كما هي قبل تطبيق تلك الكتلة**، أي الحالة القانونية
  بعد الكتلة `k·SNAPSHOT_INTERVAL`.
- **أبدًا عند القمة**: تجلس اللقطة عند `tip − 1` في أقرب
  الأحوال، دائمًا دون القمة بصرامة لحظة كتابتها. تحتم مباشر
  بعدها لا يمكنه أبدًا ترك لقطة "فوق" السلسلة المستمرة.
- **ذرية**: التجميد (مسح + نسخ جدولي `domains`/`tlds` إلى
  `snapshot_v1_*`، كتابة `snapshot_v1_meta`) يجري في نفس
  معاملة redb كإلحاق كتلة المحفّز — التحطم يترك إما اللقطة
  القديمة سليمة، أو الجديدة كاملة بكتلتها (WAL لـ redb).
- **خانة وحيدة**: كل لقطة تستبدل السابقة (جداول تُفرَّغ ثم
  تُنسخ) — لا تراكم، لا تنقية تدبّرها، وبصمة القرص محدودة
  بـ ~2× الحالة.
- صيغة الحالات المجمّدة هي بصرامة صيغة
  `DomainStateBytes`/`TldStateBytes` (إعادة استخدام، لا ترميز
  جديد)؛ فقط سطر `snapshot_v1_meta` صيغة جديدة
  (`height(8 BE) ‖ tip_hash(32)`، فك ترميز صارم: أي طول آخر
  ← `Corrupted`).

### القراءة عند الإقلاع (`load_chain`)

1. تُتحقق القمة كالعادة (hash معاد حسابه من ترويسة كتلة
   القمة مقابل `meta["tip"]`).
2. إن وُجد `snapshot_meta()`، وارتفاعه `H` يحقق
   `0 < H < tip_height`، وhash الكتلة المخزنة عند `H`
   **المعاد حسابه** يساوي `tip_hash` اللقطة (**المرساة** —
   لقطة أجنبية عن السلسلة المستمرة، أو معدَّلة، أو من ملف
   آخر تُكتشف هنا)، تُستعاد الحالة المجمدة في صفحات من 100
   ثم يُعاد تشغيل الكتل `H+1..=tip` فقط (تحقق كامل، مطابق
   للكتل الحية).
3. القمة التي تصلها إعادة التشغيل يجب أن تساوي القمة
   المخزنة.
4. **أي فشل على هذا المسار (لقطة غائبة، ارتفاع غير صالح،
   مرساة غير صالحة، بايتات غير قابلة لفك الترميز، فشل إعادة
   تشغيل) يتراجع بصمت إلى التحميل الكامل قبل M6b** (قراءة
   الجداول الحية، دون إعادة تشغيل) — لقطة سيئة لا تفشل
   الإقلاع أبدًا. التوافقية الرجعية هي الحالة الخاصة "بلا
   لقطة": مخزن كُتب قبل M6b (بلا جداول `snapshot_v1_*`) يُحمَّل
   بشكل مطابق، إذ `snapshot_meta()` تساوي `None`.

اللاحقة المعاد تشغيلها محدودة بـ `SNAPSHOT_INTERVAL` (على
الأكثر 64 كتلة وقت المحفّز + الكتل المعدَّنة منذ ذلك): الإقلاع
بتعقيد O(tip − H) مع H حديثة مضمونة.

## فهرس منع إعادة تشغيل الـ TXID يعاد بناؤه عند الإقلاع (M8)

فهرس منع إعادة التشغيل (`included`، TxId ← ارتفاع التضمين،
النافذة `REPLAY_WINDOW_BLOCKS = 256` — انظر
`/docs/en/technical/blockchain.md`) **دالة نقية في السلسلة
القانونية**: لا يُثبَّت أبدًا. وبما أن `load_chain` لا يعيد
تشغيل التاريخ، فقد بدأت سلسلة مستعادة قبل M8 بفهرس
**فارغ** — كانت العقدة المعاد تشغيلها تقبل إعادة تضمين أي
معاملة لا تزال داخل نافذة إعادة تشغيلها (قصور موثّق؛ قواعد
  الحالة بقيت الحارس الوحيد).

يغلق M8 هذه النافذة: بعد الاستعادة (المسار الكامل أو اللقطة
+ إعادة تشغيل اللاحقة)، يستدعي `load_chain` الدالة
`rebuild_replay_index_from_store`، التي تعيد قراءة آخر
`min(REPLAY_WINDOW_BLOCKS, tip_height)` كتلة مستمرة — كتلة
واحدة في RAM في كل مرة، ذاكرة محدودة ككل مكان — وتعيد إدراج
كل TxId عند **ارتفاعه الأصلي**. لذا فالمخزن الأقل من 256 كتلة
يعيد بناء فهرسه كاملًا.

الخصائص:

- **قرارات مطابقة للعقدة الحية**: نفس المداخل، نفس قاعدة
  التنقية (`h > tip − 256`) — عقدة تعيد التشغيل وعقدة لم
  تتوقف ترفضان نفس إعادات التشغيل (مُختبَر: عدد الفهرس الدقيق
  والمساواة مع الفهرس الحي المنقّى).
- **دلالات تنقية دون تغيير**: معاملة أقدم من النافذة تبقى
  مقبولة من الفهرس (ثم تفشل قواعد الحالة إن انطبق) — تمامًا
  كما قبل.
- **اللقطة لا تجمّد الفهرس**: إعادة تشغيل لاحقة اللقطة تعيد
  بناء المداخل فوق H، ومسح M8 يضيف جزء النافذة تحت H (نفس
  عقد owner_keys/grace: يعاد بناؤه، لا يُثبَّت أبدًا).
- **الكلفة**: ≤ 256 قراءة كتلة نقطية عند الإقلاع،
  O(النافذة) — مستقلة عن عمر السلسلة.
- كتلة غائبة أو غير قابلة لفك الترميز **داخل النافذة** تفشل
  الإقلاع بـ `Corrupted` (تلك البايتات خدمت سلفًا لبناء
  السلسلة)؛ خارج النافذة، الكتل التاريخية لا تُمس.

`load_chain_replay` (ثقة صفرية) يعيد بناء الفهرس بالطريقة
نفسها عبر إعادة تشغيله الكاملة — المساران يتقاربان.

## فهرس دائم Name ← Id (P0.2)

الـ `DomainId = BLAKE3-256(DOMAIN_ID_VERSION ‖ canonical name)`
غير قابل للعكس: حلّ اسم (مُرحّل/DNS) يتطلب فهرسًا دائمًا.
يضيفه P0.2 إلى المخزن، بنفس الانضباط المعامَلي كبقية الأجزاء.

### المخطط

جدولان مرافقان، يُكتبان ويُمحيان معًا:

```text
names_v3        key  = BLAKE3-256("SCONE-NAME-IDX-V1" ‖ canonical name)  (32 B)
                val  = target id (32 B : DomainId or TldId)

name_reverse_v3 key  = target id (32 B)
                val  = tag(0x01 domain | 0x02 TLD) ‖ canonical name
```

- مفتاح `names_v3` هو **hash للاسم، وليس الاسم الصريح**
  (جداول فهرس مدمجة، لا gossip للأسماء عبر الـ dumps). المفتاح
  **دالة نقية في الاسم**: الفهرس قابل لإعادة البناء في أي
  لحظة من السلسلة (`rebuild_name_index`)، ولا تُثبَّت له
  بيانات وصفية إضافية.
- يخزّن `name_reverse_v3` الاسم (مرة واحدة بالضبط) لأن مسارات
  الإزالة (GC للنطاقات المنتهية، `RevokeTld`) لا تعرف إلا
  **المعرّفات**: لا بد من إيجاد المفتاح المُhashed المزال
  بطريقة ما. الوسم يميّز فضاءي الأسماء.
- فصل صارم: لا يجيب `resolve_name` **أبدًا** بمدخل TLD ولا
  `resolve_tld` بمدخل نطاق (وسم الجدول العكسي يقرر؛
  `DomainName` له ≥ 2 علامة، وللـ TLD واحدة — اشتقاقا
  المفتاحين يتشاركان فضاء `names_v3` لا النتائج).
- يبقى الـ `DomainId` 32 بايت، ولا يُقلَّص أبدًا (قاعدة مشروع
  صارمة: هوية توافق، مقاومة تصادم).

### الاتساق المعامَلي

الـ upserts (`RegisterDomain`، `AssignDomain`، `RegisterTld` —
أسماء تحملها المعاملات بصيغة واضحة) والإزالات (GC، إلغاءات —
معرّفات مجردة) تحملها `StateDelta` للكتلة
(`name_upserts` / `name_removals`) وتُطبَّق في **نفس معاملة
redb** ككتابات الكتلة والحالة. لذا لا يستطيع تحطم ترك مدخل
فهرس يشير إلى نطاق غائب (لا أشباح)، ولا نطاق مسجّل بلا مدخله.
إلحاق فاشل لا يكتب شيئًا (مُختبَر). تقدم الـ variants المسماة
`put_domain_state_with_name` / `put_tld_state_with_name` /
`remove_domain_state` نفس الذرية لأدوات الإصلاح.

يستمد `store_block` / `store_block_with_removals` دلتا الأسماء
من نفس معاملات الكتلة — لا معامل إضافي عند واجهة المُرحّل.

### إعادة البناء (`RedbStore::rebuild_name_index`)

الفهرس دالة نقية في السلسلة القانونية، كفهرس منع إعادة التشغيل
M8. يعيد `rebuild_name_index` بناءه من **الكتل المستمرة**
(`DomainStateBytes` لا تحتوي الاسم — مالك/تسلسل/انتهاء فقط —
فمصدر الحقيقة هو تدفق المعاملات، حيث تحمل `RegisterDomain`
و`AssignDomain` الاسم القانوني بصيغة واضحة):

1. المرور 1: مسح `blocks_by_height` من التكوين إلى القمة،
   كتلة واحدة في RAM في كل مرة؛ جمع روابط `name → id`
   المرئية في `RegisterDomain`/`AssignDomain`/`RegisterTld`؛
2. المرور 2: ترشيح للأهداف **الحية** فقط (الحالة المستمرة
   هي المرجع) — نطاق سُجل ثم أزالته الـ GC/انتهى لا يُفهرَص
   مجددًا؛
3. المرور 3: محو + إعادة كتابة كاملة للجدولين في معاملة
   واحدة (تحطم ← الفهرس القديم أو الجديد كاملًا).

كتلة غائبة أو غير قابلة لفك الترميز ← `Corrupted` (نفس
البايتات التي بنت السلسلة). الكلفة O(أسماء مميزة مرئية) في
RAM (≤ 253 بايت لكل اسم) وO(كتل) في القراءات — أداة إصلاح،
لا مسار إقلاع.

### ما ليس هو الفهرس

- ليس سلطة: تبقى حالة السلسلة في RAM السلطة الوحيدة؛ الفهرس
  ذاكرة مؤقتة قابلة لإعادة البناء (التباعد خطأ معامَلية،
  يُكتشف بـ `rebuild_name_index` مقارنةً بها).
- ليس مجمدًا في لقطة M6b: جدولا `names_v3`/`name_reverse_v3`
  حيّان ويتبعان دلتا كل كتلة؛ لقطة الحالة لا تضمّنهما
  (إعادة بناء بالدلتا عند الاستئناف، أو
  `rebuild_name_index` كإصلاح).

### ما لا تلتزم به اللقطة

تحمل حالة RAM `ChainState` بنى داخلية لا يلتزم بها التوافق
(مفاتيح المالك، نوافذ المهلة). لا تُجمَّد: إعادة تشغيل
اللاحقة تعيد بناءها بتطبيق المعاملات (حتمي، نفس المحتوى
كإعادة التشغيل الكاملة للنافذة المعنية). يتبع فهرس منع إعادة
تشغيل الـ TXID نفس العقد (M8، انظر القسم السابق): يعاد بناؤه
عند الإقلاع، ولا يُجمَّد أبدًا. المساواة المطابقة بالبت مع
`load_chain_replay` متحقَّق منها بالاختبار على الحالة
القانونية (state_root + SMT).

## لقطة الحالة المتحقَّق منها — أجزاء + manifest + تحقق تشفيري (P0.3)

تسرّع لقطة M6b أعلاه إقلاع عقدة تثق بقرصها. يعالج P0.3 حاجة
مختلفة: نقل حالة بين العقد (تهيئة عقدة جديدة، إصلاح) دون
الثقة بالناقل. تعيش الصيغة والتحقق في
`crates/scone-storage/src/verified_snapshot.rs` + إعادة بناء
الجذر في
`crates/scone-blockchain/src/snapshot_verify.rs`.

### نموذج الثقة

تحمل اللقطة حالة كتلة **نهائية** — نقطة تفتيش موقّعة بنصاب
اللجنة (`CheckpointData.state_root`، جذر `state_root_smt`
بتعقيد O(1)). أصالة نقطة التفتيش (نصاب توقيعات Ed25519)
تُتحقق من طبقة السلسلة قبل الاستيراد. يتحقق الاستيراد نفسه من
التزام لقطة ← نقطة تفتيش بإعادة الحساب:

1. **hash كل صفحة**: `blake3("SCONE-SNAP-PAGE-HASH" ‖
   ترميز الصفحة كاملًا)` يجب أن يساوي الـ hash المعلن من
   الـ manifest (بايت مزوّر واحد ← رفض)؛
2. **مجموع المداخل == عدادات الـ manifest** (صفحة غائبة أو
   عداد خاطئ ← رفض)؛
3. **جذر SMT معاد حسابه من المداخل المستوردة ==
   `checkpoint.data.state_root`** — الفحص التشفيري: الحالة
   كاملة (نطاقات + TLD) تُطوى من جديد في SMT طازج
   (`snapshot_verify::recompute_state_root`، أوراق
   `SCONE-LEAF-DOM-V1`/`SCONE-LEAF-TLD-V1` تمامًا كالمسار
   الحي) ويجب أن يساوي الجذر ما وقّعته اللجنة. لقطة مزوّرة أو
   مقتطعة أو ناقصة تُرفض **قبل أي كتابة**؛
4. **اتساقات بنيوية**: `height`/`tip_hash`/`state_root`
   للـ manifest == الخاصة بنقطة التفتيش؛ معرّفات تصاعدية
   بصرامة (لا تكرارات)؛ فهارس صفحات متسلسلة؛ حدود DoS
   (≤ 10,000 مدخل/صفحة، ≤ 2^20 صفحة، ميزانية إجمالية).

فشل التحقق ← `StorageError::SnapshotRejected`، ويبقى المخزن
دون تغيير مطلق (كل شيء يُتحقق قبل معاملة الكتابة).

### الصيغة المتسلسلة (صارمة، big-endian، فك ترميز بلا رحمة)

```text
manifest = "SCONE-SNAP-MAN-V1"
        ‖ height(8) ‖ tip_hash(32) ‖ state_root(32)
        ‖ page_count(4) ‖ domain_count(8) ‖ tld_count(8)
        ‖ page_hashes(page_count × 32)

page    = "SCONE-SNAP-PAGE-V1"
        ‖ index(4) ‖ height(8) ‖ state_root(32)      ← every page is
        ‖ entry_count(4) ‖ entries                   self-identifying

entry   = kind(0x01 domain | 0x02 TLD | 0x03 TLD floor) ‖ id(32)
          ‖ [len(2) ‖ state | floor(8 BE)]
          (state = DomainStateBytes 57/89 B or TldStateBytes 2/34 B —
           the existing canonical storage formats, reused; kind
           0x03 (lifetime floor of an open TLD, owner-option) has
           a dedicated format WITHOUT a length prefix:
           id(32) ‖ floor(8 BE), fixed size)
```

ترتيب الصفحات: كل مداخل النطاقات (معرّفات تصاعدية)، ثم كل
مداخل الـ TLD (معرّفات تصاعدية)، ثم أرضيات عمر الـ TLD
**المجمّدة** عند ارتفاع اللقطة (`snapshot_tld_floors_all` —
ليس الجدول الحي) — ترتيب ترقيم مؤشر المخزن. تحمل كل صفحة
`(index, height, state_root نقطة التفتيش, entries)`: صفحة
وحيدة تعرف أي لقطة تخصها. صفحات من 256 مدخلًا عند التصدير
(`VERIFIED_SNAPSHOT_PAGE_ENTRIES`)؛ حدود DoS عند الاستيراد.
أرضيات الـ TLD (`tld_floors_v1`) جزء من الصيغة القابلة
للنقل: النوع 0x03 يحملها، ويطلب الاستيراد تصاعدها بصرامة
واستهدافها TLD **حاضرًا** في اللقطة — وإلا فلن يقتل المستورد
أبدًا ما يقتله المصدر (تشعب صامت، مرفوض).

### التصدير (`export_verified_snapshot(store, checkpoint)`)

يُسلسل حالة **آخر نقطة تفتيش نهائية** — وليس القمة. يصدر
النطاقات، ثم الـ TLD، ثم أرضيات عمر الـ TLD المجمّدة عند
ارتفاع اللقطة (تناظر تصدير/استيراد: أغفل التصدير تاريخيًا
الأرضيات — صُحّح، اختبار تراجع
`export_carries_tld_lifetime_floors`). الشرط المسبق: يحمل
المخزن لقطة M6b مستمرة (`snapshot_v1_*`) عند ارتفاع نقطة
التفتيش بالضبط (نافذة `CHECKPOINT_KEEP`/`SNAPSHOT_INTERVAL`
تضمن توفر مثل هذه الحالة بانتظام)؛ مرساة الكتلة **تُعاد
حسابها** من البايتات المستمرة ويجب أن تساوي
`checkpoint.data.block_hash`. وإلا ←
`StorageError::SnapshotUnavailable` (التصدير فعل صريح: انتظر
الفاصل/نقطة التفتيش التالية).

### الاستيراد (`import_verified_snapshot(store, checkpoint, manifest, pages)`)

يتحقق من كل شيء (انظر أعلاه)، ثم يكتب في معاملة redb واحدة:
الجداول الحية `domains`/`tlds` + العدادات + `tip = (H,
hash نقطة التفتيش)`، والجداول المجمدة `snapshot_v1_*` المرتكزة
على نفس الكتلة، والعلامة المحجوزة
`meta["verified_snapshot_v1"]` (`height ‖ tip_hash ‖
manifest_hash`). الهدف: مخزن فارغ فقط (وإلا
`SnapshotUnavailable`).

### كلفة التحقق (موثّقة)

إعادة بناء SMT عبر إدراجات مرتّبة: N مدخلًا × O(40) hash ≈
O(N·40). ~2.1 M من blake3 hashes لأجل 100,000 نطاق (عشرات
الميلي ثواني). مرة واحدة — استيراد تهيئة/إصلاح، وليس مسار
لكل كتلة: مقبول. الإدراج المرتّب (معرّفات تصاعدية) ينشئ كل
نقطة تفرّع مرة واحدة فقط؛ وفي كل الأحوال يعتمد الجذر على
المحتوى فقط (ضمان SMT، fuzz تفاضلي في `smt.rs`).

## تهيئة الحالة — دون إعادة تشغيل التكوين (P0.4)

تنضم عقدة جديدة إلى الشبكة دون إعادة تشغيل التاريخ من
التكوين:

```text
finalized checkpoint (relay, validated by the chain layer)
        │
        ▼
verified snapshot (manifest + pages, crypto verification above)
        │  import → state at H + tip (H, hash) + marker
        ▼
anchor block H (requested from the network BY HASH — append_bootstrap_anchor)
        │
        ▼
recent blocks H+1..H+k (relay, increasing height, ordinary atomic
        │               append — the storage API requires only this)
        ▼
synced — boot replays ONLY the suffix above H
```

- **API التخزين المكشوف للمُرحّل**: `append_bootstrap_anchor(H,
  hash, bytes)` (يضع كتلة المرساة: علامة مطلوبة، اتساق
  ارتفاع/hash مع العلامة، idempotent) ثم إلحاق ذري عادي
  بارتفاع تصاعدي. الجلب الشبكي (بـ hash من الـ manifest) شأن
  مُرحّل، لا مخزن.
- **`load_chain`** يتعرف على العلامة: التاريخ تحت H غائب
  بشرعية (عقدة غير أرشيف). ملموسًا: تُسقَّف إعادة مسح نافذة
  منع إعادة التشغيل M8 عند H (الكتل تحت H غير موجودة وليست
  غائبة)؛ قمة بلا كتلة مخزنة بعد استيراد (لم توضع المرساة
  بعد) ← تشخيص مُصنَّف
  `SnapshotUnavailable` ("يجب أن تأتي المرساة من الشبكة")، لا
  فسادًا.
- **عقدة أرشيف مقابل عقدة حالة كاملة**: عقدة الأرشيف (علامة
  المشغّل) تحتفظ بكل شيء — تقدّم الكتل التاريخية للشبكة
  وتقلع عبر المسارات القائمة. عقدة الحالة الكاملة (الافتراضي
  P0.4 لعقدة جديدة مُهيَّأة هكذا) تقلع عند H: تتحقق من الكتل
  المستقبلية (إعادة تشغيل اللاحقة) لكنها لا تستطيع تقديم
  التاريخ تحت H أو إعادة تشغيل التكوين. **السلوك الافتراضي
  لا يتغير**: هذا المسار نشط فقط إذا حرّكه المشغّل صراحةً
  (`import_verified_snapshot` فعل مخصص، لا تلقائي أبدًا)؛ كل
  عقدة قائمة تقلع بشكل مطابق.
- **المساواة مع العقدة الكاملة**: بعد الانضمام إلى اللاحقة
  H+1..H+k، تكون الحالة والقمة و`state_root_smt` مطابقة
  بالبت مع عقدة كاملة عند نفس القمة (مُختبَر)؛ يغطي فهرس
  منع إعادة التشغيل بالضبط المعاملات عند/فوق H — عقدة غير
  أرشيف لا تستطيع معرفة النافذة تحت H، وتبقى قواعد الحالة
  الحارس (معاملة مكررة تحت H تفشل على الحالة، ولا تُقبل
  مرتين أبدًا).

## سياسة الذاكرة

- **مؤشرات في كل مكان**: يحصر `iterate_domains` الصفحة عند
  `max` مدخلًا (100 افتراضيًا) عبر `range` الكسول في redb؛
  جدول النطاقات كله لا يُتجسَّد أبدًا. القوائم الكبيرة (TLD،
  نطاقات) تمر إلزاميًا عبر هذا المؤشر (`iterate_tlds`، نفس
  العقد، M7d).
- **دلتا فقط**: يكتب `append_block_with_state` النطاقات
  والـ TLD المعدَّلة بالكتلة فقط — وليس الحالة الكاملة أبدًا؛
- **لا تكرار متزامن**: حالة RAM لا يُعاد تثبيتها لكل كتلة؛
  حالة القرص لا يُعاد تحميلها لكل كتلة؛
- **قراءات نقطية**: كل قراءة تفتح معاملة قراءة قصيرة، تعيد
  القيمة، تغلق؛ تعيش `AccessGuard` الخاصة بـ redb فقط لمدة
  النسخة المحدودة؛
- **الكتل التاريخية ليست في RAM أبدًا**: يحمل `load_chain`
  القمة فقط؛ يبث `load_chain_replay` ارتفاعًا بارتفاع؛
- **عداد مُصان**: `domain_count` بتعقيد O(1)، لا مسحًا.

## حدود DoS

يحدّ المخزن ما يستطيع قرين عدائي إجباره على تثبيته أو تخصيصه:

- **`MAX_DHT_CACHE_ENTRY` (64 KiB)**: سجل DHT أكبر يُرفض قبل
  أي معاملة كتابة بواسطة `put_dht_cache` ←
  `StorageError::TooLarge` (لا يكتب شيء)؛
- **`MAX_DOMAIN_PAGE` (10,000)**: يحدّ `iterate_domains`
  *داخليًا* الصفحة المطلوبة عند `min(max, 10_000)` — `max`
  مفرط لا يجرّد أبدًا أكثر من 10,000 حالة في RAM؛ لنفس
  `iterate_tlds` نفس الحد (`MAX_TLD_PAGE`، M7d)؛
- **مفاتيح `meta` المحجوزة**: يرفض `meta_set` المفاتيح
  `tip`، `tip_height`، `format_version`، `domain_count`،
  `tld_count`، و`verified_snapshot_v1` (P0.3) بـ
  `StorageError::ReservedKey` — الكتابة فوق المحاسبة الداخلية
  للمخزن ستُفسده بصمت.
- **ذاكرة DHT مؤقتة محدودة مرتين (LRU)**:
  `DHT_CACHE_MAX_ENTRIES` (100,000 مدخل) و
  `DHT_CACHE_MAX_BYTES` (2 GiB — حارس الحالة العدائية؛ كل
  مدخل مسقوف أصلًا عند 64 KiB بـ `MAX_DHT_CACHE_ENTRY`)، أي
  الحدّين يُصاب أولًا يُخلي بترتيب المفتاح. العدادات (مداخل +
  بايتات) مُصانة وقت الكتابة — لا مسح للعد أبدًا؛ إعادة البناء
  الدقيقة تجري فقط عند الفتح (المسح الكامل الوحيد، عند
  الإقلاع). الدالتان `dht_cache_entries`/`dht_cache_bytes`،
  وحدود قابلة للضبط عبر `set_dht_cache_bounds` (اختبار:
  `dht_cache_respects_the_double_bound`).

## نموذج الثقة

مسارا تحميل، مستويان من الضمان:

- **`load_chain` — ثقة بالقرص المحلي**: hash القمة **يُعاد
  حسابه** من ترويسة كتلة القمة ويقارن بـ `meta["tip"]`
  المخزن (تباعد ← `StorageError::Corrupted`، وليس أبدًا سلسلة
  مستعادة على hash مزوّر)، وحالات النطاقات تُفك بصرامة.
  لكن الكتل التاريخية **لا يُعاد تشغيلها**: الحالات المستمرة
  تؤخذ على محمل الجد. هذا إقلاع عقدة سريع تثق بقرصها
  (كتبه فقط نفس العقدة، ذريًا). منذ M6b، يستخدم هذا المسار
  أولًا **لقطة الحالة** عند صلاحيتها (انظر أدناه): مرساة
  اللقطة تُعاد حسابها واللاحقة فوق H يُعاد التحقق منها
  كالكتل الحية — الجزء المعاد تشغيله ثقة-صفرية إذن، والقاعدة
  المجمدة ثقة-قرص.
- **`load_chain_replay` — ثقة صفرية**: كل الكتل يُعاد
  قراءتها والتحقق منها واحدة واحدة (تحقق كامل، مطابق
  للكتل الحية)؛ القمة الناتجة يجب أن تساوي القمة المخزنة.
  هذه أداة الضبط/الإصلاح.

**توصية**: عقدة صارمة (أو عقدة يمكن لملف تخزينها أن يُعبث
به — قرص مشترك، استعادة نسخة احتياطية مشكوك فيها) يجب أن
تقلع عبر `load_chain_replay`، لا `load_chain`.

## التزامن

يسمح redb 4.x **بكائن `Database` وحيد لكل ملف ولكل عملية**
(الفصل المزدوج المتزامن يفشل بـ `DatabaseAlreadyOpen`).
النموذج المدعوم: `RedbStore` مستنسخ (`Arc<Database>`) مشترك
بين الخيوط — الكُتّاب مُسلَّلون بـ `&mut self` + قفل redb
الداخلي، والقراء متزامنون (معاملات قراءة لقطية). بعد إفلات
كل المقابض تمامًا، يمكن إعادة فتح الملف.

## الاختبارات (`tests/redb_store.rs` + وحدات `#[cfg(test)]`)

كل اختبار يستخدم ملف redb مؤقتًا خاصًا به (`tempfile`). التغطية:

- ذهاب-إياب الكتل من التكوين إلى N، إعادة تشغيل، إعادة قراءة،
  إعادة تشغيل replay؛
- M7d: سجل الـ TLD مستمر بدلتا ذرية، مستعاد عند إعادة
  التشغيل (`RegisterDomain` تحت TLD طُلب قبل إعادة التشغيل
  تبقى مقبولة — النافذة مغلقة)، عدادات دقيقة عند إعادة
  الفتح، مؤشر `tlds` تصاعدي، إلحاق فاشل لا يترك TLD، مفتاح
  محجوز `tld_count` مرفوض؛
- الذرية: إلحاق فاشل لا يترك شيئًا (القمة، النطاقات، الفهرس
  سليمة)؛ الدلتا المكررة تُحسب مرة؛
- مؤشرات النطاقات: ترقيم 100/7، ترتيب `DomainId` تصاعدي،
  بداية بعد معرّف قائم أو غائب بصرامة، `max = 0`؛
- عداد `domain_count` الدقيق (إدراج/تحديث/إعادة فتح)؛
- ذهاب-إياب ذاكرة DHT + كتابة فوق؛
- التزامن: قراءات من خيطين على مقابض مستنسخة؛
- قاعدة بيانات تالفة: ملف مقتطع / مهمل ← خطأ مُصنَّف، لا
  panic (`catch_unwind`)؛
- M6b: لقطة مكتوبة عند الفاصل، دون القمة بصرامة؛
  إقلاع من اللقطة = إعادة تشغيل كاملة مطابقة بالبت
  (state_root + SMT، الحالة المنطقية الكاملة، القمة)؛ لقطة
  معدَّلة (tip_hash تالف، حالة غير قابلة لفك الترميز، ارتفاع
  > القمة، meta بطول خاطئ) ← تراجع صامت إلى التحميل الكامل،
  نفس السلسلة النهائية؛ اللاحقة المعاد تشغيلها < الفاصل؛
  استبدال اللقطة (لا تراكم) عند عبور الفاصل؛ مخزن قبل M6b
  بلا جداول لقطة يُحمَّل بشكل مطابق؛
- M8: فهرس منع إعادة التشغيل يعاد بناؤه عند الإقلاع — معاملة
  يعاد تضمينها داخل النافذة تُرفض (`TxReplay`) بعد الاستعادة؛
  معاملة أقدم من النافذة تُقبل (التنقية دون تغيير، قواعد
  الحالة تقرر)؛ العدد الدقيق == الفهرس الحي (==
  `load_chain_replay`) لمخزن أقصر وأطول من النافذة؛ إقلاع
  اللقطة: جزء النافذة تحت H يعاد بناؤه بالمسح، والفوق بإعادة
  تشغيل اللاحقة؛
- P0.2: فهرس الأسماء — `resolve_name == DomainId::from_name`
  لأجل 120 نطاقًا (حي، بعد إعادة التشغيل، بعد المسح + إعادة
  البناء)، و`resolve_tld` للـ TLD المطالَب به؛ GC لنطاق منتهٍ
  يزيل المدخل (لا أشباح)، قبل إعادة البناء وبعدها؛ فصل صارم
  لفضائي النطاق/TLD؛ إلحاق فاشل لا يترك مدخل فهرس؛ مفتاح
  الفهرس هو اشتقاق BLAKE3 الموثّق؛
- P0.3/P0.4 (`tests/verified_snapshot.rs`): تصدير ← استيراد ←
  إقلاع == إعادة تشغيل كاملة (الحالة، القمة، `state_root_smt`
  مطابق بالبت؛ الحالة المستوردة هي الخاصة بالكتلة النهائية،
  لا القمة)؛ صفحة مزوّرة ببايت واحد ← رفض قبل أي كتابة
  (المخزن دون تغيير مطلق)؛ صفحة غائبة ← رفض؛ `state_root`
  خاطئ (manifest ↔ نقطة تفتيش، ثم جذر معاد حسابه ≠
  جذر موقّع) ← رفض؛ عدادات/ارتفاعات خاطئة / قمم غير متسقة /
  معرّفات مكررة ← رفض؛ الاستيراد يتطلب مخزنًا فارغًا؛
  التصدير يتطلب لقطة مستمرة عند ارتفاع نقطة التفتيش؛ عقد
  المرساة (`append_bootstrap_anchor`: علامة مطلوبة، اتساق،
  idempotence)؛ صيغة متسلسلة صارمة (بايتات زائدة، وسوم،
  حدود DoS)؛ لقطة عند H ثم انضمام كتل H+1..H+k ← سلسلة
  مطابقة للعقدة الكاملة (حالة/قمة/جذر)، إقلاع بلا تاريخ تحت
  H، فهرس منع إعادة التشغيل = بالضبط المعاملات عند/فوق H.
