# UDP + TCP DNS সার্ভার (M6 + M7b) — `scone dns`

> Scone DNS পৃষ্ঠের নরমেটিভ স্পেসিফিকেশন।
> ডক/কোডের যেকোনো বৈপরীত্য = বাগ (সত্যের উৎস সংশোধন করুন)।

## ওভারভিউ

**DNS সার্ভার** হলো রিলের একটি ঐচ্ছিক পৃষ্ঠ: এটি Scone নামের জন্য
**UDP এবং TCP** DNS কোয়েরির (RFC 7766, একই পোর্ট) উত্তর দেয়
**শুধুমাত্র চেইনের বিরুদ্ধে যাচাইকৃত ডেটা থেকে**, এবং বাকি
সবকিছুর জন্য একটি **ঐচ্ছিক রিকার্সিভ ফলব্যাক** (`addr:port`) দেয়।
এটি চেইন, স্টোর বা DHT-র মালিক নয়: অস্তিত্ব/মেয়াদের
সিদ্ধান্ত **অথরিটেটিভ DNS স্ন্যাপশটের** মধ্য দিয়ে যায় (প্রতিটি
প্রয়োগকৃত ব্লকের পরে প্রকাশিত একটি RAM ভিউ — নিচে দেখুন), এবং রেকর্ড
আনা রিলের (প্রসেস) মধ্য দিয়ে যায়, অভ্যন্তরীণ
`RelayCommand`/`ResolveLocal` চ্যানেলের মাধ্যমে (ইন-প্রসেস, একটি
রাউন্ড ট্রিপ) — CLI-র মতোই একই যাচাইকৃত পাথ।

```text
              UDP+TCP :5353 (default 127.0.0.1)
                    │
             scone relay --dns 127.0.0.1:5353
                    │  ┌────────────────────────────────┐
                    ├──┤ Sharded cache, 16 ways (qname)  │
                    │  └────────────────────────────────┘
                    │  Scone-shaped name?
                    │  ├─ YES → authoritative DNS snapshot:
                    │  │        unknown/expired → NXDOMAIN (RAM,
                    │  │        zero round trips into the core)
                    │  │        → apex search by suffix
                    │  │        → internal `resolve_local` (relay)
                    │  │           chain + verified record (hash,
                    │  │           owner, sequence) → answers
                    │  │        apex without a published record → NODATA
                    │  └─ NO → upstream fallback (if configured)
                    │           otherwise REFUSED
                    │
                    │  response budget:
                    │    UDP → 512 bytes (no EDNS); overflow =
                    │          cut at the last fitting record + TC=1 →
                    │          the client retries over TCP
                    │    TCP → 64 KiB (2-byte length prefix,
                    │          RFC 1035 §4.2.2): full set
```

## স্টার্টআপ

```bash
scone relay --dns 127.0.0.1:5353            # DNS surface only
scone relay --dns 0.0.0.0:53 \
            --dns-upstream 1.1.1.1:53 \
            --dns-upstream 8.8.8.8:53       # + recursive fallback
```

রিলে কার্যকর ঠিকানা stdout-এ ঘোষণা করে
(মেশিন-পাঠযোগ্য চুক্তি, `p2p:`-এর মতো): সকেট বাইন্ড হওয়ার সাথে সাথে
একটি `dns: <addr>` লাইন।

ভ্যালিডেশন ক্লায়েন্ট: `dig <name> --dns 127.0.0.1:5353
--qtype A` (A, AAAA, TXT, MX, NS, CNAME, ANY)।

## রেজোলিউশন পাথ (AUTHORITY = চেইন, সর্বদা)

0. **অথরিটেটিভ DNS স্ন্যাপশট**: একটি অপরিবর্তনীয় ভিউ
   (`Arc<HashMap<DomainId, {valid_until, has_record}>>`,
   `tokio::sync::watch` ফিড) রিলে কোর দ্বারা **প্রতিটি
   প্রয়োগকৃত ব্লকের পরে** (পুশ, পোল নয়) এবং বুটে প্রকাশিত।
   অস্তিত্ব/মেয়াদের সিদ্ধান্ত — NXDOMAIN, মেয়াদোত্তীর্ণ ডোমেইন — RAM
   থেকে এই স্ন্যাপশটের মাধ্যমে সেবা পাওয়া যায়: একটি `Arc` ক্লোন + একটি
   ম্যাপ লুকআপ, রিলের একক-মালিক রান
   লুপে **কখনো প্রবেশ করে না**। সম্পূর্ণ পাথ
   (`RelayCommand`/`ResolveLocal`) প্রকৃত
   রেকর্ড আনার জন্য সংরক্ষিত থাকে (DHT পুল), ক্যাশের জন্য ধন্যবাদে
   বিরল। স্ন্যাপশট কখনো রেকর্ড ডেটা বহন করে **না**: শুধুমাত্র অস্তিত্ব
   ও মেয়াদ।
   - **O(touched) কপি-অন-রাইট ডেল্টা**: ম্যাপটি একটি
     `Arc<HashMap>`; একটি টিপ এক্সটেনশন ব্লকের ডেল্টা প্রকাশ করে
     (ব্লকের নিজের লেনদেন তারা যে প্রতিটি ডোমেইন পরিবর্তন করতে
     পারে তাদের নাম বহন করে — Register/Assign/Update/Renew/TransferDomain — সাথে
     পুশ টাইমে মূল্যায়িত ডিটারমিনিস্টিক মেয়াদ-GC অপসারণ)
     `Arc::make_mut`-এর মাধ্যমে: ম্যাপটি শুধুমাত্র তখনই ক্লোন হয়
     যদি একজন পাঠক এখনও পূর্ববর্তী ভিউ ধরে রাখে। বুট এবং রিঅর্গ সম্পূর্ণ
     স্ন্যাপশট পুনর্নির্মাণ করে (একটি পেজড ব্যাকএন্ড ওয়াক)।
   - সদ্যতা: একজন পাঠক একটি ব্লক প্রয়োগের সময় কয়েকশো ms পুরনো
     স্ন্যাপশট দেখতে পারে — একই স্টেলনেস একটি স্টেটাস RPC-র
     হতো; DNS ক্যাশ TTL প্রভাবিত হয় না (উত্তরগুলো তাদের
     উৎস অনুযায়ী অথরিটেটিভ থাকে)।
1. **শার্ডেড ক্যাশ**: [`ShardedCache`] — ১৬টি স্বাধীন `Cache`
   শার্ড `hash(qname)` দিয়ে কীড (qtype শার্ড ভাগ করে:
   প্রতি-নাম লোকালিটি)। একটি হট নাম হাজার হাজার
   qps-এ একটি একক মিউটেক্সের পিছনে সারিবদ্ধ হওয়ার বদলে
   ট্রাফিকের ১/১৬ অংশের সাথে প্রতিদ্বন্দ্বিতা করে। গ্লোবাল বাউন্ড
   (ডিফল্টে ১০০,০০০ এন্ট্রি / 64 MiB,
   `--dns-cache-limit` / `--dns-cache-max-mem`) প্রতি শার্ডে বিভক্ত
   (ডকুমেন্টেড সবচেয়ে খারাপ ক্ষেত্রে: একটি 1 + N/shards ফ্যাক্টর)। প্রতিটি এন্ট্রির
   প্রকৃত rdata আকার হিসাবকৃত (প্রতি
   এন্ট্রিতে ~১২৮ বাইট ওভারহেড) এবং FIFO বহিষ্করণ দুটির
   মধ্যে প্রথম বাউন্ডে ট্রিগার হয় — মেমরি ক্যাপ পূর্ণ-আকারের
   এন্ট্রির বিরুদ্ধেও থাকে (`MAX_DHT_RECORD_LEN`)। TTL 60 s
   (অথরিটেটিভ) / 600 s-এ ক্ল্যাম্পড (ফলব্যাক)। নেগেটিভ
   ক্যাশ (NXDOMAIN/NODATA) একই নিয়ম অনুসরণ করে; প্রতিটি এন্ট্রি
   তার উৎস (অথরিটেটিভ বা ফলব্যাক) বহন করে যাতে AA বিট
   হিটেও সৎ থাকে। **কখনো SERVFAIL ক্যাশ করবেন না** (ক্ষণস্থায়ী
   লোকাল ব্যর্থতা) **এবং REFUSED-ও নয়** (কনফিগারেশন অবস্থা):
   উভয়ই প্রতিটি কোয়েরিতে পুনর্গণনীত। ক্ষমতায় FIFO বহিষ্করণ।
   **হট পাথ (Cloudflare/1.1.1.1-অনুপ্রাণিত)**:
   - শেয়ারড `Arc<CacheEntry>` এন্ট্রি: একটি হিট একটি রিফকাউন্ট
     বাম্প, কখনো rdata-র গভীর ক্লোন **নয়** (`put` Arc প্রতিস্থাপন করে —
     কোনো শেয়ারড মিউটেশন নেই; TTL এখনও শার্ড
     লকের অধীনে যাচাই হয়);
   - **অ্যালোকেশন-মুক্ত লুকআপ**: দুই-স্তরের ম্যাপ
     (`Box<str>` qname → qtype → এন্ট্রি), কোয়েরির বরোড
     `&str` সরাসরি প্রোব করে (`Borrow<str>`) — পুরনো
     `(String, u16)` টাপল কী প্রতিটি
     লুকআপে একটি নতুন `String` অ্যালোকেট করত;
   - **প্যাকড ধারাবাহিক রেকর্ড**: প্রতি
     এন্ট্রিতে একটি `Box<[u8]>` বাফার (প্রতি
     রেকর্ডে `u16 rdlen ‖ u16 rtype ‖ u32 ttl ‖ rdata`) প্রতি রেকর্ডে একটি `Vec`-এর
     বদলে — মেমরি বাজেট
     ঠিক যা অ্যালোকেট করা হয়েছে তা ট্র্যাক করে;
   - **আউটপুটে RFC 1035 নেম কমপ্রেশন**: অথরিটেটিভ
     উত্তরের owner একটি ২-বাইট কমপ্রেশন
     পয়েন্টার (`0xC00C`) প্রতিধ্বনিত প্রশ্নে — প্রশ্নটি কখনো
     প্রতি রেকর্ডে সম্পূর্ণরূপে পুনঃএনকোড হয় না।
2. **Scone-আকৃতির?** কঠোর প্রি-ফিল্টার: লেবেল `[a-z0-9-_]`
   (1..63), ≥ ২টি লেবেল, TLD 1..63 বাইট `[a-z0-9-]` (দেখুন
   `TldName::MAX_LEN`), মোট দৈর্ঘ্য ≤ ২৫৩ — **এবং TLD ICANN
   রুটের বাইরে** (`is_icann_tld`, ফ্রোজেন IANA তালিকা + RFC 2606:
   `com`, `fr`, `org`… কখনো Scone-এর নয়)।
   এমন একটি নাম যা Scone নাম হতে **পারে না** (যেমন `www.foo_bar`,
   TLD-তে আন্ডারস্কোর) ফলব্যাকে যায়; একটি সম্ভাব্য Scone নাম
   (`absent.uip`) চেইনের বিষয়: অনিবন্ধিত → অথরিটেটিভ
   NXDOMAIN, কোনো আপস্ট্রিম ছাড়াও। একটি ICANN TLD (`example.com`)
   কনফিগারকৃত হলে আপস্ট্রিমে ফরওয়ার্ড হয়, অন্যথায় REFUSED
   — কখনো Scone দ্বারা অথরিটেটিভভাবে রেজোলিভ হয় না।
3. **Apex অনুসন্ধান**: দীর্ঘতম থেকে সংক্ষিপ্ততম সাফিক্স (সর্বনিম্ন
   ২টি লেবেল)। রিলের কাছে যার অন-চেইন স্টেট পরিচিত প্রথম
   সাফিক্স = apex; রেকর্ড সেট সম্পূর্ণ qname-কে সেবা দেয়
   (সাবনেমসহ — অন্তর্নিহিত ওয়াইল্ডকার্ড আচরণ, খোলা
   সিদ্ধান্ত)।
4. **`resolve_local` (অভ্যন্তরীণ চ্যানেল)**: একটি একক রাউন্ড ট্রিপ, কখনো
   একটি DHT ওয়েটার নয়। অন-চেইন স্টেট (`registered`, owner, sequence) +
   লোকাল DHT ক্যাশ রেকর্ড **পুনঃযাচাইকৃত** (owner, sequence,
   record_hash == অন-চেইন কমিটমেন্ট)। একটি অ-সামঞ্জস্যপূর্ণ রেকর্ড
   কখনো উত্তর দেয় না — প্রাপ্যতা ≠ কর্তৃত্ব।
   - অনিবন্ধিত → NXDOMAIN;
   - বৈধ রেকর্ড ছাড়া নিবন্ধিত → NODATA (NOERROR, ০
     উত্তর);
   - যাচাইকৃত রেকর্ড → qtype দ্বারা ফিল্টারকৃত উত্তর।

## কোডেক (RFC 1035, কঠোর সাবসেট)

- কোয়েরি: ১২-বাইট হেডার, **একটি** প্রশ্ন, QCLASS = IN, **কোনো
  কমপ্রেশন নেই** (পয়েন্টার = প্রত্যাখ্যান)। লেবেল লোয়ারকেসড এবং
  ভ্যালিডেটেড। QR=1, QDCOUNT≠1, অবৈধ লেবেল → **নীরবতা**
  (আবর্জনা কিছুই খরচ করে না)।
- উত্তর: QR|RD(প্রতিধ্বনি)|RA, **AA শুধুমাত্র অথরিটেটিভ উত্তরে**
  (চেইন, ফ্রেশ বা ক্যাশড — কখনো ফলব্যাকে বা ত্রুটি RCODE-তে নয়),
  প্রশ্ন হুবহু কপি করা, অথরিটেটিভ উত্তরগুলোতে একটি
  **RFC 1035 কমপ্রেসড owner** (প্রতিধ্বনিত প্রশ্নে ২-বাইট পয়েন্টার `0xC00C`);
  ফলব্যাক আপস্ট্রিম উত্তর যেমন-আছে সেবা পায় (কখনো পুনঃএনকোড হয় না)।
- সেবাকৃত টাইপ: A, AAAA, CNAME, NS, MX, TXT, **PTR, SRV, CAA**
  (+ অজান্ট হুবহু পুনঃএনকোড; মোট ৯টি নেটিভ টাইপ, rdata
  RFC অনুযায়ী এনকোড — 1035/2782/8659; কঠোর CAA: critical বিট শুধুমাত্র
  0x80, লোয়ারকেস ট্যাগ)। একটি A/AAAA কোয়েরি সেটের
  CNAME-গুলো অন্তর্ভুক্ত করে (অ্যালিয়াস চেজিং)। ANY কোয়েরি (255): কোডেক দ্বারা
  ফিল্টারকৃত সম্পূর্ণ সেট।
- সীমা (M7b): **উত্তর বাজেট ট্রান্সপোর্টের উপর নির্ভর করে** —
  UDP-তে ৫১২ বাইট (ক্লাসিক RFC 1035 §2.3.4 পেলোড, কোনো EDNS নয়),
  TCP-তে 65,535। বাজেট ছাড়ানো একটি সেট শেষ
  রেকর্ডে কাটা হয় যা ধরে, সাথে **TC=1** (সৎ ছোটকরণ, RFC 1035
  §4.2.1): ক্লায়েন্ট TCP-তে পুনঃচেষ্টা করে (RFC 7766), যেখানে সম্পূর্ণ
  সেট সেবা পায়। UDP বাজেটের চেয়ে বড় একটি আপস্ট্রিম উত্তর
  পুনঃএনকোড করে ছোট করা হয় (TC=1) যেমন-আছে দেওয়ার বদলে;
  TCP-তে এটি বাইট প্রতি বাইট যায়। ছোটকরণ ক্যাশ
  হিটেও প্রযোজ্য (বাজেট উত্তরের সময়ে প্রয়োগ হয়, ক্যাশ-ভরার সময়ে নয়)।
- RCODE: 0 NOERROR (উত্তরসহ বা ছাড়া), 2 SERVFAIL (লোকাল
  ব্যর্থতা), 3 NXDOMAIN (অথরিটেটিভ), 5 REFUSED (আপস্ট্রিম
  ছাড়া অ-স্কোন)।

## রিকার্সিভ ফলব্যাক

- আপস্ট্রিমগুলো `addr:port` (UDP), ক্রমে চেষ্টা, প্রতি
  আপস্ট্রিমে ২ সে টাইমআউট, সকেট আপস্ট্রিমের সাথে **কানেক্টেড**
  (কার্নেল ফিল্টারিং: অন্য যেকোনো উৎস থেকে একটি প্যাকেট কখনো
  গৃহীত হয় না)।
  আপস্ট্রিম উত্তর শুধুমাত্র তখনই গৃহীত হয় যদি এটি কোয়েরির সাথে
  **মিলে**: একই TXID, QR=1, প্রশ্ন (QNAME+QTYPE+QCLASS) বাইট
  প্রতি বাইট কপি। অ-সামঞ্জস্যপূর্ণ উত্তর → SERVFAIL, এবং
  কিছুই ক্যাশ হয় না।
- যাচাইকৃত আপস্ট্রিম উত্তর যেমন-আছে পাস করা হয়; এর
  উত্তরগুলো `fallback` উৎসসহ ক্যাশ হয় (AA কখনো সেট হয় না, ক্যাশ
  হিটেও) এবং TTL 600 s-এ ক্ল্যাম্পড। আপস্ট্রিম ত্রুটি
  RCODE (NOERROR/NXDOMAIN ছাড়া) ক্যাশ হয় না।
- **ডিফল্টে প্রাইভেট**: কোনো আপস্ট্রিম নেই = Scone আকৃতির
  বাইরের নামের জন্য REFUSED।

## DHT নেগেটিভ ক্যাশ (অ্যান্টি-অ্যামপ্লিফিকেশন)

একটি **উত্তরহীন DHT পুল** (রেকর্ড অন-চেইন প্রত্যাশিত —
`record_hash` কমিটেড — কিন্তু লোকাল ক্যাশ এবং
কোয়েরিকৃত পিয়ার থেকে অনুপস্থিত) নামটিকে `DHT_NEGATIVE_TTL_SECS`
(৩০ s) জন্য একটি বাউন্ডেড নেগেটিভ ক্যাশে (FIFO, ক্যাপ
`DHT_NEGATIVE_CAP` = ৪,০৯৬
নাম) পার্ক করে: TTL-এর মধ্যে একই নামের পুনরাবৃত্ত রেজোলিউশন
**দমন করা হয়** (গণনাকৃত, কখনো পুনঃপুল হয় না)। একজন স্ক্যানার — বা
এমন একটি হট নাম যার owner কখনো প্রকাশ করেনি — আর একটি DNS
কোয়েরিকে প্রতি কোয়েরিতে প্রতি মেশ পিয়ারে একটি `GetRecord`-এ
পরিণত করতে পারে না। নেগেটিভ
এন্ট্রি TTL-তে, রেকর্ড আগমনে (সফল পুল প্রকৃত
ক্যাশে লেখে), বা FIFO ক্যাপ থেকে ঠেলে বেরিয়ে মারা যায়।

উন্মুক্ত কাউন্টার (`scone_dht_negative_hits_total`,
`_expired_total`, `_capped_total` — `relay.md`-এ "Metrics" দেখুন)।

## TCP (M7b, RFC 7766)

UDP-র মতোই একই পোর্ট (`--dns` ঠিকানায় দ্বিতীয় TCP বাইন্ড)।
ট্রান্সপোর্ট RFC 1035 §4.2.2 অনুসরণ করে: প্রতিটি বার্তা **২
বাইটে** big-endian তার দৈর্ঘ্য দ্বারা প্রিফিক্সড।

- **কোয়েরি**: প্রিফিক্স দৈর্ঘ্য ≥ 1 এবং ≤ ৫১২ বাইট (একটি DNS কোয়েরি
  ক্লাসিক পেলোডে ধরে — RFC 7766 §6; কোনো EDNS সেবা নেই)। সীমার
  বাইরে → তাৎক্ষণিক সংযোগ বন্ধ।
- **উত্তর**: 65,535-বাইট বাজেট (২-বাইট প্রিফিক্সের সর্বোচ্চ) —
  UDP-র জন্য খুব বড় একটি সেট এখানে **সম্পূর্ণভাবে** সেবা পায়, TC=0।
- **পাইপলাইনিং**: প্রতি সংযোগে একাধিক কোয়েরি ক্রমান্বয়ে
  সেবা পায়, ক্রমে (একটি রাইট = একটি প্রিফিক্সড উত্তর)।
- **রিড টাইমআউট**: প্রতি রিডে ৫ সে (প্রিফিক্স বা বডি) — একটি নীরব
  ক্লায়েন্ট বিচ্ছিন্ন, তার স্লট মুক্ত।
- **সমান্তরাল সংযোগ**: সর্বাধিক ৬৪টি (সেমাফোর); ৬৫তম
  তাৎক্ষণিকভাবে প্রত্যাখ্যাত (সংযোগ বন্ধ), কখনো সারিবদ্ধ নয় — কোনো
  টাস্ক বা মেমরির অবাউন্ডেড বৃদ্ধি নেই।
- রিড/রাইট/টাইমআউট ত্রুটি: ডিবাগ লগ + পরিষ্কার বন্ধ। **নেটওয়ার্ক
  ইনপুটে কখনো প্যানিক নয়।**
- আবর্জনা (অবোধ্য কোয়েরি) নীরবতা পায় কিন্তু সংযোগ
  বন্ধ করে না: পরবর্তী (বৈধ) কোয়েরি সেবা পায়।

```text
client                     server
  │ [len u16][query]         │
  │ ─────────────────────►   │ cache → authoritative → fallback
  │ ◄─────────────────────   │ [len u16][response ≤ 64 KiB]
  │ (UDP had answered TC=1 → the client retries here)
```

## বাউন্ড ও গার্ডরেল

| গার্ডরেল | মান |
|---|---|
| UDP ডেটাগ্রাম (কোয়েরি/উত্তর) | ৪০৯৬ বাইট (বাইরে প্রত্যাখ্যাত) |
| UDP উত্তর বাজেট (বাইরে TC=1) | ৫১২ বাইট (কোনো EDNS নয়) |
| সর্বোচ্চ TCP কোয়েরি | ৫১২ বাইট (বাইরে বন্ধ) |
| সর্বোচ্চ TCP উত্তর | 65,535 বাইট |
| সমান্তরাল TCP সংযোগ | ৬৪ (সেমাফোর, তাৎক্ষণিক প্রত্যাখ্যান) |
| TCP রিড টাইমআউট | ৫ সে |
| ক্যাশ | ডিফল্টে গ্লোবাল বাউন্ড ১০০,০০০ এন্ট্রি / 64 MiB, ১৬টি শার্ডে বিভক্ত (`--dns-cache-limit` / `--dns-cache-max-mem`) |
| অথরিটেটিভ TTL | **প্রতি রেকর্ড** (`record.ttl`, সীমা 1..=2,592,000 s; ঐতিহাসিক ধ্রুবক 60 s শুধুমাত্র সেবা উত্তরের জন্য থাকে) |
| ফলব্যাক TTL (ক্ল্যাম্প) | 600 s |
| সমান্তরাল UDP কোয়েরি | ৪,০৯৬ (`MAX_INFLIGHT_UDP`, সেমাফোর; বাইরে: ড্রপ, ক্লায়েন্ট পুনঃচেষ্টা করে) — টিউনেবল `--dns-max-inflight` (সর্বনিম্ন 1) |
| DHT নেগেটিভ ক্যাশ | ৩০ s (`DHT_NEGATIVE_TTL_SECS`), FIFO ক্যাপ ৪,০৯৬ নাম |
| প্রতি আপস্ট্রিমে টাইমআউট | ২ সে |

প্রকল্পের নিয়ম সম্মানিত: নেটওয়ার্ক ডেটায় কখনো প্যানিক নয়;
সর্বত্র কঠোর ডিকোডিং; সার্ভার চেইন, স্টোর
বা DHT স্পর্শ করে না (রিলেই একমাত্র যাচাই কর্তৃত্ব থাকে)।

## টেস্ট

- ইউনিট (`scone-network::dns`): কঠোর কোডেক (QR, কমপ্রেশন,
  লেবেল প্রত্যাখ্যান), অথরিটেটিভ উত্তর, NODATA, NXDOMAIN,
  আপস্ট্রিম ছাড়া REFUSED, একটি UDP মকে ফলব্যাক, বাউন্ডেড
  ক্যাশ, TXT চাংকিং, আপস্ট্রিম পার্সিং; M6 ফিক্স-আপ: AA-বিট
  সততা (অথরিটেটিভ বনাম ফলব্যাক বনাম ত্রুটি, ক্যাশ
  হিটসহ), একটি অতিরিক্ত-আকারের সেটের TC=1 ছোটকরণ, আপস্ট্রিম উত্তর
  প্রত্যাখ্যান (TXID বা প্রশ্ন অমিল), SERVFAIL/REFUSED-এর
  কোনো ক্যাশিং নেই; শার্ডেড ক্যাশ: শার্ড বিস্তার, বিভক্ত গ্লোবাল
  বাউন্ড, একটি হট নামে ৪টি সমান্তরাল কর্মী; হট পাথ:
  অ্যালোকেশন-মুক্ত লুকআপ, প্যাকড এন্ট্রি, owner কমপ্রেশন।
- M7b: প্রতি-ট্রান্সপোর্ট বাজেট (UDP ৫১২ বাইট → TC=1, TCP → সম্পূর্ণ
  সেট), একটি ক্যাশ হিটের ছোটকরণ, প্রকৃত `run_tcp` (সেট >
  ৫১২ সম্পূর্ণ সেবাকৃত, ২টি কোয়েরির পাইপলাইনিং, অতিরিক্ত-আকারের
  কোয়েরি → বন্ধ, নীরব ক্লায়েন্ট → ৫ সে টাইমআউট, একই
  সংযোগে আবর্জনা তারপর বৈধ কোয়েরি), আপস্ট্রিম উত্তর >
  ৫১২ UDP-তে পুনঃএনকোড TC=1
  / TCP-তে বাইট প্রতি বাইট।
- প্রকৃত ইন্টিগ্রেশন (`tests/dns_server.rs`): একটি সম্পূর্ণ রিলে
  (প্রোডাকশন devnetসহ) + রেজিস্ট্রেশন + UpdateDomain +
  PutRecord, তারপর প্রকৃত UDP কোয়েরি: যাচাইকৃত A (AA বিট), TXT,
  NODATA AAAA, NXDOMAIN, মকের মাধ্যমে ফলব্যাক, পুনঃকোয়েরি, apex-এর
  মাধ্যমে সাবনেম।
- বাইনারি E2E (`crates/scone/tests/dns_cli.rs`): প্রকৃত `scone`
  বাইনারি — `relay --dns`, `identity generate`, `domain register`,
  `domain update --file`, তারপর `dig` (dnsutils) (যাচাইকৃত A, TXT,
  NXDOMAIN, REFUSED) একটি প্রকৃত UDP পোর্টে।

## খোলা সিদ্ধান্ত

- কোনো EDNS নেই (UDP বাজেট ৫১২ বাইট থাকে; TC=1 ছোটকরণ +
  TCP devnet-এর চাহিদা কভার করে)।
- রেকর্ড সেট কোনো প্রতি-রেকর্ড নাম বহন করে না: সম্পূর্ণ সেট
  apex-র প্রতিটি সাবনেমকে সেবা দেয় (অন্তর্নিহিত ওয়াইল্ডকার্ড)।
  প্রতি-রেকর্ড অ্যাড্রেসিং `DnsRecord` সম্প্রসারণ (প্রোটোকল) চাইবে।
- ফলব্যাক কাঁচা কোয়েরি ফরওয়ার্ড করে: একটি ক্ষতিকর আপস্ট্রিম
  যেকোনো কিছুর উত্তর দিতে পারে (অযাচাইকৃত উত্তর — এটিই স্ট্যান্ডার্ড
  রিকার্সিভ মডেল; Scone নাম কখনো এর মধ্য দিয়ে যায় **না**)।

## GeoDNS (ভৌগোলিক রাউটিং)

> নরমেটিভ স্পেসিফিকেশন। ডক/কোডের যেকোনো বৈপরীত্য = বাগ।

### এমবেডেড GeoIP টেবিল (স্বয়ংক্রিয়)

প্রতিটি বাইনারি রিলেতে কম্পাইলকৃত একটি **IP → দেশ ম্যাপিং টেবিল**
এমবেড করে: **কোনো কনফিগারেশন প্রয়োজন নেই**, ভৌগোলিক রাউটিং
সর্বত্র স্বয়ংক্রিয়ভাবে সক্রিয়।

- **ডেটা উৎস**: **DB-IP Lite** ("IP to Country Lite"),
  লাইসেন্স **CC BY 4.0** — অ্যাট্রিবিউশনসহ পুনঃবিতরণযোগ্য:
  `https://db-ip.com` (মাসিক কিউরেটেড; পূর্বে: RIR ডেলিগেশন
  `scripts/gen-geo-table.py`-এর মাধ্যমে, সরানো হয়েছে)।
  কোয়ান্টাইজড সেল **/20 v4 এবং /24 v6** (DB-IP-এর নেটিভ
  গ্রানুলারিটি, ~1.3M পরিসর, পার্সারের মেমরি বাউন্ড ছাড়িয়ে
  যায়) — ~96,500 নিয়ম। উৎপাদনের তারিখ টেবিল হেডারে
  (`assets/embedded-geo.table`)।
- **চেকসাম**: টেবিলের SHA-256 কম্পাইল টাইমে গণনা হয়
  (`build.rs`), **বুটে পুনঃযাচাই হয়** (অমিল = টাইপড
  প্রত্যাখ্যান — একটি পরিবর্তিত বাইনারি কখনোই ভৌগোলিক উত্তর
  সরবরাহ করে না) এবং বুটে অ্যাট্রিবিউশনসহ লগ হয়। হ্যাশ
  নিশ্চিত করে "একটি বিল্ডের প্রতিটি নোড একই টেবিল ভাগ করে" —
  সেটি যাচাই করা যায়, অনুমান করা হয় না।
- **পুনরুৎপাদন**: `scripts/geo-convert.py` (মাসের DB-IP Lite
  CSV ডাউনলোড করে, রূপান্তর করে — সাংখ্যিক দেশ, মহাদেশ
  ডেরিভড ISO→M49, ASN/অঞ্চল Lite-এ অনুপস্থিত)।
- **গ্রানুলারিটি**: দেশ (সাংখ্যিক ISO 3166-1) + মহাদেশ (UN
  M49) ডেরিভড। কোনো ASN বা অঞ্চল নয় (Lite-এ অনুপস্থিত —
  ASN/অঞ্চলের প্রয়োজন একটি এমবেডেড-পাইপলাইন বিবর্তনের
  অপেক্ষায় থাকে, কখনোই লোকাল টেবিল নয়)।
- **পারফরম্যান্স**: সাজানো পরিসরের উপর **বাইনারি সার্চ**
  লুকআপ (সূচি প্রথম ব্যবহারে একবার তৈরি, প্রতি v4/v6 পরিবারে) —
  পরিমাপকৃত হট ~৯৫ ns/লুকআপ, সম্পূর্ণ টেবিলে র‍্যান্ডম-অ্যাক্সেস
  ~৫০ µs (বেঞ্চ: `cargo test -p scone-network --release --test geo_bench
  -- --ignored`)।
- **রিলে স্ব-অবস্থান**: রাউটিং **প্রতিটি কোয়েরির সোর্স IP**
  অনুসরণ করে — একটি LAN রিলে তার লোকাল ক্লায়েন্টদের
  স্বয়ংক্রিয়ভাবে সঠিক জোনে রাউট করে।
- **আরোপিত টেবিল** (remove-geo-operator-table, 2026-10-22):
  এমবেডেড টেবিলই **একমাত্র উৎস** — কোনো অপারেটর ইমপোর্ট বা
  ওভাররাইড নেই। **কোনো রানটাইম geo অপশন নেই**: প্রতিটি
  `--geo-*` ফ্ল্যাগ একটি কঠোর clap প্রত্যাখ্যান (geozone
  build-কর্তৃক-আরোপিত)। নির্দিষ্ট প্রয়োজনের অপারেটর (ASN,
  অঞ্চল) একটি এমবেডেড-পাইপলাইন বিবর্তনের অপেক্ষায় থাকে,
  লোকাল টেবিল নয়।

### ওভারভিউ

একটি ডোমেইন তার স্বাক্ষরিত
রেকর্ড সেটে **ভৌগোলিক রাউটিং** নিয়ম প্রকাশ করতে পারে: `GEOROUTE`
রেকর্ড (Scone প্রাইভেট টাইপ `32,768`,
IANA পরিসরের বাইরে)। রিজলভার এই
ডোমেইনগুলোর A/AAAA প্রশ্নের উত্তর দেয় **নিয়ম দ্বারা নির্বাচিত
endpoint-এর ঠিকানা দিয়ে** (ক্লায়েন্টের অবস্থানের সবচেয়ে কাছের scope,
  টেবিলের মাধ্যমে তার সোর্স IP থেকে ডেরিভড), একটি স্ট্যাটিক
A/AAAA রেকর্ডের বদলে।
বাকি সবকিছু (GEOROUTE ছাড়া ডোমেইন, অন্যান্য qtype) ক্লাসিক
DNS পাথ অনুসরণ করে, **বাইট প্রতি বাইট**।

### GeoDNS মেট্রিক্স

Prometheus এন্ডপয়েন্ট geo উত্তর বিভাজন উন্মুক্ত করে:

- `scone_dns_geo_answers_total` — সেবাকৃত মোট GEOROUTE উত্তর;
- `scone_dns_geo_by_continent_total{continent=\"<M49>\"}` — মহাদেশ অনুযায়ী;
- `scone_dns_geo_by_country_total{country=\"<ISO>\"}` — দেশ অনুযায়ী
  (স্ট্যান্ডার্ড দ্বারাই সীমাবদ্ধ: ≤ ৯টি মহাদেশ, ≤ ২৫০টি
  দেশ)।

### GEOROUTE রেকর্ড (ওয়্যার)

একটি GEOROUTE = একটি **scope** + ≤ ৩২টি **endpoint** (ডিকোডে
ক্যানোনিকাল সাজানো: ঊর্ধ্বক্রম priority, অধোক্রম weight, ঊর্ধ্বক্রম target;
ডুপ্লিকেট = প্রত্যাখ্যান):

```text
GeoScope   = 0x00 (world)
           | 0x01 continent.v (UN M49 code: AF=2, AS=142, EU=150,
                                NA=3, SA=5, OC=9, AN=999)
           | 0x02 country.v   (ISO 3166-1 numeric code: US=840,
                                TW=158, FR=250…)
           | 0x03 region.v    (OPAQUE ISO 3166-2 subdivision, u32:
                                publisher-defined number, compared
                                as is — no local table)
           | 0x04 asn.v       (AS number, u32)
           | 0x05 prefix.addr[16] || prefix.len u8
             (normalized 16-byte IP prefix: IPv4 = address in the
              first 4 bytes + ZERO tail, len ≤ 32;
              IPv6 = 16 free bytes, len ≤ 128; host bits ALWAYS
              zero — a non-normalized prefix is rejected)
GeoTarget  = 0x00 octets[4]  (binary IPv4 address)
           | 0x01 octets[16] (binary IPv6 address)
GeoEndpoint = target || priority.v || weight.v
GEOROUTE    = scope || count.v(≤32) || endpoints…
```

ভ্যালিডেশন বাউন্ড (ডিকোড): `priority > 0`, `weight ≤ 100`
(`weight = 0` = নিষ্ক্রিয় endpoint, কখনো নির্বাচিত হয় না), TTL
যেকোনো রেকর্ডের মতো 1..=2,592,000 s-এর মধ্যে। লোকাল
টেবিলের কাছে অজানা একটি দেশ/মহাদেশ ওয়্যারে **অনুমোদিত**:
রাউটিং সহজভাবে একটি উচ্চতর scope-এ ফিরে যায়।

**ওয়্যার পশ্চাদগামী সামঞ্জস্য (v1 → v2)**: v1 বাইটগুলো
অপরিবর্তিত — v1 scope (world/continent/country) তাদের
ডিসক্রিমিন্যান্ট `0x00..=0x02` এবং তাদের সঠিক এনকোডিং রাখে; তিনটি
নতুন scope পরবর্তী ডিসক্রিমিন্যান্ট নেয় (`0x03..=0x05`) একটি
মোট ক্রমে যা ক্যানোনিকাল সাজানোর সাথে সামঞ্জস্যপূর্ণ
(`World < Continent < Country < Region < Asn < IpPrefix`)। একটি v1
ডিকোডার `0x03`-এর ≥ ডিসক্রিমিন্যান্টে ইতিমধ্যে কঠোরভাবে ব্যর্থ হত
(রেকর্ড প্রত্যাখ্যাত); v1-উৎপন্ন বাইট অভিন্নভাবে ডিকোড হতে থাকে
(`geo_known_bytes` টেস্ট দেখুন, ফ্রোজেন)।

### নির্বাচন (রেজোলিউশন)

1. **Scope** — হ্রাসমান নির্দিষ্টতা, **৬টি স্তর**:
   **দীর্ঘতম মিলমানো IP প্রিফিক্স → সঠিক AS → সঠিক দেশ →
   সঠিক অঞ্চল → মহাদেশ → বিশ্ব**।
   - *IpPrefix*: যেসব রুটের প্রিফিক্স ক্লায়েন্টের
     IP-এর সাথে মেলে (লোকেটরের জানা মতে: `client_ip`, অন্যথায়
     জানা উৎস প্রিফিক্স) তাদের মধ্যে **দীর্ঘতম** (`len` সর্বোচ্চ)
     জেতে; সমান `len`-এ, ক্যানোনিকাল ক্রমে প্রথমটি
     (`routes` স্লাইসের ক্রম, এনকোডিংয়ে সাজানো)। একটি
     সাবডিভিশন একটি প্রিফিক্স/AS-এর চেয়ে কম নির্দিষ্ট (যা
     সঠিক নেটওয়ার্ক শনাক্ত করে) এবং দেশের চেয়ে
     কম (অপাস নম্বরিং, নির্ভরযোগ্য শুধুমাত্র যদি প্রকাশক এবং
     লোকেটর একইটি ভাগ করে), কিন্তু মহাদেশের চেয়ে
     বেশি (এটি তার দেশে ধারণকৃত, তাই আরও অধিক কারণে তার
     মহাদেশে)।
   - *Asn*: ক্লায়েন্টের সঠিক AS নম্বর।
   - *Country*: সঠিক দেশ।
   - *Region*: সঠিক সাবডিভিশন (অপাস শনাক্তকারী)।
   - *Continent*: লোকেটর দ্বারা সরবরাহকৃত **বা দেশ থেকে
     ডেরিভড** লোকাল টেবিলের মাধ্যমে (`continent_of_country`);
     টেবিলের কাছে অজানা একটি দেশ স্পষ্ট
     মহাদেশ বা বিশ্বে ফিরে যায়।
   - *World*।
   একটি v1 [`GeoLocation`] (region/asn/prefixes/client_ip আনসেট)
   ঠিক v1 আচরণ উৎপন্ন করে: দেশ → মহাদেশ →
   বিশ্ব। কোনো মিলমানো রুট নেই (একটি World scope ছাড়াও) →
   ক্লাসিক DNS আচরণ, যেন GEOROUTE-টি অস্তিত্বহীন।
2. **Priority** — SRV-এর মতো শব্দার্থ: শুধুমাত্র **সর্বনিম্ন
   priority** গ্রুপ এলিজিবল; উচ্চতর priority-গুলো
   **ফেলওভার** স্তর।
3. **Weight** — নির্বাচিত গ্রুপের মধ্যে, **ডিটারমিনিস্টিক
   ওয়েটেড** ড্র: একটি nonce-এর (রিজলভারের
   কোয়েরি কাউন্টার) স্থিতিশীল হ্যাশ (SplitMix64) ক্রমবর্ধমান
   weight-এর বিরুদ্ধে। কোনো
   RNG নেই: একই nonce-এর দুটি কোয়েরি একই ফলাফল দেয়,
   বর্ধমান nonce গুলো weight-এর অনুপাতে বিতরণ করে।
   `weight = 0` = নিষ্ক্রিয়, কখনো নির্বাচিত হয় না (একা থাকলেও —
   পরবর্তী স্তরে যান)।
4. **স্বাক্ষরিত ক্রম, শূন্য প্রোবিং** — রিজলভার একটি
   endpoint-এর প্রাপ্যতা কখনোই রায় দেয় না: নির্বাচিত scope-এর
   প্রতিটি সক্রিয় endpoint (weight > 0) একটি প্রার্থী, সর্বনিম্ন
   স্তরের মাথাটি ওয়েটেড ড্র দ্বারা নির্বাচিত হয়, এবং
   পরবর্তীগুলি **স্বাক্ষরিত রেকর্ড-সেট ক্রমে** ফেলওভার হিসেবে
   কাজ করে (সেই ক্রমটিই ফেলওভার মেকানিজম)। Endpoint-এর
   পৌঁছানোর ক্ষমতা endpoint অপারেটরের ব্যাপার, কখনোই
   রিজলভারের নয়।

### উত্তর

- একটি একক ঠিকানা: **IPv4 হলে A, IPv6 হলে AAAA** — qtype
  অনুযায়ী পরিবার দ্বারা কঠোর
  ফিল্টারিং (একটি A প্রশ্ন কখনো একটি IPv6-এর উত্তর দেয় **না**,
  এবং বিপরীতেও)।
- TTL = সোর্স GEOROUTE রেকর্ডের (সাধারণ TTL নিয়ম দ্বারা ডিকোডে
  সীমাবদ্ধ)।
- AA সেট (অথরিটেটিভ উত্তর — GEOROUTE অন্য যেকোনোর মতো
  একটি যাচাইকৃত স্বাক্ষরিত রেকর্ড)।
- ফিল্টারিংয়ের পরে খালি উত্তর (সঠিক পরিবারের কোনো প্রার্থী
  নেই, জোনের জন্য কোনো রুট নেই) → রিজলভার
  তার ক্লাসিক পাথে চলতে থাকে (সাধারণত NODATA: NOERROR, ০
  উত্তর); ত্রুটি rcode সাধারণ নিয়ম অনুসরণ করে (কখনো ক্যাশ হয় না)।
- সেটে সহাবস্থানকারী একটি ক্লাসিক A/AAAA রেকর্ড geo-এর
  চেয়ে **অগ্রাধিকার** নেয় (geo শুধুমাত্র qtype-এর জন্য ওয়্যার
  উত্তরের অনুপস্থিতিতে প্রযোজ্য)।

### ক্যাশ: স্পষ্ট সিদ্ধান্ত

geo রাউটিং সিদ্ধান্ত কখনো `(qname, qtype)`-এর অধীনে **ক্যাশ
হয় না**: এটি রিজলভারের ক্লায়েন্ট scope-এর উপর নির্ভর করে, এবং
এমন একটি কী একটি TW ক্লায়েন্টকে US রুট সেবা দিত। Geo
উত্তর প্রতিটি কোয়েরিতে পুনর্গণনীত (খরচ: একটি select_scope + ওয়েটেড
ড্র, µs) এবং ক্যাশ বাইপাস করে। ক্লাসিক (qname, qtype) ক্যাশ
বাকি সবকিছুর জন্য অপরিবর্তিত থাকে — geo যখন কিছুই সিদ্ধান্ত
নেয় না তখন উৎপন্ন NODATAসহ। ত্রুটি rcode কখনো
ক্যাশ হয় না।

### NS ডেলিগেশন (`ns` রেকর্ড) — owner বেছে নেয় কে সেবা দেবে

একটি ডোমেইনের owner প্রতি ডোমেইনে সেবা-মোড বেছে নেয়:

- **DHT (ডিফল্ট)** — কোনো `ns` রেকর্ড না থাকলে, Scone
  নেটওয়ার্ক অন-চেইন A/AAAA সেবা দেয় (রিলে `--dns`, বা export-এর
  মাধ্যমে NSD ব্রিজ);
- **স্বাধীন NS** — owner `ns <ip-বা-নাম>` রেকর্ড যোগ করে
  (তাদের নিজস্ব nameserver, সরাসরি IP বা hostname): ডোমেইনটি
  ডেলিগেটেড — নেটওয়ার্ক তার কনটেন্ট সেবা দেওয়া বন্ধ করে
  (A/AAAA → NODATA + NS অথরিটি), এবং যে কেউ রেজলভ করে owner-এর
  NS অনুসরণ করে। সীমা: **প্রতি ডোমেইনে ১২টি স্বতন্ত্র NS**
  (সব রূপ, মান অনুযায়ী ডিডুপ্লিকেটেড — বাস্তব জগতের রেজিস্ট্রি
  ক্যাপের প্রতিফলন)। একটি NS সরালে স্লটটি মুক্ত হয়; সব সরালে
  DHT মোড ফিরে আসে।

**কোনো হেলথ চেকিং নেই**: endpoint-এর প্রাপ্যতা endpoint
অপারেটরদের ব্যাপার — রিজলভার স্বাক্ষরিত রেকর্ড সেটটিকে যেমন
আছে তেমনই সেবা দেয়, রেকর্ড ক্রমে (রেকর্ডের ক্রমই ফেলওভার
মেকানিজম)।

### সিকিউরিটি

- GEOROUTE রেকর্ড অন্য যেকোনোর মতো স্বাক্ষরিত রেকর্ড: যেকোনো
  ব্যবহারের আগে চেইনের বিরুদ্ধে যাচাইকৃত (owner, sequence,
  record_hash)। **যাচাই ছাড়া কোনো নেটওয়ার্ক ট্রাস্ট নয়** — একটি
  অযাচাইকৃত DHT GEOROUTE কখনো উত্তর দেয় না।
- ক্লায়েন্টের অবস্থান **অটো-ডিসকভারড সার্কিট** থেকে আসে:
  রিলে তার বাহ্যিক ঠিকানার (STUN/AutoNAT/UPnP) মাধ্যমে স্ব-অবস্থান
  করে, যা build-কর্তৃক-আরোপিত এমবেডেড টেবিল দ্বারা
  রেজলভ হয় — LAN ক্লায়েন্ট (প্রাইভেট সোর্স IP) সেই অবস্থান
  উত্তরাধিকার পায়, ইন্টারনেট ক্লায়েন্ট তাদের নিজের IP দ্বারা
  রেজলভ হয়, অজানা হলে World-এ ফিরে যায়। কখনো একটি নেটওয়ার্ক
  GeoIP API থেকে নয় (কোনো কোয়েরি লিক নেই, কোনো ডিপেন্ডেন্সি
  নেই) এবং কখনো একটি অপারেটর ঘোষণা থেকে নয় (জোনগুলি
  build-কর্তৃক-আরোপিত)।
- ড্রটি ডিটারমিনিস্টিক ও লোকাল: কোনো সিক্রেট নেই, কোনো
  অপূর্বানুমেয়তার প্রয়োজন নেই (সিকিউরিটি রেকর্ডের
  সিগনেচারের, ড্রয়ের নয়)।

| `--geo-ip-table`, `--geo-config`, `--geo-country/…`, `--health-*` | — | (সরানো হয়েছে — কঠোর বিরতি: geozone build-কর্তৃক-আরোপিত এবং রিজলভার কোনো হেলথ চেকিং করে না; কোনো রানটাইম ফ্ল্যাগ নেই) |

#### এমবেডেড টেবিলই একমাত্র উৎস

GeoIP টেবিল **build-কর্তৃক-আরোপিত** (DB-IP Lite, কোয়ান্টাইজড,
উপরের এমবেডেড টেবিল অংশটি দেখুন): কোনো অপারেটর টেবিল ইমপোর্ট
করা যায় না। রেজোলিউশন: **DNS কোয়েরির সোর্স IP** (প্রতি-ক্লায়েন্ট:
UDP `recv_from` / TCP `peer_addr`) এমবেডেড টেবিলের বিরুদ্ধে ১৬
বাইটে তুলনা করা হয়; **দীর্ঘতম মিলমানো প্রিফিক্স**সহ নিয়ম জেতে
(টাই-তে, ফাইল ক্রমে প্রথম)।

- **প্রাইভেট/অ-রাউটেবল সোর্স** (RFC1918, ULA fc00::/7,
  link-local, loopback): ক্লায়েন্টটি রিলের নেটওয়ার্কের ভিতরে —
  এটি রিলের নিজের আবিষ্কৃত অবস্থান উত্তরাধিকার পায়;
- **টেবিলে অনুপস্থিত পাবলিক সোর্স**: World (কোনো geo বিভাজন
  নেই — কখনো ভুল উত্তর নয়)।

যেকোনো ভবিষ্যৎ টেবিল সারফেসের জন্য **কঠোরতা** বজায় থাকে:
একটি অবৈধ লাইন অপরাধী লাইন নম্বর বহনকারী একটি টাইপড
স্টার্টআপ ত্রুটি; কখনো নীরবে উপেক্ষিত লাইন নয়, কখনো আংশিক
টেবিল নয়।

#### অপশন অগ্রাধিকার

- **লোকেটর**: এমবেডেড টেবিলই জিওলোকেশন আরোপ করে — কোনো
  অপারেটর ওভাররাইড নেই। রিলে তার বাহ্যিক ঠিকানা থেকে তার
  অবস্থান আবিষ্কার করে (টেবিল দ্বারা রেজলভকৃত
  STUN/AutoNAT/UPnP); LAN ক্লায়েন্টরা সেই অবস্থান
  উত্তরাধিকার পায়; ইন্টারনেট ক্লায়েন্টরা তাদের সোর্স IP দ্বারা
  রেজলভ হয়; অজানা হলে World-এ ফিরে যায়।

উদাহরণ (কোনো geo ফ্ল্যাগ ছাড়াই geo রাউটিং সক্রিয়):

```bash
scone relay --dns 127.0.0.1:5353
```


## DoH / DoT (এনক্রিপ্টেড ট্রান্সপোর্ট) — বাহ্যিক ফ্রন্টএন্ডের মাধ্যমে

Scone DNS সার্ভার **সরল UDP এবং TCP** কথা বলে (RFC 1035 / 7766)
— এটিই নেটিভ সুযোগ, সম্পূর্ণ এবং পরীক্ষিত। *এন্ড ক্লায়েন্টের*
কাছে এনক্রিপ্টেড ট্রান্সপোর্ট (DoH — DNS-over-HTTPS, RFC 8484;
DoT — DNS-over-TLS, RFC 7858) **একটি স্ট্যান্ডার্ড
ফ্রন্টএন্ডে ডেলিগেট করা হয়**: Scone ডেটা সেবা দেয়, ফ্রন্টএন্ড
ট্রান্সপোর্ট সেবা দেয়।

কেন এই ডিজাইন: একটি নেটিভ DoH সার্ভারের জন্য নোডের ভেতরে একটি
সম্পূর্ণ HTTPS স্ট্যাক লাগবে (সার্টিফিকেট, নবায়ন, HTTP/2) — একটি
বড় অপারেশনাল পৃষ্ঠ শূন্য সুবিধার জন্য যখন ব্রাউজার-পক্ষের
এন্ড ব্যবহারকারী নেই। বিদ্যমান ফ্রন্টএন্ডগুলো এটি আরও ভালো এবং
আরও দীর্ঘদিন করে; নোডটি
ন্যূনতম থাকে।

### উদাহরণ: একটি Scone রিলের সামনে unbound করে DoH

`/etc/unbound/unbound.conf`:

```
server:
    interface: 127.0.0.1
    port: 5354
    do-ip4: yes
    do-udp: no
    do-tcp: yes

    # DoH (RFC 8484) on 443
    https-port: 443
    tls-service-key: "/etc/unbound/scone.key"
    tls-service-pem: "/etc/unbound/scone.pem"

forward-zone:
    name: "."
    forward-addr: 127.0.0.1@5353   # the Scone relay (--dns 127.0.0.1:5353)
```

সার্টিফিকেট (`scone.pem`/`scone.key`) যেকোনো TLS
সেবার মতোই পাওয়া যায় — যেমন রিজলভারের ডোমেইনে certbot/acme.sh।
তারপর DoH ক্লায়েন্টরা `https://dns.example.tld/dns-query`-এ
নির্দেশ করে।

### উদাহরণ: knot-resolver করে DoT

`/etc/knot-resolver/kresd.conf`:

```
net.listen('127.0.0.1', 5353, { kind = 'dns' })
net.listen('0.0.0.0', 853, { kind = 'tls' })
tls.cert_file = '/etc/knot-resolver/scone.pem'
tls.key_file  = '/etc/knot-resolver/scone.key'
```

### ফ্রন্টএন্ড কী যোগ করে

- **ক্লায়েন্ট→ফ্রন্টএন্ড চ্যানেলের এনক্রিপশন** (শত্রু
  সেগমেন্ট: ব্যবহারকারীর নেটওয়ার্ক); ফ্রন্টএন্ড→রিলে সেগমেন্ট
  লোকাল থাকে (একই মেশিন বা বিশ্বস্ত নেটওয়ার্ক)।
- **একটি অতিরিক্ত ফ্রন্টএন্ড-পার্শ্ব ক্যাশ** (unbound/knot ক্যাশও —
  নিরীহ, Scone TTL-গুলো ঊর্ধ্ব বাউন্ড থাকে)।
- **একটি স্থিতিশীল এন্ডপয়েন্ট** (IPv4/IPv6, ডোমেইন) যখন রিলেরা
  চলাচল করে।

### ফ্রন্টএন্ড কী করে না

- এটি কিছুই *যাচাই* করে না: রিলের সেবাকৃত প্রতিটি উত্তর
  ক্যাশ হওয়ার আগেই চেইনের বিরুদ্ধে যাচাইকৃত ("রেজোলিউশন পাথ"
  দেখুন)। ফ্রন্টএন্ড ইতিমধ্যে-অথরিটেটিভ
  উত্তর রিলে করে।
- এটি বিকেন্দ্রীকরণ প্রতিস্থাপন করে না: একটি DoH ফ্রন্টএন্ড একটি
  *পরিচালিত* সেবা — রিজলভার অপারেটরের পছন্দ, প্রোটোকলের
  নয়। প্রতিটি Scone রিলে নেটিভ UDP/TCP-র
  উপরে স্বাধীনভাবে ব্যবহারযোগ্য থাকে।

### ভবিষ্যৎ নেটিভ ইমপ্লিমেন্টেশন (ডকুমেন্টেড, প্রতিশ্রুতিবদ্ধ নয়)

একটি নেটিভ DoH ট্রান্সপোর্ট (`--doh ADDR`) কল্পনাসম্মত থাকে:
ওয়্যার ফরম্যাট অভিন্ন হওয়ায় (RFC 8484 বাইনারি DNS বার্তা
পুনঃব্যবহার করে), এটি একটি TLS প্রক্সির
পেছনে একটি POST/GET ডিকোড + HTTP/2 হতো
(caddy/nginx সার্টিফিকেট হ্যান্ডেল করে), নোড নিজে
TLS-মুক্ত থাকে। কোনো চলমান কাজ নেই — চাহিদা এন্ড ব্যবহারকারীর
সাথে আসবে।
