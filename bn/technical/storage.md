# স্টোরেজ — লোকাল নোড পারসিস্টেন্স (redb)

> নরমেটিভ ডকুমেন্ট। এই ডকুমেন্ট এবং
> `crates/scone-storage/src/`-এর মধ্যে যেকোনো বৈপরীত্য একটি বাগ
> (সত্যের উৎস চিহ্নিত করে সংশোধন করুন)। ইমপ্লিমেন্টেশন রেফারেন্স: ক্রেট
> `scone-storage` (ফরম্যাট v1), `redb` 4.2 ব্যাকএন্ড।

## উদ্দেশ্য

নোডের এমবেডেড লোকাল পারসিস্টেন্স: ক্যানোনিকাল ব্লক, ডোমেইন
স্টেট, DHT ক্যাশ, মেটাডেটা। স্টোরটি একটি **পারসিস্টেন্স**, কখনো
কর্তৃত্ব নয়: RAM স্টেট ([`ChainState`], কনসেনসাসের উৎস)
স্টার্টআপে স্টোর থেকে পুনর্নির্মিত হয়, এবং প্রতিটি
রাইট একটি **ডেল্টা** (একটি ব্লক দ্বারা পরিবর্তিত ডোমেইন), কখনো
স্টেটের সম্পূর্ণ কপি নয়।

ক্রস-কাটিং শর্ত (ব্যবহারকারীমুখী, প্রতিটি মাইলস্টোন): **ন্যূনতম
মেমরি ফুটপ্রিন্ট**। বড় ভলিউম (ব্লক, ডোমেইন স্টেট, DHT
ক্যাশ) redb-তে বাস করে এবং কার্সার/পরিসরের মাধ্যমে অ্যাক্সেস হয় — কখনো
RAM-এ সম্পূর্ণ লোড হয় না, কখনো অকারণে প্রতিলিপি হয় না।

## সীমানা: `NodeStore` trait

`crates/scone-storage/src/lib.rs` কোডের বাকি অংশে (ব্লকচেইন, ভবিষ্যৎ M4 রিলে)
দৃশ্যমান একমাত্র স্টোরেজ মুখ সংজ্ঞায়িত করে:

- `append_block(height, hash, bytes)` /
  `append_block_with_state(..., deltas)` — অ্যাটমিক অ্যাপেন্ড (নিচে
  দেখুন);
- `block_at_height(h)` / `block_by_hash(hash)` — পয়েন্ট রিড;
- `tip() -> (height, hash)` — O(1), `meta` থেকে পড়া;
- `put_domain_state` / `domain_state` / `domain_count` —
  **বজায় থাকা** কাউন্টার (`meta["domain_count"]`), কখনো
  `COUNT(*)` নয়;
- `iterate_domains(after, max) -> DomainPage` — কার্সার-ভিত্তিক
  পেজিনেশন (ডিফল্টে ১০০টির ব্যাচ), `DomainId`-র
  ঊর্ধ্বক্রম বাইট ক্রম;
- `put_tld_state` / `tld_state` / `tld_count` / `iterate_tlds` —
  TLD রেজিস্ট্রির জন্য একই চুক্তি (`tld_count` বজায় থাকা,
  বাউন্ডেড কার্সার) (M7d);
- `put_dht_cache` / `dht_cache` — অপাস `SignedDnsRecord` বাইট;
- `resolve_name(canonical)` / `resolve_tld(tld)` — স্থায়ী
  Name→Id ইনডেক্স (P0.2), O(1) পয়েন্ট লুকআপ, ডোমেইনের
  উপর কোনো ইটারেশন নেই (ডিফল্ট `None` = ইনডেক্স ছাড়া ব্যাকএন্ড, কলার
  `iterate_domains` বা চেইন স্টেটে ফিরে যায়);
- `tld_floors_all` / `snapshot_tld_floors_all` — ওপেন
  TLD-র আজীবন ফ্লোর পড়ুন (owner-অপশন: নিবেদিত টেবিল,
  লাইভ `tld_floors_v1` এবং ফ্রোজেন `snapshot_v1_floors`);
- `rewind_to_height(h)` — রিঅর্গ: `h`-এর উপরের ব্লকগুলো সরায় এবং
  একটি লেনদেনে `tip`/`tip_height`-কে `h`-এ ফিরিয়ে আনে
  (`persist_state_snapshot`-এর প্রাথমিক, নিচে দেখুন);
- `meta_get` / `meta_set`;
- `snapshot_meta` / `snapshot_domains` / `snapshot_tlds` — বুট
  স্টেট স্ন্যাপশট রিড (M6b; খালি ডিফল্ট = স্ন্যাপশট ছাড়া ব্যাকএন্ড,
  `load_chain` তখন সম্পূর্ণ লোডিংয়ে ফিরে যায়)।

নিয়ম:

- **API-তে কোনো redb টাইপ নেই**: বাইট (`&[u8]`, `[u8; 32]`) এবং
  কোর টাইপ। ব্যাকএন্ড প্রতিস্থাপনযোগ্য।
- **অ্যাসিঙ্ক-মুক্ত, কোনো ইন্টেরিয়র মিউটেবিলিটি নেই**: রাইট `&mut self`
  নেয় (redb রাইটার সিরিয়ালাইজ করে), রিড `&self` নেয় (প্রতি কলে
  একটি সংক্ষিপ্ত রিড লেনদেন)।
- API কখনো ব্লক পুনঃভ্যালিডেট করে না: `append_block*`-এ পাস করা
  হ্যাশ কলার দ্বারা সরবরাখকৃত **পুনর্গণনাকৃত** হ্যাশ
  (`Blockchain::push_block`)।

| টেবিল | কী (সাজানো) | মান |
|---|---|---|
| `blocks_by_height` | `u64` উচ্চতা (ক্রমবদ্ধ b-tree) | `hash(32) ‖ height(8 BE) ‖ canonical block` |
| `blocks_by_hash` | ব্লক হ্যাশ (32 B) | ব্লকের ক্যানোনিকাল এনকোডিং |
| `domains` | `DomainId` (32 B, বাইট ক্রম) | `DomainStateBytes` (নিচে) |
| `tlds` | `TldId` (32 B, বাইট ক্রম) | `TldStateBytes` (নিচে, M7d) |
| `dht_cache` | `DomainId` (32 B) | `SignedDnsRecord` বাইট (অপাস) |
| `names_v3` (P0.2) | ইনডেক্স কী (32 B, বাইট ক্রম) | লক্ষ্য id (32 B) |
| `name_reverse_v3` (P0.2) | লক্ষ্য id (32 B, বাইট ক্রম) | `tag(1) ‖ canonical name` |
| `meta` | `&[u8]` | `&[u8]` |
| `snapshot_v1_meta` (M6b) | `u64` = 0 (একক স্লট) | `height(8 BE) ‖ tip_hash(32)` = ঠিক 40 B |
| `snapshot_v1_domains` (M6b) | `DomainId` (32 B, বাইট ক্রম) | `DomainStateBytes` (`domains`-এর মতোই ফরম্যাট) |
| `snapshot_v1_tlds` (M6b) | `TldId` (32 B, বাইট ক্রম) | `TldStateBytes` (`tlds`-এর মতোই ফরম্যাট) |
| `tld_floors_v1` (owner-অপশন) | `TldId` (32 B, বাইট ক্রম) | `u64` (মেয়াদ ফ্লোর, redb অন্তর্নিহিত BE) |
| `snapshot_v1_floors` (M6b) | `TldId` (32 B, বাইট ক্রম) | `u64` — ফ্লোরের ফ্রোজেন কপি (স্ন্যাপশটের স্টেট, টিপ নয়) |

অতিরিক্ত `meta` কী (P0.3/P0.4):

| কী | মান |
|---|---|
| `verified_snapshot_v1` (P0.3) | `height(8 BE) ‖ tip_hash(32) ‖ manifest_hash(32)` = 72 B — একটি VERIFIED ইমপোর্টেড স্ন্যাপশটের মার্কার (সংরক্ষিত, `tip`-এর মতো) |

`meta` কী:

| কী | মান |
|---|---|
| `format_version` | `u64 BE` = `STORAGE_FORMAT_VERSION` (1) |
| `tip` | টিপ ব্লকের হ্যাশ (32 B) |
| `tip_height` | `u64 BE` (`tip()`-কে O(1) করে) |
| `domain_count` | `u64 BE` (বজায় থাকা কাউন্টার) |
| `tld_count` | `u64 BE` (বজায় থাকা কাউন্টার, M7d) |

`blocks_by_height`-এর `hash ‖ height` হেডার প্রতিটি ইনডেক্সকে
স্বয়ংসম্পূর্ণ করে (ব্লক না পড়েই যাচাইযোগ্য); উভয় ইনডেক্স
একই লেনদেনে আপডেট হয়।

### জেনেসিস প্রথা

জেনেসিস ব্লক ডিটারমিনিস্টিক (প্রোটোকল ধ্রুবক) এবং বাইট
হিসেবে **কখনো সংরক্ষিত হয় না**। একটি সদ্য স্টোরে `tip == (0,
genesis_hash)`; প্রথম অ্যাপেন্ডকৃত ব্লকের উচ্চতা ১। জেনেসিস
হ্যাশ সর্বদা পুনঃডেরিভড
(`scone_blockchain::genesis_hash()`), কখনো পড়া হয় না।

## `DomainStateBytes` এনকোডিং ফরম্যাট (M8b)

অগ্রণী ভার্সন ট্যাগের উপর নির্ভর করে ৬৫ বা ৯৭ বাইট, নির্দিষ্ট-প্রস্থ
big-endian পূর্ণসংখ্যা (ক্যানোনিকাল, বাইট-প্রতি-বাইট তুলনাযোগ্য):

```text
DomainStateBytes = tag ‖ owner(32) ‖ sequence(8 BE) ‖ registered_at(8 BE)
                   ‖ valid_until(8 BE) ‖ mutations(8 BE) [‖ record_hash(32)]

tag = 0x01 : record_hash present → exactly 97 bytes
tag = 0x02 : record_hash absent  → exactly 65 bytes
```

`mutations` হলো নেমস্পেসের একমুখী বর্ধনশীল মিউটেশন কাউন্টার (CAS
অ্যান্টি-রিপ্লে জেনারেশন — দেখুন `transactions.md`, মিউটেশন
কাউন্টার)। M8b এনকোডিংগুলো (৫৭/৮৯ বাইট, কোনো কাউন্টার নেই)
**অবৈধ**: কঠোর ডিকোডিং → `Corrupted` (টেস্টনেট রিসেট; একটি
প্রি-কাউন্টার স্টোর রিপ্লের মাধ্যমে পুনরুৎপন্ন হয়)।

- `registered_at` / `valid_until` (M8b): রেজিস্ট্রেশনের
  মেয়াদ উত্তীর্ণ (ক্লেইমে ১ বছর, নবায়নযোগ্য, দেখুন
  `/docs/en/technical/blockchain.md`)।

M7 এনকোডিংগুলো (৪১/৭৩ বাইট, কোনো মেয়াদ নেই) M8b থেকে
**অবৈধ**: কঠোর ডিকোডিং → `Corrupted`। (একটি M7 স্টোর
রিপ্লের মাধ্যমে পুনরুৎপন্ন হয়: `load_chain_replay`।)

- `owner`: `OwnerId` (32 B);
- `sequence`: শেষ প্রয়োগকৃত `UpdateDomain` সিকোয়েন্স (একটি
  `RegisterDomain`-এর ঠিক পরে 0);
- `record_hash`: DNS রেকর্ড
  সেটের বর্তমান অন-চেইন কমিটমেন্ট (কোনো `UpdateDomain`
  প্রয়োগ না হওয়া পর্যন্ত `None`)।

**কঠোর** ডিকোডিং (`DomainStateBytes::decode`): অজানা ট্যাগ,
ভুল দৈর্ঘ্য, বা অতিরিক্ত বাইট → `StorageError::Corrupted`, কখনো
প্যানিক নয়।

## `TldStateBytes` এনকোডিং ফরম্যাট (owner-অপশন)

enum ভ্যারিয়েন্টের উপর নির্ভর করে পরিবর্তনশীল দৈর্ঘ্য — একটি
**প্রাইভেট** TLD-র জন্য ৫০ বাইট, একটি **ওপেন** TLD-র জন্য ১০টি (কোনো
সিকোয়েন্স বা
রেকর্ড হ্যাশ নেই):

```text
TldStateBytes = tag(0x04) ‖ flag(0x00|0x01) ‖ owner(32)? ‖ until(8)
                [‖ mutations(8)]
```

- `flag` (owner-অপশন, `TldState` enum): `0x00` =
  `TldState::Open` (কারো নয় — স্ব-সেবা + PoW, কোনো owner বাইট নেই),
  `0x01` = `TldState::Private` (৩২টি owner বাইট + ৮টি কাউন্টার বাইট
  অনুসরণ করে)। কঠোরভাবে
  ক্যানোনিকাল — অন্য যেকোনো বাইট → `Corrupted`। "open ⟺
  কোনো owner নেই" অপরিবর্তনীয় সত্যটি কাঠামোগত: দুটি অবস্থা
  বিভ্রান্ত হতে পারে না।
- **`until` (৮ বাইট, BE64)**: TLD-র নিজের ঘড়ি — প্রাইভেট
  মেয়াদের শেষ (ক্লেইম/নবায়ন + ৩ বছর) বা ওপেন মৃত্যুর সময়সূচি
  (জন্মে ১-বছর ফ্লোর, প্রতিটি জীবিত ডোমেইন দ্বারা ঠেলা)। এটি
  আবার এন্ট্রির একটি বৈশিষ্ট্য (TLD জীবনচক্র পরিবর্তন)। ডেরিভড
  `tld_floors_v1` টেবিল (+ তার ফ্রোজেন কপি
  `snapshot_v1_floors`) এখনও ফ্লোর ট্র্যাক করে, রিপ্লেতে পুনর্নির্মিত
  এবং বুটে পুনরুদ্ধারকৃত — একটি পুনরায় চালু নোড একটি অবিচ্ছিন্ন
  নোডের মতোই একই TLD-র মৃত্যু ঘটায়।

M7d (৩৩ বাইট, ট্যাগ `0x01`), M8b (৩৪ বাইট, ট্যাগ `0x02`, বুলিয়ান
`open`), লিগ্যাসি ট্যাগ `0x03` (এমবেডেড `until`) এবং প্রি-কাউন্টার
ট্যাগ `0x04` লেআউটগুলো (৪২/২ বাইট, কোনো কাউন্টার নেই) এনকোডিংগুলো
**অবৈধ**: কঠোর ডিকোডিং → `Corrupted` (প্রি-মেইননেট,
রিপ্লের মাধ্যমে পুনরুৎপাদনই মাইগ্রেশন পাথ)।

ট্যাগটি শুধুমাত্র ফরম্যাট বিবর্তনের জন্য বিদ্যমান: একটি ভবিষ্যৎ
লেআউট ট্যাগ বাড়ায় এবং পুরনো রিডাররা অনুমানের বদলে `Corrupted`-এ
ব্যর্থ হয়।
**কঠোর** ডিকোডিং (`TldStateBytes::decode`): অজানা ট্যাগ, ভুল
দৈর্ঘ্য, অতিরিক্ত বাইট, বা অ-ক্যানোনিকাল ফ্ল্যাগ →
`StorageError::Corrupted`, কখনো প্যানিক নয়।

## অ্যাটমিসিটি নিশ্চয়তা

`append_block_with_state` **একটি একক** redb
`WriteTransaction`-এ লেখে:

1. `blocks_by_height`-তে ব্লক (পূর্ব যাচাই: ভিন্ন
   কনটেন্টসহ উচ্চতা বিদ্যমান থাকলে,
   অন্যথায় `StorageError::Conflict`);
2. `blocks_by_hash`-তে ব্লক;
3. প্রতিটি ডোমেইন স্টেট ডেল্টা (`domains`);
4. `domain_count` কাউন্টার (শুধুমাত্র **নতুন**
   ডোমেইনের সংখ্যা দ্বারা বৃদ্ধি; একটি বিদ্যমান ডোমেইনের
   `UpdateDomain` এটি বাড়ায় না);
5. প্রতিটি TLD রেজিস্ট্রি ডেল্টা (`tlds`, M8b: ক্লেইম, ট্রান্সফার,
   ওপেন/ক্লোজ) — **একই লেনদেনে**: তার TLD
   পরিবর্তন ছাড়া লেখা একটি ব্লক কাঠামোগতভাবে অসম্ভব;
6. `tld_count` কাউন্টার (শুধুমাত্র নতুন TLD);
7. প্রতিটি **অপসারণ** (M8b): ডিটারমিনিস্টিক
   GC দ্বারা মেয়াদোত্তীর্ণ ডোমেইন (`removed_domains`) এবং প্রত্যাহৃত TLD-গুলো (`removed_tlds`) একই
   লেনদেনে স্টোর ছাড়ে, কাউন্টার হ্রাসকৃত — একটি
   পুনরায় চালু কখনো মেয়াদোত্তীর্ণ রেজিস্ট্রেশন পুনরুত্থিত করতে পারে না;
8. P0.2-এর **নেম ইনডেক্স** ডেল্টা (আপসার্ট এবং অপসারণ, নিচে
   দেখুন) — একই নিশ্চয়তা: একটি ক্র্যাশ কখনো এমন একটি ইনডেক্স এন্ট্রি
   রেখে যেতে পারে না যা একটি অনুপস্থিত ডোমেইনকে নির্দেশ করে;
9. `tip` এবং `tip_height`।

redb WAL-স্টাইলে কমিট করে: লেখার মাঝখানে একটি ক্র্যাশ **পূর্ববর্তী**
সুসংগত অবস্থা রেখে যায়। **তাই তার স্টেট ছাড়া লেখা একটি ব্লক
কাঠামোগতভাবে অসম্ভব** — এটিই মাইলস্টোনের মূল অপরিবর্তনীয় সত্য।

অতিরিক্ত নিশ্চয়তা:

- **একচেটিয়া বর্ধমানতা**: `tip_height + 1` ≠ উচ্চতায় অ্যাপেন্ড →
  `StorageError::NonMonotonicHeight`, কিছুই লেখা হয় না (রাইট
  লেনদেন খোলার *আগে* যাচাইকৃত);
- **ইডেম্পোটেন্স**: একই `(height, hash)` জোড়াসহ বর্তমান টিপ
  ব্লক পুনঃঅ্যাপেন্ড একটি নো-অপ (ফাস্ট পাথ উচ্চতা এবং
  হ্যাশ তুলনা করে; সমান উচ্চতায়, অভিন্ন ব্লক বাইটও
  একটি নীরব নো-অপ, ভিন্ন বাইট একটি `Conflict`);
- **দূষিত ডেটাবেস**: ছোট/দূষিত ফাইল → টাইপড ত্রুটি
  (`StorageError::Database`/`Corrupted`) খোলায় বা পড়ায়, কখনো
  প্যানিক নয় (পরীক্ষিত);
- **ফরম্যাট ভার্সন**: `format_version` ≠ 1 →
  `StorageError::UnsupportedFormat` (একটি স্পষ্ট মাইগ্রেশন পাথ
  প্রয়োজন, কখনো অনুমান নয়)।

## ব্লকচেইন ইন্টিগ্রেশন (`integration.rs`)

ভূমিকা পৃথককরণ: RAM-এ [`ChainState`] = কনসেনসাস কর্তৃত্ব;
স্টোর = পারসিস্টেন্স। নির্বাচিত কৌশল (ডকুমেন্টেড হিসেবে সরলতম):
**প্রতিটি ব্লকে স্টেট পারসিস্ট করুন** — `store_block`
ব্লক + সেই
ব্লক দ্বারা **স্পর্শকৃত** ডোমেইনের স্টেট লেখে (ডেল্টা)। সম্পূর্ণ
রিপ্লে সম্ভব থাকে এবং একটি
নিয়ন্ত্রণ/মেরামত পাথ হিসেবে সেবা দেয়।

- `store_block(store, chain, block, hash)`: ব্লকটি
  ক্যানোনিকালি এনকোড করে, স্পর্শকৃত ডোমেইন এবং
  ক্লেইমড TLD-র চূড়ান্ত স্টেট RAM স্টেট থেকে পড়ে
  (`push_block` দ্বারা ইতিমধ্যে আপডেটেড), অ্যাটমিক অ্যাপেন্ড।
- `load_chain(store)`: **রিপ্লে ছাড়া** — টিপ + টিপ ব্লক পড়ে
  (O(1) ব্লক রিড), ডোমেইন স্টেট ১০০-এর পৃষ্ঠায় (`DOMAIN_PAGE`)
  **এবং TLD রেজিস্ট্রি ১০০-এর পৃষ্ঠায়**
  (`TLD_PAGE`, M7d — পুনরায় চালুর উইন্ডো বন্ধ করে: এটি ছাড়া,
  পুনরায় চালু একটি নোড প্রতিটি ক্লেইমড TLD ভুলে যেত এবং সেই
  TLD-র অধীনে প্রতিটি `RegisterDomain` `UnknownTld` দিয়ে
  প্রত্যাখ্যান করত, যদিও
  তার ডিস্ক সম্পূর্ণ স্টেট ধারণ করত)। RAM চেইন শুধুমাত্র
  জেনেসিস + টিপ রাখে; ঐতিহাসিক ব্লক স্টোরে থাকে এবং
  এটি থেকে সেবা পায়। M8 থেকে, `load_chain` তারপর **TXID
  অ্যান্টি-রিপ্লে ইনডেক্স** পুনর্নির্মাণ করে (নিচে দেখুন)।
- `load_chain_replay(store)`: সংরক্ষিত সব ব্লক একটি একটি করে
  রিপ্লে করে (কখনো সব RAM-এ নয়) সম্পূর্ণ ভ্যালিডেশনসহ; ফলস্বরূপ
  টিপকে সংরক্ষিত টিপের সমান হতে হবে, অন্যথায় `Corrupted`।
- `rebuild_replay_index_from_store(store, chain, tip_height)`
  (M8): সর্বশেষ
  `min(REPLAY_WINDOW_BLOCKS, tip_height)` পারসিস্টেড ব্লক
  পুনঃস্ক্যান করে (একবারে RAM-এ একটি
  ব্লক) এবং প্রতিটি TxId চেইনের ইনডেক্সে **তার মূল ইনক্লুশন
  উচ্চতায়** পুনঃসন্নিবেশ করায়, পাবলিক API
  `Blockchain::rebuild_replay_index`-এর মাধ্যমে (প্রাইভেট
  ফিল্ডে কোনো অ্যাক্সেস নেই)। টিপের নিচে অনুপস্থিত ব্লক বা
  উইন্ডোর মধ্যে অ-ডিকোডযোগ্য → `Corrupted` (সেই
  বাইটগুলো ইতিমধ্যে চেইন তৈরি করেছে: এখানে একটি ব্যর্থতা একটি
  ক্ষতিগ্রস্ত স্টোর সংকেত দেয়)।
- `touched_domains(block)`: ব্লকের লেনদেন দ্বারা পরিবর্তিত
  ডোমেইনের id, ডিডুপ্লিকেটেড, ব্লক ক্রম।
- `touched_tlds(block)`: ব্লক দ্বারা মিউটেট করা TLD-র id
  (`RegisterTld`, `TransferTld`, `RevokeTld`, `SetTldOpen`),
  ডিডুপ্লিকেটেড, ব্লক ক্রম (M8b)।
- `store_block_with_removals(...)`: `store_block`-এর ভ্যারিয়েন্ট
  যা ব্লকের GC দ্বারা সরানো ডোমেইনগুলোও (M8b) গ্রহণ করে
  উপরে বর্ণিত অ্যাটমিক রাইটের জন্য। রিলে এই তালিকা
  `Blockchain::push_block_with_gc` থেকে সরবরাহ করে (প্রয়োগের
  ফলাফল `gc_removed_domains` উন্মুক্ত করে)। **DHT
  ক্যাশের GC বহিষ্করণ**: সরানো ডোমেইনের `dht_cache` এন্ট্রি
  ব্লকের মতো **একই** লেনদেনে মুছে যায় (অ্যাপেন্ড ডেল্টা
  `dht_cache` টেবিল বহন করে) — একটি DHT রেকর্ড কখনো তার
  সেবাকৃত ডোমেইনের চেয়ে বেশি বাঁচে না, মেয়াদোত্তীর্ণ এন্ট্রি
  চিরকাল জমা হয় না (টেস্ট:
  `gc_evicts_the_dht_cache_entry`)।

রিলে (M4) ব্যবহার করবে: স্টার্টআপে `load_chain`, তারপর প্রতিটি
গৃহীত ব্লকের জন্য `push_block` (RAM) তারপর `store_block` (ডিস্ক)।

## রিঅর্গ পারসিস্টেন্স (`rewind_to_height` + `persist_state_snapshot`)

একটি রিঅর্গ (একটি শক্তিশালী বোন ব্রাঞ্চে স্যুইচ) একচেটিয়া
বর্ধমান অ্যাপেন্টের মধ্য দিয়ে যেতে পারে না — বিজয়ী সাফিক্স
লিখলে `NonMonotonicHeight` দিয়ে ব্যর্থ হত। নিবেদিত পাথ
(sticky-minority সংশোধন,
রিলে + স্টোর):

1. `rewind_to_height(fork_height)` — একটি redb লেনদেন
   ফর্ক পয়েন্টের উপরের ব্লকগুলো সরায় এবং `tip`/`tip_height`
   ফিরিয়ে আনে (নেম ইনডেক্স এবং লাইভ স্টেট পরবর্তী
   ধাপে ঠিক হয়);
2. `persist_state_snapshot(store, chain)` — লাইভ
   টেবিলগুলো (`domains`, `tlds`, নেম ইনডেক্স, TLD ফ্লোর)
   পুনঃলিখে রিঅর্গ-পরবর্তী RAM স্টেট এক্সপোর্ট থেকে: লাইভ
   টেবিলগুলো বুটে কখনো পরাজিত
   ব্রাঞ্চ বর্ণনা করে না;
3. দত্তক নেওয়া সাফিক্সের একচেটিয়া বর্ধমান পুনঃঅ্যাপেন্ড (সাধারণ
   ডেল্টা)।

এই পাথে একটি পারসিস্টেন্স ব্যর্থতা লগ করা হয় এবং অবনমিত (স্টোর
বুটে রিপ্লের মাধ্যমে সারায়) — কখনো মারাত্মক নয়।

## বুট স্টেট স্ন্যাপশট (M6b)

উপরে বর্ণিত `load_chain` এখনও O(স্টেটের আকার): কোনো
ব্লক রিপ্লে হয় না, কিন্তু সম্পূর্ণ `domains` টেবিল পুনঃপঠিত হয়।
প্রতি-ব্লক-পারসিস্টেড-স্টেট পাথটিই রিপ্লেকে অপ্রয়োজনীয় করে।
M6b স্ন্যাপশট একটি ভিন্ন খরচ সমাধান করে: যে ক্ষেত্রে
RAM স্টেট **রিপ্লের মাধ্যমে** পুনর্নির্মাণ করতে হবে (মেরামত, নিয়ন্ত্রণ,
বা প্রতি-ব্লক পারসিস্টেড স্টেট ছাড়া ব্যাকএন্ড)। এটি একটি বুট দেয়
**O(tip − H)**-এ — স্ন্যাপশটের উপরের সাফিক্স রিপ্লে করে।

### রাইট

- **ব্যবধান**: `SNAPSHOT_INTERVAL = 64` (`scone-storage`-র
  পাবলিক ধ্রুবক)। ট্রিগার হলো `k·SNAPSHOT_INTERVAL + 1`
  ব্লকের অ্যাপেন্ড: সেই লেনদেনটি লাইভ টেবিলের স্টেট
  **সেই ব্লক প্রয়োগের আগে যেমন আছে** ফ্রিজ করে, অর্থাৎ
  ব্লক `k·SNAPSHOT_INTERVAL`-এর পরে ক্যানোনিকাল স্টেট।
- **কখনো টিপে নয়**: স্ন্যাপশট তাই সবচেয়ে কাছে `tip − 1`-এ
  থাকে, লেখার মুহূর্তে সর্বদা কঠোরভাবে টিপের নিচে। ঠিক
  পরে একটি ক্র্যাশ কখনো পারসিস্টেড চেইনের "উপরে" একটি স্ন্যাপশট
  রেখে যেতে পারে না।
- **অ্যাটমিক**: ফ্রিজ (`domains`/`tlds`
  টেবিলের ক্লিয়ার + কপি `snapshot_v1_*`-এ, `snapshot_v1_meta`-র
  রাইট) ট্রিগার ব্লকের অ্যাপেন্টের **একই** redb লেনদেনে ঘটে —
  একটি ক্র্যাশ হয় পুরনো স্ন্যাপশট অক্ষত রেখে যায়, বা নতুনটি
  তার ব্লকসহ সম্পূর্ণ (redb WAL)।
- **একক স্লট**: প্রতিটি স্ন্যাপশট পূর্ববর্তীটিকে প্রতিস্থাপন করে
  (টেবিল খালি করে তারপর পুনঃকপি) — কোনো সঞ্চয় নেই, পরিচালনা
  করার কোনো প্রুনিং নেই, ডিস্ক ফুটপ্রিন্ট ~২× স্টেট দ্বারা সীমাবদ্ধ।
- ফ্রোজেন স্টেটের ফরম্যাট কঠোরভাবে
  `DomainStateBytes`/`TldStateBytes`-এর (পুনঃব্যবহার, কোনো নতুন এনকোডিং নয়);
  শুধুমাত্র `snapshot_v1_meta` সারিটি একটি নতুন ফরম্যাট
  (`height(8 BE) ‖ tip_hash(32)`, কঠোর ডিকোডিং: অন্য
  যেকোনো দৈর্ঘ্য → `Corrupted`)।

### বুটে রিড (`load_chain`)

1. টিপ সর্বদার মতোই যাচাই হয় (টিপ ব্লকের হেডার থেকে
   পুনর্গণনাকৃত হ্যাশ বনাম `meta["tip"]`)।
2. `snapshot_meta()` বিদ্যমান থাকলে, তার উচ্চতা `H` শর্ত
   `0 < H < tip_height` পূরণ করে, এবং `H`-তে
   সংরক্ষিত ব্লকের পুনর্গণনাকৃত হ্যাশ স্ন্যাপশটের `tip_hash`-এর
   সমান (**অ্যাঙ্কর** — পারসিস্টেড চেইনের বাইরের, পরিবর্তিত,
   বা অন্য ফাইলের একটি স্ন্যাপশট এখানে সনাক্ত হয়), ফ্রোজেন
   স্টেট ১০০-এর পৃষ্ঠায় পুনরুদ্ধার হয় তারপর শুধুমাত্র ব্লক
   `H+1..=tip` রিপ্লে হয় (সম্পূর্ণ
   ভ্যালিডেশন, লাইভ ব্লকের মতোই অভিন্ন)।
3. রিপ্লে দ্বারা পৌঁছানো টিপকে সংরক্ষিত টিপের সমান হতে হবে।
4. **এই পাথে যেকোনো ব্যর্থতা (অনুপস্থিত স্ন্যাপশট, অব্যবহারযোগ্য
   উচ্চতা, অবৈধ অ্যাঙ্কর, অ-ডিকোডযোগ্য বাইট, ব্যর্থ রিপ্লে) নীরবে
   প্রি-M6b সম্পূর্ণ লোডিংয়ে অবনমিত হয়** (লাইভ
   টেবিল পড়ে, রিপ্লে ছাড়া) — একটি খারাপ স্ন্যাপশট কখনো বুট
   ব্যর্থ করে না।
   পশ্চাদগামী সামঞ্জস্য হলো বিশেষ ক্ষেত্র "কোনো স্ন্যাপশট নেই":
   M6b-এর আগে লেখা একটি স্টোর (`snapshot_v1_*` টেবিল
   ছাড়া) অভিন্নভাবে লোড হয়, `snapshot_meta()` হলো `None`।

রিপ্লেকৃত সাফিক্স `SNAPSHOT_INTERVAL` দ্বারা সীমাবদ্ধ (ট্রিগার
সময়ে সর্বাধিক ৬৪টি ব্লক + তারপর থেকে মাইন করা ব্লক): বুট
O(tip − H), H নিশ্চিতভাবে সাম্প্রতিক।

## বুটে TXID অ্যান্টি-রিপ্লে ইনডেক্স পুনর্নির্মাণ (M8)

অ্যান্টি-রিপ্লে ইনডেক্স (`included`, TxId → ইনক্লুশন উচ্চতা, উইন্ডো
`REPLAY_WINDOW_BLOCKS = 256` — দেখুন
`/docs/en/technical/blockchain.md`) ক্যানোনিকাল চেইনের একটি
**বিশুদ্ধ ফাংশন**: এটি কখনো পারসিস্ট হয় না। যেহেতু `load_chain`
ইতিহাস রিপ্লে করে না, M8-এর আগে শুরু হওয়া একটি পুনরুদ্ধারকৃত
চেইন একটি **খালি** ইনডেক্স নিয়ে শুরু হত — একটি পুনরায় চালু
নোড তার রিপ্লে উইন্ডোর মধ্যে থাকা যেকোনো লেনদেনের
পুনঃইনক্লুশন গ্রহণ করত (ডকুমেন্টেড
সীমাবদ্ধতা; স্টেট নিয়মই একমাত্র সুরক্ষা ছিল)।

M8 এই উইন্ডো বন্ধ করে: পুনরুদ্ধারের পরে (সম্পূর্ণ পাথ বা স্ন্যাপশট +
সাফিক্স রিপ্লে), `load_chain`
`rebuild_replay_index_from_store` কল করে, যা সর্বশেষ
`min(REPLAY_WINDOW_BLOCKS, tip_height)` পারসিস্টেড ব্লক
পুনঃপড়ে — একবারে RAM-এ একটি ব্লক, সর্বত্রের মতোই
মেমরি-বাউন্ডেড — এবং প্রতিটি TxId তার **মূল
উচ্চতায়** পুনঃসন্নিবেশ করায়। তাই ২৫৬টির কম
ব্লকসহ একটি স্টোর তার সম্পূর্ণ ইনডেক্স পুনর্নির্মাণ করে।

বৈশিষ্ট্য:

- **লাইভ নোডের মতোই সিদ্ধান্ত**: একই এন্ট্রি, একই
  প্রুনিং নিয়ম (`h > tip − 256`) — পুনরায় চালু হওয়া একটি নোড
  এবং কখনো না থামা একটি নোড একই রিপ্লে প্রত্যাখ্যান করে
  (পরীক্ষিত: সঠিক ইনডেক্স গণনা এবং প্রুনড লাইভ ইনডেক্সের
  সাথে সমতা)।
- **অপরিবর্তিত প্রুনিং শব্দার্থ**: উইন্ডোর চেয়ে পুরনো একটি
  লেনদেন ইনডেক্স দ্বারা গৃহীত থাকে (এবং তারপর
  প্রযোজ্য হলে স্টেট নিয়মে ব্যর্থ হয়) — ঠিক আগের মতো।
- **স্ন্যাপশট ইনডেক্স ফ্রিজ করে না**: স্ন্যাপশটের
  সাফিক্স রিপ্লে H-এর উপরের এন্ট্রি পুনর্নির্মাণ করে, M8 রিস্ক্যান
  উইন্ডোর H-এর নিচের অংশ যোগ করে (owner_keys/grace-র
  মতোই চুক্তি: পুনর্নির্মিত, কখনো পারসিস্টেড নয়)।
- **খরচ**: বুটে ≤ ২৫৬টি পয়েন্ট ব্লক রিড, O(উইন্ডো) —
  চেইনের বয়স থেকে স্বাধীন।
- উইন্ডোর **মধ্যে** একটি অনুপস্থিত বা অ-ডিকোডযোগ্য ব্লক
  বুট `Corrupted` দিয়ে ব্যর্থ করে (সেই
  বাইটগুলো ইতিমধ্যে চেইন তৈরি করেছে); উইন্ডোর
  বাইরে, ঐতিহাসিক ব্লক অস্পৃশ্য থাকে।

`load_chain_replay` (শূন্য ট্রাস্ট) ইনডেক্স একই
ভাবে তার সম্পূর্ণ রিপ্লের মাধ্যমে পুনর্নির্মাণ করে — উভয় পাথ
অভিসৃত হয়।

## স্থায়ী Name → Id ইনডেক্স (P0.2)

`DomainId = BLAKE3-256(DOMAIN_ID_VERSION ‖ canonical name)`
উল্টানো যায় না: একটি নাম রেজোলিউশন (রিলে/DNS) একটি স্থায়ী
ইনডেক্স চায়। P0.2 এটি স্টোরে যোগ করে, বাকির
মতোই লেনদেন শৃঙ্খলার সাথে।

### স্কিমা

দুটি সহচর টেবিল, একসাথে লেখা এবং মোছা:

```text
names_v3        key  = BLAKE3-256("SCONE-NAME-IDX-V1" ‖ canonical name)  (32 B)
                val  = target id (32 B : DomainId or TldId)

name_reverse_v3 key  = target id (32 B)
                val  = tag(0x01 domain | 0x02 TLD) ‖ canonical name
```

- `names_v3` কী হলো **নামের একটি হ্যাশ, পরিষ্কার নাম
  নয়** (কমপ্যাক্ট ইনডেক্স টেবিল, ডাম্পের মাধ্যমে কোনো নাম
  গসিপ নেই)। কীটি নামের একটি **বিশুদ্ধ ফাংশন**: ইনডেক্স
  চেইন থেকে যেকোনো সময় পুনর্নির্মাণযোগ্য
  (`rebuild_name_index`), এর জন্য কোনো অতিরিক্ত
  মেটাডেটা পারসিস্ট হয় না।
- `name_reverse_v3` নামটি (ঠিক একবার) সংরক্ষণ করে কারণ
  অপসারণ পাথগুলো (মেয়াদোত্তীর্ণ ডোমেইনের GC,
  `RevokeTld`) শুধুমাত্র **id** জানে: মোছার জন্য
  হ্যাশড কীকে কোথাও খুঁজে পেতে হবে। ট্যাগটি
  দুটি নেমস্পেস আলাদা করে।
- কঠোর পৃথকীকরণ: `resolve_name` কখনো একটি TLD এন্ট্রির
  উত্তর দেয় **না** এবং `resolve_tld` কখনো ডোমেইন এন্ট্রির
  নয় (বিপরীত টেবিলের ট্যাগ
  সিদ্ধান্ত নেয়; একটি `DomainName`-এর ≥ ২টি লেবেল, একটি TLD-র
  ১টি — উভয় কী ডেরিভেশন `names_v3` স্পেস ভাগ করে
  কিন্তু ফলাফল নয়)।
- `DomainId` ৩২ বাইট থাকে, কখনো হ্রাস পায় না (কঠোর
  প্রকল্প নিয়ম:
  কনসেনসাস পরিচয়, সংঘর্ষ প্রতিরোধ)।

### লেনদেন সামঞ্জস্য

আপসার্ট (`RegisterDomain`, `AssignDomain`, `RegisterTld` —
লেনদেন দ্বারা পরিষ্কারভাবে বহনিত নাম) এবং অপসারণ (GC,
প্রত্যাহার — খালি id) ব্লকের `StateDelta` দ্বারা
(`name_upserts` / `name_removals`) বহনকৃত এবং ব্লক ও
স্টেট রাইটের **একই redb লেনদেনে** প্রয়োগকৃত। তাই একটি
ক্র্যাশ না এমন একটি ইনডেক্স এন্ট্রি রেখে যেতে পারে যা একটি
অনুপস্থিত ডোমেইনকে নির্দেশ করে (কোনো
ভূত নেই), না তার এন্ট্রি ছাড়া একটি নিবন্ধিত ডোমেইন। একটি
ব্যর্থ অ্যাপেন্ড কিছুই লেখে না (পরীক্ষিত)। নামী
ভ্যারিয়েন্টগুলো
`put_domain_state_with_name` / `put_tld_state_with_name` /
`remove_domain_state` মেরামত টুলে একই
অ্যাটমিসিটি দেয়।

`store_block` / `store_block_with_removals` নেম ডেল্টা
ব্লকের একই
লেনদেন থেকে ডেরিভ করে — রিলে
ইন্টারফেসে কোনো অতিরিক্ত প্যারামিটার নেই।

### পুনর্নির্মাণ (`RedbStore::rebuild_name_index`)

ইনডেক্সটি ক্যানোনিকাল চেইনের একটি বিশুদ্ধ ফাংশন, M8
অ্যান্টি-রিপ্লে ইনডেক্সের মতো। `rebuild_name_index` এটি
**পারসিস্টেড ব্লক** থেকে পুনর্নির্মাণ করে (`DomainStateBytes`
নাম ধারণ করে **না** — শুধুমাত্র owner/সিকোয়েন্স/মেয়াদ — তাই
সত্যের উৎস হলো লেনদেন প্রবাহ, যেখানে `RegisterDomain`
এবং `AssignDomain`
ক্যানোনিকাল নাম পরিষ্কারভাবে বহন করে):

1. পাস ১: `blocks_by_height` জেনেসিস→টিপ স্ক্যান, একবারে RAM-এ
   একটি ব্লক; `RegisterDomain`/`AssignDomain`/`RegisterTld`-তে
   দেখা `name → id` বাঁধাই সংগ্রহ;
2. পাস ২: শুধুমাত্র **জীবিত** লক্ষ্যে ফিল্টার (পারসিস্টেড
   স্টেটই কর্তৃত্ব) — নিবন্ধিত তারপর GC/মেয়াদোত্তীর্ণ
   একটি ডোমেইন পুনঃইনডেক্সড হয় **না**;
3. পাস ৩: একটি লেনদেনে উভয় টেবিল মুছে + সম্পূর্ণ পুনঃলিখন
   (ক্র্যাশ → পুরনো বা নতুন সম্পূর্ণ ইনডেক্স)।

একটি অনুপস্থিত বা অ-ডিকোডযোগ্য ব্লক → `Corrupted` (একই
বাইট যা চেইন তৈরি করেছে)। খরচ RAM-এ O(দেখা ভিন্ন
নাম) (প্রতি নামে ≤ ২৫৩
B) এবং রিডে O(ব্লক) — একটি মেরামত টুল, বুট
পাথ নয়।

### ইনডেক্স যা নয়

- কর্তৃত্ব নয়: RAM চেইন স্টেটই একমাত্র
  কর্তৃত্ব; ইনডেক্স একটি পুনর্নির্মাণযোগ্য ক্যাশ (একটি বৈপরীত্য একটি
  লেনদেনযোগ্যতা বাগ, `rebuild_name_index` দ্বারা
  সনাক্তযোগ্য এটির সাথে তুলনা করে)।
- M6b স্ন্যাপশটে ফ্রোজেন নয়: `names_v3`/`name_reverse_v3`
  টেবিল লাইভ এবং প্রতিটি ব্লকের ডেল্টা অনুসরণ করে; স্টেট
  স্ন্যাপশট সেগুলো এমবেড করে না (পুনরায় শুরুতে
  ডেল্টা দ্বারা পুনর্নির্মাণ, বা মেরামত হিসেবে `rebuild_name_index`)।

### স্ন্যাপশট যা কমিট করে না

RAM স্টেট `ChainState` অভ্যন্তরীণ কাঠামো বহন করে যা
কনসেনসাস দ্বারা কমিট করা হয় না (owner কী, গ্রেস উইন্ডো)।
সেগুলো ফ্রোজেন **নয়**: সাফিক্স রিপ্লে লেনদেন
প্রয়োগ করে সেগুলো পুনর্নির্মাণ করে (ডিটারমিনিস্টিক, প্রাসঙ্গিক
উইন্ডোর জন্য সম্পূর্ণ রিপ্লের মতোই কনটেন্ট)। TXID অ্যান্টি-রিপ্লে
ইনডেক্স একই
চুক্তি অনুসরণ করে (M8, পূর্ববর্তী অংশ দেখুন): বুটে
পুনর্নির্মিত, কখনো
ফ্রোজেন নয়। `load_chain_replay`-এর সাথে বিট-সঠিক সমতা
ক্যানোনিকাল স্টেটে (state_root + SMT) টেস্ট দ্বারা
যাচাইকৃত।

## VERIFIED স্টেট স্ন্যাপশট — চাংক + ম্যানিফেস্ট + ক্রিপ্টো যাচাই (P0.3)

উপরের M6b স্ন্যাপশট এমন একটি নোডের বুট দ্রুত করে যেটি তার
ডিস্ক বিশ্বাস করে। P0.3 একটি ভিন্ন প্রয়োজন সমাধান করে:
ট্রান্সপোর্টকে বিশ্বাস না করে নোডের মধ্যে একটি স্টেট
পরিবহন (একটি নতুন নোড বুটস্ট্র্যাপ, মেরামত)। ফরম্যাট এবং
যাচাই
`crates/scone-storage/src/verified_snapshot.rs` + রুট
পুনর্নির্মাণ
`crates/scone-blockchain/src/snapshot_verify.rs`-এ থাকে।

### ট্রাস্ট মডেল

স্ন্যাপশট একটি **ফাইনালাইজড** ব্লকের স্টেট বহন করে — কমিটির
কোরাম দ্বারা স্বাক্ষরিত একটি চেকপয়েন্ট
(`CheckpointData.state_root`,
O(1) `state_root_smt` রুট)। চেকপয়েন্টের সত্যতা
(Ed25519 সিগনেচারের কোরাম) ইমপোর্টের আগে
চেইন স্তর দ্বারা যাচাইকৃত। ইমপোর্ট নিজেই পুনর্গণনার মাধ্যমে
স্ন্যাপশট ↔ চেকপয়েন্ট সংযুক্তি যাচাই করে:

1. **প্রতিটি পৃষ্ঠার হ্যাশ**: `blake3("SCONE-SNAP-PAGE-HASH" ‖
   সম্পূর্ণ পৃষ্ঠা এনকোডিং)` অবশ্যই ম্যানিফেস্ট দ্বারা
   ঘোষিত হ্যাশের সমান হতে হবে (একটি মিথ্যা বাইট → প্রত্যাখ্যান);
2. **এন্ট্রির যোগফল == ম্যানিফেস্ট কাউন্টার** (একটি অনুপস্থিত
   পৃষ্ঠা বা ভুল কাউন্টার → প্রত্যাখ্যান);
3. **ইমপোর্টকৃত এন্ট্রি থেকে পুনর্গণনাকৃত SMT রুট ==
   `checkpoint.data.state_root`** — দা ক্রিপ্টোগ্রাফিক চেক:
   সম্পূর্ণ স্টেট (ডোমেইন + TLD) একটি নতুন SMT-তে
   পুনঃফোল্ড করা হয়
   (`snapshot_verify::recompute_state_root`, লিফ
   `SCONE-LEAF-DOM-V1`/`SCONE-LEAF-TLD-V1` ঠিক লাইভ
   পাথের মতো) এবং রুটকে অবশ্যই কমিটির স্বাক্ষরিতটির সমান হতে হবে।
   একটি মিথ্যা, ছোট, বা অসম্পূর্ণ
   স্ন্যাপশট যেকোনো রাইটের আগে প্রত্যাখ্যাত হয়;
4. **কাঠামোগত সামঞ্জস্য**: ম্যানিফেস্টের
   `height`/`tip_hash`/`state_root`
   == চেকপয়েন্টের; কঠোরভাবে
   বর্ধমান id (কোনো ডুপ্লিকেট নেই); ক্রমিক পৃষ্ঠা সূচি; DoS
   বাউন্ড (≤ ১০,০০০ এন্ট্রি/পৃষ্ঠা, ≤ 2^20 পৃষ্ঠা, মোট বাজেট)।

যাচাই ব্যর্থতা → `StorageError::SnapshotRejected`, স্টোর
কঠোরভাবে অপরিবর্তিত থাকে (সবকিছু রাইট
লেনদেনের আগে যাচাই হয়)।

### সিরিয়ালাইজড ফরম্যাট (কঠোর, big-endian, নির্মম ডিকোডিং)

```text
manifest = "SCONE-SNAP-MAN-V1"
        ‖ height(8) ‖ tip_hash(32) ‖ state_root(32)
        ‖ page_count(4) ‖ domain_count(8) ‖ tld_count(8)
        ‖ page_hashes(page_count × 32)

page    = "SCONE-SNAP-PAGE-V1"
        ‖ index(4) ‖ height(8) ‖ state_root(32)      ← every page is
        ‖ entry_count(4) ‖ entries                   self-identifying

entry   = kind(0x01 domain | 0x02 TLD | 0x03 TLD floor) ‖ id(32)
          ‖ [len(2) ‖ state | floor(8 BE)]
          (state = DomainStateBytes 57/89 B or TldStateBytes 2/34 B —
           the existing canonical storage formats, reused; kind
           0x03 (lifetime floor of an open TLD, owner-option) has
           a dedicated format WITHOUT a length prefix:
           id(32) ‖ floor(8 BE), fixed size)
```

পৃষ্ঠার ক্রম: সব ডোমেইন এন্ট্রি (বর্ধমান id), তারপর সব TLD
এন্ট্রি (বর্ধমান id), তারপর স্ন্যাপশট
উচ্চতায় ফ্রোজেন TLD আজীবন ফ্লোর (`snapshot_tld_floors_all` —
লাইভ টেবিল নয়) — স্টোরের
কার্সার পেজিনেশনের ক্রম। প্রতিটি পৃষ্ঠা বহন করে `(index, height,
চেকপয়েন্টের state_root, এন্ট্রি)`: একটি একা পৃষ্ঠা জানে কোন
স্ন্যাপশটের অন্তর্গত। এক্সপোর্টে ২৫৬ এন্ট্রির
পৃষ্ঠা (`VERIFIED_SNAPSHOT_PAGE_ENTRIES`); ইমপোর্টে DoS বাউন্ড।
TLD
ফ্লোর (`tld_floors_v1`) পোর্টেবল ফরম্যাটের অংশ: kind
0x03 সেগুলো বহন করে, এবং ইমপোর্ট সেগুলোর কঠোরভাবে
বর্ধমান এবং স্ন্যাপশটে উপস্থিত একটি TLD-কে
লক্ষ্য করা চায় —
অন্যথায় ইমপোর্টার কখনো তা হত্যা করত না যা একজন
এক্সপোর্টার হত্যা করত (নীরব ফর্ক, প্রত্যাখ্যাত)।

### এক্সপোর্ট (`export_verified_snapshot(store, checkpoint)`)

শেষ ফাইনালাইজড চেকপয়েন্টের স্টেট সিরিয়ালাইজ করে — টিপ
নয়। ডোমেইন, TLD, তারপর স্ন্যাপশট
উচ্চতায় ফ্রোজেন TLD আজীবন ফ্লোর নির্গত করে (এক্সপোর্ট/ইমপোর্ট
প্রতিসাম্য: এক্সপোর্ট ঐতিহাসিকভাবে
ফ্লোর বাদ দিত — সংশোধিত, রিগ্রেশন টেস্ট
`export_carries_tld_lifetime_floors`)। পূর্বশর্ত: স্টোরে ঠিক
চেকপয়েন্টের উচ্চতায় একটি M6b পারসিস্টেড স্ন্যাপশট
(`snapshot_v1_*`) আছে (`CHECKPOINT_KEEP`/`SNAPSHOT_INTERVAL`
উইন্ডো নিশ্চিত করে যে এমন একটি
স্টেট নিয়মিত পাওয়া যায়); ব্লকের অ্যাঙ্কর সংরক্ষিত
বাইট থেকে পুনর্গণনাকৃত এবং `checkpoint.data.block_hash`-এর
সমান হতে হবে। অন্যথায় →
`StorageError::SnapshotUnavailable` (এক্সপোর্ট একটি স্পষ্ট
ক্রিয়া: পরবর্তী ব্যবধান/চেকপয়েন্টের অপেক্ষা করুন)।

### ইমপোর্ট (`import_verified_snapshot(store, checkpoint, manifest, pages)`)

সবকিছু যাচাই করে (উপরে দেখুন), তারপর একটি redb
লেনদেনে লেখে: লাইভ টেবিল `domains`/`tlds` + কাউন্টার +
`tip = (H, checkpoint hash)`, ফ্রোজেন টেবিল `snapshot_v1_*`
একই
ব্লকে অ্যাঙ্করড, এবং সংরক্ষিত মার্কার
`meta["verified_snapshot_v1"]` (`height ‖ tip_hash ‖
manifest_hash`)। লক্ষ্য: শুধুমাত্র খালি স্টোর (অন্যথায়
`SnapshotUnavailable`)।

### যাচাই খরচ (ডকুমেন্টেড)

ক্রমবদ্ধ ইনসারশনের মাধ্যমে SMT পুনর্নির্মাণ: N এন্ট্রি × O(40)
হ্যাশ ≈ O(N·40)। ১০০,০০০ ডোমেইনের জন্য ~2.1 M blake3 হ্যাশ
(কয়েক ডজন
ms)। একবারের জন্য — একটি বুটস্ট্র্যাপ/মেরামত ইমপোর্ট, কখনো
প্রতি-ব্লক পাথ নয়: গ্রহণযোগ্য। ক্রমবদ্ধ ইনসারশন (বর্ধমান id)
প্রতিটি
ব্রাঞ্চ পয়েন্ট শুধুমাত্র একবার তৈরি করে; যেকোনো ক্ষেত্রে রুট
শুধুমাত্র কনটেন্টের উপর নির্ভর করে (SMT নিশ্চয়তা, `smt.rs`-এ
ডিফারেনশিয়াল ফাজ)।

## স্টেট বুটস্ট্র্যাপ — জেনেসিস রিপ্লে ছাড়া (P0.4)

একটি নতুন নোড জেনেসিস থেকে ইতিহাস রিপ্লে না
করে নেটওয়ার্কে যোগ দেয়:

```text
finalized checkpoint (relay, validated by the chain layer)
        │
        ▼
verified snapshot (manifest + pages, crypto verification above)
        │  import → state at H + tip (H, hash) + marker
        ▼
anchor block H (requested from the network BY HASH — append_bootstrap_anchor)
        │
        ▼
recent blocks H+1..H+k (relay, increasing height, ordinary atomic
        │               append — the storage API requires only this)
        ▼
synced — boot replays ONLY the suffix above H
```

- **রিলেতে উন্মুক্ত স্টোরেজ API**: `append_bootstrap_anchor(H,
  hash, bytes)` (অ্যাঙ্কর ব্লক স্থাপন করে: প্রয়োজনীয় মার্কার,
  উচ্চতা/মার্কারের সাথে হ্যাশ সামঞ্জস্য, ইডেমপোটেন্ট) তারপর
  বর্ধমান উচ্চতায় সাধারণ
  অ্যাটমিক অ্যাপেন্ট। নেটওয়ার্ক পুনরুদ্ধার (ম্যানিফেস্ট থেকে
  হ্যাশ দিয়ে) রিলের বিষয়, স্টোরের নয়।
- **`load_chain`** মার্কার চেনে: H-এর নিচের ইতিহাস
  বৈধভাবে অনুপস্থিত (অ-আর্কাইভ নোড)। স্পষ্টভাবে: M8
  অ্যান্টি-রিপ্লে উইন্ডো রিস্ক্যান H-এ ফ্লোরড (H-এর নিচের
  ব্লক নেই এবং অনুপস্থিতও নয়); একটি ইমপোর্টের
  পরে সংরক্ষিত ব্লক ছাড়া একটি টিপ (অ্যাঙ্কর এখনও স্থাপিত নয়) →
  টাইপড নির্ণয়
  `SnapshotUnavailable` ("অ্যাঙ্করকে অবশ্যই নেটওয়ার্ক থেকে
  আসতে হবে"), দুর্নীতি নয়।
- **আর্কাইভ বনাম ফুল-স্টেট নোড**: একটি আর্কাইভ নোড (অপারেটর
  ফ্ল্যাগ)
  সবকিছু রাখে — এটি নেটওয়ার্ককে ঐতিহাসিক ব্লক সেবা দেয়
  এবং বিদ্যমান পাথ দিয়ে বুট হয়। একটি ফুল-স্টেট নোড (P0.4
  ডিফল্ট এভাবে কনফিগারকৃত একটি নতুন নোডের জন্য) H-তে বুট হয়:
  এটি ভবিষ্যৎ ব্লক ভ্যালিডেট করে (সাফিক্স রিপ্লে) কিন্তু H-এর
  নিচের ইতিহাস সেবা দিতে বা জেনেসিস রিপ্লে করতে
  পারে না। **ডিফল্ট আচরণ পরিবর্তন হয়
  না**: এই পাথটি শুধুমাত্র তখনই সক্রিয় যদি অপারেটর
  স্পষ্টভাবে ইমপোর্ট ট্রিগার করে (`import_verified_snapshot`
  একটি নিবেদিত ক্রিয়া, কখনো স্বয়ংক্রিয় নয়); প্রতিটি বিদ্যমান নোড
  অভিন্যভাবে বুট হয়।
- **ফুল নোডের সাথে সমতা**: সাফিক্স
  H+1..H+k-তে যোগ দেওয়ার পরে, স্টেট, টিপ, এবং `state_root_smt`
  একই টিপে একটি ফুল নোডের সাথে বিট-সঠিক
  (পরীক্ষিত); অ্যান্টি-রিপ্লে
  ইনডেক্স ঠিক H-এ/H-এর উপরে tx কভার করে — একটি অ-আর্কাইভ
  নোড H-এর নিচের উইন্ডো জানতে পারে না, স্টেট নিয়মই
  সুরক্ষা থাকে (H-এর নিচে একটি ডুপ্লিকেটেড tx স্টেটে ব্যর্থ হয়, কখনো
  দুবার গৃহীত হয় না)।

## মেমরি নীতি

- **সর্বত্র কার্সার**: `iterate_domains` পৃষ্ঠাকে
  `max` এন্ট্রিতে সীমাবদ্ধ করে (ডিফল্টে ১০০) redb-র অলস
  `range`-এর মাধ্যমে;
  সম্পূর্ণ ডোমেইন টেবিল কখনো উপাদানীকৃত হয় না। বড় তালিকা (TLD,
  ডোমেইন) বাধ্যতামূলকভাবে এই কার্সারের মধ্য দিয়ে যায়
  (`iterate_tlds`, একই চুক্তি, M7d)।
- **শুধুমাত্র-ডেল্টা**: `append_block_with_state` শুধুমাত্র
  ব্লক দ্বারা পরিবর্তিত ডোমেইন এবং TLD লেখে — কখনো সম্পূর্ণ
  স্টেট নয়;
- **কোনো সিঙ্ক্রোনাস প্রতিলিপি নয়**: RAM স্টেট
  প্রতি ব্লকে পুনঃপারসিস্ট হয় না; ডিস্ক স্টেট
  প্রতি ব্লকে পুনঃলোড হয় না;
- **পয়েন্ট রিড**: প্রতিটি রিড একটি সংক্ষিপ্ত রিড লেনদেন
  খোলে, মান ফেরায়, বন্ধ করে; redb `AccessGuard` শুধুমাত্র
  বাউন্ডেড কপির
  সময়কালের জন্য বাঁচে;
- **ঐতিহাসিক ব্লক কখনো RAM-এ নয়**: `load_chain` শুধুমাত্র
  টিপ লোড করে; `load_chain_replay` উচ্চতা অনুযায়ী
  স্ট্রিম করে;
- **বজায় থাকা কাউন্টার**: `domain_count` O(1), কোনো
  স্ক্যান নয়।

## DoS বাউন্ড

স্টোর সীমাবদ্ধ করে একটি শত্রু পিয়ার তাকে কী পারসিস্ট করাতে
বা অ্যালোকেট করাতে পারে:

- **`MAX_DHT_CACHE_ENTRY` (64 KiB)**: এর চেয়ে বড় একটি DHT
  রেকর্ড যেকোনো রাইট লেনদেনের আগে `put_dht_cache` দ্বারা
  প্রত্যাখ্যাত → `StorageError::TooLarge` (কিছুই লেখা হয়
  না);
- **`MAX_DOMAIN_PAGE` (10,000)**: `iterate_domains` *অভ্যন্তরীণভাবে*
  অনুরোধকৃত পৃষ্ঠাকে `min(max, 10_000)`-এ সীমাবদ্ধ করে — একটি
  অতিরিক্ত
  `max` কখনো ১০,০০০-এর বেশি স্টেট RAM-এ উপাদানীকৃত করে
  না; `iterate_tlds`-র একই বাউন্ড (`MAX_TLD_PAGE`, M7d);
- **সংরক্ষিত `meta` কী**: `meta_set` প্রত্যাখ্যান করে
  `tip`, `tip_height`, `format_version`, `domain_count`,
  `tld_count`, এবং `verified_snapshot_v1`
  (P0.3) `StorageError::ReservedKey` দিয়ে — স্টোরের
  অভ্যন্তরীণ হিসাব ওভাররাইট করলে নীরবে এটি
  দূষিত হত।
- **দ্বি-বাউন্ডেড DHT ক্যাশ (LRU)**:
  `DHT_CACHE_MAX_ENTRIES` (১০০,০০০ এন্ট্রি) এবং
  `DHT_CACHE_MAX_BYTES` (2 GiB — শত্রু
  ক্ষেত্রে গার্ড; প্রতিটি এন্ট্রি ইতিমধ্যে
  `MAX_DHT_CACHE_ENTRY` দ্বারা 64 KiB-এ সীমাবদ্ধ), যেটি
  আগে লাগে সেটি কী ক্রমে বহিষ্কার করে। কাউন্টারগুলো
  (এন্ট্রি + বাইট) রাইট
  টাইমে বজায় থাকে — গণনা করতে কখনো স্ক্যান নয়; সঠিক
  পুনর্নির্মাণ শুধুমাত্র খোলায় ঘটে (একক সম্পূর্ণ স্ক্যান, বুটে)।
  অ্যাক্সেসর
  `dht_cache_entries`/`dht_cache_bytes`, `set_dht_cache_bounds`-এর
  মাধ্যমে টিউনেবল বাউন্ড (টেস্ট:
  `dht_cache_respects_the_double_bound`)।

## ট্রাস্ট মডেল

দুটি লোডিং পাথ, দুটি নিশ্চয়তার স্তর:

- **`load_chain` — লোকাল ডিস্ক ট্রাস্ট**: টিপের হ্যাশ
  টিপ ব্লকের হেডার থেকে **পুনর্গণনাকৃত** এবং সংরক্ষিত
  `meta["tip"]`-এর সাথে তুলনাকৃত (বৈপরীত্য →
  `StorageError::Corrupted`, কখনো একটি জাল হ্যাশের উপর
  চেইন পুনরুদ্ধার হয় না), এবং ডোমেইন স্টেট
  কঠোরভাবে ডিকোড হয়। তবে, ঐতিহাসিক ব্লক **রিপ্লে
  হয় না**: পারসিস্টেড স্টেটগুলো মুখের কথায় নেওয়া
  হয়। এটি এমন একটি নোডের দ্রুত স্টার্টআপ যেটি তার
  নিজের ডিস্ক বিশ্বাস করে (শুধুমাত্র
  সেই নোড দ্বারা লেখা, অ্যাটমিকভাবে)। M6b থেকে, এই
  পাথ প্রথমে
  **স্টেট স্ন্যাপশট** ব্যবহার করে যখন ব্যবহারযোগ্য (নিচে
  দেখুন): স্ন্যাপশটের অ্যাঙ্কর পুনর্গণনা হয় এবং H-এর উপরের
  সাফিক্স লাইভ ব্লকের মতোই পুনঃভ্যালিডেট হয় — রিপ্লেকৃত
  অংশ তাই শূন্য-ট্রাস্ট, ফ্রোজেন বেস ডিস্ক-ট্রাস্ট।
- **`load_chain_replay` — শূন্য ট্রাস্ট**: সব ব্লক
  পুনঃপঠিত এবং একটি একটি করে পুনঃভ্যালিডেট হয় (সম্পূর্ণ
  ভ্যালিডেশন, লাইভ ব্লকের সাথে অভিন্ন); ফলস্বরূপ
  টিপকে সংরক্ষিত টিপের সমান হতে হবে। এটি
  নিয়ন্ত্রণ/মেরামত টুল।

**সুপারিশ**: একটি কঠোর নোডের (বা এমন একটি নোডের যার
স্টোরেজ ফাইল হস্তক্ষেপ করা হতে পারে — ভাগ করা ডিস্ক, একটি
সন্দেহজনক
ব্যাকআপের পুনরুদ্ধার) অবশ্যই `load_chain`-এর বদলে
`load_chain_replay`-এর মাধ্যমে শুরু করতে হবে।
