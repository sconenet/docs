# স্বাক্ষরিত লেনদেন (ফরম্যাট v1)

স্বাক্ষরিত লেনদেন ফরম্যাটের **নরমেটিভ** রেফারেন্স ডকুমেন্ট।
এটি ফিল্ডগুলো, সঠিক ওয়্যার ক্রম, আকার, স্বাক্ষরিত
পেলোড এবং ভ্যালিডেশন নিয়ম নির্দিষ্ট করে, যাতে Rust না
পড়েই একটি স্বাধীন ইমপ্লিমেন্টেশন সম্ভব হয়। রেফারেন্স ইমপ্লিমেন্টেশন
হলো [`scone-protocol`](../../../crates/scone-protocol) (এনকোডিং) এবং
[`scone-blockchain`](../../../crates/scone-blockchain) (ভ্যালিডেশন)।

`PROTOCOL_VERSION` = **1**। ফরম্যাটের একটি সেটই আছে: (একটি লেনদেনে)
`0x01` ছাড়া যেকোনো ভার্সন বাইট বা (একটি ব্লকে) লোকাল
ভার্সন থেকে ভিন্ন হলে `UnsupportedVersion` দিয়ে প্রত্যাখ্যাত।

## ওভারভিউ

```text
Transaction = disc u8 || version u8 || payload
```

| ফিল্ড | আকার | ভূমিকা |
|---|---|---|
| `disc` | 1 B | লেনদেনের ধরন (নিচের টেবিল) |
| `version` | 1 B | **ঠিক `0x01`** (tx ফরম্যাট ভার্সন) |

**লেনদেন আর ওয়্যারে কোনো `network` ফিল্ড বহন করে না**
(2026-09 পরিবর্তন): `network_id` (`str` ≤ 16, ASCII `[a-z0-9-]` —
যেমন `scone-testnet`, ১৩ বাইট) **শুধুমাত্র সাইনিং পেলোডে** থাকে —
স্বাক্ষরকারী এটিকে সেখানে প্রথম ফিল্ড হিসেবে ইনজেক্ট করে ([স্বাক্ষরিত
পেলোড](#স্বাক্ষরিত-পেলোড) দেখুন) — এবং PoW ডাইজেস্টে প্রতি-নেটওয়ার্ক থাকে।
তাই একটি নেটওয়ার্কের জন্য **স্বাক্ষরিত** লেনদেন অন্যটিতে কখনো
যাচাই হয় না: চেইনের পুনর্গণনাকৃত পেলোডের বিরুদ্ধে এর সিগনেচার
ব্যর্থ হয় (`InvalidSignature`), যা নিজের নেটওয়ার্ক ইনজেক্ট করে (দেখুন
`/docs/en/technical/blockchain.md` — নেটওয়ার্ক ও জেনেসিস)।

### ডিসক্রিমিন্যান্ট (নরমেটিভ টেবিল)

প্রতিটি ডিসক্রিমিন্যান্ট একটি **নির্দিষ্ট, স্বেচ্ছাসেবী অপাস ধ্রুবক**: মানগুলো
সচেতনভাবে ভিন্ন বেছে নেওয়া হয়েছে, যাতে ওয়্যার কখনো টাইপের মধ্যে
লজিক্যাল ক্রম বোঝায় **না** (কোনো 0x01/0x02/0x03… ক্রম নেই)। `0x00`
কখনো একটি বৈধ টাইপ **নয়** (সাধারণ দুর্নীতি বাইট)। ভবিষ্যৎ
টাইপগুলো যেকোনো অব্যবহৃত মুক্ত মান নেবে, এই টেবিলে একবারই
ডকুমেন্টেড।

| ডিসক্রিমিন্যান্ট | টাইপ | ভূমিকা |
|---|---|---|
| `0x21` | `RegisterDomain` | একটি ডোমেইনের ক্লেইম |
| `0x52` | `UpdateDomain` | একটি ডোমেইনের DNS ডেটার নতুন ভার্সন |
| `0x93` | `RegisterTld` | একটি টপ-লেভেল ডোমেইনের ক্লেইম (M7) |
| `0x47` | `TransferTld` | একটি TLD-র নতুন owner-এ ট্রান্সফার (M8a) |
| `0x6B` | `RevokeTld` | একটি TLD-র পরিত্যাগ (M8a) |
| `0xB8` | `SetTldOpen` | স্ব-নিবন্ধনের জন্য একটি TLD-র **অপরিবর্তনীয়** উন্মুক্তকরণ (একমুখী, owner-অপশন; `open=false` একটি টাইপড প্রত্যাখ্যান) |
| `0xD4` | `AssignDomain` | TLD-র owner দ্বারা একটি ডোমেইনের সরাসরি অ্যাসাইনমেন্ট (M8a) |
| `0x3C` | `RenewDomain` | একটি ডোমেইন রেজিস্ট্রেশনের সম্প্রসারণ (M8a; owner-অপশন থেকে ক্যানোনিকাল নাম বহন করে — একটি ওপেন TLD মেয়াদ অনুসরণ করে) |
| `0x8F` | `RenewTld` | একটি প্রাইভেট TLD-র ৩-বছর মেয়াদের নবায়ন (সৃষ্টির সমান PoW) |
| `0x15` | `SlashTx` | অ্যাঙ্কর ইকুইভোকেশনের প্রমাণ + ব্যান (M9) |
| `0xE2` | `TransferDomain` | একটি ডোমেইনের নতুন owner-এ ট্রান্সফার (M8c) |
| `0x71` | `Heartbeat` | একজন অপারেটরের লাইভনেস প্রুফ (proof-of-service RFC) |
| `0xA9` | `SetTldOperator` | একটি প্রাইভেট TLD-র অপারেশনের ডেলিগেশন (proof-of-service RFC) |
| `0x5E` | `SetDomainOperator` | একটি ডোমেইনের অপারেশনের ডেলিগেশন (proof-of-service RFC) |

`0x01` ছাড়া যেকোনো ভার্সন বাইট স্পষ্টভাবে প্রত্যাখ্যাত
(`UnsupportedVersion(গৃহীত মান)`): একটি অজানা বা অপ্রচলিত ফরম্যাট
কখনো দুর্ঘটনাক্রমে পার্স হয় না।

## SLASH_TX (0x15, M9)

একটি অ্যাঙ্কর **একই এপোকে দুটি সংঘর্ষপূর্ণ চেকপয়েন্ট** স্বাক্ষর
করেছে (ইকুইভোকেশন) তার অন-চেইন প্রমাণ। যে কেউ এটি জমা দিতে
পারে — প্রমাণ ক্রিপ্টোগ্রাফিক এবং স্বয়ংসম্পূর্ণ:

```text
offender[32] | evidence_a (CheckpointData 116 B)
  | sig_a[64] | evidence_b (CheckpointData) | sig_b[64]
  | reporter_pk[32] | reporter_signature[64]
```

- `validate()` কাঠামো যাচাই করে: একই এপোক, ভিন্ন
  `signing_hash`, দুটি ভিন্ন সিগনেচার, ক্যানোনিকাল পেলোডের উপর
  রিপোর্টার সিগনেচার;
- স্টেট নিয়ম (জার্নালড, রিঅর্গে প্রত্যাবর্তনযোগ্য): অভিযুক্তের উভয়
  সিগনেচার একই এপোকের দুটি ভিন্ন সাইনিং হ্যাশের বিরুদ্ধে যাচাই হতে
  হবে; অভিযুক্তকে এলিজিবল পুলে থাকতে হবে
  (অন্যথায় `SlashOffenderNotInPool`); তারপর **ব্যানিং** — কীটি
  PoS পুল থেকে স্থায়ীভাবে সরানো হয় (স্টেটে ব্ল্যাকলিস্ট);
- ন্যূনতম শাস্তি: অভিযুক্তের ডোমেইন/TLD বাজেয়াপ্ত হয় **না**
  (ডকুমেন্টেড M9 সিদ্ধান্ত);
- একই চেকপয়েন্ট দুবার = ইকুইভোকেশন নয় (প্রত্যাখ্যাত); ভিন্ন
  এপোক = প্রত্যাখ্যাত; জাল সিগনেচার = প্রত্যাখ্যাত।

## REGISTER_DOMAIN (0x21)

```text
name(str ≤ 253) domain_id[32] owner[32] timestamp.v proof(bytes ≤ 256) public_key[32] signature[64]
```

| ফিল্ড | টাইপ | শর্ত |
|---|---|---|
| `name` | `str` ≤ 253 | ক্লেইমড ডোমেইনের ক্যানোনিকাল নাম, **পরিষ্কারভাবে বহনিত** (নিচে দেখুন) |
| `domain_id` | ৩২ কাঁচা বাইট | অবশ্যই `DomainId(name)`-এর সমান (পুনর্গণনীত, কখনো বিশ্বাস করা হয় না) |
| `owner` | ৩২ কাঁচা বাইট | অবশ্যই `public_key`-র ডেরিভেশন হতে হবে (নিচে দেখুন) |
| `timestamp` | varint | ক্রম তথ্য (Unix, সেকেন্ড) |
| `proof` | `bytes` ≤ 256 | রেজিস্ট্রেশন PoW পেলোড ([নিচে](#রেজিস্ট্রেশন-প্রুফ-অব-ওয়ার্ক-pow) দেখুন) |
| `public_key` | ৩২ কাঁচা বাইট | স্বাক্ষরকারীর Ed25519 পাবলিক কী (RFC 8032) |
| `signature` | **ঠিক ৬৪ বাইট** | স্বাক্ষরিত পেলোডের Ed25519 সিগনেচার |

### নাম লেনদেন দ্বারা বহনিত

`RegisterDomain` ক্যানোনিকাল নাম পরিষ্কারভাবে পরিবহন করে, তার
পরে তার `DomainId`। `domain_id == DomainId(name)` সামঞ্জস্য
এনকোডিং, ডিকোডিং ও ভ্যালিডেশনে পুনঃযাচাই হয় (গভীর প্রতিরক্ষা):
এমন একটি `RegisterDomain` যার id বহনিত নামের সাথে মেলে না
অবৈধ। `DomainId` কনসেনসাস পরিচয় থাকে (চেইন ও DHT
কী); বহনিত নাম চেইনকে স্ব-বর্ণনাময় করে এবং সিগনেচারে
সম্পূর্ণ ক্লেইম কভার করে।

## REGISTER_TLD (0x93)

একটি টপ-লেভেল ডোমেইনের ক্লেইম (TLD রেজিস্ট্রি, M7):

```text
tld(str ≤ 63) tld_id[32] owner[32] timestamp.v proof(bytes ≤ 256) open(0x00|0x01) public_key[32] signature[64]
```

| ফিল্ড | টাইপ | শর্ত |
|---|---|---|
| `tld` | `str` ≤ 63 | TLD-র ক্যানোনিকাল নাম **পরিষ্কারভাবে বহনিত** (M8b: PoW চ্যালেঞ্জ নাম থেকে ডেরিভ হয়, ঠিক যেমন `RegisterDomain` নিজেরটি বহন করে) |
| `tld_id` | ৩২ কাঁচা বাইট | TLD-র পরিচয়: `BLAKE3-256(\"SCONE-TLD-V1\" || tld)` — অবশ্যই `tld`-র ডেরিভেশন হতে হবে (পুনর্গণনীত) |
| `owner` | ৩২ কাঁচা বাইট | `public_key`-র ডেরিভেশন |
| `timestamp` | varint | ক্রম তথ্য (Unix, সেকেন্ড) |
| `proof` | `bytes` ≤ 256 | রেজিস্ট্রেশন PoW পেলোড ([নিচে](#রেজিস্ট্রেশন-প্রুফ-অব-ওয়ার্ক-pow) দেখুন) |
| `open` | `0x00\|0x01` | **ওপেন** জন্ম: TLD সরাসরি `TldState::Open`-এ অবতরণ করে (কারো নয়, স্ব-সেবা + PoW, `open_tld_pow_difficulty` হারে একটি একক PoW — প্রাইভেটের চেয়ে সস্তা: সাধারণ রিসোর্স, কোনো PoS সিট বা এক্সক্লুসিভিটি নেই); **প্রাইভেট** জন্ম: ঐতিহাসিক আচরণ (owner, PoS সিট, `tld_pow_difficulty`) |
| `public_key` | ৩২ কাঁচা বাইট | স্বাক্ষরকারীর Ed25519 পাবলিক কী |
| `signature` | **ঠিক ৬৪ বাইট** | স্বাক্ষরিত পেলোডের Ed25519 সিগনেচার |

`TldId` স্পেস `DomainId` স্পেস থেকে **বিচ্ছিন্ন** (ভিন্ন
ডেরিভেশন প্রিফিক্স — দেখুন `/docs/en/general/naming.md`): TLD
`uip` নিবন্ধন করা (`*.uip` নেমস্পেসের উপর একটি ক্লেইম) কখনোই একটি
ডোমেইনের পরিচয় দখল করতে পারে না, বিপরীতেও নয়। প্রয়োগের সময়
স্টেট নিয়ম: TLD অবশ্যই মুক্ত হতে হবে (ডোমেইন রেজিস্ট্রি থেকে পৃথক
রেজিস্ট্রি)।

## M8a পরিবার — ওয়্যার ফরম্যাট

পাঁচটি টাইপ TLD রেজিস্ট্রি এবং ডোমেইন জীবনচক্র সম্পূর্ণ করে।
M8a থেকে নরমেটিভ ওয়্যার ফরম্যাট; **সম্পূর্ণ স্টেট নিয়ম M8b থেকে**
(দেখুন `/docs/en/technical/blockchain.md`): TLD owner প্রয়োজন, যেখানে
ক্লেইম স্ব-সেবামূলক সেখানে PoW, ডোমেইন দিকে মেয়াদ ও গ্রেস। কোনো
পেলোড ওয়্যারে `network` ফিল্ড বহন করে না (এটি শুধুমাত্র সাইনিং
পেলোডে থাকে)।

### TRANSFER_TLD (0x47)

```text
tld_id[32] owner[32] new_owner[32] public_key[32] signature[64]
```

| ফিল্ড | টাইপ | শর্ত |
|---|---|---|
| `tld_id` | ৩২ কাঁচা বাইট | ট্রান্সফারকৃত TLD |
| `owner` | ৩২ কাঁচা বাইট | `public_key`-র ডেরিভেশন (বর্তমান owner / স্বাক্ষরকারী) |
| `new_owner` | ৩২ কাঁচা বাইট | প্রাপকের পরিচয় (অপাস: যেকোনো মান সিনট্যাক্টিক্যালি বৈধ; এটি খর্চ করতে পারে এমন কী-এর সাথে বাঁধা একটি M8b স্টেট নিয়ম) |
| `public_key` | ৩২ কাঁচা বাইট | স্বাক্ষরকারীর Ed25519 পাবলিক কী |
| `signature` | **ঠিক ৬৪ বাইট** | স্বাক্ষরিত পেলোডের Ed25519 সিগনেচার |

কোনো টাইমস্ট্যাম্প বা সিকোয়েন্স নেই: একটি TLD-র এক সময়ে ঠিক
একজন owner; প্রথম প্রয়োগকৃত ট্রান্সফার জেতে (শুধুই চেইন ক্রম)।

### REVOKE_TLD (0x6B)

```text
tld_id[32] owner[32] public_key[32] signature[64]
```

একটি TLD-র স্বেচ্ছাসেবী পরিত্যাগ (পরে একটি নতুন
`RegisterTld` দ্বারা পুনরায় ক্লেইমযোগ্য)। বর্তমান owner দ্বারা
স্বাক্ষরিত; সচেতনভাবে টাইমস্ট্যাম্প বা সিকোয়েন্স ছাড়া — একটি
রিভোক বর্তমান অবস্থার বিরুদ্ধে এক-শট।

### SET_TLD_OPEN (0xB8)

```text
tld_id[32] owner[32] open u8 open_proof(proof) public_key[32] signature[64]
```

| ফিল্ড | টাইপ | শর্ত |
|---|---|---|
| `open` | ১ বাইট | **কঠোরভাবে `0x00` বা `0x01`** (ক্যানোনিকাল রূপ; অন্য যেকোনো মান → ডিকোডিং ত্রুটি, কখনো বলপ্রয়োগ নয়) |
| `open_proof` | `proof` (দৈর্ঘ্য-ভ্যারিন্ট + বাইট) | **স্বাক্ষরিত** ফিল্ড; `open = 0x01` হলে বাধ্যতামূলক ও যাচাইকৃত (উন্মুক্তকরণ PoW, নেটওয়ার্কের `open_tld_pow_difficulty`, চ্যালেঞ্জ `SCONE-TLD-OPEN-V1 ‖ tld_id`); `open = 0x00` হলে খালি (বন্ধ করা বিনামূল্যে) |

একটি **বন্ধ** TLD = শুধু-অ্যাসাইন (ডোমেইনগুলো একচেটিয়াভাবে TLD-র
owner দ্বারে `AssignDomain`-এর মাধ্যমে তৈরি); একটি **ওপেন** TLD =
যে কেউ রেজিস্ট্রেশন PoW করে এবং একটি মুক্ত ডোমেইন ক্লেইম করতে
পারে (`RegisterDomain`)। **উন্মুক্তকরণে** একটি অতিরিক্ত প্রুফ অব
ওয়ার্ক খরচ হয় (TLD ক্লেইমের চেয়ে হালকা:
মেইননেটে ~৩ দিন বনাম ~১ সপ্তাহ), owner দ্বারা `SetTldOpen`-এ
একবার পরিশোধিত — প্রুফ স্বাক্ষরিত `open_proof` ফিল্ডে ভ্রমণ করে
এবং স্বাক্ষরের পরে প্রতিস্থাপন করা যায় না।

### ASSIGN_DOMAIN (0xD4)

```text
name(str ≤ 253) domain_id[32] owner[32] assignee[32] public_key[32] signature[64]
```

`RegisterDomain`-এর আয়না: ক্যানোনিকাল নাম পরিষ্কারভাবে বহনিত
এবং `domain_id` অবশ্যই `DomainId(name)`-এর সমান হতে হবে
(ডিকোডিং, এনকোডিং ও ভ্যালিডেশনে পুনর্গণনীত)। **নামের TLD-র
owner** দ্বারা স্বাক্ষরিত (প্রয়োগে যাচাই, M8b); `assignee`
ডোমেইনের প্রথম owner হয় (অপাস, `new_owner`-এর মতো)।

### RENEW_DOMAIN (0x3C)

```text
name(str ≤ 253) domain_id[32] owner[32] valid_until.v proof(bounded) public_key[32] signature[64]
```

| ফিল্ড | টাইপ | শর্ত |
|---|---|---|
| `name` | `str` ≤ 253 | ক্যানোনিকাল নাম **পরিষ্কারভাবে বহনিত** (owner-অপশন: নবায়ন অন্তর্নিহিত ওপেন TLD-র মৃত্যু স্থগিত করে, চেইনকে নাম জানতে হবে); `domain_id` অবশ্যই `DomainId(name)`-এর সমান হতে হবে (পুনর্গণনীত) |
| `valid_until` | varint | নতুন রেজিস্ট্রেশন মেয়াদ (Unix, সেকেন্ড) |
| `proof` | বাউন্ডেড | **নবায়ন অনুমোদন** (নিচে দেখুন) |

ডোমেইনের বর্তমান owner দ্বারা স্বাক্ষরিত; `valid_until` প্রকৃতপক্ষে
মেয়াদ সম্প্রসারিত করে কিনা (এবং সর্বাধিক একটি নবায়ন মেয়াদে)
তা একটি স্টেট নিয়ম (M8b)।

#### নবায়ন অনুমোদন — TLD অনুযায়ী PoW বা PoS

নবায়নের খরচ অন্তর্নিহিত TLD-র প্রকৃতির উপর নির্ভর করে
(প্রয়োগের সময়, ব্লক স্টেটে মূল্যায়িত):

- **ওপেন TLD**: নবায়নের খরচ **সৃষ্টির মতোই PoW** —
  একই চ্যালেঞ্জ (`SCONE-DOMAIN-V1 ‖ canonical name`), একই
  প্রতি-লেবেল-দৈর্ঘ্য ও প্রতি-নেটওয়ার্ক ডিফিকাল্টি, একই এপোক বৈধতা
  উইন্ডো। একটি ডোমেইন কখনো বিনামূল্যে "সংগ্রহ" করা হয় না: জীবনের
  প্রতিটি মেয়াদ কাজে পরিশোধিত।
- **প্রাইভেট TLD**: নেমস্পেস TLD owner-এর স্টেক (PoS)।
  লেনদেনটি অবশ্যই **TLD owner দ্বারা স্বাক্ষরিত** হতে হবে (বা তার
  ডেলিগেটেড অপারেটর) — সিগনেচারই অনুমোদন,
  `proof` ফিল্ড খালি হতে হবে (২০টি শূন্য বাইট)। TLD owner
  নিজের নিয়মে তার নেমস্পেসের ডোমেইন নবায়ন করে।

### RENEW_TLD (0x8F)

```text
tld(str ≤ 63) tld_id[32] owner[32] valid_until.v proof(bounded) public_key[32] signature[64]
```

| ফিল্ড | টাইপ | শর্ত |
|---|---|---|
| `tld` | `str` ≤ 63 | ক্যানোনিকাল TLD নাম; `tld_id` অবশ্যই `TldId(tld)`-র সমান হতে হবে (পুনর্গণনীত) |
| `valid_until` | varint | অবশ্যই ঠিক `now + 3 years` হতে হবে (নির্দিষ্ট মেয়াদ — প্রয়োগে পুনঃডেরিভড, অন্য যেকোনো মান প্রত্যাখ্যাত) |
| `proof` | বাউন্ডেড | নবায়ন PoW (নিচে দেখুন) |

TLD-র বর্তমান **প্রাইভেট** owner দ্বারা স্বাক্ষরিত। প্রয়োগ নিয়ম:

- শুধুমাত্র একটি প্রাইভেট TLD-তে প্রযোজ্য (একটি ওপেন TLD তার
  ডোমেইনের মাধ্যমে বাঁচে — টাইপড প্রত্যাখ্যান `TldIsOpen`);
- মেয়াদের সময় AND মেয়াদের পরে **৬০-দিনের গ্রেস** জুড়ে
  বৈধ; এর বাইরে TLD মৃত (GC) এবং
  প্রত্যাখ্যান `TldExpiredFrozen`;
- **সৃষ্টির সমান PoW**: চ্যালেঞ্জ
  `SCONE-TLD-V1 ‖ name ‖ current_expiry(BE64)` (অ্যান্টি-রিইউজ
  সাফিক্স প্রতিটি PoW-কে একটি মেয়াদের সাথে বাঁধে), প্রাথমিক
  ক্লেইমের মতোই একই প্রতি-দৈর্ঘ্য ডিফিকাল্টি;
- গ্রেসের সময় নবায়ন ফ্রোজেন **নয়** — এটিই মেয়াদোত্তীর্ণ owner-এর
  কাছে এখনো উপলব্ধ একমাত্র ম্যানেজমেন্ট অপারেশন।

## UPDATE_DOMAIN (0x52)

```text
domain_id[32] owner[32] sequence.v record_hash[32] public_key[32] signature[64]
```

| ফিল্ড | টাইপ | শর্ত |
|---|---|---|
| `domain_id` | ৩২ কাঁচা বাইট | লক্ষ্য ডোমেইন |
| `owner` | ৩২ কাঁচা বাইট | `public_key`-র ডেরিভেশন |
| `sequence` | varint | **> 0**, প্রয়োগে `current + 1`-এর সমান হতে হবে |
| `record_hash` | ৩২ কাঁচা বাইট | DHT রেকর্ড সেটের প্রতি কমিটমেন্ট |
| `public_key` | ৩২ কাঁচা বাইট | স্বাক্ষরকারীর Ed25519 পাবলিক কী |
| `signature` | **ঠিক ৬৪ বাইট** | স্বাক্ষরিত পেলোডের Ed25519 সিগনেচার |

নোট: `UpdateDomain` **কোনো** `timestamp` বহন করে না — ক্রম
`sequence`-এর মধ্য দিয়ে যায়। এটি নামও বহন করে না: ডোমেইন
ইতিমধ্যে নিবন্ধিত, id যথেষ্ট।

### কঠোর সীমা

- `public_key`: **ঠিক ৩২ কাঁচা বাইট**, কোনো দৈর্ঘ্য প্রিফিক্স নেই। এমন একটি pk
  যা বক্ররেখার বিন্দু হিসেবে ডিকোড হয় না → ডিকোডিংয়ে
  `InvalidTransactionKey` ত্রুটি।
- `signature`: **ঠিক ৬৪ কাঁচা বাইট**, কোনো দৈর্ঘ্য প্রিফিক্স নেই, কোনো মার্জিন নেই।
  অন্য যেকোনো আকার একটি কঠোর ডিকোডিং ত্রুটি (ছোটকরণ প্রত্যাখ্যাত)।
- `proof`: দৈর্ঘ্য-ভ্যারিন্ট + বাইট, ২৫৬-এ সীমাবদ্ধ
  (`MAX_PROOF_LEN`), অ্যালোকেশনের আগে যাচাইকৃত।
- `name`: দৈর্ঘ্য-ভ্যারিন্ট + UTF-8 বাইট, ২৫৩-এ সীমাবদ্ধ
  (`MAX_NAME_LEN`), `scone-core` নামকরণ নিয়ম দ্বারা পুনঃভ্যালিডেটেড।

## Owner ডেরিভেশন

কঠোর নিয়ম: **owner সর্বদা পুনর্গণনীত, কখনো বিশ্বাস করা হয় না**।

```text
PublicKeyRef = BLAKE3-256("SCONE-PUBKEY-V1" || public_key)
OwnerId      = BLAKE3-256("SCONE-OWNER-V1" || PublicKeyRef)
```

এমন একটি লেনদেন যার `owner` তার নিজের
`public_key`-র ডেরিভেশনের সাথে মেলে না অবৈধ (`InvalidOwner` কোর
দিকে, `OwnerKeyMismatch` চেইন দিকে), এনকোডিং, ডিকোডিং
**এবং** চেইন ভ্যালিডেশনে প্রত্যাখ্যাত (গভীর প্রতিরক্ষা)।

## স্বাক্ষরিত পেলোড

স্বাক্ষরিত পেলোড হলো **সিগনেচার ফিল্ড ছাড়া** লেনদেনের
ক্যানোনিকাল এনকোডিং, একটি ডোমেইন পৃথকীকরণ ট্যাগ দ্বারা প্রিফিক্সড —
**লক্ষ্য চেইনের `network_id` মাথায় ইনজেক্টেড**:

```text
signing_payload(tx, network) = "SCONE-TX-SIG-V1"
                              || canonical_encode(tx_without_signature, network)
```

যেখানে `canonical_encode(tx_without_signature, network)` উপরের
ওয়্যার কাঠামো অনুসরণ করে, ডিসক্রিমিন্যান্ট ও ভার্সন বাইটসহ, `signature`-এর
আগে থেমে, **`network`-কে প্রথম ফিল্ড হিসেবে** — এটিই নেটওয়ার্কের
উপস্থিতির একমাত্র স্থান। চেইন পেলোডটি তার নিজের নেটওয়ার্ক দিয়ে
পুনর্গণনা করে: অন্য নেটওয়ার্কের জন্য স্বাক্ষরিত একটি লেনদেন
সিগনেচার ভেরিফিকেশনে ব্যর্থ হয় (`InvalidSignature`); এটিই অ্যান্টি
ক্রস-চেইন রিপ্লে প্রক্রিয়া।

```text
REGISTER_DOMAIN_no_sig = disc(0x21) version(0x01) network name domain_id[32] owner[32]
                            timestamp.v proof public_key[32]
REGISTER_TLD_no_sig    = disc(0x93) version(0x01) network tld tld_id[32] owner[32]
                            timestamp.v proof public_key[32]
UPDATE_DOMAIN_no_sig   = disc(0x52) version(0x01) network domain_id[32] owner[32]
                            sequence.v record_hash[32] public_key[32]
TRANSFER_TLD_no_sig    = disc(0x47) version(0x01) network tld_id[32] owner[32]
                            new_owner[32] public_key[32]
REVOKE_TLD_no_sig      = disc(0x6B) version(0x01) network tld_id[32] owner[32]
                            public_key[32]
SET_TLD_OPEN_no_sig    = disc(0xB8) version(0x01) network tld_id[32] owner[32]
                            open(0x00|0x01) open_proof(proof) public_key[32]
ASSIGN_DOMAIN_no_sig   = disc(0xD4) version(0x01) network name domain_id[32] owner[32]
                            assignee[32] public_key[32]
RENEW_DOMAIN_no_sig    = disc(0x3C) version(0x01) network name domain_id[32] owner[32]
                            valid_until.v proof public_key[32]
TRANSFER_DOMAIN_no_sig = disc(0xE2) version(0x01) network domain_id[32] owner[32]
                            new_owner[32] public_key[32]
```

বৈশিষ্ট্য:

- ডিটারমিনিস্টিক ও বিশুদ্ধ: একই লেনদেন ⇒ সর্বত্র একই পেলোড;
- ASCII প্রিফিক্স `SCONE-TX-SIG-V1` (১৫ বাইট,
  হেক্স `53434f4e452d54582d5349472d5631`) প্রোটোকলের অন্য কোনো
  হ্যাশ ডোমেইনে সিগনেচারের যেকোনো পুনঃব্যবহার রোধ করে;
- `signature` ছাড়া সব ফিল্ড কভারড — **একটি `RegisterDomain`-এর
  বহনিত নামসহ**: এগুলোর যেকোনো একটি পরিবর্তন করলে
  সিগনেচার অবৈধ হয়;
- ইনজেক্টেড `network_id` কভারড: একই অস্বাক্ষরিত tx দুটি
  নেটওয়ার্কের জন্য স্বাক্ষর করলে দুটি ভিন্ন পেলোড উৎপন্ন হয় (ফলে
  দুটি ভিন্ন সিগনেচার)।

## রেজিস্ট্রেশন প্রুফ অব ওয়ার্ক (PoW)

`RegisterDomain` এবং `RegisterTld`-র `proof` ফিল্ড রেজিস্ট্রেশন
প্রুফ অব ওয়ার্ক বহন করে (`scone-core::pow` মডিউল)।

### ডাইজেস্ট (এপোক সল্ট, অ্যান্টি প্রি-মাইনিং)

```text
epoch  = block_height / POW_WINDOW        (POW_WINDOW = 144 blocks)
salt   = BLAKE3-256("SCONE-POW-V1-ARGON2" || network || challenge || epoch_le64)
digest = Argon2id(m, t, p = 1; password = nonce_le64, salt = salt[0..16])
```

`network` হলো ক্যানোনিকাল `network_id` (M8b): একটি
নেটওয়ার্কে মাইন করা প্রুফ অন্যটিতে প্রুফ নয়।

`SCONE-POW-V1-ARGON2` এছাড়াও প্রতি-নেটওয়ার্ক Argon2id প্যারামিটার
পিন করে (`pow_params`: মেইননেট m = 64 MiB, t = 2, p = 1; testnet/devnet
m = 8 KiB, t = 1, p = 1): Argon2id কোর (RFC 9106) প্রতি
হ্যাশের খরচকে মেমরি-প্রধান করে (GPU/ASIC প্রতিরোধ), এবং একটি
প্যারামিটার সেটের অধীনে মাইন করা প্রুফ অন্যটির অধীনে কখনো
যাচাই হয় না।

`challenge` হলো ক্লেইমড বস্তুর ডেরিভেশন ইনপুট —
একটি TLD-র জন্য `"SCONE-TLD-V1" || tld`, একটি
ডোমেইনের জন্য `"SCONE-DOMAIN-V1" || name`: ঠিক সেই বাইট
যা `TldId` / `DomainId`-র জন্য হ্যাশ করা হয়, যাতে একটি
প্রুফ কখনো নেমস্পেস জুড়ে বা বস্তুর ধরন জুড়ে রিপ্লেযোগ্য না হয়।
`epoch_le64` এবং `nonce_le64` হলো এপোক এবং nonce-এর
লিটল-এন্ডিয়ান ৮-বাইট এনকোডিং।

`digest`-এ অন্তত `difficulty` সংখ্যক শুরুর শূন্য বিট থাকলে প্রুফ
বৈধ।

#### এপোক সল্ট — অ্যান্টি প্রি-মাইনিং

একটি আনসল্টেড ডাইজেস্ট সময় বা উচ্চতার সাথে বাঁধে না: যে কেউ
আজ হাজার হাজার নামের প্রুফ প্রি-মাইন করতে পারত, তারপর মেইননেট
উৎক্ষেপে একটি বিস্ফোরণে সেগুলো নিবন্ধন করত (স্কোয়াটিং) — প্রুফ
স্বয়ংসম্পূর্ণ ছিল এবং যে ব্লক আগে আসত সেখানে বৈধ ছিল। ডাইজেস্ট
**যে ব্লক লেনদেনটি প্রয়োগ করে তার এপোক** দিয়ে সল্টেড:

- `epoch = block_height / POW_WINDOW`, `POW_WINDOW = 144` ব্লক
  (৬৫ সে/ব্লকে ~২.৬ ঘণ্টা): সৎ ব্যবহারকারীর জন্য একটি গ্রেস উইন্ডো
  (মাইন করুন, তারপর উইন্ডোর মধ্যে জমা দিন), এর বাইরে বাধ্যতামূলক
  পুনঃমাইনিং;
- প্রুফ ওয়্যারে তার এপোক ঘোষণা করে; প্রয়োগে,
  ঘোষিত এপোককে প্রয়োগকারী ব্লকের **বৈধতা
  উইন্ডো**তে পড়তে হবে — শুধুমাত্র পশ্চাদমুখী সহনশীলতা (দেরিতে
  জমা শোষিত হয়, "ভবিষ্যতের জন্য" মাইনিং অসম্ভব), উইন্ডোর আকার
  `epoch_validity_window(difficulty)` = `1 << max(0, difficulty −
  16)` এপোক (প্রশস্ত উইন্ডো: উচ্চ মেইননেট ডিফিকাল্টি দিন-থেকে-সপ্তাহ
  মাইন করে, একটি এপোকের চেয়ে বেশি; মজুদ কিছু লাভ করে না
  কারণ উইন্ডো ≈ মাইনিং খরচ — একটি বিস্ফোরণের প্রতিটি প্রুফ
  উইন্ডোর ভেতরে তার সম্পূর্ণ `2^difficulty` হ্যাশ খরচ করে)। ডিফিকাল্টি
  ≤ ১৬ বিটে (টেস্টনেট, দীর্ঘ নাম) কঠোর-সমতা নিয়ম অপরিবর্তিত;
- মেমপুল ভর্তি (সর্বোচ্চ প্রচেষ্টা): ভবিষ্যৎ ব্লক উচ্চতা
  অজানা — রিলে `current height + 1`-এর এপোকের বিরুদ্ধে যাচাই
  করে; কঠোর প্রয়োগ-সময়ের যাচাইই কর্তৃত্ব থাকে;
- ডিটারমিনিস্টিক রিপ্লে: প্রুফ তার এপোক বহন করে এবং উইন্ডো
  (difficulty, block epoch)-এর বিশুদ্ধ ফাংশন — একটি ঐতিহাসিক
  ব্লক যেকোনো নোডে অভিন্নভাবে পুনঃযাচাই হয়।

প্রি-মেইননেট বিরতিকারী পরিবর্তন: পুরনো কমপ্যাক্ট ফরম্যাট (১২ বাইট)
কোনো পশ্চাদগামী সামঞ্জস্য ছাড়াই প্রত্যাখ্যাত।

### ওয়্যার পেলোড (২০ নির্দিষ্ট বাইট)

```text
nonce_le64 || epoch_le64 || difficulty_le32
```

ডিফিকাল্টি এবং এপোক প্রুফের সাথে ভ্রমণ করে, কিন্তু সেগুলো
**প্রোডিউসার-ঘোষিত এবং তাই কখনো বিশ্বাস করা হয় না**: ভেরিফায়ার
ডিফিকাল্টিকে রেজিস্ট্রেশন ধরনের **প্রোটোকল ধ্রুবকের** বিরুদ্ধে
তুলনা করে (যে পেলোডের ঘোষিত ডিফিকাল্টি ধ্রুবক থেকে ভিন্ন — কম *বা*
বেশি — সেটি প্রত্যাখ্যাত, `InvalidProof`), এবং
এপোককে প্রয়োগকারী ব্লকের এপোকের বিরুদ্ধে (অমিলে
`ProofEpochMismatch`)। তারপর nonce ধ্রুবক ডিফিকাল্টিতে পুনঃযাচাই
হয়, ডাইজেস্ট শূন্য থেকে পুনর্গণনীত।

### ডিফিকাল্টি (**দৈর্ঘ্য-ভিত্তিক** বক্ররেখা, M8b + পরিমাপকৃত ক্যালিব্রেশন)

ডিফিকাল্টি কোনো সমতল প্যারামিটার নয়: এটি **তৈরি হওয়া
লেবেলের দৈর্ঘ্যের** ডিটারমিনিস্টিক ফাংশন (`scone-core::pow_length` —
`RegisterTld`-র জন্য TLD, `RegisterDomain`-র জন্য বাম-দিকের
লেবেল), প্রতি নেটওয়ার্কে:

```text
difficulty(len) = apex − round(0.415 × (len − 1)), clamped at the floor
```

| নেটওয়ার্ক | প্রাইভেট TLD (apex/floor) | জন্মগত-ওপেন TLD / ডোমেইন (apex/floor) |
|---|---|---|
| testnet | 8 bits / 2 bits | 6 bits / 2 bits |
| mainnet | 42 bits / 30 bits | 40 bits / 30 bits |
| devnet | 2 bits / 1 bit | 1 bit / 1 bit |

একটি **জন্মগত-ওপেন** TLD (`RegisterTld` `open = 0x01` সহ)
"ওপেনিং" বক্ররেখা পরিশোধ করে (apex − 2, `domain_difficulty`-র
মতো); **একটি বিদ্যমান প্রাইভেট TLD উন্মুক্ত করা**
(`SetTldOpen`) সমতল ডিফিকাল্টিতে থাকে
(`open_tld_pow_difficulty`: ৬ বিট টেস্টনেট / ২২ বিট মেইননেট /
২ বিট devnet — tx
শুধুমাত্র `tld_id` বহন করে, নামটি সৃষ্টিতে তার দৈর্ঘ্যের জন্য পরিশোধ
করেছে)। মেইননেট বেঞ্চমার্ক (প্রাইভেট TLD, ~৬ M হ্যাশ/সে): ১ অক্ষর
= ৪২ বিট (≥ ৭ দিন), ৫ অক্ষর = ৪০ বিট (~২ দিন), ১৯ অক্ষর = ৩৫ বিট
(~১.৬ ঘণ্টা), ২৯+ অক্ষর = ৩০-বিট ফ্লোর (~৩ মিনিট)। বক্ররেখাগুলো
`scone-core::pow_length`-এ থাকে (ধ্রুবক `MAINNET_APEX = 42`,
`MAINNET_FLOOR = 30`, `TESTNET_APEX = 8`, `TESTNET_FLOOR = 2`,
`DEVNET_APEX = 2`, `DEVNET_FLOOR = 1`); সমতল
প্যারামিটারগুলো (`tld_pow_difficulty` ইত্যাদি)
`scone-core::network::NetworkParams`-এ থাকে। একটি মান
পরিবর্তন = **সেই নেটওয়ার্কের জন্য** একটি কনসেনসাস
পরিবর্তন। অপরিবর্তনীয় সত্য: devnet একটি সম্পূর্ণ
তৃতীয় `NetworkParams` এবং টেস্টনেট তার
প্রি-ডেভনেট ধ্রুবকগুলোর সাথে কঠোরভাবে অভিন্ন থাকে (Argon2id
প্যারামিটার, বক্ররেখা, উইন্ডো) — devnet কোড
নিজে ছাড়া অন্য নেটওয়ার্কগুলোর সাথে কোনো ধ্রুবক ভাগ করে না।

সমতল শিখরগুলোর পরিমাপকৃত ক্যালিব্রেশন (2026-10, `cargo run
--release -p scone-core --example pow_bench` — একটি রেফারেন্স
x86-64-তে একক-থ্রেড থ্রুপুট ~7.7 M H/s):

| ধরন (মেইননেট) | ডিফিকাল্টি | গড় প্রকৃত সময় |
|---|---|---|
| `RegisterTld` | 24 bits | ~7 s |
| `RegisterDomain` | 20 bits | ~54 ms |

~৬৫ সে/ব্লকে: একটি TLD ক্লেইম ~0.1 ব্লকের একক-কোর CPU খরচ
করে, একটি ডোমেইন ~1 ms ব্লকের — ব্যবহারকারীর জন্য প্রতীকী,
স্কেলে ইন্ডাস্ট্রিয়ালাইজ করতে ব্যয়বহুল (অ্যান্টি-স্কোয়াট)। হার্ডওয়্যার
টার্গেট কমলে পুনঃক্যালিব্রেট করতে (মোবাইল ARM: ~৪–৮× ধীর)।

স্টেট শাখা (M8b, শিপড): `RegisterTld` সর্বদা তার PoW চায়;
`RegisterDomain` একটি **ওপেন** TLD-তে এটি চায় (বন্ধ পাথ
শুধু-অ্যাসাইন — `AssignDomain`, কোনো PoW নেই, TLD-র owner
দ্বারা স্বাক্ষরিত)।

## ভ্যালিডেশন নিয়ম

একটি লেনদেন তখনই বৈধ যদি এবং কেবল যদি:

1. **কঠোর ডিকোডিং**: উপরের কাঠামো ও সীমা সম্মানিত (পরিচিত
   ডিসক্রিমিন্যান্ট, ভার্সন `0x01`, pk ৩২ B, সিগনেচার ৬৪ B, কোর
   অপরিবর্তনীয় সত্য ডিকোডিংয়ে পুনঃযাচাইকৃত);
2. **owner/pk বাঁধাই**: `owner == OwnerId::from(public_key)`
   (পুনর্গণনীত);
3. **নাম/id সামঞ্জস্য** (RegisterDomain): `domain_id ==
   DomainId(name)` (পুনর্গণনীত);
4. **সিগনেচার**: চেইনের নেটওয়ার্ক দিয়ে **শূন্য থেকে পুনর্গণনাকৃত**
   স্বাক্ষরিত পেলোডের বিরুদ্ধে `signature`-র Ed25519
   `verify_strict` (কখনো একটি পিয়ার বা প্রদত্ত লেনদেন থেকে
   নেওয়া হয় না) — অন্য নেটওয়ার্কের জন্য স্বাক্ষরিত tx এখানে
   ব্যর্থ হয় (`InvalidSignature`, অ্যান্টি ক্রস-চেইন
   রিপ্লে);
5. **স্টেট নিয়ম** (একটি ব্লকে প্রয়োগের সময় — M8b, দেখুন
   `/docs/en/technical/blockchain.md`):
   RegisterTld → TLD মুক্ত + ICANN নয় + PoW (দৈর্ঘ্য-ভিত্তিক
   ডিফিকাল্টি); RegisterDomain → TLD নিবন্ধিত **এবং ওপেন** + মুক্ত
   ডোমেইন (গ্রেসসহ) + PoW (দৈর্ঘ্য-ভিত্তিক);
   UpdateDomain → বিদ্যমান ডোমেইন, বর্তমান `owner`,
   `sequence == current + 1`;
   TransferTld / RevokeTld / SetTldOpen / AssignDomain → বিদ্যমান
   **এবং প্রাইভেট** TLD, স্বাক্ষরকারী = TLD-র owner;
   TransferDomain → বিদ্যমান ডোমেইন, owner;
   RenewDomain → বিদ্যমান ডোমেইন, কঠোর সম্প্রসারণ ≤ ৩ বছর,
   PoW অনুমোদন (ওপেন TLD: সৃষ্টির মতোই PoW,
   **বর্তমান মেয়াদের সাথে আবদ্ধ** — নিবন্ধন এবং প্রতিটি পূর্বের
   নবায়ন থেকে ভিন্ন একটি চ্যালেঞ্জ) বা PoS
   (প্রাইভেট TLD: TLD owner-এর — বা তার কার্যকর অপারেটরের —
   সিগনেচার, খালি `proof`)।

ভেরিফিকেশন `verify_strict` ব্যবহার করে (ম্যালিয়েবল সিগনেচার
এবং দুর্বল/অ-ক্যানোনিকাল কী প্রত্যাখ্যান), অবিশ্বস্ত ডেটার জন্য
যেমন প্রয়োজন।

## `push_block`-এ অপারেশন ক্রম

ক্রিপ্টোগ্রাফিক ভ্যালিডেশন (২ থেকে ৪) প্রতিটি লেনদেনের জন্য
স্টেট প্রয়োগের **আগে** ঘটে, প্রতি ব্লকে একটি অ্যাটমিক ওয়ার্কিং
স্টেটের উপর; যেকোনো ত্রুটি চেইনকে কঠোরভাবে অপরিবর্তিত রাখে।

## ব্লক সমাবেশ

`BlockBuilder` (`scone-blockchain`) একটি
লেনদেন সারি থেকে একটি ব্লক সমাবেশ করে: ক্রমবদ্ধ তালিকার উপর
`tx_root` পুনর্গণনীত, হেডার প্যারেন্ট হ্যাশের সাথে শৃঙ্খলাবদ্ধ
(`prev_hash`), `version` =
`PROTOCOL_VERSION`। কনসেনসাস পেলোড (স্বাক্ষরিত প্রোডিউসার পেলোড)
এবং টাইমস্ট্যাম্প কলার দ্বারা সরবরাহকৃত; বিদ্যমান `Consensus` trait
ভ্যালিডেশনের সাথে প্রতিসমভাবে ব্যবহৃত হয়।

## হেক্স এখন কোথায় থাকে

অফলাইন `tx build|sign|verify` কমান্ড অপসারিত
(cli-simplify-v1)। স্বাক্ষরিত-হেক্স ফরম্যাট নিজে অপরিবর্তিত এবং
**web/API প্রবাহের** ওয়্যার ফরম্যাট থাকে: রেজিস্ট্রার
ওয়েব অ্যাপ API-এর উপর ক্যানোনিকাল হেক্স হিসেবে লেনদেন
তৈরি, স্বাক্ষর (ব্রাউজার-ইন কীস্টোরে) ও জমা দেয়। CLI দিকে,
ব্যবহারকারী পাথগুলো হলো এক-কমান্ড রূপ:

```bash
scone domain register example.uip        # mines, signs, submits
scone domain renew example.uip                      # renewal proof, signs, submits
scone domains                            # what you own
```

সব কোড পাথে owner এবং কী সাইনিং পরিচয় থেকে
**পুনর্গণনীত**, কোনো ইনপুট থেকে কখনো নেওয়া হয় না।
