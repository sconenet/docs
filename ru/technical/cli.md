# CLI (`scone`) — логирование и уровень детализации

> Нормативное поведение логирования бинарника `scone`. Любое
> расхождение документации с кодом = баг (исправить источник
> истины).

## Принципы

- **stdout зарезервирован для вывода команд** (`scone status`,
  `identity list`, `status`, …). Скрипт может перенаправить stdout,
  никогда не находя в нём логов — пайпы остаются надёжными.
  Допустимое исключение: `scone relay` выдаёт строки данных
  `p2p: <multiaddr>`, `dns: <addr>` и `metrics: <addr>` в stdout,
  как только листенеры привязаны (пригодные для использования
  данные для `--bootstrap` / конфигурации, не логи; выводятся
  ровно по одному разу, с немедленным сбросом буфера).
- **Все логи идут в stderr** (компактный формат `tracing`),
  включая логи реле — реле и до миграции писал в stderr.
- Пользовательские сообщения об ошибках CLI (`scone: <error>`)
  остаются в stderr: это UX, а не логи.

## Уровни и `--verbose` / `-v`

| Вызов | Действующий уровень |
|---|---|
| `scone <cmd>` (без `-v`) | `warn` |
| `scone relay` (без `-v`) | `info` |
| `scone -v <cmd>` / `scone relay -v` | `info` |
| `scone -vv …` | `debug` |
| `scone -vvv …` (и более) | `trace` |

`-v`/`--verbose` — **глобальный и повторяемый** флаг: он принят
до или после подкоманды (`scone -vv identity list` и
`scone identity list -vv` эквивалентны).

**Почему `scone relay` остаётся на INFO по умолчанию**: реле —
это демон — он должен логировать свою активность (прослушивание
RPC/p2p, принятые и созданные блоки, подключённые пиры, отказы),
чтобы им можно было оперировать, без требования флага.
Одноразовые же команды, напротив, молчат (WARN), чтобы не
загрязнять терминал или скрипт.

## `RUST_LOG` (переопределение)

Если установлена переменная окружения `RUST_LOG`, она **полностью
замещает** уровень, выведенный из `-v` (синтаксис `env-filter`):

```bash
RUST_LOG=debug scone identity list        # debug без -v
RUST_LOG=error scone -vv relay            # error побеждает -vv
RUST_LOG=scone_network=trace,info scone relay   # по цели
```

## Конфигурация окружения (`.env`)

Перед разбором аргументов `scone` загружает файл `.env` из текущего
каталога (`dotenvy::dotenv()` в `main.rs`). Отсутствие файла =
молчаливая пустая операция, никогда не ошибка. Загруженные
значения становятся базовой линией опций реле, которые объявляют
переменную окружения (`env = "…"` в `cli.rs`).

Приоритет (одна опция, три источника):

```text
explicit CLI flag  >  .env variable  >  built-in default
```

- флаг, переданный в командной строке, ВСЕГДА побеждает;
- иначе переменная (загруженная из `.env` или установленная
  в реальном окружении процесса — одна переменная, одинаковый
  эффект);
- иначе встроенное значение по умолчанию clap.

Повторяемые переменные (`SCONE_BOOTSTRAP`, `SCONE_DNS_UPSTREAM`)
накапливаются: по одной строке на значение в `.env` (dotenvy
добавляет).

Полная таблица переменных `SCONE_*` (сеть, прослушивание P2P,
bootstrap, генезис, mDNS, UPnP, DNS-поверхность, метрики, профиль
топологии, якорь) и семантика каждой живёт в
[`relay.md`](relay.md#environment-configuration-env);
комментированный шаблон — `.env.example` в корне репозитория
(скопировать в `.env`, никогда не коммитить — `.env` в
gitignore).

## Семантика уровней (конвенция кода)

- `error!`: сбои (сегодня нет точек вызова — сетевые сбои
  поглощаются как `warn!`, и только фатальные локальные сбои
  всплывают как типизированная ошибка из `run()`);
- `warn!`: отвергнутые враждебные или вредоносные сетевые записи,
  устаревшие tx, вытесненные из мемпула, конфликтующие tx,
  отброшенные при продакшене, сбои исходящих/входящих,
  несоответствие ключей DHT;
- `info!`: блок принят/создан, прослушивание RPC/p2p, подключение
  пира, старт реле (чекпоинты состояния);
- `debug!`: внутренние детали (tx принят, пир отключён, RPC-раунд,
  листинг keystore, события kad под `SCONE_KAD_DEBUG`);
- `trace!`: зарезервировано для полезных нагрузок (сегодня нет
  точек вызова).

Библиотечные крейты (`scone-network`, …) используют макросы
`tracing`, но **не инициализируют подписчика**: инициализация
живёт только в бинарнике `scone` (перед диспетчеризацией
подкоманд — реле нужны его логи с самого запуска).


## Простое использование (cli-simplify-v1)

- **`--peer` не нужен**: команды по умолчанию общаются с локальным
  реле; переменная `SCONE_PEER` или `--peer` переопределяет.
- **`--identity` не нужен**, когда в keystore одна идентичность
  (используется молча; несколько → ошибка их перечисляет).
- Удалены (заглушки подсказывают замену): `show`, `submit`,
  `lookup`, `owned`.
- Новое: `scone domain renew <name>`, `scone domains`,
  `scone domain get|set` (одна запись, без файла).

```bash
scone identity generate me
scone domain register example.scone
scone domain set example.scone A 192.0.2.1
scone domain renew example.scone
```

## Жизненный цикл TLD (cli-unified-lifecycle)

`scone tld register <tld>` — точка входа в TLD одной командой,
симметричная `scone domain register` — состояние в цепочке
читается ПЕРВЫМ, затем выполняется правильное действие:

- **свободный TLD** → регистрируется, рождается **ОТКРЫТЫМ по
  умолчанию** (без флага: пространство самообслуживания, 1/3 PoW).
  `--private` выбирает пространство с владельцем по полной цене
  PoW, с явным подтверждением (экономическое решение). `--yes`
  пропускает подтверждения (скрипты).
- **ваш, истекает в течение 90 дней** → предлагается ПРОДЛЕНИЕ
  (PoW, привязанное к текущему сроку — защита от повторного
  использования) и выполняется после подтверждения.
- **ваш, далеко от истечения** → делать нечего (`tld renew --force`
  чтобы продлить принудительно).
- **чужой** → чистая типизированная ошибка с владельцем.

```bash
scone tld register mytld            # open birth (default)
scone tld register mytld --private  # owned namespace (confirm)
scone tld renew mytld               # explicit renewal
```

Аналогично, `scone domain register <name>` на имени, которым вы
владеете и которое истекает в течение 90 дней, предлагает
продление вместо отказа.

## Продвинутые команды

Значения по умолчанию выше покрывают повседневное использование.
Для скриптов и веб/API-интероперабельности остаётся доступной
полная поверхность:

- `scone show <name>` — внутренний DomainId имени.
- `scone lookup <name>` / `scone owned <pubkey>` — псевдонимы
  `domain get` / `domains --pubkey` (тот же вывод).
- `scone renew <name>` — псевдоним `scone domain renew`.
- `scone domain info` — псевдоним `scone domain get`.

Автономная hex-поверхность (подкоманды `tx build|sign|verify`,
`submit tx`) была УДАЛЕНА (remove-tx-surface-v2): операции M8b,
которые она обслуживала, теперь являются полноценными командами —
`scone tld open <tld>` (одностороннее самообслуживаемое открытие,
открывающий PoW майнится для вас), `scone tld transfer <tld>
<owner>`, `scone tld revoke <tld>`, `scone domain assign <name>
<owner>` (владелец TLD, частный TLD) и `scone domain transfer
<name> <owner>`. Каждая: чтение состояния, подпись, отправка, txid.
Разрешение DNS-записей переехало в `scone domain resolve <name>`
(бывший `record get`); канал hex-публикации (`record put`)
удалён — редактирование идёт через `domain set` / `domain update`.
- `scone domain export <name> [--out FILE]` — записывает
  проверенный по цепочке набор записей в точном формате
  `update --file` (гарантированный круговорот: export →
  редактирование → update повторно отправляет тот же набор).
  Без `--out`: stdout. `domain resolve` использует тот же
  читаемый формат, так что `resolve > zone.txt` напрямую
  импортируем. Виды без текстового синтаксиса (GEOROUTE,
  неизвестные) экспортируются как закомментированные
  предупреждения — никогда не выбрасываются молча.

`domain get` также печатает `domain_id` и `valid_until`.

## Сборки: dev с поддержкой mainnet (mainnet-compile-gate)

Сборки по умолчанию **не содержат mainnet**: `scone relay --network
mainnet` (и сервисы регистратора с `SCONE_NETWORK=mainnet`)
немедленно падают с подсказкой пересборки. Официальный
распространяемый бинарник собирается так:

```bash
cargo build --release --features mainnet
```

`scone --version` показывает `+mainnet` на таких сборках, а
стартовый лог реле говорит `build: mainnet-enabled`.

Значение `--network` по умолчанию тоже следует сборке: `mainnet`
на сборках с поддержкой mainnet (официальный бинарник приводит
пользователей в производственную сеть), иначе `testnet`. Явный
флаг `--network` или переменная `SCONE_NETWORK` всегда побеждают
(порядок clap: флаг > env > значение по умолчанию). Это
эксплуатационный барьер (случайные запуски, dev/CI-бинарники) —
а не криптографическая граница; защитой от враждебных узлов
остаются правила консенсуса.
