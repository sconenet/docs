# Keystore — спецификация формата файла ключей `.sconekey`

> Нормативный документ. Любое расхождение между этим документом
> и `crates/scone-keystore/src/lib.rs` — баг (определить источник
> истины, исправить). Референс реализации: крейт `scone-keystore`
> (v2).

## Назначение

Хранить приватный ключ Ed25519 (*seed*, 32 байта) на диске,
зашифрованным парольной фразой. Ключ **никогда** не попадает на диск
в открытом виде; все секреты (парольная фраза, выведенный материал)
обнуляются в памяти после использования.

## Обзор

- **KDF**: Argon2id (v0x13), параметры по умолчанию `m_cost` =
  64 МиБ, `t_cost` = 3, `p_cost` = 1 (значения по умолчанию крейта
  `argon2`).
- **Шифрование**: XChaCha20-Poly1305 (AEAD), 32-байтовый ключ,
  выведенный из KDF, 24-байтовый случайный nonce на файл.
- **Зашифрованное содержимое**: ровно seed Ed25519 (32 байта); тег
  Poly1305 (16 байт) хранится как суффикс шифртекста (стандартный
  вывод AEAD-функции `encrypt`).

## Герметизация байтов (модуль `bytes`, web)

`scone_keystore::bytes::{seal_to_bytes, open_from_bytes}`
производит и потребляет ТОТ ЖЕ формат, не касаясь файловой системы:
веб-клиент генерирует идентичность в браузере (`scone-crypto` +
bip39) и герметизирует точные байты файла ключей (можно скачать,
открыть CLI как есть — тест интероперабельности в наборе).
Нативный путь (`create`/`create_with_phrase`) делегирует той же
герметизации: одна кодировка формата, три адресата.

## Бинарный формат (v2) — заголовок 52 байта + публичные метаданные + шифртекст

```text
Offset  Size        Field
0       9           magic: "SCONEKEY1" (ASCII — unchanged since v1)
9       1           version: u8 = 2
10      1           m_cost_mib: u8 (m_cost in MiB; m_cost_kib = value × 1024)
11      1           t_cost: u8 (Argon2id iterations)
12      16          Argon2id salt (random per file)
28      24          XChaCha20-Poly1305 nonce (random per file)
52      32          public_key: Ed25519 public key (32 bytes, IN THE CLEAR)
84      8           created_at: u64 big-endian (Unix, seconds)
92      1           label_len: u8 (0..=255)
93      label_len   label: UTF-8 (readable without the passphrase, may be empty)
—       48          ciphertext (32 bytes encrypted seed) || Poly1305 tag (16 bytes)
```

Метаданные `public_key`/`created_at`/`label` публичны: читаются
**без парольной фразы** (`public_metadata_from_bytes`). Публичный
ключ по своей природе публичен; метка — просто отображаемое имя —
её скрытие ничего не даёт и стоит листинга без парольной фразы.
Общая длина зависит от метки: 141 байт с пустой меткой
(KEYFILE_LEN + 32 + 8 + 1), плюс длина метки.

**v1 (заменён, ровно 100 байт)**: magic ‖ version=1 ‖ m ‖ t ‖
salt ‖ nonce ‖ шифртекст — публичный ключ НЕ хранился (заблокированный
файл был анонимным). Файлы v1 остаются **читаемыми** (метаданные
`None`, парольная фраза требуется для `identity show`;
повторная герметизация через `scone identity restore` переносит
их в v2).

### Проектные решения

- **Параметры KDF в файле**: `m_cost_mib` и `t_cost` читаются из
  заголовка (не зашиты жёстко при чтении), что позволит повышать
  их в будущих версиях, не ломая существующие файлы.
- **Границы безопасности при чтении**: файл, объявляющий
  `m_cost_mib` > 64 или `t_cost` = 0 или > 10, отклоняется
  (`Error::InvalidParams`) *до* любой аллокации — вредоносный
  файл не может заставить узел выделить гигабайты или зациклиться
  бесконечно. По умолчанию при записи `m_cost_mib` = 64,
  `t_cost` = 3.
- **Явный magic + версия**: файл, не являющийся файлом ключей
  (`Error::InvalidFile`), или с неподдерживаемой версией
  (`Error::UnsupportedVersion`) чисто отклоняется, без паники.
- **Неверная парольная фраза**: сбой аутентификации Poly1305 не
  указывает, *почему* он произошёл; неверная парольная фраза
  и повреждённый шифртекст, следовательно, неразличимы и всплывают
  как одна и та же отдельная ошибка `Error::WrongPassphrase`.

## Вывод ключа шифрования

```text
key = Argon2id(passphrase, salt, m_cost = m_cost_mib × 1024 KiB,
               t_cost = t_cost, p_cost = 1, output = 32 bytes)
```

Затем:

```text
ciphertext || tag = XChaCha20-Poly1305-Seal(key, nonce, plaintext = seed)
```

Без ассоциированных данных (AAD) в v1. 24-байтовый nonce, случайный
на файл, делает риск повторного использования nonce пренебрежимым
(файлы ключей записываются только один раз).

## API (`scone-keystore`)

| Функция | Роль |
|---|---|
| `create(path, passphrase) -> GeneratedKey` | Генерирует ключ, записывает зашифрованный файл ключей (создаёт родительские каталоги); **отказывается перезаписывать** существующий файл (`Error::KeyfileExists`); возвращает ключ в памяти |
| `create_overwriting(path, passphrase) -> GeneratedKey` | То же, но явно заменяет существующий файл ключей |
| `open(path, passphrase) -> SigningKey` | Расшифровывает и возвращает ключ подписи |
| `list(dir) -> Vec<KeyEntry>` | Перечисляет файлы `*.sconekey` в каталоге (отсортированы по имени); отсутствие каталога = пустой список |

`GeneratedKey.signing_key` обнуляется при drop благодаря
`ed25519-dalek` (фича `zeroize` по умолчанию). Выведенный AEAD-ключ,
seed и расшифрованный открытый текст обёрнуты в
`zeroize::Zeroizing`: Drop покрывает все пути выхода, включая
ошибки, пробрасываемые через `?`.

## Права доступа к файлам

На Unix файл ключей создаётся с правами `0600` (чтение/запись
только владельцем), через `OpenOptions` + `set_permissions` —
независимо от umask процесса. Проверка существования и создание
атомарны (`create_new`, `O_EXCL`): две конкурирующие генерации не
могут молча перезаписать друг друга.

## CLI

```bash
scone identity generate <n> [--dir <directory>] [--passphrase-env VAR] [--force]
scone identity list [--dir <directory>]
scone identity show <n> [--dir <directory>] [--passphrase-env VAR]
```

- Каталог по умолчанию: `$HOME/.scone/keys`.
- Имя идентичности строго валидируется: пустое, `.`, `..`, `/`,
  `\\\\`, NUL, ведущая точка и суффикс `.sconekey` отклоняются
  (имя становится именем файла внутри каталога ключей — ни один
  компонент пути не может выйти за пределы keystore).
- Без `--passphrase-env` парольная фраза запрашивается
  в терминале **со скрытым вводом** (`rpassword`: без эха; дважды
  с подтверждением для `generate`).
- `identity generate` **показывает фразу восстановления BIP39
  (24 слова)** ровно один раз — свежая 256-битная энтропия, одни
  только слова восстанавливают тот же ключ (`scone identity
  restore`); они нигде никогда не хранятся.
- `identity generate` **отказывается перезаписывать** существующий
  файл ключей; `--force` явно заменяет его (новые salt/nonce,
  новый ключ, новая фраза).
- `identity list` показывает для файлов v2 публичный ключ и метку
  **без парольной фразы** (публичные метаданные).
- `identity show` читает публичные метаданные файла v2 и показывает
  публичный ключ, `OwnerId` в строчном hex (64 символа, та же
  конвенция, что и `DomainId`), метку и дату создания **без
  парольной фразы**; файл v1 (без метаданных) всё же просит её.

## Чего этот формат сознательно не делает

- Несколько ключей в одном файле (один seed на файл).
- Смена парольной фразы (если когда-нибудь появится: перезапись
  файла с новыми salt/nonce).


## Идентичность по умолчанию (cli-simplify-v1)

Команды, которым нужна подписывающая идентичность (`domain
register`, `domain set`, `domain update`, `domain renew`),
используют ЕДИНСТВЕННУЮ идентичность keystore без `--identity`,
когда она ровно одна. При нескольких идентичностях команда
завершается ошибкой и перечисляет их (`scone identity list`);
передайте `--identity <name>` явно.
