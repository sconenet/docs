# Сетевое реле (M4) — архитектура, потоки и управление из CLI

> Нормативная спецификация сетевого реле Scone (`scone-network`).
> Любое расхождение документации с кодом = баг (исправить
> источник истины).

## Обзор

**Реле** — это полноценный P2P-узел Scone: он поддерживает
канонический блокчейн (ОЗУ + `NodeStore` redb), ретранслирует
транзакции и блоки, продюсирует блоки (режим devnet),
обслуживает протокол синхронизации, публикует и разрешает
`SignedDnsRecord` в DHT Kademlia и предоставляет **p2p-протокол**
(`/scone/reqres/1`), который CLI запрашивает напрямую
(унификация RPC→p2p: JSON TCP-канал исчез).

```text
                    ┌────────────────────────────────────────┐
                    │              scone relay               │
  P2P (libp2p)      │                                        │
  QUIC (udp,        │  Swarm libp2p                          │
  ephemeral port    │  ├─ identify  (address discovery)      │
  by default) ◄─────┤  ├─ ping      (liveness)               │
                    │  ├─ kad       (record DHT)             │
                    │  └─ reqres    (scone-prot. messages)   │
                    │                                        │
                    │  Relay core (single task)              │
                    │  ├─ Blockchain (full validation)       │
                    │  ├─ Mempool (bounded, dedup by TxId)   │
                    │  ├─ BlockBuilder (devnet production)   │
                    │  ├─ Fork parking (bounded, 2048)       │
                    │  └─ Sync driver (batched catch-up)     │
                    │                                        │
  CLI ◄─────────────┤  reqres p2p (QUIC, same messages)      │
                    └────────────────┬───────────────────────┘
                                     │
                              NodeStore (redb)
```

`crates/scone-network` — **единственный async-крейт** в
воркспейсе: всё под ним (crypto → core → protocol → blockchain →
storage) остаётся синхронным и чистым.

## Допуск соединений (P1.5)

Жёсткие границы на уровне роя (поведение libp2p
`connection_limits`, первая запись `SconeBehaviour`):

- `MAX_TOTAL_CONNECTIONS = 128` — потолок установленных
  соединений (входящие + исходящие) на реле; избыточные входящие
  ОТКАЗЫВАЮТСЯ, никогда в очередь;
- `MAX_PER_PEER_CONNECTIONS = 4` — один пир не может
  монополизировать общую квоту, открывая много соединений;
- `MAX_PENDING_INCOMING = 32` — защита от slowloris:
  неаутентифицированные полусоединения никогда не ждут
  бесконечно.

Эти границы дополняют существующие границы на сообщение
(`MAX_MESSAGE_LEN` 1 МиБ) и на бюджеты (синхронизация `max ≤ 128`
блоков, DNS TCP 64 соединения/512 Б/5 с). Атакующий с флудом
соединений получает отказы, а не рост памяти.

## Обнаружение пиров

Три дополнительных механизма, в этом порядке приоритета:

1. **Явные seeds** (`--bootstrap`, полные multiaddr) — всегда
   имеют приоритет; предоставление непустого списка ЗАМЕНЯЕТ всё
   остальное. `--no-builtin-seeds` опустошает встроенные seeds
   для 100% приватных развёртываний.
2. **Встроенные seeds** (`builtin_seeds(network)` в
   `scone-network/src/config.rs`) — заморожены на каждом
   официальном релизе бинарника, по сетям. Ненастроенное реле
   присоединяется к сети в одиночку. (Пусто на testnet, пока
   публичный testnet не развёрнут.)
3. **Выученная директория** (`<data-dir>/peers.json`) — каждый
   адрес, выученный через `identify`, сохраняется (последний
   визит; потолок **2 000 записей** — адреса, а не соединения,
   ~400 КиБ ОЗУ на максимуме — и **отсечка по возрасту 90
   дней**: запись, замеченная более 90 дней назад, удаляется при
   записи и игнорируется при загрузке, держа 2000 слотов
   заполненными правдоподобными пирами вместо доисторических
   ископаемых, чей единственный вклад — таймаут набора при
   загрузке) и сохраняется ~1×/мин на тике продакшена. При
   загрузке без seed и без bootstrap директория
   реконструируется: реле находит своих обычных пиров без
   конфигурации. Это кэш: отсутствие/повреждение файла =
   пустая директория, никогда не ошибка.
4. **UPnP** (`--upnp`, опционально) — проброска QUIC-порта
   прослушивания домашним маршрутизатором: узел становится
   достижимым извне БЕЗ circuit relay. На `NewExternalAddr`
   внешний адрес регистрируется как реальный внешний адрес роя
   (`add_external_address` — виден identify/autonat, кандидат
   в транспортные реле). Нет IGD-шлюза (`GatewayNotFound`) или
   немаршрутизируемый шлюз (`NonRoutableGateway`): простой
   info-лог, проброска пропускается — обычные случаи в домашней
   LAN. Истёкшая проброска (неудачное обновление) —
   предупреждение.

UPnP остаётся **выключенным по умолчанию** (`enable_upnp` =
`false` в `config.rs`): публичное развёртывание не общается
с маршрутизатором без согласия. **Обнаружение mDNS удалено**
(remove-mdns-discovery, 2026-10-22): пиринг приходит исключительно
из явного bootstrap, встроенных seeds и Kademlia — унаследованный
флаг `--mdns`/`SCONE_MDNS` по-прежнему принимается без эффекта
(совместимость скриптов, то же обращение, что и `--rpc`).

### Оптимизация локальной топологии (всегда включена)

Реле активно оптимизирует своё окружение чистым движком
`scone-topology` (см. документацию крейта). **Всегда включено**;
единственная открытая настройка — **профиль**
(`--topology-profile`, env `SCONE_TOPOLOGY_PROFILE`, по
умолчанию `default`):

| Профиль | мин / цель / макс | оценка | для кого |
|---|---|---|---|
| `tiny` | 2 / 4 / 6 | 120 с | Raspberry Pi, домашний ящик, VPS на 1 vCPU |
| `small` | 4 / 8 / 12 | 90 с | маленький сервер, домашний NAS |
| `default` | 8 / 16 / 32 | 60 с | стандартный сервер (по умолчанию) |
| `high` | 16 / 32 / 64 | 45 с | суверенный узел, хребет |
| `very-high` | 32 / 64 / 128 | 30 с | хабы основателей |
| `devtest` | 2 / 4 / 6 | 5 с | **ТОЛЬКО ЛАБ/ТЕСТ** (нестабилен по замыслу) |

```
scone relay --topology-profile tiny
```

Защитные параметры (гистерезис 0.15, остывание 600 с, льгота
120 с, измерение 15 с) идентичны везде: они охраняют
стабильность и не должны масштабироваться с размером узла.
Неизвестное имя — типизированная ошибка старта.

Неконсистентная конфигурация (`мин > цель > макс`, порог вне
`[0,1]` — включая `NaN` —, нулевой интервал) — **типизированная
ошибка старта**, никогда молчаливое поведение.

**Представление (`TopologyView`)** — питается событиями роя:

- успешный `ping` → наблюдение RTT (медианное окно из 8
  выборок);
- проваленный `ping` → штраф надёжности;
- `identify` получен → адреса (≤ 4/пир) + анонсированные
  протоколы (битовая маска kad/reqres/identify/relay);
- соединение установлено → состояние подключённости,
  направление (входящее/исходящее), возраст, обнаруженный
  circuit-relay;
- соединение закрыто → штраф + счётчик churn ТОЛЬКО если
  незапрошенное (добровольное вытеснение не считается);
- провал исходящего набора → штраф надёжности.

Представление ограничено (500 пиров; сверх — запоминаются только
подключённые пиры).

**`kad_required` из kbuckets** — перед каждой оценкой реле
обходит таблицу маршрутизации Kademlia: пир защищён, если он
`Connected` в корзине или `Disconnected` в НАСЫЩЕННОЙ корзине
(k = 20). Защищённый пир НИКОГДА не выбирается для вытеснения.

**Цикл оптимизации** — на интервале оценки профиля (60 с при
`default`; см. таблицу выше):

1. перевычислить `kad_required` (kbuckets);
2. оценка движком (гистерезис: льготный период 120 с,
   минимальное улучшение счёта +15%, остывание вытеснения
   600 с);
3. решение применено: `AddCandidate` → набрать кандидата;
   `Replace` → закрыть вытесненного пира (ОДИН РАЗ —
   прогрессивно, без зацикливания), затем набрать замену;
4. снимок **метрик** логируется (уровень INFO): счётчики
   известных/подключённых/входящих/исходящих/circuit/
   защищённых, средний/медианный RTT, различные IP-корзины,
   максимальная концентрация, churn (замены/отключения).

Счёт окружения НИКОГДА не является мерой доверия (см.
документацию `scone-topology`): из него не выводится ни одно
решение консенсуса.

### Достижимость (AutoNAT) и транспортное реле (circuit-relay v2)

Каждое реле запускает AutoNAT (клиент + сервер): узел просит
своих пиров попытаться набор ОБРАТНО к нему; вердикт
(`reachable`: да = достижим извне, нет = за NAT, unknown = ещё
не тестировался) обновляется каждые 5 мин и выставлен в
`NodeStatus` (поле `nat_reachable`, wire-варинт 0/1/2) — CLI
его показывает (`scone status`). Приватные адреса считаются
(`only_global_ips = false`): локальная сеть тестирует свою
локальную достижимость.

Достижимое реле включает circuit-relay v2 **hop** (оно может
ретранслировать трафик для пиров за NAT) и **DCUtR**
(пробивание дыр: два узла, соединённые через цепь, пытаются
прямое соединение и освобождают реле). Реле, признанное
за-NAT, автоматически запрашивает резервацию у первого
известного достижимого пира и слушает через него (адрес
`/p2p/<relay>/p2p-circuit`).

Правило продакшена: ретранслируемый узел за NAT не должен
становиться продюсером блоков (деградированные задержки/
доступность) — правило PoS (место = живой домен) пока этого не
запрещает; задокументировать как эксплуатационное требование
до публичного testnet.

## Транспорт и протоколы libp2p

| Протокол | Имя | Роль |
|---|---|---|
| QUIC (quic-v1) | — | Основной транспорт (udp) |
| identify | `/scone/id/1` | Обнаружение адресов пиров (заполняет таблицу Kademlia) |
| ping | стандарт libp2p | Живость |
| Kademlia | `/scone/kad/1` | DHT: ключ = `DomainId` (32 Б), значение = каноническое кодирование `SignedDnsRecord` |
| request-response | `/scone/reqres/1` | прикладные сообщения scone-protocol |

### Кадр приложения (`/scone/reqres/1`)

Каждый кадр — `len: u32 BE || байты`, где байты — каноническое
кодирование `Message` из `scone-protocol` (существующий кодек —
никакого второго формата). Длина ограничена
`limits::MAX_MESSAGE_LEN` **до** любого чтения или аллокации:
пиры, анонсирующие больший кадр, отклоняются без затрат
памяти.

Обмениваемые сообщения (по одному на раунд запрос/ответ):

| Сообщение | Направление | Ответ |
|---|---|---|
| `Hello { version }` | рукопожатие | `Hello` (локальная версия) |
| `Ping` / `Pong` | живость | `Pong` |
| `GetBlock { hash }` | запрос | `Block` (ОЗУ-окно) или `Pong`, если неизвестен |
| `GetBlocks { start, max }` | синхронизация | **один** `Block` (высота `start`) или `Pong`, если нет |
| `Block (b)` | реле блока | `Pong` (ack) |
| `Transaction (tx)` | реле tx | `Pong` (ack) |
| `GetRecord { domain_id }` | локальный DHT | `Record` (локальный кэш) или `Pong` |
| `Record (r)` | публикация | `Pong`, если принят, иначе ошибка |

Правило: **ровно один ответ на запрос**; сообщения-подтверждения
— `Pong`. Ответы синхронизации несут по одному блоку за раз —
догоняющая итерация на стороне запрашивающего (см.
«Синхронизация»). Это сознательно ограничено: никогда больше
одного блока в полёте на пира.

## Поведение реле

### Запуск

0. разрешение сети (`--network testnet|mainnet|devnet`, testnet
   по умолчанию, пока проект в разработке — M8b). Data-dir
   **на сеть** (`~/.scone/<network>/`): непустое хранилище,
   держащее цепочку другой сети, отказывается (`Corrupted`);
1. открыть/создать хранилище redb (`<data-dir>/chain.redb`);
2. `load_chain(store, network)`: тип O(1) + пагинированные
   состояния доменов (ОЗУ-окно: генезис + тип);
3. построение роя (эфемерная на-сессию идентичность Ed25519 —
   персистирование сетевой идентичности — открытое решение);
4. составление загрузочного списка (см. [Обнаружение
   пиров](#обнаружение-пиров)): явный `--bootstrap` (должен
   заканчиваться `/p2p/<peer-id>`) ИЛИ встроенные seeds сети
   ИЛИ выученная директория (`peers.json`);
5. набор каждого multiaddr и регистрация в таблице Kademlia
   (мёртвый набор игнорируется — остальные составляют сеть).

### Получение транзакции (P2P или подача через CLI `submit tx`)

1. строгое ограниченное декодирование (`MAX_MESSAGE_LEN`);
2. полная криптографическая валидация (`validate_transaction`:
   привязка владелец/ключ, `verify_strict` по канонической
   нагрузке);
3. **анти-replay ПЕРВЫМ** (дёшево, независимо от состояния,
   окончательно), затем пред-проверка состояния (дешёвое
   зеркало правил `push_block` — PoW, дорогое, проверяется
   только при push): повторённый `RenewDomain` отвечает
   `TxReplay`, а не лживая ошибка PoW (его доказательство
   привязано к истечению, которое первое применение сдвинуло).
   Разделение сетей обеспечивается на шаге 2: подписываемая
   нагрузка вводит сеть РЕЛЕ, tx, подписанная в другом месте,
   проваливается с `InvalidSignature` (wire 2026-09: больше
   нет поля `network`); `RegisterDomain` → TLD регистрируемого
   имени (иначе `UnknownTld`, D1/M7c) **и открыт** (иначе
   `TldClosed`, M8b), затем имя свободно; `UpdateDomain` →
   известный домен, точная последовательность `current + 1`,
   владелец; `RegisterTld` → свободный TLD;
   `TransferTld`/`RevokeTld`/`SetTldOpen` → известный TLD +
   подписант-владелец; `AssignDomain` → владелец TLD + свободное
   имя; `RenewTld` → известный частный TLD + владелец,
   фиксированный срок перевыведен, пред-проверка льготного
   окна; `RenewDomain` → известный домен + владелец,
   пред-проверка PoW продления (привязанного к текущему
   истечению) на следующей высоте;
4. вставка в мемпул (фиксированная ёмкость, дедуп по `TxId` —
   повторная подача tx, уже в пуле, — пустая операция);
5. широковещательная рассылка пирам (кроме отправителя).

### Получение блока (P2P, синхронизация или собственный)

1. `push_block`: существующая полная валидация (родитель =
   канонический тип, высота, перевычисленный корень Меркла,
   каждая транзакция валидирована, затем применена — атомарно
   на блок);
2. если принят: реле читает результат применения
   (`push_block_with_gc` → хеш + домены, удалённые
   детерминированным GC) и персистирует через
   `store_block_with_removals` (атомарное дельта-добавление:
   блок + тип + изменённые состояния — upsert'ы И удаления:
   истёкшие домены, отозванные TLD). Перезапуск,
   следовательно, никогда не воскресит истёкшую регистрацию;
3. сверка мемпула (включённые tx удалены);
4. широковещательная рассылка пирам (кроме отправителя).

Невалидный блок отклоняется с типизированной ошибкой; реле
продолжает работать. Никакой паники на сетевых данных. Тяжёлые
применения (Argon2 + коммит redb) проходят через
`tokio::task::block_in_place` (синхронный драйвер, p2p-приём,
продакшен): рантайм перемещает готовые задачи на других
воркеров — применение блока больше не останавливает DNS-сервис
или метрики.

### DNS-снапшот (публикация)

После КАЖДОГО применённого блока (p2p-приём — реорги включены —,
драйвер синхронизации, продакшен) И при загрузке (перезапуск не
должен NXDOMAIN'ить живые имена до следующего блока) реле
публикует **авторитетный DNS-снапшот** в канал `watch`, читаемый
DNS-поверхностью (полная спецификация в `dns.md`):

- расширение типa (подавляющий путь): **дельта O(тронуто)**,
  копи-он-райт — транзакции блока называют тронутые домены,
  плюс удаления детерминированного GC
  (`AppliedBlock.gc_removed_domains`, вычисленные при push);
- реорг / загрузка: **полная перестройка** (один пагинированный
  обход `ChainState::dns_facts`).

### Продакшен блоков (M5: подписанный продюсер)

Каждые `produce_interval` секунд (2 с по умолчанию): если мемпул
непуст, блок собирается `BlockBuilder` (`timestamp = now`)
**подписанным авторизованным продюсером** (нагрузка
`SCONE-BLOCK-V1` в `header.consensus`, см.
`/docs/en/technical/blockchain.md`) и идёт ровно путём приёма
полученного блока. Реле без tx ничего не продюсирует.

Ключ продакшена: ключ якоря (`--anchor-key`), когда реле
вооружено им — якорь является авторизованным продюсером, — иначе
фиксированный ключ devnet, валидный, пока пул продюсеров пуст
(открытый бутстрап: генезис). Как только существует живой
домен/TLD, блок, подписанный ключом devnet, отклоняется
(`InvalidProducer`).

### Цикл якорей (финальность, M5)

С `--anchor-key` (файл ключей `.sconekey`, парольная фраза через
`--anchor-passphrase-env`, по умолчанию `SCONE_ANCHOR_PASS` —
библиотечное значение по умолчанию `scone-network`
`SCONE_ANCHOR_PASSPHRASE` никогда не достигается через
бинарник, clap всегда его переопределяет):

- **ротация пропонента**: ровно ОДИН назначенный член комитета
  предлагает сам за эпоху (`committee[epoch % size]`,
  детерминированно); остальные члены никогда не подписывают
  собственный тип — содержимое чекпоинта зависит от типа
  пропонента, а непропущенные самопредложения раскололи бы эпоху
  на соперничающие содержимые, каждый из которых guard по праву
  отвергает как эквивокацию (testnet, 2026-10-21);
- после каждого принятого/продюсированного блока, если этот узел
  член текущего комитета **и** комитет достигает
  `MIN_FINALITY_COMMITTEE_SIZE`, реле подписывает предложенный
  чекпоинт через свой `SignerGuard` (`signer-state.dat` в
  data-dir — один ключ = один голос/эпоху, устойчиво к краху,
  fail-closed) и gossip'ит его;
- **голосование при получении**: предложение, чьё содержимое
  валидно на НАШЕЙ цепочке (упомянутый блок присутствует, под тем
  же хешем) и несёт подпись члена комитета, получает и НАШУ
  подпись — без этого каждый якорь подписывал только содержимое
  своего собственного типа, и кворум никогда не собирался;
- полученные подписи (`Message::Checkpoint`) накапливаются по
  хешу `CheckpointData` (ограничено 256 записями); при
  `quorum_for(размер комитета)` подписях членов на ТЕХ ЖЕ
  данных → `accept_checkpoint` + широковещательная рассылка
  финализированного чекпоинта;
- **персистентность финальности**: окно чекпоинтов и замороженная
  база записываются в store при каждой финализации и
  перезагружаются при старте. Чекпоинты — состояние gossip
  (никогда не переносятся блоками) — перезапуск без этой
  персистентности начинался с пустой базы и больше никогда не
  смог бы сцепить окно, обслуженное пирами (якоря эпох ниже окна
  сети исчезли);
- **догонка финальности**: реле с пустой базой (старт нового
  узла) запрашивает `GetCheckpoints` у пира на каждом тике,
  пока база не восстановлена;
- реле без ключа якоря остаётся **пассивным**: оно накапливает,
  финализирует и ретранслирует, но никогда не подписывает;
- `GetCheckpoints` → отдаётся окно `checkpoint_window()`;
- любая ошибка цикла логируется и проглатывается — никогда
  не фатальна;
- статус (`GetStatus`) выставляет `checkpoints` и
  `finalized_epoch`.

### Парковка форков и реорги (фикс залипающего меньшинства)

Блок-сестра на той же высоте, или блок, чей родитель не текущий
тип (`ParentNotTip`/`UnknownParent`), НИКОГДА не теряется: он
**паркуется** (ограниченная карта, `PARKED_CAP = 2048` блоков,
~КиБ каждый — ограниченное худшее ОЗУ; полная парковка молча
игнорирует новичков). Хеши, уже предложенные `accept_block`,
дедуплицируются (`seen_blocks`): повторно gossip'нутый
проигравший блок не переоценивается.

На КАЖДОМ тике `Produce`, `reconsider_parked`:

1. линейный дренаж припаркованных блоков, чей родитель стал
   типом;
2. если припаркованная ветвь сильнее текущего типa (правила
   выбора форка НЕИЗМЕННЫ: порог финальности, самая длинная
   цепочка, наименьший хеш), усыновление — вытесненный суффикс
   сам паркуется (ОБЕ стороны форка остаются оцениваемыми).

Это расшатывает узел, усыновивший проигравшую сторону форка
равной высоты: блок-победитель, предложенный однажды затем
отказанный, периодически переоценивается вместо того, чтобы
быть забытым навсегда (находка chaos-30: два блока-сестры
в 15 мс друг от друга).

**Персистирование реорга**: усыновление другой ветви не может
пройти через монотонное добавление (`NonMonotonicHeight`). Реле
применяет `rewind_to_height(точка форка)`, затем
`persist_state_snapshot` (перезапись живого состояния из
экспорта цепочки), затем монотонное повторное добавление
победившего суффикса (см. `storage.md`). Сбой персистирования
логируется и деградирует (заживляет при загрузке через повтор)
— никогда не фатален.

## Синхронизация (догон)

При каждом соединении с пиром реле запрашивает
`GetBlocks(start = локальная_высота + 1)`. Каждый полученный
`Block`, точно завершающий ожидаемую высоту, вызывает запрос
следующей высоты, до исчерпания (`Pong` = больше ничего) или
`MAX_SYNC_ROUNDS` (10 000) партий — абсолютная граница даже
против лгущего пира. Полученные блоки проходят полную
валидацию: вредоносный пир не может протолкнуть что-либо
невалидное.

### DHT записей

- **put** (поток API/web — hex-канал CLI удалён): строгое
  ограниченное декодирование (`MAX_DHT_CACHE_ENTRY`), проверка
  против состояния в цепочке (владелец, последовательность,
  перевычисленный `record_hash` — см. «Проверка записей»),
  затем `kad.put_record` (локальное хранилище + репликация
  ближайшим пирам, `Quorum::Majority` фактора репликации)
  и персистентный кэш redb.
- **get** (`domain resolve`): `kad.get_record`; ожидатель
  привязан к своему `QueryId` и запрошенному `DomainId` — ответ
  разрешает только совпадающий запрос, и ключ записи должен
  быть ровно запрошенным доменом (проверяется **до** проверки
  против цепочки). Результат затем проверяется против цепочки
  перед возвратом. Потолок одновременных запросов:
  `MAX_DHT_WAITERS` (256); сверх — немедленная ошибка.
  Успешно проверенное разрешение пишется в персистентный кэш
  (M5): локальные чтения (`domain_info`) затем обслуживают его
  без нового DHT-запроса.
- Kademlia работает в серверном режиме, без TTL записей
  (валидностью управляет цепочка, а не время).

### Проверка записей (правило «цепочка — авторитет»)

Разрешённая или полученная `SignedDnsRecord` принимается/
возвращается, только если:

1. домен зарегистрирован в цепочке;
2. `record.owner` = текущий владелец в цепочке;
3. `record.sequence` = текущая последовательность в цепочке;
4. `record_hash(record.record)` (перевычисленный BLAKE3) =
   `record_hash`, закреплённый в цепочке.

Иначе: молчаливый отказ на стороне P2P, явная ошибка на
стороне CLI. Подпись Ed25519 записи **проверяется при получении**
реле (`ResolveLocal`: публичный ключ владельца известен
в цепочке, подпись должна подходить — запись, подписанная другим
ключом, отклоняется, `record rejected`); она также переносится
для будущих верификаторов — обязательательство в цепочке
остаётся первичным контролем целостности.

## Метрики Prometheus

HTTP-точка (текстовый формат Prometheus 0.0.4, самодельная
экспозиция — без новой зависимости), обслуживаемая выделенной
задачей:

- **Отключено по умолчанию**: HTTP-сервер не запускается без `--metrics-addr` (метрики опциональны).
- `--metrics-addr ADDR:PORT`: привязывает endpoint к этому адресу (напр. `127.0.0.1:9101` локально, `0.0.0.0:9101` для наружу).
- `--metrics-token TOKEN`: переключает в **приватный** режим —
  `Authorization: Bearer *** required (сравнение за
  константное время, иначе `401`; токен никогда не появляется
  в логах и экспозиции).
- Сбой привязки **отключает точку** (нефатальное
  предупреждение) — никогда не узел.

Действующая привязка объявляется в stdout (машиночитаемый
контракт, как `p2p:`): строка `metrics: <addr>`, как только
слушает.

**19 счётчиков** (`counter`, монотонные — горячие пути:
`fetch_add(Relaxed)` на общем `Arc<Metrics>`, никогда не вход
в консенсус):

| Группа | Серии |
|---|---|
| Цепочка | `scone_blocks_applied_total`, `scone_blocks_rejected_total`, `scone_checkpoints_signed_total`, `scone_checkpoint_sigs_received_total` |
| Мемпул | `scone_txs_admitted_total`, `scone_txs_rejected_total`, `scone_txs_evicted_grace_total`, `scone_txs_included_total` |
| DNS | `scone_dns_queries_total`, `scone_dns_cache_hits_total`, `scone_dns_cache_misses_total`, `scone_dns_local_chain_total`, `scone_dns_dht_answers_total`, `scone_dns_rejected_unverified_total` |
| DHT | `scone_dht_pulls_issued_total`, `scone_dht_negative_hits_total`, `scone_dht_negative_expired_total`, `scone_dht_negative_capped_total`, `scone_dht_cache_evictions_total` |
| Сеть пиров | `scone_peer_connections_established_total`, `scone_peer_connections_closed_total`, `scone_peer_connections_incoming_total`, `scone_peer_dial_failures_total`, `scone_peer_blocks_received_total`, `scone_peer_transactions_received_total` |

**6 гейджей** (`scone_height`, `scone_mempool`, `scone_peers`,
`scone_domains`, `scone_finalized_epoch`,
`scone_addr_book_entries`) — первые пять обновляются каждые
15 с через канал `RelayCommand` (тот же путь, что CLI `status`
— единый источник истины); `scone_addr_book_entries`
поддерживается реестром напрямую (обновляется при каждой
вставке в адресную книгу).

E2E-тест: `metrics_endpoint_public_and_private` (200 +
экспозиция, 401 без/с неверным токеном, 200 с Bearer).

## Управление из CLI (унификация RPC→p2p)

JSON TCP RPC-сервер **удалён**: CLI (и axum-мост регистратора)
говорят p2p-протокол **напрямую** — тот же wire
(`/scone/reqres/1`), те же обработчики на стороне реле, нуль
параллельных каналов. Каждая команда открывает QUIC-соединение
к multiaddr узла (`--peer`), обменивается ОДНИМ `Message`,
закрывает.

Управляющие сообщения, обслуживаемые реле:

- `GetStatus` → `NodeStatus { network, nat_reachable, tip,
  height, domain_count, mempool, peers, finalized_epoch,
  checkpoints, fresh_operators }` (отображается `scone status` —
  `fresh_operators` = операторы со свежим пульсом, RFC
  proof-of-service);
- `LookupName { name }` → `NameState` (состояние в цепочке, как
  `lookup`);
- `GetOwnedNames { owner }` → `OwnedNames` (живые домены + TLD
  `OwnerId`);
- `Transaction (tx)` → подача со свободным gossip (реле
  перетранслирует пирам);
- `GetRecord { domain_id }` / `Record (r)` — разрешение
  и публикация DHT (как `scone domain resolve` на стороне CLI);
- отказ применения → `Message::Error(msg)` (достигает клиента
  читаемым сообщением, а не EOF).

Клиент поднимает минимальный рой libp2p (request-response +
identify), таймаут вызова 30 с (раунд 20 с). По умолчанию
`--peer`: `/ip4/127.0.0.1/udp/4001/quic-v1/p2p/12D3KooW…`
(локальный dev-узел; полный multiaddr с настоящим peer id
объявляется реле в stdout через строку `p2p:`).

Внутренний канал `RelayCommand` выживает для встроенной
DNS-поверхности (`ResolveLocal`, один внутрипроцессный раунд,
никогда ожидатель DHT — см. `dns.md`).

## CLI

```
scone relay [--network testnet|mainnet|devnet] [--data-dir DIR] [--listen MULTIADDR]
            [--bootstrap MULTIADDR]... [--upnp]
            [--anchor-key PATH] [--no-anchor-auto] [--anchor-passphrase-env VAR] [--genesis FILE]
            [--topology-profile tiny|small|default|high|very-high|devtest]
            [--dns ADDR] [--dns-upstream ADDR]...
            [--metrics-addr ADDR:PORT] [--metrics-token TOKEN]
scone status [--peer MULTIADDR]
scone domains [--identity ID | --pubkey HEX] [--peer MULTIADDR]
scone domain register NAME [--identity ID] [--dir DIR] [--passphrase-env VAR] [--peer MULTIADDR]
scone domain set NAME TYPE VALUE [TTL] [--identity ID] [--peer MULTIADDR]   # express single record
scone domain update NAME --file FILE [--identity ID] [--peer MULTIADDR]
scone domain get NAME [--peer MULTIADDR]
scone domain renew NAME [--identity ID] [--peer MULTIADDR]
scone domain resolve NAME [--peer MULTIADDR]

# --peer defaults to the local relay (SCONE_PEER env overrides);
# --identity defaults to the single keystore identity when there
# is exactly one. Removed (stubs suggest replacements): show,
# submit, lookup, owned.
```

Каждая управляющая команда говорит QUIC напрямую с multiaddr
реле (`--peer`, по умолчанию локальный узел — унификация RPC→p2p,
больше никакого JSON TCP-канала). Реле отсутствует → ясное
сообщение «p2p node unreachable — is a relay running?», ненулевой
выход. Флаг `--rpc` сохранён, но **устарел и игнорируется**
(RPC-сервер удалён; только совместимость скриптов).

### Конфигурация окружения (`.env`)

При старте `scone` загружает (через dotenvy, до разбора clap)
файл `.env` из текущего каталога: отсутствие файла = молчаливая
пустая операция, никогда не ошибка. Загруженные значения
становятся **экологической базовой линией** опций, объявляющих
переменную (`env = "…"` в `cli.rs`); **явный флаг CLI всегда
побеждает** `.env`, а `.env` побеждает встроенные значения
по умолчанию:

```text
explicit CLI flag  >  .env variable  >  built-in default
```

Файл `.env.example` в корне репозитория документирует каждую
переменную (скопировать в `.env` и подстроить; `.env`
в **gitignore** — никогда не коммитить настоящий `.env`).
Переменные:

| Переменная | Зеркальный флаг | Семантика |
|---|---|---|
| `SCONE_NETWORK` | `--network` | `testnet` (по умолчанию), `mainnet`, `devnet` |
| `SCONE_DATA_DIR` | `--data-dir` | каталог данных (по умолчанию `~/.scone/<network>/`) |
| `SCONE_LISTEN` | `--listen` | multiaddr прослушивания P2P (по умолчанию: все интерфейсы, эфемерный порт) |
| `SCONE_BOOTSTRAP` | `--bootstrap` | seeds бутстрапа, **повторяемая** (одна строка на значение — dotenvy накапливает); заменяет встроенные seeds |
| `SCONE_GENESIS` | `--genesis` | файл генезиса (узлы-основатели) |
| `SCONE_MDNS` | `--mdns` | (устарела — обнаружение mDNS удалено; принимается, игнорируется) |
| `SCONE_UPNP` | `--upnp` | проброска портов UPnP (`true` = включено) |
| `SCONE_DNS_ADDR` | `--dns` | адрес привязки UDP DNS-сервера |
| `SCONE_DNS_UPSTREAM` | `--dns-upstream` | рекурсивные фолбэки, **повторяемая** |
| `SCONE_DNS_CACHE_LIMIT` | `--dns-cache-limit` | потолок записей DNS-кэша |
| `SCONE_DNS_CACHE_MAX_MEM` | `--dns-cache-max-mem` | потолок памяти DNS-кэша (например `64MB`) |
| `SCONE_DNS_MAX_INFLIGHT` | `--dns-max-inflight` | потолок одновременных DNS-запросов |
| `SCONE_METRICS_ADDR` | `--metrics-addr` | metrics endpoint address (`ADDR:PORT`)|
| `SCONE_METRICS_TOKEN` | `--metrics-token` | bearer-токен точки метрик |
| `SCONE_TOPOLOGY_PROFILE` | `--topology-profile` | профиль топологии (`tiny`/`small`/`default`/`high`/`very-high`/`devtest`; по умолчанию `default`) |
| `SCONE_ANCHOR_KEY` | `--anchor-key` | файл ключей якоря (чекпоинт + продакшен) |

`SCONE_ANCHOR_PASS` — НЕ переменная опции: это ИМЯ ПО УМОЛЧАНИЮ
**переменной, держащей парольную фразу якоря**
(`--anchor-passphrase-env`, по умолчанию `SCONE_ANCHOR_PASS`
на уровне CLI) — реле читает парольную фразу из переменной,
которую называет этот флаг.

**Авто-якорь (по умолчанию ВКЛ)**: без `--anchor-key` файл
ключей якоря генерируется/персистируется автоматически в
каталоге данных (`anchor.sconekey`, парольная фраза
`SCONE_ANCHOR_PASS`, если определена, иначе случайно
сгенерированная и записанная в `anchor.pass`) — реле становится
продюсером, как только его ключ владеет живыми доменами/TLD
(право PoS никогда не бесплатно). `--no-anchor-auto` держит
реле строго пассивным. Переменная окружения по умолчанию для
`--anchor-passphrase-env` — `SCONE_ANCHOR_PASS`.

`--network`: значение по умолчанию следует СБОРКЕ (mainnet на
бинарниках с поддержкой mainnet, иначе testnet); `devnet` —
сбрасываемая локальная сеть (собственный генезис `scone-devnet`,
почти нулевой PoW 0..=2 бита — стирание `~/.scone/devnet/`
и перезапуск сбрасывает цепочку). Задаёт генезис, сложности PoW
и data-dir по умолчанию (`~/.scone/<network>/`); tx из другой
сети отказывается типизированно (`WrongNetwork`).

Автономная hex-поверхность (подкоманды `tx` и `submit`)
исчезла (remove-tx-surface-v2). CLI покрывает пользовательские
пути (`domain register`, `domain renew`, `domains`) И семейство
M8b как полноценные команды: `tld open`, `tld transfer`, `tld
revoke`, `domain assign`, `domain transfer`. Заявки `register`
майнят свой PoW на сетевой сложности (миллисекунды на devnet).

**Никакой гео- или health-опции не существует**: геозона
**навязывается сборкой** (встроенная таблица DB-IP Lite — полная
семантика документирована в
[`dns.md`](dns.md#geodns-geographic-routing)); географическая
маршрутизация **всегда включена** без всякой опции, и резолвер
не выполняет никаких проверок здоровья — он обслуживает
подписанный набор записей как есть (доступность конечных точек —
забота их операторов). Любой флаг `--geo-*`/`--health-*` — жёсткий
отказ clap.

### `domain register|update` (M5) — подписанные транзакции одной командой

Эти команды сцепляют сборка → подпись (keystore) → подача →
(подтверждение) в одном вызове.

- **register**: собирает подписанный `RegisterDomain`
  (временная метка = now, пустое доказательство в devnet),
  подаёт, ждёт подтверждения в цепочке (последовательность
  ≥ 0, таймаут 30 с). Уже зарегистрированное имя отказывается
  на клиенте И на реле.
- **update**: файл записей — единственный источник истины.
  Последовательность (в цепочке + 1) и `record_hash`
  (канонический BLAKE3 записей файла) **выводятся**, никогда
  не вводятся: подписант и верификаторы не могут разойтись.
  После подтверждения UpdateDomain `SignedDnsRecord` (записи
  из файла + владелец + подпись Ed25519 по каноническому
  кодированию) публикуется в DHT через `put_record` (который
  перепроверяет против цепочки). Незарегистрированный домен,
  чужая идентичность или ошибка файла проваливаются чисто,
  не трогая цепочку.

#### Файл записей

Текст, одна запись на строку, `#` = комментарий, пустые строки
игнорируются; отсортированное каноническое кодирование делает
порядок файла не влияющим на закреплённый хеш. Файл — ПОЛНЫЙ
набор (update заменяет, а не сливает). Типы:

```text
A 192.0.2.1
AAAA 2001:db8::1
CNAME www.example.uip
NS ns1.example.uip
MX 10 mail.example.uip
TXT free text (spaces normalized)
```

Типизированные ошибки: неизвестный тип, некорректный IP/имя
(с номером строки), пустой набор, дубликат, >
`MAX_RECORDS_PER_SET`.

## `--genesis` (основатели)

`scone relay --genesis genesis.bin` — **только узлы-основатели**
(кампания kickstarter; файл производится бинарником
`scone-genesis`). Нормативные правила:

1. Файл отклоняется **до чтения**, если превышает 1 МиБ, затем
   строго декодируется (`decode_complete`: без хвостовых
   байт). Хеш блока 0 **перевычисляется**, никогда не читается
   из файла.
2. Семантическая валидация: высота 0, `consensus`, начинающийся
   с network id запрошенной сети (`--network`), без транзакций,
   канонический манифест распределений. Любое нарушение =
   типизированная ошибка при старте (никогда паника, демон не
   стартует).
3. **Девственный** data-dir: цепочка рождается на генезисе
   с распределениями — распределения применяются в ОЗУ **до
   любой записи на диск**, затем персистируются (посеянные
   состояния + генезисный блок под мета-ключом). Первый
   продюсированный блок, следовательно, может только расширять
   генезис с распределениями.
4. **Уже продуктивный** data-dir: родовой генезис хранилища —
   это `prev_hash` блока 1 (самосертифицирующийся). Равный хеш
   файла = молчаливый OK (опция **избыточна после первого
   старта}); иной = типизированный отказ — узел присоединяется
   к сети через синхронизацию, никогда через `--genesis`.
5. Перезапуск **без** опции: data-dir, рождённый основателем,
   восстанавливает свой генезис с распределениями через
   мета-ключ (ОЗУ-перепривязка при каждой загрузке).

Закрепление константного хеша генезиса (анти-расхождение сетей)
— отдельный поток работ.

### Манифест бинарника `scone-genesis` (kickstarter)

Бинарник `scone-genesis` (крейт `scone-genesis`) готовит
манифест `genesis-manifest.json` (формат `ALLOC-V1`), затем
производит `genesis.bin`. Нормативные правила:

- `scone-genesis new --network <network>` создаёт пустой
  манифест; `add`/`remove`/`list` управляют распределениями,
  `build` производит `genesis.bin` (+ хеш), `verify`
  перепроверяет его.
- `add domain <name>` требует, чтобы **TLD домена уже был
  распределён в манифесте** (немедленный отказ иначе — цепочка
  отказала бы при применении генезиса); его `valid_until`
  **автоматический**: `born_at + 1 год` (default_validity
  манифеста), никогда не вводится вручную.
- `add tld <name>`: **открытый по умолчанию** (ничей,
  самообслуживание, годовой порог, владелец = ноль на wire —
  вид `0x03`); `--private` = частный (владелец, генезисный срок
  `born_at + TLD_TERM_SECS` — 3 года, стандартный жизненный
  цикл: `RenewTld`, 60-дневный льготный период).
- Каноническая сортировка по имени (равное содержимое → тот же
  блок → тот же хеш, в каком бы порядке ни вставляли);
  дубликаты отказываются.

## Границы и гарантии памяти

| Ресурс | Граница |
|---|---|
| P2P-кадр | `MAX_MESSAGE_LEN` (1 МиБ) до разбора |
| Мемпул | 4096 tx (свыше — типизированный отказ); `MAX_PENDING_PER_DOMAIN = 4` ожидающих tx на домен |
| Льгота мемпула | `MAX_GRACE_ATTEMPTS = 10` повторных вставок tx, смытым по неред definitive-причине (≈ 7 мин при 40 с/цикл), затем вытеснение |
| Парковка форков | `PARKED_CAP = 2048` конкурирующих блоков |
| Накопленные чекпоинты | `MAX_PENDING_CHECKPOINTS = 256` (вытеснение: наименьший хеш данных) |
| Одновременные ожидатели DHT | `MAX_DHT_WAITERS` (256); поиск DHT ограничен 30 с (`DHT_LOOKUP_TIMEOUT`) |
| Блоков на ответ синхронизации | 1 на раунд; ≤ 10 000 партий на пира (`MAX_SYNC_ROUNDS`); протокольная граница `MAX_BLOCKS_PER_REQUEST = 128` на запросе |
| Запись DHT | `MAX_DHT_CACHE_ENTRY` (64 КиБ) |
| Персистентный кэш DHT (диск) | двойная граница LRU: `DHT_CACHE_MAX_ENTRIES` (100 000 записей) И `DHT_CACHE_MAX_BYTES` (2 ГиБ) — что раньше наступит, вытесняет по порядку ключей; GC-вытеснение в ТОЙ ЖЕ транзакции, что блок (домен, убитый GC цепочки, никогда не оставляет записи-сироты) |
| Отрицательный кэш DHT | `DHT_NEGATIVE_TTL_SECS` (30 с), FIFO-потолок `DHT_NEGATIVE_CAP` (4 096) |
| Цепочка в ОЗУ | генезис + окно типa (история отдаётся из хранилища) |

Анти-цикловое правило (H2): транзакция ретранслируется, только
если она **фактически вставлена** в мемпул (первый взгляд);
дубликат (уже в пуле или уже в цепочке) никогда повторно не
ретранслируется. Уже канонический блок обнаруживается
и игнорируется до `push_block` (без повторного сохранения, без
повторной рассылки).

Открытые решения: персистентная сетевая идентичность реле,
широковещательный gossip (сейчас: уникастный request-response
каждому известному пиру). Решено с первоначальной записи:
настоящий выбор форка (парковка + reconsider_parked, см. выше),
консенсус PoW (подписанный продюсер + комитет якорей),
DNS-резолвер (поверхность `--dns`, см. dns.md), управляющий
канал (унификация RPC→p2p: больше никакого JSON TCP).

## Грациозное завершение (SIGTERM / SIGINT)

Демон `scone relay` (на переднем плане) ловит SIGTERM и SIGINT
через `tokio::signal`: по сигналу футура `Relay::run`
отменяется (`tokio::select!` в бинарнике), что дропает рой
libp2p и закрывает QUIC-сокеты. Затем рантайм tokio
останавливается с ограниченным завершением (≤ 2 с), которое
дропает отсоединённые DNS-задачи (UDP/TCP) и закрывает их сокеты
— цель в том, чтобы `kill` не оставлял осиротевшего UDP-сокета
(случай, наблюдавшийся на testnet 60). Завершение по сигналу
логирует `relay shutting down (signal)` (INFO, stderr) и выходит
с кодом **0**: запрошенное завершение — не сбой. Если установка
обработчиков провалилась, применяется поведение сигнала по
умолчанию (деградация, никогда паника).


## Транспорт Tor (открытый вопрос)

QUIC/UDP не проходит через чистые SOCKS-прокси, поэтому реле
не могут тривиально работать поверх Tor сегодня. Нативный
Tor-транспорт libp2p (реле с onion-адресами) — отслеживаемый
путь вперёд — см. руководство по сопротивлению цензуре на сайте
о текущем состоянии и мост `.tor` CNAME (читаемые имена
для скрытых сервисов, поддерживается уже сегодня).
