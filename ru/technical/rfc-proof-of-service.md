# RFC — Доказательство работы и комитет финальности (proof-of-service)

> Статус: НОРМАТИВНО — реализовано от начала до конца (шаги с 1 по
> 5: core/protocol/blockchain/network/CLI; этот документ —
> консолидированная форма). Каждое правило ниже проверено против
> кода; цитируемые константы — закодированные значения.
> Дата: октябрь 2026 (нормативная консолидация). Затрагивает:
> `scone-core`, `scone-protocol`, `scone-blockchain`,
> `scone-network`, `scone` (CLI).

## 1. Мотивация

Пул финальности — это пул владельцев (владельцы живых
доменов/TLD). Владение даёт место — **работа** не даёт ничего.
Этот RFC привязывает право подписывать чекпоинты к доказательству
работы онлайн-реле, никогда не обусловливая владение:

- **Сохранённая свобода**: частный TLD остаётся назначаемым без
  условия активности, пока продлевается его срок (`RenewTld`,
  3-летний срок). Только *подписывание чекпоинтов* зарабатывается
  присутствием.
- **Стимул работать**: работа частного TLD (или любого места) =
  место в комитете. Оператор участвует в поддержании сети,
  и протокол это признаёт.
- **Измеримая децентрализация**: комитет становится множеством
  операторов, *фактически онлайн*, а не спящих ключей.

## 2. Обзор

Лёгкая транзакция `Heartbeat` (дискриминант `0x71`), подписанная
ключом **оператора**, выпускается один раз за эпоху. Состояние
держит скользящее окно недавних пульсов. Комитет эпохи
избирается **из подмножества пула, чей эффективный оператор
имеет свежий пульс**. Без пульса: нет подписывания, но нет и
потери прав владения.

## 3. Транзакция Heartbeat

```
Heartbeat {
    operator: PublicKey,     // Ed25519 key of the operator (the signer)
    owner: OwnerId,          // identity RE-DERIVED from operator (never trusted)
    tip_seen: [u8; 32],      // last tip seen by the node
    height_seen: u64,        // corresponding height
    timestamp: u64,          // Unix seconds
} + Ed25519 signature over the canonical payload (network injected)
```

Подписанное тело (wire, `scone-protocol`):
`operator[32] ‖ owner[32] ‖ tip_seen[32] ‖ height_seen.v ‖
timestamp.v ‖ operator[32]` (ключ подписанта стоит в хвосте
тела, как у каждой tx) `‖ signature[64]`, то есть ~230 байт
в кодировке — **без PoW**: цена — непрерывное присутствие (один
пульс за эпоху, месяцами).

Подписант и есть оператор: `owner` всегда перевыводится из
`operator` (никогда не берётся из ввода), а декодирование
отклоняет с типизированной ошибкой (`InvalidOwner`) ключ
подписи, отличный от головного поля `operator`.

- `tip_seen`/`height_seen` служат наблюдаемости (обнаружение
  ошибочных или отстающих операторов); они НЕ влияют на
  валидность (слегка отстающий узел — всё ещё живой узел).

### 3.1 Чистая валидация (scone-core)

1. Валидная подпись Ed25519 по канонической полезной нагрузке
   сети.
2. `owner` == идентичность, выведенная из `operator`
   (иначе `InvalidOwner`) — проверяется при кодировании, при
   декодировании И в `validate()`.

### 3.2 Правила состояния (применение, scone-blockchain)

При применении пульса в несущем блоке высоты `block_height`
(каждый отказ предшествует любой мутации):

1. **Анти-replay между эпохами**: `timestamp` строго
   возрастает на оператора — типизированный отказ
   `StaleHeartbeat`, если `timestamp <= operator_last_hb[operator]`.
2. **Уникальность на эпоху**: принимается только один пульс на
   (`operator`, эпоху несущего блока) — дубликат отклоняется
   с типизированной ошибкой (`HeartbeatDuplicate`). Эпоха — это
   `block_height / epoch_min_blocks` (то же определение, что
   у финальности, никогда новая константа).
3. Журналируемая вставка в окно + обновление
   `operator_last_hb` (обратимо при реорганизации,
   побитово-точный откат).

### 3.3 Антиспам

- 1 принятая tx на оператора за эпоху — максимальный поток
  `pool_size / epoch_secs`, пренебрежим.
- Без сборов (до-экономика): скорость структурно ограничена.

## 4. Делегирование работы

Связь место → оператор идёт через две выделенные транзакции:

- `SetTldOperator { tld_id, operator }` (дискриминант `0xA9`),
  подписанная **текущим** владельцем **частного** TLD (у
  открытого TLD нет того, кто мог бы законно подписать —
  типизированный отказ `TldIsOpen`). `operator: None` =
  отзыв, возврат к самоуправлению ключом владельца; отзывается
  мгновенно.
- `SetDomainOperator { domain_id, operator }` (дискриминант
  `0x5E`), подписанная текущим владельцем домена. Та же
  семантика.
- `RegisterTld` / `RegisterDomain` / `AssignDomain` НЕ несут
  поля `operator`: связь место → оператор — всегда недавний
  факт в цепочке, разрешаемый на типе.

Опция оператора в wire канонична: `0x00` = `None`
(самоуправление), `0x01` = «сырой» 32-байтовый ключ; любое
другое значение отклоняется при декодировании.

Состояние поддерживает:

```
seat_operators: HashMap<OwnerId, OperatorKey>   // per seat
operator_seats: HashMap<OperatorKey, u64>       // bounded counter
operator_last_hb: HashMap<OperatorKey, u64>     // last accepted ts
```

Правила применения (`apply_seat_operator`, журналируется):

- **Идемпотентность**: повторное делегирование тому же
  оператору (или отзыв несуществующего делегирования) —
  нежурналируемая пустая операция (побитово-точный откат этого
  требует).
- **Граница анти-аренды**: оператор может быть делегирован
  **ровно одним местом** одновременно
  (`MAX_SEATS_PER_OPERATOR = 1`). Второе место, делегирующее
  уже занятому оператору → типизированный отказ
  `OperatorAlreadyDelegated`. Обоснование: без границы крупный
  оператор продаёт подписи оптом и воссоздает централизацию —
  ровно то, чего избранный комитет призван избежать.

## 5. Окно свежести

### 5.1 Скользящее окно

```
recent_heartbeats: BTreeMap<(epoch, OperatorKey), ()>
```

- Запись вставляется при применении валидного пульса (§3.2).
- Детерминированная чистка при применении КАЖДОГО блока
  (`gc_heartbeats_journaled`): любая запись эпохи `e`, для
  которой `e + HEARTBEAT_WINDOW_EPOCHS <= epoch`, удаляется
  (журналируется — обратимо при реорганизации, как и очереди
  истечения).
- `HEARTBEAT_WINDOW_EPOCHS = 2`: текущая эпоха + предыдущая —
  оператор может пропустить ОДНУ эпоху без потери свежести,
  вторая его истекает.
- **Структурный потолок памяти**: окно держит не более
  `HEARTBEAT_WINDOW_EPOCHS × operator_count` записей (по одной
  на оператора за эпоху, ключ-кортеж); `operator_last_hb`
  ограничен числом операторов и никогда не чистится (правило
  анти-replay монотонно).

### 5.2 Свежесть

«Свежий» = наличие записи `(e, operator)` для `e` из
`[epoch − HEARTBEAT_WINDOW_EPOCHS + 1, epoch]`. Поскольку
состояние чистит на каждом блоке, присутствие
в `recent_heartbeats` ЕСТЬ свежесть (`operator_is_fresh`).

### 5.3 Эффективный оператор

**Эффективный оператор** места — это `seat_operators[seat]`,
если живое делегирование существует, иначе ключ владельца
(`effective_operator`). Место подписывает под этим
эффективным ключом — делегирование переносит право подписи,
но никогда владение.

## 6. Избрание комитета

```
eligible = { effective operators of the frozen pool's seats
             (banned key excluded) having a fresh heartbeat }

if |eligible| >= MIN_FINALITY_COMMITTEE_SIZE (= 4) :
    committee = select_committee(seed, eligible)   // existing draw
else :
    committee = select_committee(seed, pool)       // safe degradation
```

Нормативные детали (проверено в `finality.rs`, специфицировано
в `/docs/en/technical/blockchain.md` § «Места и комитет
финальности»):

- `pool` — это пул, **замороженный на последнем финализированном
  чекпоинте** (`FinalizedBase.pool` — никогда живое состояние):
  локальные представления разошлись бы между узлами, и кворум
  никогда бы не сформировался;
- `seed` выводится из хеша содержимого предыдущего чекпоинта
  (`signing_hash`);
- каждое место замороженного пула разрешается в его
  ЭФФЕКТИВНОГО оператора состоянием на типе (делегирование и
  пульсы — недавние факты в цепочке: два узла на одном типе
  вычисляют одно и то же множество); забаненные ключи остаются
  исключёнными;
- жеребьёвка идёт по отсортированному/дедуплицированному
  множеству эффективных ключей (`select_committee` без
  изменений).

**Явная и безопасная деградация**: бутстрапящаяся сеть (без
пульсов) или общий отказ операторов откатывается ко всему пулу —
финальность никогда не теряется по построению. Это правило
проекта «никогда не тупик», применённое здесь.

### 6.1 Холодный бутстрап

Эпоха 0 (и пока свежих операторов меньше
`MIN_FINALITY_COMMITTEE_SIZE`): весь пул. Ограничение естественным
образом ужесточается по мере того, как операторы выпускают
пульсы. Никакого особого переходного периода настраивать не
нужно.

## 7. Автоматический выпуск (scone-network)

На каждом цикле продакшена (`Wake::Produce` — без нового
таймера) реле проверяет, была ли пересечена ГРАНИЦА ЭПОХИ
(`height / epoch_min_blocks`, то же определение, что у
финальности). В первом цикле новой эпохи оно выпускает пульс,
если:

1. ключ якоря взведён (`--anchor-key` или автоматически), И
2. сам этот ключ держит живое место (ЛОКАЛЬНАЯ проверка: ключ
   в пуле права цепочки — владельцы живых доменов/TLD,
   забаненные ключи исключены).

Локальный антиспам: максимум ОДИН выпуск за эпоху на узел
(памятка `last_emitted_epoch`, локальная память, никогда
состояние цепочки); памятка берётся только после успешной
инъекции в мемпул — при сбое повтор на следующем цикле. Ничего
здесь не фатально: в худшем случае пульс ждёт следующего
цикла.

**Делегированный оператор** (который сам не владелец) не
покрыт автоматическим выпуском: он выпускает через
CLI-конструктор §8 (ручная или air-gapped работа). Пульс НЕ
обязательно продюсируется в блок самим отправителем: это tx
как любая другая (мемпул, продакшен кем угодно).

## 8. CLI (`scone`)

Автономный конструктор пульсов (удалён вместе с поверхностью
`tx`) был удалён вместе с автономной tx-поверхностью
(cli-simplify-v1). Реле выпускают свой пульс автоматически (§7);
ручной/air-gapped выпуск, если он снова понадобится, вернётся
как отдельная команда. Значения по умолчанию были:
`tip_seen` = 32 нулевых байта (только наблюдаемость),
`height_seen` = 0, `timestamp` = now.
- Как и для каждой tx, `tx sign` **перепривязывает** оператора
  и владельца к РЕАЛЬНОМУ ключу подписи (входные значения
  никогда не доверяются); `tx verify` валидирует локально.

## 9. Наблюдаемость

- `NodeStatus` (wire p2p-сообщение `0x0d`) несёт
  `fresh_operators: u32` (варинт): число операторов со свежим
  пульсом — живое подмножество пула, имеющее право на комитет
  (эффективные операторы мест пула, забаненные ключи
  исключены, отсортировано/дедуплицировано). Заполняется реле
  из `state().fresh_operators(height)`; отображается
  `scone status` как `fresh operators: N`.
- Аргумент кампании: «работа частного TLD = место в комитете
  финальности децентрализованного DNS» — проверяемо в цепочке.
- Будущая поверхность (не специфицирована): `operator_status` —
  на каждое место делегированный оператор, свежесть (свежий /
  истёк / никогда не видел), последний `tip_seen`. Локальный
  управляющий RPC удалён (узел только p2p); поверхность ещё
  предстоит определить.

## 10. Чего этот RFC НЕ делает

- **Никакой потери владения** за неактивность (вариант A —
  распад не-управляемого TLD — явно отвергнут).
- **Никакого вознаграждения** (вариант C ждёт экономического
  слоя).
- Пульс не доказывает *качество* обслуживания (созданные
  блоки, отданные DHT-записи) — только присутствие. Подсчёт
  реального вклада — возможное будущее расширение, более
  поддающееся игровым манипуляциям.

## 11. Защищённые инварианты

- Побитово-точный детерминизм: окно и избрание — чистые
  функции применённого состояния (журналируется,
  побитово-точный откат).
- Никогда не паниковать на сетевых данных: некорректный пульс
  или делегирование → типизированные отказы (`InvalidOwner`,
  `StaleHeartbeat`, `HeartbeatDuplicate`,
  `OperatorAlreadyDelegated`, `TldIsOpen`, `NotTldOwner`,
  `NotOwner`).
- Владение безусловно; обусловлено только подписывание
  чекпоинтов.
