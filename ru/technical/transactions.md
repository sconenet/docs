# Подписанные транзакции (формат v1)

**Нормативный** референс-документ формата подписанных транзакций.
Он определяет поля, точный порядок в wire, размеры, подписываемую
полезную нагрузку и правила валидации, чтобы обеспечить независимую
реализацию без чтения Rust. Референсная реализация —
[`scone-protocol`](https://github.com/sconenet/scone/tree/main/crates/scone-protocol)
(кодирование) и
[`scone-blockchain`](https://github.com/sconenet/scone/tree/main/crates/scone-blockchain)
(валидация).

`PROTOCOL_VERSION` = **1**. Существует только один набор форматов:
любой байт версии, отличный от `0x01` (в транзакции) или
отличный от локальной версии (в блоке), отклоняется с
`UnsupportedVersion`.

## Обзор

```text
Transaction = disc u8 || version u8 || payload
```

| Поле | Размер | Роль |
|---|---|---|
| `disc` | 1 Б | тип транзакции (таблица ниже) |
| `version` | 1 Б | **ровно `0x01`** (версия формата tx) |

**Транзакции больше не несут поля `network` в wire** (изменение
2026-09): `network_id` (`str` ≤ 16, ASCII `[a-z0-9-]` — например,
`scone-testnet`, 13 байт) живёт **только в подписываемой полезной
нагрузке** — она вводится туда первым полем подписантом (см.
[Подписываемая полезная нагрузка](#подписываемая-полезная-нагрузка))
— и остаётся по-сетевой в дайджесте PoW. Транзакция,
**подписанная** для одной сети, следовательно, никогда не
верифицируется в другой: подпись падает (`InvalidSignature`)
против полезной нагрузки, перевычисленной цепочкой, которая
вводит собственную сеть (см. `/docs/en/technical/blockchain.md`
— сети и генезис).

### Дискриминанты (нормативная таблица)

Каждый дискриминант — **фиксированная, произвольная непрозрачная
константа**: значения сознательно выбраны различными, чтобы wire
**никогда** не наводил на логический порядок между типами (без
последовательности 0x01/0x02/0x03…). `0x00` **никогда** не
является валидным типом (типичный байт порчи). Будущие типы
возьмут любое свободное значение, задокументированное раз и
навсегда в этой таблице.

| Дискриминант | Тип | Роль |
|---|---|---|
| `0x21` | `RegisterDomain` | заявка на домен |
| `0x52` | `UpdateDomain` | новая версия DNS-данных домена |
| `0x93` | `RegisterTld` | заявка на домен верхнего уровня (M7) |
| `0x47` | `TransferTld` | передача TLD новому владельцу (M8a) |
| `0x6B` | `RevokeTld` | отказ от TLD (M8a) |
| `0xB8` | `SetTldOpen` | **необратимое** открытие TLD для саморегистрации (одностороннее, опция владельца; `open=false` — типизированный отказ) |
| `0xD4` | `AssignDomain` | прямое назначение домена владельцем TLD (M8a) |
| `0x3C` | `RenewDomain` | продление регистрации домена (M8a; несёт каноническое имя со времён опции владельца — открытый TLD следует за истечением) |
| `0x8F` | `RenewTld` | продление 3-летнего срока ЧАСТНОГО TLD (PoW, равное созданию) |
| `0x15` | `SlashTx` | доказательство эквивокации якоря + бан (M9) |
| `0xE2` | `TransferDomain` | передача домена новому владельцу (M8c) |
| `0x71` | `Heartbeat` | доказательство живости оператора (RFC proof-of-service) |
| `0xA9` | `SetTldOperator` | делегирование работы частного TLD (RFC proof-of-service) |
| `0x5E` | `SetDomainOperator` | делегирование работы домена (RFC proof-of-service) |

Любой байт версии, отличный от `0x01`, явно отклоняется
(`UnsupportedVersion(полученное значение)`): неизвестный или
устаревший формат никогда не разбирается случайно.

## SLASH_TX (0x15, M9)

Доказательство в цепочке того, что якорь подписал два
**конфликтующих чекпоинта в одной эпохе** (эквивокация). Любой
может его отправить — доказательство криптографично и
самодостаточно:

```text
offender[32] | evidence_a (CheckpointData 116 B)
  | sig_a[64] | evidence_b (CheckpointData) | sig_b[64]
  | reporter_pk[32] | reporter_signature[64]
```

- `validate()` проверяет структуру: одна эпоха, различные
  `signing_hash`, две различные подписи, подписи репортёра по
  канонической полезной нагрузке;
- правила состояния (журналируемые, обратимые при реорганизации):
  ОБЕ подписи обвиняемого должны верифицироваться против ДВУХ
  различных подписывающих хешей в одной эпохе; обвиняемый должен
  быть в пуле права (иначе `SlashOffenderNotInPool`); затем
  **бан** — ключ удаляется из пула PoS устойчиво (чёрный список
  в состоянии);
- минимальная санкция: домены/TLD обвиняемого НЕ конфискуются
  (задокументированное решение M9);
- один и тот же чекпоинт дважды = не эквивокация (отклоняется);
  разные эпохи = отклоняется; поддельная подпись = отклоняется.

## REGISTER_DOMAIN (0x21)

```text
name(str ≤ 253) domain_id[32] owner[32] timestamp.v proof(bytes ≤ 256) public_key[32] signature[64]
```

| Поле | Тип | Ограничения |
|---|---|---|
| `name` | `str` ≤ 253 | каноническое имя заявляемого домена, **несётся открытым текстом** (см. ниже) |
| `domain_id` | 32 «сырых» байта | **должно** равняться `DomainId(name)` (перевычисляется, никогда не доверяется) |
| `owner` | 32 «сырых» байта | **должно** быть выведением из `public_key` (см. ниже) |
| `timestamp` | варинт | информация упорядочивания (Unix, секунды) |
| `proof` | `bytes` ≤ 256 | полезная нагрузка PoW регистрации (см. [ниже](#доказательство-работы-регистрации-pow)) |
| `public_key` | 32 «сырых» байта | публичный ключ Ed25519 подписанта (RFC 8032) |
| `signature` | **ровно 64 байта** | подпись Ed25519 подписываемой полезной нагрузки |

### Имя переносится транзакцией

`RegisterDomain` переносит каноническое имя открытым текстом,
за которым следует его `DomainId`. Согласованность
`domain_id == DomainId(name)` перепроверяется при кодировании,
декодировании и валидации (эшелонированная защита):
`RegisterDomain`, чей id не соответствует перенесённому имени,
невалиден. `DomainId` остаётся идентичностью консенсуса (ключи
цепочки и DHT); перенесённое имя делает цепочку
самоописательной и покрывает всю заявку в подписи.

## REGISTER_TLD (0x93)

Заявка на домен верхнего уровня (реестр TLD, M7):

```text
tld(str ≤ 63) tld_id[32] owner[32] timestamp.v proof(bytes ≤ 256) open(0x00|0x01) public_key[32] signature[64]
```

| Поле | Тип | Ограничения |
|---|---|---|
| `tld` | `str` ≤ 63 | каноническое имя TLD, **несётся открытым текстом** (M8b: задача PoW выводится из имени, как и `RegisterDomain` несёт своё) |
| `tld_id` | 32 «сырых» байта | идентичность TLD: `BLAKE3-256("SCONE-TLD-V1" || tld)` — **должен** быть выведением из `tld` (перевычисляется) |
| `owner` | 32 «сырых» байта | выведение из `public_key` |
| `timestamp` | варинт | информация упорядочивания (Unix, секунды) |
| `proof` | `bytes` ≤ 256 | полезная нагрузка PoW регистрации (см. [ниже](#доказательство-работы-регистрации-pow)) |
| `open` | `0x00\|0x01` | рождение **открытым**: TLD попадает прямо в `TldState::Open` (никому не принадлежит, самообслуживание + PoW, единственный PoW по ставке `open_tld_pow_difficulty` — дешевле частного: общий ресурс, без места PoS и эксклюзивности); рождение **частным**: историческое поведение (владелец, место PoS, `tld_pow_difficulty`) |
| `public_key` | 32 «сырых» байта | публичный ключ Ed25519 подписанта |
| `signature` | **ровно 64 байта** | подпись Ed25519 подписываемой полезной нагрузки |

Пространство `TldId` **не пересекается** с пространством
`DomainId` (различные префиксы выведения — см.
`/docs/en/general/naming.md`): регистрация TLD `uip` (заявка на
пространство имён `*.uip`) никогда не может захватить
идентичность домена, и наоборот. Правило состояния при
применении: TLD должен быть свободен (реестр, отдельный от
реестра доменов).

## Семейство M8a — форматы wire

Пять типов дополняют реестр TLD и жизненный цикл домена.
Нормативные форматы wire с M8a; **полные правила состояния
с M8b** (см. `/docs/en/technical/blockchain.md`): требуется
владелец TLD, PoW везде, где заявка самообслуживаемая,
истечения и льготные периоды на стороне домена. Ни одна полезная
нагрузка не несёт поля `network` в wire (он живёт только
в подписываемой полезной нагрузке).

### TRANSFER_TLD (0x47)

```text
tld_id[32] owner[32] new_owner[32] public_key[32] signature[64]
```

| Поле | Тип | Ограничения |
|---|---|---|
| `tld_id` | 32 «сырых» байта | передаваемый TLD |
| `owner` | 32 «сырых» байта | выведение из `public_key` (текущий владелец / подписант) |
| `new_owner` | 32 «сырых» байта | идентичность получателя (непрозрачна: любое значение синтаксически валидно; привязка к ключам, которые смогут им распоряжаться, — правило состояния M8b) |
| `public_key` | 32 «сырых» байта | публичный ключ Ed25519 подписанта |
| `signature` | **ровно 64 байта** | подпись Ed25519 подписываемой полезной нагрузки |

Без временной метки или последовательности: у TLD ровно один
владелец в каждый момент; побеждает первая применённая передача
(порядок цепочки сам по себе).

### REVOKE_TLD (0x6B)

```text
tld_id[32] owner[32] public_key[32] signature[64]
```

Добровольный отказ от TLD (впоследствии доступен для новой
заявки через свежий `RegisterTld`). Подписан текущим владельцем;
сознательно без временной метки или последовательности — отказ
одноразовый против текущего состояния.

### SET_TLD_OPEN (0xB8)

```text
tld_id[32] owner[32] open u8 open_proof(proof) public_key[32] signature[64]
```

| Поле | Тип | Ограничения |
|---|---|---|
| `open` | 1 байт | **строго `0x00` или `0x01`** (каноническая форма; любое другое значение → ошибка декодирования, никогда принуждение) |
| `open_proof` | `proof` (варинт-длина + байты) | **подписанное** поле; обязательно и проверяется при `open = 0x01` (открывающий PoW, сетевой `open_tld_pow_difficulty`, задача `SCONE-TLD-OPEN-V1 ‖ tld_id`); пусто при `open = 0x00` (закрытие бесплатно) |

**Закрытый** TLD = только назначение (домены создаются
исключительно владельцем TLD через `AssignDomain`); **открытый**
TLD = любой может сделать PoW регистрации и заявить свободный
домен (`RegisterDomain`). **Открытие** стоит дополнительного
доказательства работы (легче заявки TLD: ~3 дня на mainnet
против ~1 недели), оплаченного один раз владельцем в
`SetTldOpen` — доказательство едет в подписанном поле
`open_proof` и не может быть подменено после подписания.

### ASSIGN_DOMAIN (0xD4)

```text
name(str ≤ 253) domain_id[32] owner[32] assignee[32] public_key[32] signature[64]
```

Зеркало `RegisterDomain`: каноническое имя несётся открытым
текстом, и `domain_id` должен равняться `DomainId(name)`
(перевычисляется при декодировании, кодировании и валидации).
Подписано **владельцем TLD имени** (проверяется при применении,
M8b); `assignee` становится первым владельцем домена
(непрозрачен, как `new_owner`).

### RENEW_DOMAIN (0x3C)

```text
name(str ≤ 253) domain_id[32] owner[32] valid_until.v proof(bounded) public_key[32] signature[64]
```

| Поле | Тип | Ограничения |
|---|---|---|
| `name` | `str` ≤ 253 | каноническое имя, **несётся открытым текстом** (опция владельца: продление отодвигает смерть нижележащего открытого TLD, цепочка должна знать имя); `domain_id` должен равняться `DomainId(name)` (перевычисляется) |
| `valid_until` | варинт | новый срок регистрации (Unix, секунды) |
| `proof` | ограничено | **авторизация продления** (см. ниже) |

Подписано текущим владельцем домена; действительно ли
`valid_until` продлевает срок (и максимум на один срок
продления) — правило состояния (M8b).

#### Авторизация продления — PoW или PoS в зависимости от TLD

Стоимость продления зависит от природы нижележащего TLD
(вычисляется при применении, на состоянии блока):

- **Открытый TLD**: продление стоит **тот же PoW, что
  создание** — та же задача (`SCONE-DOMAIN-V1 ‖ каноническое
  имя`), та же сложность по длине метки и по сети, то же окно
  действия эпохи. Домен никогда не «собирается» бесплатно:
  каждый срок жизни оплачивается работой.
- **Частный TLD**: пространство имён — доля владельца TLD (PoS).
  Транзакция должна быть **подписана владельцем TLD** (или его
  делегированным оператором) — подпись и есть авторизация,
  поле `proof` должно быть пустым (20 нулевых байт). Владелец
  TLD продлевает домены своего пространства по собственным
  правилам.

### RENEW_TLD (0x8F)

```text
tld(str ≤ 63) tld_id[32] owner[32] valid_until.v proof(bounded) public_key[32] signature[64]
```

| Поле | Тип | Ограничения |
|---|---|---|
| `tld` | `str` ≤ 63 | каноническое имя TLD; `tld_id` должен равняться `TldId(tld)` (перевычисляется) |
| `valid_until` | варинт | должно быть РОВНО `now + 3 года` (фиксированный срок — перевыводится при применении, любое другое значение отклоняется) |
| `proof` | ограничено | PoW продления (см. ниже) |

Подписано текущим **частным** владельцем TLD. Правила применения:

- применяется только к ЧАСТНОМУ TLD (открытый TLD живёт через
  свои домены — типизированный отказ `TldIsOpen`);
- действителен в течение срока И через **60-дневный льготный
  период**, следующий за истечением; дальше TLD мёртв (GC),
  и отказ — `TldExpiredFrozen`;
- **PoW, равное созданию**: задача
  `SCONE-TLD-V1 ‖ имя ‖ текущее_истечение(BE64)` (суффикс
  анти-повтора привязывает каждый PoW к ОДНОМУ сроку), та же
  сложность по длине, что и первоначальная заявка;
- продление НЕ заморожено в течение льготного периода — это
  единственная операция управления, ещё доступная владельцу
  с истёкшим сроком.

## UPDATE_DOMAIN (0x52)

```text
domain_id[32] owner[32] sequence.v record_hash[32] public_key[32] signature[64]
```

| Поле | Тип | Ограничения |
|---|---|---|
| `domain_id` | 32 «сырых» байта | целевой домен |
| `owner` | 32 «сырых» байта | выведение из `public_key` |
| `sequence` | варинт | **> 0**, должно равняться `current + 1` при применении |
| `record_hash` | 32 «сырых» байта | обязательательство по набору записей DHT |
| `public_key` | 32 «сырых» байта | публичный ключ Ed25519 подписанта |
| `signature` | **ровно 64 байта** | подпись Ed25519 подписываемой полезной нагрузки |

Примечание: `UpdateDomain` несёт **без** `timestamp` —
упорядочивание идёт через `sequence`. Он также не несёт имя:
домен уже зарегистрирован, id достаточно.

### Строгие границы

- `public_key`: **ровно 32 «сырых» байта**, без префикса длины.
  pk, не декодируемый как точка кривой → ошибка
  `InvalidTransactionKey` при декодировании.
- `signature`: **ровно 64 «сырых» байта**, без префикса длины,
  без запаса. Любой другой размер — жёсткая ошибка
  декодирования (усечение отклоняется).
- `proof`: варинт-длина + байты, потолок 256
  (`MAX_PROOF_LEN`), проверяется до аллокации.
- `name`: варинт-длина + UTF-8-байты, потолок 253
  (`MAX_NAME_LEN`), ревалидируется правилами именования
  `scone-core`.

## Выведение владельца

Жёсткое правило: **владелец всегда перевычисляется, никогда
не доверяется**.

```text
PublicKeyRef = BLAKE3-256("SCONE-PUBKEY-V1" || public_key)
OwnerId      = BLAKE3-256("SCONE-OWNER-V1" || PublicKeyRef)
```

Транзакция, чей `owner` не соответствует выведению из
собственного `public_key`, невалидна (`InvalidOwner` на стороне
ядра, `OwnerKeyMismatch` на стороне цепочки), отклоняется при
кодировании, декодировании **и** валидации цепочкой
(эшелонированная защита).

## Подписываемая полезная нагрузка

Подписываемая полезная нагрузка — каноническое кодирование
транзакции **без поля подписи**, с префиксом-тегом разделения
доменов — **с `network_id` целевой цепочки, введённым в голове**:

```text
signing_payload(tx, network) = "SCONE-TX-SIG-V1"
                              || canonical_encode(tx_without_signature, network)
```

где `canonical_encode(tx_without_signature, network)` следует
структуре wire выше, включая дискриминант и байт версии,
останавливаясь перед `signature`, **с `network` первым полем** —
это ЕДИНСТВЕННОЕ место, где появляется сеть. Цепочка
перевычисляет полезную нагрузку со СВОЕЙ сетой: транзакция,
подписанная для другой сети, проваливает верификацию подписи
(`InvalidSignature`); это механизм анти-replay между цепочками.

```text
REGISTER_DOMAIN_no_sig = disc(0x21) version(0x01) network name domain_id[32] owner[32]
                            timestamp.v proof public_key[32]
REGISTER_TLD_no_sig    = disc(0x93) version(0x01) network tld tld_id[32] owner[32]
                            timestamp.v proof public_key[32]
UPDATE_DOMAIN_no_sig   = disc(0x52) version(0x01) network domain_id[32] owner[32]
                            sequence.v record_hash[32] public_key[32]
TRANSFER_TLD_no_sig    = disc(0x47) version(0x01) network tld_id[32] owner[32]
                            new_owner[32] public_key[32]
REVOKE_TLD_no_sig      = disc(0x6B) version(0x01) network tld_id[32] owner[32]
                            public_key[32]
SET_TLD_OPEN_no_sig    = disc(0xB8) version(0x01) network tld_id[32] owner[32]
                            open(0x00|0x01) open_proof(proof) public_key[32]
ASSIGN_DOMAIN_no_sig   = disc(0xD4) version(0x01) network name domain_id[32] owner[32]
                            assignee[32] public_key[32]
RENEW_DOMAIN_no_sig    = disc(0x3C) version(0x01) network name domain_id[32] owner[32]
                            valid_until.v proof public_key[32]
TRANSFER_DOMAIN_no_sig = disc(0xE2) version(0x01) network domain_id[32] owner[32]
                            new_owner[32] public_key[32]
```

Свойства:

- детерминированность и чистота: одна транзакция ⇒ одна
  полезная нагрузка везде;
- ASCII-префикс `SCONE-TX-SIG-V1` (15 байт,
  hex `53434f4e452d54582d5349472d5631`) предотвращает любое
  повторное использование подписи в другой хеш-области
  протокола;
- покрыты все поля, кроме `signature` — **включая имя,
  переносимое `RegisterDomain`**: изменение любого из них
  инвалидирует подпись;
- введённый `network_id` покрыт: одна и та же неподписанная tx,
  подписанная для двух сетей, производит две различные
  полезные нагрузки (а значит, две различные подписи).

## Доказательство работы регистрации (PoW)

Поле `proof` транзакций `RegisterDomain` и `RegisterTld` несёт
доказательство работы регистрации (модуль `scone-core::pow`).

### Дайджест (соль эпохи, анти-премайнинг)

```text
epoch  = block_height / POW_WINDOW        (POW_WINDOW = 144 blocks)
salt   = BLAKE3-256("SCONE-POW-V1-ARGON2" || network || challenge || epoch_le64)
digest = Argon2id(m, t, p = 1; password = nonce_le64, salt = salt[0..16])
```

`network` — канонический `network_id` (M8b): доказательство,
намайненное для одной сети, не является доказательством в
другой.

`SCONE-POW-V1-ARGON2` также закрепляет параметры Argon2id по
сетям (`pow_params`: mainnet m = 64 МиБ, t = 2, p = 1;
testnet/devnet m = 8 КиБ, t = 1, p = 1): ядро Argon2id
(RFC 9106) делает стоимость хеша доминируемой по памяти
(сопротивление GPU/ASIC), а доказательство, намайненное при
одном наборе параметров, никогда не верифицируется при другом.

`challenge` — вход выведения заявляемого объекта —
`"SCONE-TLD-V1" || tld` для TLD, `"SCONE-DOMAIN-V1" || имя` для
домена: ровно те байты, что хешируются для `TldId` /
`DomainId`, так что доказательство никогда не воспроизводимо
между пространствами имён и между видами объектов. `epoch_le64`
и `nonce_le64` — 8-байтовые little-endian кодирования эпохи и
nonce.

Доказательство валидно, когда `digest` имеет не менее
`difficulty` ведущих нулевых бит.

#### Соль эпохи — анти-премайнинг

Несолёный дайджест не привязывает ни время, ни высоту: любой
мог бы премайнить доказательства сегодня на тысячи имён, затем
зарегистрировать их залпом на запуске mainnet (сквоттинг) —
доказательство было самодостаточным и валидным на любом блоке,
пришедшем первым. Дайджест солится **эпохой блока, который
ПРИМЕНЯЕТ транзакцию**:

- `epoch = block_height / POW_WINDOW`, `POW_WINDOW = 144` блока
  (~2.6 ч при 65 с/блок): льготное окно для честного
  пользователя (майнить, затем отправить в окне), обязательный
  перемайн за его пределами;
- доказательство ЗАЯВЛЯЕТ свою эпоху в wire; при применении
  заявленная эпоха должна попадать в **окно действия**
  применяемого блока — только ОБРАТНАЯ толерантность (поздняя
  отправка поглощается, майнить «на будущее» невозможно), окно
  размечено `epoch_validity_window(difficulty)` =
  `1 << max(0, difficulty − 16)` эпох (расширенное окно:
  высокие сложности mainnet майнятся от дней до недель, дольше
  одной эпохи; накопление ничего не даёт, потому что окно ≈
  стоимости майнинга — каждое доказательство залпа стоит своих
  полных `2^difficulty` хешей ВНУТРИ окна). При сложности
  ≤ 16 бит (testnet, длинные имена) правило строгого равенства
  не меняется;
- допуск в мемпул (best effort): будущая высота блока
  неизвестна — реле проверяет против эпохи
  `текущая высота + 1`; строгая проверка времени применения
  остаётся авторитетом;
- детерминированный повтор: доказательство НЕСЁТ свою эпоху,
  а окно — чистая функция (сложность, эпоха блока) —
  исторический блок переверяется идентично на любом узле.

Ломающее изменение перед mainnet: старый компактный формат
(12 байт) отклоняется без обратной совместимости.

### Полезная нагрузка wire (20 фиксированных байт)

```text
nonce_le64 || epoch_le64 || difficulty_le32
```

Сложность и эпоха едут вместе с доказательством, но они
**заявлены продюсером и потому никогда не доверяются**:
верификатор сравнивает сложность с **константой протокола** для
вида регистрации (полезная нагрузка, чья заявленная сложность
отличается от константы — ниже *или* выше — отклоняется,
`InvalidProof`), а эпоху — с эпохой применяемого блока
(`ProofEpochMismatch` при несоответствии). Затем nonce
переверяется на константной сложности, дайджест перевычисляется
с нуля.

### Сложности (кривая **по длине**, M8b + измеренная калибровка)

Сложность — НЕ плоский параметр: это детерминированная функция
**длины создаваемой метки** (`scone-core::pow_length` — TLD для
`RegisterTld`, крайняя левая метка для `RegisterDomain`), по
сетям:

```text
difficulty(len) = apex − round(0.415 × (len − 1)), clamped at the floor
```

| Сеть | Частный TLD (apex/floor) | Рождённо-открытый TLD / домен (apex/floor) |
|---|---|---|
| testnet | 8 бит / 2 бита | 6 бит / 2 бита |
| mainnet | 42 бита / 30 бит | 40 бит / 30 бит |
| devnet | 2 бита / 1 бит | 1 бит / 1 бит |

**Рождённо-открытый** TLD (`RegisterTld` с `open = 0x01`) платит
по «открывающей» кривой (apex − 2, как `domain_difficulty`);
**открытие существующего частного TLD** (`SetTldOpen`) остаётся
на плоской сложности (`open_tld_pow_difficulty`: 6 бит testnet /
22 бита mainnet / 2 бита devnet — tx несёт только `tld_id`, имя
оплатило свою длину при создании). Бенчмарки mainnet (частный
TLD, ~6 М хешей/с): 1 символ = 42 бита (≥ 7 дней), 5 символов =
40 бит (~2 дня), 19 символов = 35 бит (~1.6 ч), 29+ символов =
30-битный минимум (~3 мин). Кривые живут в
`scone-core::pow_length` (константы `MAINNET_APEX = 42`,
`MAINNET_FLOOR = 30`, `TESTNET_APEX = 8`, `TESTNET_FLOOR = 2`,
`DEVNET_APEX = 2`, `DEVNET_FLOOR = 1`); плоские параметры
(`tld_pow_difficulty` и т. д.) остаются в
`scone-core::network::NetworkParams`. Изменение значения =
изменение консенсуса **для этой сети**. Инвариант: devnet —
полноценный третий `NetworkParams`, а testnet остаётся строго
идентичным своим константам до-devnet (параметры Argon2id,
кривые, окна) — devnet НЕ разделяет ни одной константы с другими
сетями, кроме самого кода.

Измеренная калибровка плоских вершин (2026-10, `cargo run
--release -p scone-core --example pow_bench` — однопоточная
пропускная способность ~7.7 М H/s на референсном x86-64):

| Вид (mainnet) | сложность | среднее реальное время |
|---|---|---|
| `RegisterTld` | 24 бита | ~7 с |
| `RegisterDomain` | 20 бит | ~54 мс |

При ~65 с/блок: заявка TLD стоит ~0.1 блока одноядерного CPU,
домен ~1 мс блока — символически для пользователя, дорого для
индустриализации в масштабе (анти-сквоттинг). Перекалибровать,
если аппаратные цели снизятся (мобильный ARM: ~4–8× медленнее).

Ветви состояния (M8b, поставлено): `RegisterTld` ВСЕГДА требует
свой PoW; `RegisterDomain` требует его на **открытом** TLD
(закрытый путь — только назначение — `AssignDomain`, без PoW,
подписано владельцем TLD).

## Правила валидации

Транзакция валидна тогда и только тогда, когда:

1. **строгое декодирование**: структура и границы выше соблюдены
   (известный дискриминант, версия `0x01`, pk 32 Б, подпись
   64 Б, инварианты ядра перепроверяются при декодировании);
2. **привязка владелец/pk**: `owner == OwnerId::from(public_key)`
   (перевычисляется);
3. **согласованность имя/id** (RegisterDomain):
   `domain_id == DomainId(name)` (перевычисляется);
4. **подпись**: Ed25519 `verify_strict` подписи `signature`
   против подписываемой полезной нагрузки, **перевычисленной
   с нуля** с сетью цепочки (никогда не взятой у пира или из
   транзакции как предоставленной) — tx, подписанная для другой
   сети, проваливается здесь (`InvalidSignature`, анти-replay
   между цепочками);
5. **правила состояния** (при применении в блоке — M8b, см.
   `/docs/en/technical/blockchain.md`):
   RegisterTld → TLD свободен + не ICANN + PoW (сложность по
   длине); RegisterDomain → TLD зарегистрирован **и открыт** +
   домен свободен (включая льготный период) + PoW (по длине);
   UpdateDomain → существующий домен, текущий `owner`,
   `sequence == current + 1`;
   TransferTld / RevokeTld / SetTldOpen / AssignDomain →
   существующий **и частный** TLD, подписант = владелец TLD;
   TransferDomain → существующий домен, владелец;
   RenewDomain → существующий домен, строгое продление ≤ 3 лет,
   авторизация PoW (открытый TLD: тот же PoW, что создание,
   **привязанный к текущему истечению** — задача, отличная от
   регистрации и каждого более раннего продления) или PoS
   (частный TLD: подпись владельца TLD — или его эффективного
   оператора — пустой `proof`).

Верификация использует `verify_strict` (отклонение
маллеабельных подписей и слабых/неканонических ключей), как
требуется для недоверенных данных.

## Порядок операций в `push_block`

Криптографическая валидация (2–4) выполняется для каждой
транзакции **до** применения состояния, на атомарном рабочем
состоянии на блок; любая ошибка оставляет цепочку строго
неизменной.

## Сборка блока

`BlockBuilder` (`scone-blockchain`) собирает блок из очереди
транзакций: `tx_root` перевычисляется по упорядоченному списку,
заголовок сцепляется с хешем родителя (`prev_hash`), `version` =
`PROTOCOL_VERSION`. Полезная нагрузка консенсуса (подписанная
полезная нагрузка продюсера) и временная метка предоставляются
вызывающим; существующий трейт `Consensus` используется
симметрично с валидацией.

## Где теперь живёт hex

Автономные команды `tx build|sign|verify` были удалены
(cli-simplify-v1). Сам формат подписанного hex не изменился
и остаётся форматом wire **потока web/API**: веб-приложение
регистратора собирает, подписывает (keystore в браузере) и
отправляет транзакции как канонический hex через API. На стороне
CLI пользовательские пути — одно-командные формы:

```bash
scone domain register example.uip        # mines, signs, submits
scone renew example.uip                  # renewal proof, signs, submits
scone domains                            # what you own
```

Во всех путях кода владелец и ключ **перевычисляются** из
подписывающей идентичности, никогда не берутся из какого-либо
ввода.
