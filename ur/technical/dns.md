# UDP + TCP DNS سرور (M6 + M7b) — `scone dns`

> Scone DNS سطح کی نافذہ تفصیل۔
> کوئی بھی دستاویز/کوڈ تضاد = نقص (سچائی کے ذریعے کا درست کریں)۔

## جائزہ

**DNS سرور** ریلے کی ایک اختیاری سطح ہے: یہ Scone ناموں کے لیے
**UDP اور TCP** DNS سوالات (RFC 7766، وہی پورٹ) کا جواب دیتا ہے
**صرف چین کے خلاف تصدیق شدہ ڈیٹا سے**، اور سب کچھ اور کے لیے ایک
**اختیاری ریکرسو فال بیک** (`addr:port`) فراہم کرتا ہے۔
یہ نہ چین کا مالک ہے، نہ اسٹور، نہ DHT: وجود/میعاد
فیصلے **مستند DNS اسنیپ شاٹ** (ہر لاگو شدہ بلاک کے بعد شائع شدہ
ایک RAM منظر — نیچے دیکھیں) سے ہوتے ہیں، اور ریکارڈ
بازیافت ریلے (پروسیس) سے، اندرونی
`RelayCommand`/`ResolveLocal` چینل کے ذریعے (ان-پروسیس، ایک
راؤنڈ ٹرپ) — وہی تصدیق شدہ پاتھ جیسے CLI۔

```text
              UDP+TCP :5353 (default 127.0.0.1)
                    │
             scone relay --dns 127.0.0.1:5353
                    │  ┌────────────────────────────────┐
                    ├──┤ Sharded cache, 16 ways (qname)  │
                    │  └────────────────────────────────┘
                    │  Scone-shaped name?
                    │  ├─ YES → authoritative DNS snapshot:
                    │  │        unknown/expired → NXDOMAIN (RAM,
                    │  │        zero round trips into the core)
                    │  │        → apex search by suffix
                    │  │        → internal `resolve_local` (relay)
                    │  │           chain + verified record (hash,
                    │  │           owner, sequence) → answers
                    │  │        apex without a published record → NODATA
                    │  └─ NO → upstream fallback (if configured)
                    │           otherwise REFUSED
                    │
                    │  response budget:
                    │    UDP → 512 bytes (no EDNS); overflow =
                    │          cut at the last fitting record + TC=1 →
                    │          the client retries over TCP
                    │    TCP → 64 KiB (2-byte length prefix,
                    │          RFC 1035 §4.2.2): full set
```

## اسٹارٹ اپ

```bash
scone relay --dns 127.0.0.1:5353            # DNS surface only
scone relay --dns 0.0.0.0:53 \
            --dns-upstream 1.1.1.1:53 \
            --dns-upstream 8.8.8.8:53       # + recursive fallback
```

ریلے مؤثر پتہ stdout پر اعلان کرتا ہے
(مشین پڑھنے کے قابل معاہدہ، `p2p:` کی طرح): ساکٹ بندھتے ہی ایک
`dns: <addr>` لائن۔

تصدیق کلائنٹ: `dig <name> --dns 127.0.0.1:5353
--qtype A` (A, AAAA, TXT, MX, NS, CNAME, ANY)۔

## ریزولوشن پاتھ (اختیار = چین، ہمیشہ)

0. **مستند DNS اسنیپ شاٹ**: ایک غیر متغیر منظر
   (`Arc<HashMap<DomainId, {valid_until, has_record}>>`،
   `tokio::sync::watch` فیڈ) جو ریلے کور **ہر لاگو شدہ بلاک کے
   بعد** (push، poll نہیں) اور بوٹ پر شائع کرتا ہے۔
   وجود/میعاد فیصلے — NXDOMAIN، ختم شدہ ڈومین — RAM سے اس
   اسنیپ شاٹ کے ذریعے دیے جاتے ہیں: ایک `Arc` کلون + ایک
   میپ تلاش، **ریلے کے اکلوتے مالک رن لوپ میں کبھی داخل نہیں
   ہوتے**۔ مکمل پاتھ
   (`RelayCommand`/`ResolveLocal`) اصل ریکارڈ بازیافت (DHT
   پُلز) کے لیے ریکزا ہے، کیش کی بدولت نایاب۔
   اسنیپ شاٹ کبھی ریکارڈ ڈیٹا نہیں رکھتی: صرف وجود اور میعاد۔
   - **O(چھوئے گئے) copy-on-write ڈیلٹاز**: میپ ایک
     `Arc<HashMap>` ہے؛ ٹِپ توسیع بلاک کا ڈیلٹا شائع کرتی ہے
     (بلاک کی اپنی ٹرانزیکشنز ہر اُس ڈومین کا نام لیتی ہیں جو وہ
     بدل سکتی ہیں — Register/Assign/Update/Renew/TransferDomain —
     مزید push وقت پر جانچی گئی متعین میعاد-GC ہٹاوں
     سمیت) `Arc::make_mut` کے ذریعے: میپ صرف اُس وقت کلون ہوتی
     ہے جب کوئی پڑھنے والا پچھلا منظر اب بھی تھامے ہو۔ بوٹ اور
     ری آرگ پورا اسنیپ شاٹ دوبارہ بناتے ہیں (ایک صفحہ وار بیک
     اینڈ واک)۔
   - تازگی: پڑھنے والا بلاک اطلاق کے دوران کچھ سو ms پرانا
     اسنیپ شاٹ دیکھ سکتا ہے — وہی فرسودگی جو status RPC کی
     ہوتی؛ DNS کیش TTLs غیر متاثر (جوابات اپنے ماخذ کے مطابق
     مستند رہتے ہیں)۔
1. **شارڈڈ کیش**: [`ShardedCache`] — 16 آزاد `Cache`
   شارڈز `hash(qname)` سے کلید شدہ (qtype شارڈ شیئر کرتا ہے:
   فی نام قربت)۔ گرم نام ٹریفک کے 1/16 سے مقابل کرتا ہے بجائے
   ہزاروں qps پر اکیلے mutex کے پیچھے قطار میں لگنے کے۔ عالمی
   حدود (ڈیفالٹ 100,000 اندراجات / 64 MiB،
   `--dns-cache-limit` / `--dns-cache-max-mem`) فی شارڈ تقسیم
   (دستاویز شدہ بدترین معاملہ: 1 + N/shards فیکٹر)۔ ہر اندراج کا
   اصل rdata سائز شمار ہے (فی اندراج ~128 بائٹس اوور ہیڈ) اور
   FIFO بے دخلی دو حدود میں سے پہلی پر چلتی ہے — میموری کیپ
   مکمل سائز اندراجات (`MAX_DHT_RECORD_LEN`) کے خلاف بھی قائم
   رہتی ہے۔ TTL 60 s
   (مستند) / 600 s پر clamp (فال بیک)۔ منفی
   کیش (NXDOMAIN/NODATA) وہی قواعد مانتا ہے؛ ہر اندراج
   اپنا ماخذ (مستند یا فال بیک) رکھتا ہے تاکہ AA بٹ ہٹ پر
   ایماندار رہے۔ **SERVFAIL کبھی کیش نہ کریں** (عارضی
   مقامی ناکامی) **نہ REFUSED** (کنفیگریشن اسٹیٹ): دونوں ہر
   سوال پر دوبارہ حساب ہوتے ہیں۔ گنجائش پر FIFO بے دخلی۔
   **ہاٹ پاتھ (Cloudflare/1.1.1.1 سے متاثر)**:
   - مشترکہ `Arc<CacheEntry>` اندراجات: ہٹ ایک refcount bump ہے،
     کبھی rdata کی گہری کلون نہیں (`put` Arc کو **بدل دیتا** ہے —
     کوئی مشترکہ تبدیلی نہیں؛ TTL اب بھی شارڈ
     لاک کے تحت چیک)؛
   - **بغیر مختص تلاش**: دو سطحی میپ
     (`Box<str>` qname → qtype → entry)، سوال کا قرض لیا گیا
     `&str` براہِ راست جانچتا ہے (`Borrow<str>`) — پرانا
     `(String, u16)` tuple کلید ہر تلاش پر نئی
     `String` مختص کرتا تھا؛
   - **پیک شدہ متصل ریکارڈز**: فی اندراج ایک `Box<[u8]>` بفر
     (فی ریکارڈ `u16 rdlen ‖ u16 rtype ‖ u32 ttl ‖ rdata`)
     بجائے فی ریکارڈ ایک `Vec` کے — میموری بجٹ
     بالکل وہی ٹریک کرتا ہے جو مختص ہے؛
   - **آؤٹ پٹ پر RFC 1035 نام کمپریشن**: مستند
     جوابات کا مالک 2 بائٹ کمپریشن پوائنٹر
     (`0xC00C`) گونجے گئے سوال میں — سوال کبھی فی ریکارڈ مکمل
     دوبارہ انکوڈ نہیں ہوتا۔
2. **Scone شکل؟** سخت پری فلٹر: لیبلز `[a-z0-9-_]`
   (1..63)، ≥ 2 لیبل، TLD 1..63 بائٹس `[a-z0-9-]` (دیکھیں
   `TldName::MAX_LEN`)، کل لمبائی ≤ 253 — **اور TLD ICANN روٹ سے
   باہر** (`is_icann_tld`، منجمد IANA فہرست + RFC 2606:
   `com`، `fr`، `org`… کبھی Scone کے نہیں ہوں گے)۔
   جو نام Scone نام **نہیں ہو سکتا** (مثلاً `www.foo_bar`،
   TLD میں انڈر اسکور) فال بیک جاتا ہے؛ ممکنہ Scone نام
   (`absent.uip`) چین کا معاملہ ہے: غیر رجسٹرڈ → مستند
   NXDOMAIN، اپ اسٹریم کے بغیر بھی۔ ICANN TLD (`example.com`)
   اپ اسٹریمز کو بھیجا جاتا ہے اگر کنفیگر ہو، ورنہ REFUSED
   — کبھی Scone کی جانب سے مستند طور پر حل نہیں۔
3. **Apex تلاش**: سابقے سب سے لمبے سے سب سے چھوٹے تک (کم از کم
   2 لیبل)۔ پہلا سابقہ جس کی آن چین اسٹیٹ ریلے کو معلوم ہو = apex؛
   ریکارڈ سیٹ پورے qname کی خدمت کرتا ہے
   (ذیلی نام سمیت — مضمر وائلڈ کارڈ رویہ، کھلا
   فیصلہ)۔
4. **`resolve_local` (اندرونی چینل)**: ایک راؤنڈ ٹرپ، کبھی
   DHT منتظر نہیں۔ آن چین اسٹیٹ (`registered`، مالک، sequence،
   mutations) + مقامی DHT کیش ریکارڈ **دوبارہ تصدیق شدہ** (مالک،
   sequence، record_hash == آن چین commitment؛ ریکارڈ کا دستخط
   مالک سے بھی آ سکتا ہے اور ریکارڈ delegate سے بھی — وہی قاعدہ
   جو ریلے کی تصدیق کا ہے)۔ غیر مطابق ریکارڈ کبھی
   جواب نہیں دیتا — دستیابی ≠ اختیار۔
   - غیر رجسٹرڈ → NXDOMAIN؛
   - درست ریکارڈ کے بغیر رجسٹرڈ → NODATA (NOERROR، 0
     جوابات)؛
   - تصدیق شدہ ریکارڈ → qtype کے مطابق فلٹر شدہ جوابات۔

## کوڈیک (RFC 1035، سخت ذیلی سیٹ)

- سوال: 12 بائٹ ہیڈر، **ایک** سوال، QCLASS = IN، **کوئی
  کمپریشن نہیں** (پوائنٹر = مسترد)۔ لیبلز چھوٹے اور
  تصدیق شدہ۔ QR=1، QDCOUNT≠1، غلط لیبلز → **خاموشی**
  (کچرا کچھ نہیں کھاتا)۔
- جواب: QR|RD(گونج)|RA، **AA صرف مستند جوابات پر**
  (چین، تازہ یا کیش شدہ — کبھی فال بیک یا خرابی RCODEs پر نہیں)،
  سوال جوں کا توں کاپی، مستند جوابات **RFC 1035 کمپریس شدہ
  مالک** کے ساتھ (2 بائٹ پوائنٹر `0xC00C` گونجے گئے
  سوال میں)؛ فال بیک اپ اسٹریم جوابات جوں کی توں دیے جاتے ہیں
  (کبھی دوبارہ انکوڈ نہیں)۔
- خدمت کردہ اقسام: A، AAAA، CNAME، NS، MX، TXT، **PTR، SRV، CAA**
  (+ Unknown جوں کا توں دوبارہ انکوڈ؛ کل 9 مقامی اقسام، rdata
  RFC کے مطابق انکوڈ — 1035/2782/8659؛ سخت CAA: کریٹیکل بٹ صرف 0x80،
  چھوٹے حروف ٹیگز)۔ A/AAAA سوال سیٹ کے
  CNAMEs شامل کرتا ہے (alias chasing)۔ ANY سوال (255): پورا سیٹ کوڈیک
  کے فلٹر سے۔
- حدود (M7b): **جواب کا بجٹ ٹرانسپورٹ پر منحصر ہے** —
  UDP پر 512 بائٹس (کلاسک RFC 1035 §2.3.4 پے لوڈ، کوئی EDNS نہیں)،
  TCP پر 65,535۔ بجٹ سے بڑا سیٹ آخری فٹ ہونے والے ریکارڈ پر کٹتا
  ہے، **TC=1** کے ساتھ (ایماندار کتراؤ، RFC 1035
  §4.2.1): کلائنٹ TCP پر دوبارہ کوشش کرتا ہے (RFC 7766)، جہاں پورا
  سیٹ ملتا ہے۔ UDP بجٹ سے بڑا اپ اسٹریم جواب دوبارہ انکوڈ
  کٹا (TC=1) جاتا ہے بجائے جوں کا توں دیے جانے کے؛
  TCP پر بائٹ در بائٹ گزرتا ہے۔ کتراؤ کیش ہٹس پر بھی لاگو
  (بجٹ جواب کے وقت لگتا ہے، کیش بھرنے کے وقت نہیں)۔
- RCODEs: 0 NOERROR (جوابات کے ساتھ یا بغیر)، 2 SERVFAIL (مقامی
  مقامی ناکامی)، 3 NXDOMAIN (مستند)، 5 REFUSED (غیر Scone
  بغیر اپ اسٹریم)۔

## ریکرسو فال بیک

- اپ اسٹریمز `addr:port` (UDP)، ترتیب سے، فی
  اپ اسٹریم 2 s ٹائم آؤٹ، ساکٹ اپ اسٹریم سے **کنیکٹڈ**
  (کرنل فلٹرنگ: کسی اور ذریعے کا پیکٹ کبھی قبول نہیں)۔
  اپ اسٹریم جواب صرف اُس وقت قبول ہوتا ہے جب وہ سوال سے
  **مطابق** ہو: وہی TXID، QR=1، سوال (QNAME+QTYPE+QCLASS) بائٹ در
  بائٹ کاپی۔ غیر مطابق جواب → SERVFAIL، اور
  کچھ کیش نہیں۔
- تصدیق شدہ اپ اسٹریم جواب جوں کا توں گزارا جاتا ہے؛ اس کے
  جوابات ماخذ `fallback` کے ساتھ کیش (AA کبھی سیٹ نہیں، کیش
  ہٹ پر بھی) اور TTL 600 s پر clamp۔ اپ اسٹریم خرابی
  RCODEs (NOERROR/NXDOMAIN کے سوا) کیش نہیں۔
- **بطور ڈیفالٹ نجی**: کوئی اپ اسٹریم نہیں = Scone شکل سے باہر
  ناموں کے لیے REFUSED۔

## DHT منفی کیش (اینٹی ایمپلیفیکیشن)

ایک **بے جواب DHT پُل** (ریکارڈ کی آن چین توقع —
`record_hash` commit شدہ — مگر مقامی کیش اور پوچھے گئے
پیرز سے غائب) نام کو `DHT_NEGATIVE_TTL_SECS` (30 s) کے لیے
ایک محدود منفی کیش (FIFO، کیپ `DHT_NEGATIVE_CAP` = 4,096
نام) میں رکھتا ہے: TTL کے اندر اسی نام کی بار بار ریزولوشنز
**دبا دی جاتی ہیں** (گنی جاتی ہیں، کبھی دوبارہ پُل نہیں)۔ کوئی
اسکینر — یا گرم نام جس کے مالک نے کبھی شائع نہ کیا — اب ایک DNS
سوال کو فی سوال فی میش پیر `GetRecord` میں نہیں بڑھا سکتا۔ منفی
اندراج TTL پر، ریکارڈ کی آمد پر (کامیاب پُل اصل
کیش میں لکھتا ہے)، یا FIFO کیپ سے نکالے جانے پر مرتا ہے۔

ظاہر کردہ گنٹیاں (`scone_dht_negative_hits_total`،
`_expired_total`، `_capped_total` — دیکھیں "Metrics" در `relay.md`)۔

## TCP (M7b، RFC 7766)

UDP جیسا ہی پورٹ (`--dns` پتے پر دوسرا TCP بائنڈ)۔
ٹرانسپورٹ RFC 1035 §4.2.2 کی پیروی کرتی ہے: ہر پیغام اپنی
لمبائی کے **2 بائٹ** big-endian سابقے سے آتا ہے۔

- **سوال**: سابقہ لمبائی ≥ 1 اور ≤ 512 بائٹس (DNS سوال کلاسک
  پے لوڈ میں سمٹتا ہے — RFC 7766 §6؛ کوئی EDNS نہیں)۔ حدود سے
  باہر → فوری کنکشن بند۔
- **جواب**: 65,535 بائٹ بجٹ (2 بائٹ سابقے کی زیادہ سے زیادہ) —
  UDP کے لیے بہت بڑا سیٹ یہاں **مکمل** ملتا ہے، TC=0۔
- **Pipelining**: فی کنکشن متعدد سوالات ترتیب سے
  کرم سے خدمت پاتے ہیں (ایک لکھائی = ایک سابقہ دار جواب)۔
- **پڑھنے کا ٹائم آؤٹ**: فی پڑھائی 5 s (سابقہ یا جسم) — خاموش
  کلائنٹ منقطع، اس کا سلاٹ آزاد۔
- **بیک وقت کنکشنز**: 64 زیادہ سے زیادہ (سمیفر)؛ 65واں فوراً
  مسترد (کنکشن بند)، کبھی قطار میں نہیں — کوئی
  بے حد اضافہ نہیں۔
- پڑھائی/لکھائی/ٹائم آؤٹ خرابیاں: debug لاگ + صاف بند۔ **نیٹ
  ورک ان پٹ پر کبھی panic نہیں۔**
- کچرا (ناقابل فہم سوال) خاموشی پاتا ہے مگر کنکشن
  بند نہیں کرتا: اگلا (درست) سوال خدمت پاتا ہے۔

```text
client                     server
  │ [len u16][query]         │
  │ ─────────────────────►   │ cache → authoritative → fallback
  │ ◄─────────────────────   │ [len u16][response ≤ 64 KiB]
  │ (UDP had answered TC=1 → the client retries here)
```

## حدود اور محافظ ریل

| محافظ ریل | قیمت |
|---|---|
| UDP ڈیٹاگرام (سوال/جواب) | 4096 بائٹس (اس سے آگے مسترد) |
| UDP جواب بجٹ (آگے TC=1) | 512 بائٹس (کوئی EDNS نہیں) |
| زیادہ سے زیادہ TCP سوال | 512 بائٹس (آگے بند) |
| زیادہ سے زیادہ TCP جواب | 65,535 بائٹس |
| بیک وقت TCP کنکشنز | 64 (سمیفر، فوری انکار) |
| TCP پڑھائی ٹائم آؤٹ | 5 s |
| کیش | عالمی حدود ڈیفالٹ 100,000 اندراجات / 64 MiB، 16 شارڈز میں تقسیم (`--dns-cache-limit` / `--dns-cache-max-mem`) |
| مستند TTL | **فی ریکارڈ** (`record.ttl`، حدود 1..=2,592,000 s؛ تاریخی مستقل 60 s صرف سروس جوابات کے لیے باقی) |
| فال بیک TTL (clamp) | 600 s |
| متوازی UDP سوالات | 4,096 (`MAX_INFLIGHT_UDP`، سمیفر؛ آگے: گراؤ، کلائنٹ دوبارہ کوشش) — قابل ترتیب `--dns-max-inflight` (کم از کم 1) |
| DHT منفی کیش | 30 s (`DHT_NEGATIVE_TTL_SECS`)، FIFO کیپ 4,096 نام |
| فی اپ اسٹریم ٹائم آؤٹ | 2 s |

پروجیکٹ قواعد کا خیال: نیٹ ورک ڈیٹا پر کبھی panic نہیں؛ ہر جگہ سخت
ڈی کوڈنگ؛ سرور نہ چین چھوتا ہے، نہ اسٹور، نہ
DHT (ریلے اکلوتا تصدیقی اختیار رہتا ہے)۔

## ٹیسٹس

- یونٹ (`scone-network::dns`): سخت کوڈیک (QR، کمپریشن،
  لیبل انکاری)، مستند جوابات، NODATA، NXDOMAIN،
  اپ اسٹریم کے بغیر REFUSED، UDP mock پر فال بیک، محدود
  کیش، TXT ٹکڑا بندی، اپ اسٹریم پارسنگ؛ M6 درستگی: AA بٹ
  ایمانداری (مستند بمقابلہ فال بیک بمقابلہ خرابیاں، کیش
  ہٹس سمیت)، بڑے سیٹ کی TC=1 کتراؤ، اپ اسٹریم جواب کی
  مستردی (TXID یا سوال بے میلانی)، SERVFAIL/REFUSED کا کیش نہ
  ہونا؛ شارڈڈ کیش: شارڈ پھیلاؤ، تقسیم شدہ عالمی
  حدود، گرم نام پر 4 متوازی ورکرز؛ ہاٹ پاتھ:
  بغیر مختص تلاش، پیک شدہ اندراجات، مالک کمپریشن۔
- M7b: فی ٹرانسپورٹ بجٹ (UDP 512 بائٹس → TC=1، TCP → مکمل
  سیٹ)، کیش ہٹ کا کتراؤ، حقیقی `run_tcp` (سیٹ > 512
  مکمل ملتا ہے، 2 سوالوں کی pipelining، بڑا سوال →
  بند، خاموش کلائنٹ → 5 s ٹائم آؤٹ، کچرا پھر درست سوال اسی
  کنکشن پر)، اپ اسٹریم جواب > 512 UDP پر دوبارہ انکوڈ TC=1
  / TCP پر بائٹ در بائٹ۔
- حقیقی انضمام (`tests/dns_server.rs`): مکمل ریلے
  (پیداوار ڈیو نیٹ سمیت) + رجسٹریشن + UpdateDomain +
  PutRecord، پھر حقیقی UDP سوالات: تصدیق شدہ A (AA بٹ)، TXT،
  NODATA AAAA، NXDOMAIN، mock کے ذریعے فال بیک، دوبارہ سوال، apex کے
  ذریعے ذیلی نام۔
- بائنری E2E (`crates/scone/tests/dns_cli.rs`): حقیقی `scone`
  بائنری — `relay --dns`، `identity generate`، `domain register`،
  `domain update --file`، پھر `dig` (dnsutils) (تصدیق شدہ A، TXT،
  NXDOMAIN، REFUSED) حقیقی UDP پورٹ پر۔

## GeoDNS (جغرافیائی روٹنگ)

> نافذہ تفصیل۔ کوئی دستاویز/کوڈ تضاد = نقص۔

### ایمبیڈڈ GeoIP ٹیبل (خودکار)

ہر بائنری ریلے میں کمپائل شدہ ایک **IP → ملک میپنگ ٹیبل** ایمبیڈ
کرتی ہے: **کوئی کنفیگریشن ضروری نہیں**، جغرافیائی روٹنگ
ہر جگہ، خودکار طور پر فعال ہے۔

- **ڈیٹا ذریعہ**: **DB-IP Lite** («IP to Country Lite»)،
  لائسنس **CC BY 4.0** — تصدیق کے ساتھ دوبارہ تقسیم قابل:
  `https://db-ip.com` (ماہانہ کیوریٹڈ؛ پہلے: RIR delegations
  بذریعہ `scripts/gen-geo-table.py`، ہٹا دیا گیا)۔
  مقدار دار خلیے **/20 v4 اور /24 v6** (DB-IP کی مقامی
  granularity، ~1.3M رینجز، پارسر کی میموری حد سے بڑھ جاتی
  ہے) — ~96,500 قواعد۔ پیداوار کی تاریخ ٹیبل ہیڈر میں
  (`assets/embedded-geo.table`)۔
- **چیکسم**: ٹیبل کا SHA-256 کمپائل وقت پر حساب ہوتا ہے
  (`build.rs`)، **بوٹ پر دوبارہ تصدیق** (مسمچ = ٹائپڈ انکار —
  بدلا ہوا بائنری کبھی جغرافیائی جوابات نہیں دیتا) اور بوٹ
  پر تصدیق کے ساتھ لاگ ہوتا ہے۔ ہیش یہ ضمانت ہے کہ «ایک ہی
  بلڈ کے تمام نوڈز ایک ہی ٹیبل شیئر کرتے ہیں» قابلِ جانچ
  ہے، مفروضہ نہیں۔
- **دوبارہ پیداوار**: `scripts/geo-convert.py` (مہینے کی
  DB-IP Lite CSV ڈاؤن لوڈ، تبدیل — عددی ملک، براعظم اخذ
  ISO→M49، ASN/علاقہ Lite میں غائب)۔
- **دقت**: ملک (عددی ISO 3166-1) + براعظم (UN
  M49) اخذ شدہ۔ کوئی ASN نہ علاقہ (Lite میں غائب —
  ASN/علاقے کی ضرورت ایمبیڈڈ پائپ لائن ارتقاء کا منتظر،
  کبھی مقامی ٹیبل نہیں)۔
- **کارکردگی**: ترتیب شدہ رینجز پر **بائنری تلاش**
  (انڈیکس پہلے استعمال پر ایک بار بنتا، فی v4/v6 خاندان) — ناپا
  گیا ~95 ns/تلاش ہاٹ، مکمل ٹیبل پر ~50 µs بے ترتیب رسائی
  (بینچ: `cargo test -p scone-network --release --test geo_bench
  -- --ignored`)۔
- **ریلے کی خود جگہ**: روٹنگ ہر
  سوال کے **سورس IP** کی پیروی کرتی ہے — ایک LAN ریلے اپنے
  مقامی کلائنٹس کو صحیح زون میں خودکار روٹ کرتا ہے۔
- **عائد ٹیبل** (remove-geo-operator-table، 2026-10-22):
  ایمبیڈڈ ٹیبل **اکیلا ذریعہ** ہے — کوئی آپریٹر امپورٹ یا
  override موجود نہیں۔ **کوئی رن ٹائم geo آپشن موجود نہیں**:
  ہر `--geo-*` flag سخت clap مستردی ہے (geozone بلڈ سے
  عائد ہے)۔ مخصوص ضرورتوں والا آپریٹر (ASN، علاقہ) ایمبیڈڈ
  پائپ لائن ارتقاء کا منتظر، مقامی ٹیبل نہیں۔

### جائزہ

کوئی ڈومین اپنے دستخط شدہ ریکارڈ سیٹ میں **جغرافیائی روٹنگ**
قواعد شائع کر سکتی ہے: `GEOROUTE` ریکارڈز (Scone ذاتی قسم
`32,768`، IANA حد سے باہر)۔ ریزالور ان ڈومینز کے A/AAAA سوالوں کا
جواب **قاعدے کے چنے گئے endpoint کے پتے** سے دیتا ہے (سابقہ
کلائنٹ کی پوزیشن کے سب سے قریب، اس کے
سورس IP سے ٹیبل کے ذریعے اخذ)، بجائے ساکن A/AAAA ریکارڈ کے۔
سب کچھ اور (GEOROUTE کے بغیر ڈومینز، دیگر qtypes) کلاسک
DNS پاتھ کی پیروی کرتا ہے، **بائٹ در بائٹ**۔

### GeoDNS میٹرکس

Prometheus اینڈ پوائنٹ geo جواب کی تقسیم ظاہر کرتا ہے:

- `scone_dns_geo_answers_total` — کل GEOROUTE جوابات؛
- `scone_dns_geo_by_continent_total{continent="<M49>"}` — براعظم کے مطابق؛
- `scone_dns_geo_by_country_total{country="<ISO>"}` — ملک کے مطابق
  (خود معیاروں سے محدود: ≤ 9 براعظم، ≤ 250
  ممالک)۔

### GEOROUTE ریکارڈ (وائر)

ایک GEOROUTE = ایک **scope** + ≤ 32 **endpoints** (ڈی کوڈ پر
کیننیکل ترتیب: بڑھتی priority، گھٹتی weight، بڑھتی target؛
ڈپلیکیٹ = مسترد):

```text
GeoScope   = 0x00 (world)
           | 0x01 continent.v (UN M49 code: AF=2, AS=142, EU=150,
                                NA=3, SA=5, OC=9, AN=999)
           | 0x02 country.v   (ISO 3166-1 numeric code: US=840,
                                TW=158, FR=250…)
           | 0x03 region.v    (OPAQUE ISO 3166-2 subdivision, u32:
                                publisher-defined number, compared
                                as is — no local table)
           | 0x04 asn.v       (AS number, u32)
           | 0x05 prefix.addr[16] || prefix.len u8
             (normalized 16-byte IP prefix: IPv4 = address in the
              first 4 bytes + ZERO tail, len ≤ 32;
              IPv6 = 16 free bytes, len ≤ 128; host bits ALWAYS
              zero — a non-normalized prefix is rejected)
GeoTarget  = 0x00 octets[4]  (binary IPv4 address)
           | 0x01 octets[16] (binary IPv6 address)
GeoEndpoint = target || priority.v || weight.v
GEOROUTE    = scope || count.v(≤32) || endpoints…
```

تصدیق حدود (ڈی کوڈ): `priority > 0`، `weight ≤ 100`
(`weight = 0` = غیر فعال endpoint، کبھی منتخب نہیں)، TTL
1..=2,592,000 s جیسے ہر ریکارڈ۔ مقامی ٹیبلز سے نامعلوم
ملک/براعظم وائر پر **اجازت شدہ** ہے: روٹنگ سادہ طور پر اعلیٰ
scope پر گر جاتی ہے۔

**وائر پیچھے کی ہم آہنگی (v1 → v2)**: v1 بائٹس **بے تبدیل**
ہیں — v1 scopes (world/continent/country) اپنے
ڈسکریمیننٹس `0x00..=0x02` اور اپنی بالکل انکوڈنگ رکھتے ہیں؛ تین
نئے scopes اگلے ڈسکریمیننٹس (`0x03..=0x05`) لیتے ہیں ایک
کل ترتیب میں جو کیننیکل ترتیب سے ہم آہنگ ہے
(`World < Continent < Country < Region < Asn < IpPrefix`)۔ v1
ڈی کوڈر جو ڈسکریمیننٹ ≥ `0x03` سے ملے پہلے ہی سخت ناکام ہوتا تھا
(ریکارڈ مسترد)؛ v1 کی بنی بائٹس یکساں ڈی کوڈ رہتی ہیں
(دیکھیں `geo_known_bytes` ٹیسٹ، منجمد)۔

### انتخاب (ریزولوشن)

1. **Scope** — گھٹتی خاصیت، **6 سطریں**:
   **سب سے لمبا میچ IP سابقہ → exact AS → exact ملک →
   exact علاقہ → براعظم → دنیا**۔
   - *IpPrefix*: جن راستوں کا سابقہ کلائنٹ کے IP سے میچ ہو
     (جیسے locator جانتا ہے: `client_ip`، ورنہ معلوم ماخذ
     سابقے)، **سب سے لمبا** (`len` max)
     جیتتا ہے؛ برابر `len` پر، کیننیکل ترتیب میں پہلا
     (`routes` slice کی ترتیب، انکوڈنگ پر ترتیب شدہ)۔ کوئی
    subdivision سابقے/AS سے کم خاص ہے (جو
     exact نیٹ ورک پہچانتے ہیں) اور ملک سے کم (اپاہج
     نمبرنگ، قابلِ بھروسہ صرف اگر اشاعتی کار اور
     locator وہی شیئر کریں)، مگر براعظم سے زیادہ (وہ اپنے
     ملک میں شامل ہے، اس لیے بالضرورت اپنے
     براعظم میں)۔
   - *Asn*: کلائنٹ کا exact AS نمبر۔
   - *Country*: exact ملک۔
   - *Region*: exact subdivision (اپاہج شناخت کنندہ)۔
   - *Continent*: locator کا فراہم کردا **یا ملک سے اخذ شدہ**
     مقامی ٹیبل کے ذریعے (`continent_of_country`)؛ ٹیبل سے
     نامعلوم ملک واضح
     براعظم یا دنیا پر گر جاتا ہے۔
   - *World*۔
   v1 [`GeoLocation`] (region/asn/prefixes/client_ip غیر سیٹ)
   بالکل v1 رویہ پیدا کرتا ہے: ملک → براعظم →
   دنیا۔ کوئی میچنگ راستہ نہیں (بغیر World scope سمیت) →
   کلاسک DNS رویہ، جیسے GEOROUTE موجود ہی نہ ہو۔
2. **Priority** — SRV جیسے معنی: صرف **کم از کم
   priority** گروپ اہل ہے؛ اعلیٰ prioritiess **failover**
   سطریں ہیں۔
3. **Weight** — منتخب گروپ میں، **متعین وزنی** قرعہ: nonce (ریزارور
   کی سوال گنٹی) کا مستقل ہیش (SplitMix64) مجموعی وزنوں کے
   خلاف۔ کوئی RNG نہیں: ایک جیسے nonce کے دو سوال وہی نتیجہ دیتے
   ہیں، بڑھتے nonce وزنوں کے تناسب سے تقسیم کرتے ہیں۔
   `weight = 0` = غیر فعال، کبھی منتخب نہیں (اکیلا ہو تو بھی — اگلی
   سطح پر جائیں)۔
4. **دستخط شدہ ترتیب، صفر جانچ** — ریزالور کبھی endpoint کی
   دستیابی کا فیصلہ نہیں کرتا: منتخب scope کا ہر فعال
   endpoint (weight > 0) امیدوار ہے، کم سے کم سطح کا سر
   وزنی قرعے سے منتخب ہوتا ہے، اور اگلے دستخط شدہ ریکارڈ سیٹ
   کی ترتیب میں failover کا کام کرتے ہیں (ترتیب ہی
   failover میکانزم ہے)۔ endpoint کی قابلِ رسائی اس کے
   آپریٹر کا معاملہ ہے، کبھی ریزالور کا نہیں۔

### جواب

- ایک اکیلا پتہ: **IPv4 ہو تو A، IPv6 ہو تو AAAA** — qtype کے
  مطابق خاندان کی سخت
  فلٹرنگ (A سوال کبھی IPv6 کا جواب نہیں دیتا، اور اس کا الٹ)۔
- TTL = ماخذ GEOROUTE ریکارڈ کا (ڈی کوڈ پر عمومی TTL قواعد سے
  محدود)۔
- AA سیٹ (مستند جواب — GEOROUTE ہر دوسرے کی طرح تصدیق شدہ
  دستخط شدہ ریکارڈ ہے)۔
- فلٹرنگ کے بعد خالی جواب (درست خاندان کا کوئی امیدوار نہیں،
  زون کے لیے کوئی route نہیں) → ریزالور اپنے کلاسک پاتھ پر
  جاری رہتا ہے (عام طور پر NODATA: NOERROR، 0
  جوابات)؛ خرابی rcodes عمومی قواعد کی پیروی کرتے ہیں (کبھی کیش
  نہیں)۔
- سیٹ میں شامل کلاسک A/AAAA ریکارڈ geo سے **پہلے** آتا
  ہے (geo صرف qtype کے لیے وائر جواب کی غیر موجودگی میں لاگو
  ہوتا ہے)۔

### کیش: واضح فیصلہ

geo روٹنگ فیصلہ `(qname, qtype)` کے تحت **کبھی کیش نہیں** ہوتا:
یہ ریزالور کے کلائنٹ scope پر منحصر ہے، اور ایسی کلید TW
کلائنٹ کو US راستہ دے دیتی۔ Geo جوابات ہر سوال پر دوبارہ حساب
ہوتے ہیں (لاگت: ایک select_scope + وزنی قرعہ، µs) اور کیش سے
بچتے ہیں۔ کلاسک (qname, qtype) کیش باقی سب کے لیے بے تبدیل —
بشمول وہ NODATA جو geo کچھ بھی فیصلہ نہ کرے۔ خرابی rcodes کبھی
کیش نہیں رہتے۔

### NS delegation (`ns` ریکارڈز) — مالک خود طے کرتا ہے کون خدمت کرے

ڈومین کا مالک فی ڈومین serving موڈ منتخب کرتا ہے:

- **DHT (ڈیفالٹ)** — NS ریکارڈ کے بغیر، Scone نیٹ ورک آن چین
  A/AAAA خدمت کرتا ہے (ریلے `--dns`، یا export کے ذریعے NSD
  پُل)؛
- **آزاد NS** — مالک `ns <ip-or-name>` ریکارڈز لگاتا ہے
  (اس کے اپنے nameservers، براہِ راست IP یا hostname): ڈومین
  **ڈیلیگیٹ** ہو جاتا ہے — نیٹ ورک اس کے مواد کی خدمت بند
  کر دیتا ہے (A/AAAA → NODATA + NS اتھارٹی)، اور جو بھی
  resolve کرے مالک کے NS کی پیروی کرتا ہے۔ حد: **فی ڈومین
  12 ممیز NS** (تمام شکلیں، قیمت سے ڈیڈپلیکیٹ — حقیقی
  رجسٹری کیپس کا عکس)۔ ایک NS ہٹانے سے سلاٹ آزاد ہوتا ہے؛
  سب ہٹانے پر DHT موڈ بحال۔

**کوئی health checking موجود نہیں**: endpoint دستیابی endpoint
آپریٹرز کا معاملہ ہے — ریزالور دستخط شدہ ریکارڈ سیٹ جوں کی
توں، ریکارڈ ترتیب میں خدمت کرتا ہے (ریکارڈ ترتیب ہی
failover میکانزم ہے)۔

### سیکیورٹی

- GEOROUTE ریکارڈز ہر دوسرے کی طرح دستخط شدہ ہیں: کسی بھی
  استعمال سے پہلے چین کے خلاف تصدیق (مالک، sequence،
  record_hash)۔ **تصدیق کے بغیر کوئی نیٹ ورک اعتماد نہیں** —
  غیر تصدیق شدہ DHT GEOROUTE کبھی جواب نہیں دیتا۔
- کلائنٹ کی پوزیشن **خود دریافت شدہ سرکٹ** سے آتی ہے: ریلے
  اپنی بیرونی پتے (STUN/AutoNAT/UPnP) کے ذریعے خود کو مقام
  دیتا ہے، جو بلڈ سے عائد ایمبیڈڈ ٹیبل سے حل ہوتا ہے — LAN
  کلائنٹس (پرائیویٹ سورس IP) وہی پوزیشن ورثتے ہیں، انٹرنیٹ
  کلائنٹس اپنے IP سے حل ہوتے ہیں، نامعلوم World پر گرتا ہے۔
  کبھی نیٹ ورک GeoIP API سے نہیں (کوئی سوال لیک نہیں، کوئی
  انحصار نہیں) اور کبھی آپریٹر اعلان سے نہیں (زونز بلڈ سے
  عائد ہیں)۔
- قرعہ متعین اور مقامی ہے: کوئی راز نہیں، کوئی
  غیر متوقع ہونا ضروری نہیں (سیکیورٹی ریکارڈ کے
  دستخط کی ہے، قرعے کی نہیں)۔

### مکمل مثال (حوالہ تفصیل)

`www.example.scone` شائع کرتا ہے (apex `example.scone`، پورا
سیٹ ہر ذیلی نام کی خدمت کرتا ہے):

| Scope | Endpoint | Priority | Weight |
|---|---|---|---|
| US (840) | 10.1.0.1 | 10 | 70 |
| US (840) | 10.1.0.2 | 10 | 30 |
| US (840) | 10.2.0.1 | 20 | 100 |
| TW (158) | 10.3.0.1 | 10 | 80 |
| TW (158) | 10.4.0.1 | 10 | 20 |
| TW (158) | 10.2.0.1 | 20 | 100 |
| WORLD | 10.0.0.1 | 100 | 100 |

متوقع رویہ:

- **US** کلائنٹ → 10.1.0.1 (≈70%) یا 10.1.0.2 (≈30%)؛ p20
  سطح صرف اُس وقت پہنچی جاتا ہے جب کوئی p10 endpoint فعال
  نہ ہو (weight = 0 ہر جگہ) → پھر **10.2.0.1**؛
- **TW** کلائنٹ → 10.3.0.1 (≈80%) یا 10.4.0.1 (≈20%)؛
- **FR** کلائنٹ (250) → سیٹ میں کوئی FR یا EU راستہ نہیں → WORLD →
  **10.0.0.1**؛
- صرف IPv6 راستے پر **A** سوال → خالی جواب (A میں کبھی IPv6
  نہیں)؛
- لاگو قاعدہ کے بغیر ڈومین → وہی سوال، کلاسک رویہ (NODATA:
  GEOROUTE کے پاس کوئی وائر A rdata نہیں)۔

### CLI آپشنز (`scone relay`)

| آپشن | ڈیفالٹ | کردار |
|---|---|---|
| (کوئی نہیں — GeoDNS ہمیشہ آن، ایمبیڈڈ ٹیبل) | آن | سورس IP کے ذریعے خودکار روٹنگ |
| `--geo-ip-table`، `--geo-config`، `--geo-country/…`، `--health-*` | — | (ہٹا دیا گیا — سخت ٹوٹ: geozone بلڈ سے عائد اور ریزالور کوئی health جانچ نہیں کرتا؛ کوئی رن ٹائم flag موجود نہیں) |

#### ایمبیڈڈ ٹیبل اکیلا ذریعہ ہے

GeoIP ٹیبل **بلڈ سے عائد** ہے (DB-IP Lite، مقدار دار، اوپر
ایمبیڈڈ ٹیبل سیکشن دیکھیں): کوئی آپریٹر ٹیبل امپورٹ نہیں ہو
سکتی۔ حل: **DNS سوال کا سورس IP** (فی کلائنٹ:
UDP `recv_from` / TCP `peer_addr`) 16 بائٹس میں ایمبیڈڈ ٹیبل
کے خلاف موازنہ؛ جس قاعدے کا **سب سے لمبا میچ سابقہ** ہو وہ
جیتتا ہے (برابری پر، فائل ترتیب میں پہلا)۔

- **پرائیویٹ/غیر روٹ قابل سورس** (RFC1918، ULA fc00::/7،
  link-local، loopback): کلائنٹ ریلے کے نیٹ ورک کے اندر
  ہے — وہ ریلے کی اپنی دریافت شدہ پوزیشن ورثتا ہے؛
- **ٹیبل میں غائب عوامی سورس**: World (کوئی geo تقسیم نہیں —
  کبھی غلط جواب نہیں)۔

**سختی** کسی مستقبل کے ٹیبل سطح کے لیے محفوظ: غلط لائن
گناہگار لائن نمبر لیتی ٹائپڈ اسٹارٹ اپ خرابی ہے؛ کبھی
خاموشی سے نظر انداز لائن نہیں، کبھی جزوی ٹیبل نہیں۔

#### آپشن ترجیحات

- **Locator**: ایمبیڈڈ ٹیبل جیو لوکیشن **عائد** کرتا ہے —
  کوئی آپریٹر override نہیں۔ ریلے اپنی بیرونی پتے سے اپنی
  پوزیشن دریافت کرتا ہے (STUN/AutoNAT/UPnP ٹیبل سے حل)؛
  LAN کلائنٹس وہ پوزیشن ورثتے ہیں؛ انٹرنیٹ کلائنٹس اپنے
  سورس IP سے حل ہوتے ہیں؛ نامعلوم World پر گرتا ہے۔

مثال (geo روٹنگ کسی geo فلیگ کے بغیر فعال):

```bash
scone relay --dns 127.0.0.1:5353
```


## DoH / DoT (خفیہ ٹرانسپورٹس) — بیرونی فرنٹ اینڈ کے ذریعے

Scone DNS سرور **سادہ UDP اور TCP** بولتا ہے (RFC 1035 / 7766)
— وہی مقامی دائرہ ہے، مکمل اور ٹیسٹ شدہ۔ *آخری کلائنٹ* تک خفیہ
ٹرانسپورٹس (DoH — DNS-over-HTTPS، RFC 8484؛
DoT — DNS-over-TLS، RFC 7858) ایک **معیاری
فرنٹ اینڈ کو سونپی گئی ہیں**: Scone ڈیٹا دیتا ہے، فرنٹ اینڈ
ٹرانسپورٹ دیتا ہے۔

یہ ڈیزائن کیوں: مقامی DoH سرور نوڈ کے اندر مکمل HTTPS
اسٹیک مانگتا (سرٹیفکیٹ، تجدید، HTTP/2) — بڑا
عملی سطح جس کا کوئی فائدہ نہیں جب تک براؤزر کی طرف سے آخری
صارفین نہ ہوں۔ موجودہ فرنٹ اینڈز اسے بہتر اور زیادہ عرصے سے کرتے
ہیں؛ نوڈ کم سے کم رہتا ہے۔

### مثال: unbound Scone ریلے کے آگے DoH کرتے ہوئے

`/etc/unbound/unbound.conf`:

```
server:
    interface: 127.0.0.1
    port: 5354
    do-ip4: yes
    do-udp: no
    do-tcp: yes

    # DoH (RFC 8484) on 443
    https-port: 443
    tls-service-key: "/etc/unbound/scone.key"
    tls-service-pem: "/etc/unbound/scone.pem"

forward-zone:
    name: "."
    forward-addr: 127.0.0.1@5353   # the Scone relay (--dns 127.0.0.1:5353)
```

سرٹیفکیٹ (`scone.pem`/`scone.key`) ہر TLS
سروس کی طرح ملتا ہے — مثلاً ریزالور کے ڈومین پر certbot/acme.sh۔
DoH کلائنٹس پھر `https://dns.example.tld/dns-query` کی طرف اشارہ
کرتے ہیں۔

### مثال: knot-resolver DoT کرتے ہوئے

`/etc/knot-resolver/kresd.conf`:

```
net.listen('127.0.0.1', 5353, { kind = 'dns' })
net.listen('0.0.0.0', 853, { kind = 'tls' })
tls.cert_file = '/etc/knot-resolver/scone.pem'
tls.key_file  = '/etc/knot-resolver/scone.key'
```

### فرنٹ اینڈ کیا شامل کرتا ہے

- **کلائنٹ→فرنٹ اینڈ چینل کی خفیہ کاری** (معاندار
  حصہ: صارف کا نیٹ ورک)؛ فرنٹ اینڈ→ریلے حصہ مقامی رہتا
  ہے (وہی مشین یا بھروسہ مند نیٹ ورک)۔
- **ایک اضافی فرنٹ اینڈ کیش** (unbound/knot کیش بھی —
  بے ضرر، Scone TTLs اوپری حد رہتے ہیں)۔
- **ایک مستقل اینڈ پوائنٹ** (IPv4/IPv6، ڈومین) جبکہ ریلے ہلتے
  ہیں۔

### فرنٹ اینڈ کیا نہیں کرتا

- یہ کچھ *تصدیق* نہیں کرتا: ریلے کا ہر جواب کیش ہونے سے پہلے
  پہلے ہی چین کے خلاف تصدیق شدہ ہے (دیکھیں
  "ریزولوشن پاتھ")۔ فرنٹ اینڈ پہلے سے مستند
  جوابات آگے بڑھاتا ہے۔
- یہ غیر مرکزیت کی جگہ نہیں لیتا: DoH فرنٹ اینڈ ایک
  *چلایا گیا* خدمت ہے — ریزالور آپریٹر کا انتخاب، نہ کہ
  پروٹوکول کا۔ ہر Scone ریلے مقامی UDP/TCP پر آزادانہ قابلِ
  استعمال رہتا ہے۔

### مستقبل کا مقامی نفاذ (دستاویز شدہ، عزم نہیں)

مقامی DoH ٹرانسپورٹ (`--doh ADDR`) تصور قائم رہتا ہے: وائر
فارمیٹ یکساں ہونے کی وجہ سے (RFC 8484 بائنری DNS پیغامات دوبارہ
استعمال کرتا ہے)، یہ ایک POST/GET ڈی کوڈ + HTTP/2 ہو گا TLS پراکسی
کے پیچھے (caddy/nginx سرٹیفکیٹ سنبھالتے)، نوڈ خود TLS سے پاک
رہتا۔ کوئی کام جاری نہیں — طلب آخری صارفین کے ساتھ آئے گا۔
