# نیٹ ورک ریلے (M4) — فنِ تعمیر، فلو، اور CLI کنٹرول

> Scone نیٹ ورک ریلے (`scone-network`) کی نافذہ تفصیل۔
> کوئی بھی دستاویز/کوڈ تضاد = نقص (سچائی کے ذریعے کا درست کریں)۔

## جائزہ

**ریلے** Scone کا مکمل P2P نوڈ ہے: یہ کیننیکل
بلاکچین (RAM + `NodeStore` redb) برقرار رکھتا ہے، ٹرانزیکشنز اور بلاکس
ریلے کرتا ہے، بلاکس پیدا کرتا ہے (ڈیو نیٹ موڈ)، سنک پروٹوکول خدمت
دیتا ہے، `SignedDnsRecord`s کو Kademlia DHT میں شائع اور حل
کرتا ہے، اور وہ **p2p پروٹوکول** (`/scone/reqres/1`) ظاہر کرتا ہے
جو CLI براہِ راست سوال کرتی ہے
(RPC→p2p یکساں کاری: JSON TCP چینل ختم)۔

```text
                    ┌────────────────────────────────────────┐
                    │              scone relay               │
  P2P (libp2p)      │                                        │
  QUIC (udp,        │  Swarm libp2p                          │
  ephemeral port    │  ├─ identify  (address discovery)      │
  by default) ◄─────┤  ├─ ping      (liveness)               │
                    │  ├─ kad       (record DHT)             │
                    │  └─ reqres    (scone-prot. messages)   │
                    │                                        │
                    │  Relay core (single task)              │
                    │  ├─ Blockchain (full validation)       │
                    │  ├─ Mempool (bounded, dedup by TxId)   │
                    │  ├─ BlockBuilder (devnet production)   │
                    │  ├─ Fork parking (bounded, 2048)       │
                    │  └─ Sync driver (batched catch-up)     │
                    │                                        │
  CLI ◄─────────────┤  reqres p2p (QUIC, same messages)      │
                    └────────────────┬───────────────────────┘
                                     │
                              NodeStore (redb)
```

`crates/scone-network` ورک اسپیس کی **اکلوت async crate** ہے:
اس کے نیچے سب کچھ (crypto → core → protocol → blockchain →
storage) ہم وقتی اور خالص رہتا ہے۔

## کنکشن داخلہ (P1.5)

سوارم سطح پر سخت حدود (libp2p `connection_limits` رویہ،
`SconeBehaviour` کا پہلا اندراج):

- `MAX_TOTAL_CONNECTIONS = 128` — فی ریلے قائم کنکشنز کی کیپ
  (آمد + رفت)؛ اضافی آمد REFUSED،
  کبھی قطار میں نہیں؛
- `MAX_PER_PEER_CONNECTIONS = 4` — ایک اکیلا پیر کئی
  کنکشنز کھول کر کل کوٹہ پر قبضہ نہیں کر سکتا؛
- `MAX_PENDING_INCOMING = 32` — slowloris محافظ: غیر تصدیق شدہ
  آدھے کنکشنز کبھی بے انتہا انتظار نہیں کرتے۔

یہ حدود موجودہ فی پیغام حدود
(`MAX_MESSAGE_LEN` 1 MiB) اور فی بجٹ حدود (سنک `max ≤ 128`
بلاکس، DNS TCP 64 کنکشنز/512 B/5 s) کو مکمل کرتی ہیں۔ کنکشن سیلاب
حملہ آور کو انکاری ملتی ہے، میموری اضافہ نہیں۔

## پیر دریافت

تین باہمی تکمیلی میکانزم، اس ترجیحی ترتیب میں:

1. **واضح seeds** (`--bootstrap`، مکمل multiaddrs) — ہمیشہ
   ترجیح؛ غیر خالی فہرست دینا باقی سب کی جگہ لے لیتا ہے
   (REPLACES)۔
   `--no-builtin-seeds` ایمبیڈڈ seeds خالی کرتا ہے 100% نجی
   تعیناتیوں کے لیے۔
2. **ایمبیڈڈ seeds** (`builtin_seeds(network)` در
   `scone-network/src/config.rs`) — ہر سرکاری بائنری
   ریلیز پر منجمد، فی نیٹ ورک۔ غیر کنفیگر شدہ ریلے نیٹ ورک میں
   اکیلا شامل ہوتا ہے۔ (ٹیسٹ نیٹ پر خالی جب تک عوامی ٹیسٹ نیٹ
   تعینات نہ ہو۔)
3. **سیکھی ہوئی ڈائریکٹری** (`<data-dir>/peers.json`) — ہر وہ پتہ
   جو `identify` کے ذریعے سیکھا گیا رکھا جاتا ہے (آخری بار دیکھا
   گیا؛ **2000 اندراجات** کی کیپ — پتے، کنکشنز نہیں، زیادہ سے زیادہ
   ~400 KiB RAM — اور **90 دن کی عمر کٹ**)۔ 90 دن سے زیادہ پہلے
   دیکھا گیا اندراج لکھنے کے وقت گرایا اور لوڈ
   کے وقت نظر انداز جاتا ہے، 2000 سلاٹس کو قابلِ امکان پیرز سے بھرا
   رکھتے ہوئے بجائے پری چرن فوسلز کے جن کا اکلوٹا حصہ بوٹ
   ٹائم ڈائل ٹائم آؤٹ ہوتا) اور پیداوار ٹک پر ~1×/منٹ محفوظ۔ بغیر
   seed اور bootstrap کے بوٹ پر، ڈائریکٹری دوبارہ ترتیب دی جاتی
   ہے: ریلے بغیر
   کنفیگریشن کے اپنے عام پیرز ڈھونڈ لیتا ہے۔ یہ کیش ہے: غائب/خراب
   فائل = خالی ڈائریکٹری، کبھی خرابی نہیں۔
4. **LAN mDNS** (`--mdns`) — مقامی لنک پر زیرو کنفیگ دریافت:
   اسی نیٹ ورک سیگمنٹ پر پڑوسی ریلے بغیر کسی
   seed کے ایک دوسرے ڈھونڈتے ہیں (زیرو کنفیگ ڈیو نیٹ
   پاتھ)۔ **ڈیفالٹ: ڈیو نیٹ پر آن، باقی جگہ آف** (ایک ری سیٹ قابل
   مقامی نیٹ ورک ڈیزائن کے مطابق دریافت نیٹ ورک ہے؛ عوامی
   تعیناتی کچھ بھی ملٹی کاسٹ نہیں کرتی)۔ رویہ: ملٹی کاسٹ ساکٹ کا بائنڈ؛ بائنڈ ناکامی
   (انٹرفیس پر کوئی ملٹی کاسٹ نہیں، سینڈ باکسڈ ماحول)
   mDNS کو ایک تنبیہ کے ساتھ **بند** کر دیتی ہے — کبھی مہلک نہیں (دریافت
   ایک سہولت ہے، کبھی lifeline نہیں)۔ ہر `Discovered` پڑوسی
   Kademlia ٹیبل میں داخل ہوتا ہے (`kad.add_address`)، بالکل واضح
   bootstrap جیسا مائنس کنفیگریشن؛ `Expired` اندراجات
   libp2p خود ٹریک کرتا ہے (کنکشن اپنے
   ٹائم آؤٹ پر بند)۔ رویہ کے `mdns`/`upnp` ممبران `Toggle`s
   ہیں (تعمیر پر فعال/بند،
   `build_behaviour(key, enable_mdns, enable_upnp)`)۔
5. **UPnP** (`--upnp`، آپٹ اِن) — ہوم روٹر کے ذریعے QUIC
   سننے کے پورٹ کی میپنگ: نوڈ بغیر
   سرکٹ ریلے کے باہر سے قابلِ رسائی بن جاتا ہے۔ `NewExternalAddr`
   پر، بیرونی پتہ سوارم کے اصل بیرونی پتے کے طور پر رجسٹر ہوتا ہے
   (`add_external_address` — identify/autonat کے دیکھے ہوئے، ایک
   ٹرانسپورٹ ریلے امیدوار)۔ کوئی IGD گیٹ وے نہیں (`GatewayNotFound`)
   یا غیر قابلِ روٹ گیٹ وے (`NonRoutableGateway`): ایک سادہ info
   لاگ، میپنگ چھوڑی جاتی ہے — ہوم LAN پر عام معاملات۔ میعاد
   ختم میپنگ (ناکام تجدید) ایک تنبیہ ہے۔

mDNS نیٹ ورک کی پیروی کرتا ہے (واضح `--mdns`/`SCONE_MDNS`
ہمیشہ جیتتا ہے): **ڈیو نیٹ پر بطور ڈیفالٹ آن**، ٹیسٹ
نیٹ/مین نیٹ پر آف؛ UPnP **بطور ڈیفالٹ بند** رہتا ہے
(`enable_mdns`/`enable_upnp` = `false` در `config.rs`، ریلے
ڈیو نیٹ کے لیے mDNS آن کرتا ہے): عوامی تعیناتی کچھ بھی ملٹی کاسٹ
نہیں کرتی اور کسی روٹر سے نہیں بولتی۔

### مقامی ٹوپولوجی بہتری (ہمیشہ آن)

ریلے خالص `scone-topology` انجن (crate کی دستاویزات دیکھیں) کے
ذریعے اپنا محلہ فعال طور پر بہتر کرتا ہے۔ **ہمیشہ فعال**؛
اکلوتی ظاہر کرنے والی tuning ایک **پروفائل** ہے
(`--topology-profile`،
env `SCONE_TOPOLOGY_PROFILE`، ڈیفالٹ `default`):

| پروفائل | کم / ہدف / زیادہ | جانچ | کس کے لیے |
|---|---|---|---|
| `tiny` | 2 / 4 / 6 | 120 s | Raspberry Pi، ہوم باکس، 1-vCPU VPS |
| `small` | 4 / 8 / 12 | 90 s | چھوٹا سرور، ہوم NAS |
| `default` | 8 / 16 / 32 | 60 s | معیاری سرور (ڈیفالٹ) |
| `high` | 16 / 32 / 64 | 45 s | خودمختار نوڈ، بیک بون |
| `very-high` | 32 / 64 / 128 | 30 s | بانی ہبز |
| `devtest` | 2 / 4 / 6 | 5 s | **صرف لیب/ٹیسٹ** (ڈیزائن کے مطابق غیر مستحکم) |

```
scone relay --topology-profile tiny
```

حفاظتی پیرامیٹرز (hysteresis 0.15، cooldown 600 s، grace
120 s، پیمائش 15 s) ہر جگہ یکساں ہیں: یہ استحکام کے محافظ ہیں
اور نوڈ سائز کے ساتھ پیمانہ ہونے کی کوئی وجہ نہیں۔ نامعلوم نام
ٹائپ شدہ اسٹارٹ اپ خرابی ہے۔

غیر ہم آہنگ کنفیگریشن (`min > target > max`، حد `[0,1]` سے
باہر — `NaN` سمیت —، صفر وقفہ) ایک **ٹائپ شدہ اسٹارٹ اپ
خرابی** ہے، کبھی خاموش رویہ نہیں۔

**منظر (`TopologyView`)** — سوارم واقعات سے کھلایا جاتا ہے:

- کامیاب `ping` → RTT مشاہدہ (8 نمونوں کی میڈیان ونڈو)؛
- ناکام `ping` → قابلِ بھروسہ سزا؛
- `identify` موصول → پتے (≤ 4/پیر) + اعلان شدہ پروٹوکولز
  (kad/reqres/identify/relay بٹ ماسک)؛
- کنکشن قائم → کنیکٹڈ اسٹیٹ، سمت
  (آمد/رفت)، عمر، پائی گئی سرکٹ ریلے؛
- کنکشن بند → سزا + churn گنٹی صرف اس صورت میں جب بے درخواست
  ہو (رضاکارانہ بے دخلی گنٹی نہیں ہوتی)؛
- رفت ڈائل ناکامی → قابلِ بھروسہ سزا۔

منظر محدود ہے (500 پیرز؛ اس سے آگے، صرف کنیکٹڈ پیرز
یاد رکھے جاتے ہیں)۔

**kbuckets سے `kad_required`** — ہر جانچ سے پہلے،
ریلے Kademlia روٹنگ ٹیبل چلتا ہے: ایک پیر محفوظ ہے اگر وہ کسی
بکٹ میں `Connected` ہو، یا ایک سیر شدہ (SATURATED) بکٹ میں
`Disconnected` ہو (k = 20)۔ محفوظ پیر کبھی بے دخلی کے لیے
نہیں چنا جاتا۔

**بہتری لوپ** — پروفائل کے جانچ وقفے پر
(`default` کے تحت 60 s؛ اوپر جدول دیکھیں):

1. `kad_required` دوبارہ حساب (kbuckets)؛
2. انجن جانچ (hysteresis: 120 s مہلت مدت، کم از کم اسکور
   بہتری +15%، بے دخلی cooldown 600 s)؛
3. فیصلہ لاگو: `AddCandidate` → امیدوار ڈائل کریں؛
   `Replace` → بے دخل پیر بند کریں (ایک بار — تدریجی، کوئی
   لوپنگ نہیں) پھر متبادل ڈائل کریں؛
4. ایک **میٹرکس** اسنیپ شاٹ لاگ ہوتی ہے (INFO سطح):
   معروف/کنیکٹڈ/آمد/رفت/سرکٹ/محفوظ گنتیاں،
   اوسط/میڈیان RTT، الگ IP بکٹس، زیادہ سے زیادہ ارتکاز، churn
   (تبدینیاں/منقطعیں)۔

محلے کا اسکور کبھی اعتماد کا پیمانہ نہیں (`scone-topology`
دستاویزات دیکھیں): کوئی کنسنسس فیصلہ اس سے اخذ نہیں ہوتا۔

### پہنچ (AutoNAT) اور ٹرانسپورٹ ریلے (سرکٹ ریلے v2)

ہر ریلے AutoNAT چلاتا ہے (کلائنٹ + سرور): نوڈ اپنے پیرز سے
اپنی طرف واپس ڈائل کی کوشش مانگتا ہے؛ فیصلہ (`reachable`: ہاں =
باہر سے قابلِ رسائی، نہیں = NAT کے پیچھے، نامعلوم = ابھی
ٹیسٹ نہیں) ہر 5 منٹ تازہ ہوتا ہے اور `NodeStatus` میں ظاہر
(فیلڈ `nat_reachable`، وائر varint 0/1/2) — CLI دکھاتی ہے
(`scone status`)۔ نجی پتے شمار
ہوتے ہیں (`only_global_ips = false`): ایک LAN میش اپنی LAN
پہنچ جانچتی ہے۔

قابلِ رسائی ریلے سرکٹ ریلے v2 **hop** فعال کرتا ہے (یہ NATed
پیرز کے لیے ٹریفک ریلے کر سکتا ہے) اور **DCUtR** (ہول پنچنگ:
سرکٹ کے ذریعے جڑے دو نوڈ براہِ راست کنکشن کی کوشش کرتے ہیں اور
ریلے آزاد کرتے ہیں)۔ NATed فیصلہ ہونے والا ریلے پہلے معروف
قابلِ رسائی پیر سے تحفظ مانگتا ہے اور اس کے ذریعے سنتا ہے (پتہ
`/p2p/<relay>/p2p-circuit`)۔

پیداوار قاعدہ: ریلے شدہ NATed نوڈ بلاک
پیدا کار نہیں بننا چاہیے (گرادی شدہ تاخیر/دستیابی) — PoS قاعدہ (سیٹ =
زندہ ڈومین) ابھی اسے منع نہیں کرتا؛ عوامی ٹیسٹ نیٹ سے پہلے
عملی ضرورت کے طور پر دستاویز کرنا ہے۔

## ٹرانسپورٹ اور libp2p پروٹوکولز

| پروٹوکول | نام | کردار |
|---|---|---|
| QUIC (quic-v1) | — | مرکزی ٹرانسپورٹ (udp) |
| identify | `/scone/id/1` | پیر پتے کی دریافت (Kademlia ٹیبل بھرتا ہے) |
| ping | libp2p معیاری | زندگی |
| Kademlia | `/scone/kad/1` | DHT: کلید = `DomainId` (32 B)، قیمت = `SignedDnsRecord` کی کیننیکل انکوڈنگ |
| request-response | `/scone/reqres/1` | scone-protocol ایپلیکیشن پیغامات |

### ایپلیکیشن فریم (`/scone/reqres/1`)

ہر فریم `len: u32 BE || bytes` ہے جہاں بائٹس
`scone-protocol` کے `Message` کی کیننیکل انکوڈنگ ہیں (موجودہ
کوڈیک — کوئی دوسرا فارمیٹ نہیں)۔ لمبائی کسی بھی پڑھائی یا مختص سے
پہلے `limits::MAX_MESSAGE_LEN` سے **بندھی** ہے: بڑا فریم اعلان
کرنے والا پیر صفر میموری لاگت پر مسترد ہے۔

تبادلہ شدہ پیغامات (فی درخواست/جواب راؤنڈ ٹرپ ایک):

| پیغام | سمت | جواب |
|---|---|---|
| `Hello { version }` | ہینڈ شیک | `Hello` (مقامی ورژن) |
| `Ping` / `Pong` | زندگی | `Pong` |
| `GetBlock { hash }` | سوال | `Block` (RAM ونڈو) یا نامعلوم پر `Pong` |
| `GetBlocks { start, max }` | سنک | **ایک** `Block` (اونچائی `start`)، یا نہ ہو تو `Pong` |
| `Block (b)` | بلاک ریلے | `Pong` (ack) |
| `Transaction (tx)` | tx ریلے | `Pong` (ack) |
| `GetRecord { domain_id }` | مقامی DHT | `Record` (مقامی کیش) یا `Pong` |
| `Record (r)` | اشاعت | قبول پر `Pong`، ورنہ خرابی |

قاعدہ: **فی درخواست بالکل ایک جواب**؛ تصدیقی پیغامات
`Pong` ہیں۔ سنک جواب ایک وقت میں ایک بلاک لے جاتے ہیں — طرفے کی
جانب پکڑ_ITERATE کرتا ہے ("سنک" دیکھیں)۔ یہ جان بوجھ کر
محدود ہے: فی پیر ایک سے زیادہ بلاک ہوا میں کبھی نہیں۔

## ریلے رویہ

### اسٹارٹ اپ

0. نیٹ ورک حل (`--network testnet|mainnet|devnet`، جبکہ پروجیکٹ
   dev میں ہے ڈیفالٹ ٹیسٹ نیٹ — M8b)۔ ڈیٹا ڈائر **فی
   نیٹ ورک** ہے (`~/.scone/<network>/`): غیر خالی اسٹور جو کسی
   دوسرے نیٹ ورک کی چین رکھتا ہو مسترد (`Corrupted`)؛
1. redb اسٹور کھولیں/بنائیں (`<data-dir>/chain.redb`)؛
2. `load_chain(store, network)`: O(1) ٹِپ + صفحہ وار ڈومین اسٹیٹس
   (RAM ونڈو: جنسیس + ٹِپ)؛
3. سوارم تعمیر (فی سیشن عارضی Ed25519 شناخت —
   نیٹ ورک شناخت محفوظ کرنا کھلا فیصلہ)؛
4. بوٹ فہرست ترتیب دیں (دیکھیں
   [پیر دریافت](#پیر-دریافت)): واضح `--bootstrap`
   (آخر `/p2p/<peer-id>` پر ختم ہو) ورنہ نیٹ ورک کے ایمبیڈڈ
   seeds ورنہ سیکھی ڈائریکٹری (`peers.json`)؛
5. ہر multiaddr ڈائل کریں اور Kademlia ٹیبل میں رجسٹر کریں
   (مردہ ڈائل نظر انداز — باقی نیٹ ورک بناتے ہیں)۔

### ٹرانزیکشن وصول کرنا (P2P یا CLI جمع کروانا)

1. سخت محدود ڈی کوڈنگ (`MAX_MESSAGE_LEN`)؛
2. مکمل خفیہ تصدیق (`validate_transaction`:
   مالک/کلید بندھن، کیننیکل پے لوڈ پر `verify_strict`)؛
3. **اینٹی ری پلے پہلے** (سستا، اسٹیٹ سے آزاد، حتمی)،
   پھر اسٹیٹ پری چیک (`push_block` قواعد کا سستا عکس —
   PoW، جو مہنگا ہے، صرف push وقت پر تصدیق ہوتا ہے): دوبارہ
   چلی `RenewDomain` `TxReplay` جواب دیتی ہے، جھوٹی PoW
   خرابی نہیں (اس کا ثبوت اُس میعاد سے بندھا ہے جو پہلی اطلاق آگے
   لے گئی)۔ نیٹ ورک
   علیحدگی مرحلے 2 پر نافذ ہے: دستخط پے لوڈ ریلے کا
   نیٹ ورک ڈالتا ہے، کہیں اور دستخط شدہ tx
   `InvalidSignature` سے ناکام (وائر 2026-09: اب کوئی `network`
   فیلڈ نہیں)؛
   `RegisterDomain` → رجسٹرڈ نام کی TLD
   (ورنہ `UnknownTld`، D1/M7c) **اور کھلی** (ورنہ
   `TldClosed`، M8b) پھر نام آزاد؛ `UpdateDomain` → معروف ڈومین،
   بالکل sequence `current + 1`، مالک؛ `RegisterTld` → آزاد TLD؛
   `TransferTld`/`RevokeTld`/`SetTldOpen` → معروف TLD + مالک
   دستخط کنندہ؛ `AssignDomain` → TLD مالک + آزاد نام؛
   `RenewTld` → معروف ذاتی TLD + مالک، مقررہ مدت دوبارہ اخذ، مہلت کھڑکی پری چیک؛ `RenewDomain` → معروف ڈومین + مالک، تجدید PoW پری چیک
   (موجودہ میعاد سے بندھا) اگلی اونچائی پر؛
4. mempool داخلہ (مقررہ گنجائش، `TxId` سے ڈی ڈپ —
   پول میں موجود tx دوبارہ جمع کرنا no-op)؛
5. پیرز کو نشریات (بھیجنے والے کے سوا)۔

### بلاک وصول کرنا (P2P، سنک، یا خود پیدا شدہ)

1. `push_block`: موجودہ مکمل تصدیق (والد = کیننیکل ٹِپ،
   اونچائی، دوبارہ حساب شدہ Merkle جڑ، ہر ٹرانزیکشن تصدیق پھر
   لاگو — فی بلاک ایٹمی)؛
2. قبول پر: ریلے اطلاق کا نتیجہ پڑھتا ہے
   (`push_block_with_gc` → ہیش + متعین GC کے ہٹائے ہوئے
   ڈومینز) اور `store_block_with_removals` کے ذریعے محفوظ کرتا
   ہے (ایٹمی ڈیلٹا اپینڈ: بلاک + ٹِپ + تبدیل شدہ اسٹیٹس — اپسرٹس
   اور ہٹاؤ: ختم شدہ ڈومینز، منسوخ TLDs)۔ ری سٹارٹ اس لیے
   کبھی ختم شدہ رجسٹریشن بحال نہیں کر سکتا؛
3. mempool حساب (شامل txs ہٹا دیے جاتے ہیں)؛
4. پیرز کو نشریات (بھیجنے والے کے سوا)۔

غلط بلاک ٹائپ شدہ خرابی سے مسترد؛ ریلے چلتا
رہتا ہے۔ نیٹ ورک ڈیٹا پر کوئی panic نہیں۔ بھاری اطلاق (Argon2 +
redb commit) `tokio::task::block_in_place` سے گزرتے ہیں (سنک
ڈرائیور، p2p قبول، پیداوار): رن ٹائم تیار کامز دوسرے
ورکرز پر ہٹا دیتا ہے — بلاک لاگو کرنا DNS خدمت یا
میٹرکس کو اب رکٹ نہیں کرتا۔

### DNS اسنیپ شاٹ (اشاعت)

ہر لاگو شدہ بلاک کے بعد (p2p قبول — ری آرگس سمیت —، سنک
ڈرائیور، پیداوار) اور بوٹ پر (ری سٹارٹ اگلے بلاک تک زندہ
ناموں کو NXDOMAIN نہیں کر سکتا)، ریلے DNS سطح کے پڑھے گئے
`watch` فیڈ پر **مستند DNS اسنیپ شاٹ** شائع کرتا ہے (مکمل تفصیل
`dns.md` میں):

- ٹِپ توسیع (زبردست اکثر پاتھ): **O(چھوئے گئے) ڈیلٹا**،
  copy-on-write — بلاک کی ٹرانزیکشنز چھوئی گئی
  ڈومینز نام لیتی ہیں، مزید متعین GC ہٹاؤ
  (`AppliedBlock.gc_removed_domains`، push وقت پر جانچے گئے)؛
- ری آرگ / بوٹ: **مکمل دوبارہ تعمیر** (ایک صفحہ وار
  `ChainState::dns_facts` واک)۔

### بلاک پیداوار (M5: دستخط شدہ پیدا کار)

ہر `produce_interval` سیکنڈ (ڈیفالٹ 2 s): اگر mempool
غیر خالی ہے، ایک بلاک `BlockBuilder` کے ذریعے اسمبل ہوتا ہے
(`timestamp = اب`) **مجاز پیدا کار کے دستخط شدہ** (پے لوڈ
`SCONE-BLOCK-V1` در `header.consensus`، دیکھیں
`/docs/en/technical/blockchain.md`) اور وصول شدہ بلاک کے
قبولے کے پاتھ کی بالکل پیروی کرتا ہے۔ بغیر tx والا ریلے کچھ
پیدا نہیں کرتا۔

پیداکاری کلید: اینکر کلید (`--anchor-key`) جب ریلے
مسلح ہو — اینکر ایک مجاز پیدا کار ہے — ورنہ
مقررہ ڈیو نیٹ کلید، جب تک پیدا کار پول خالی ہے درست
(کھلا بوٹ اسٹریپ: جنسیس)۔ جیسے ہی کوئی زندہ ڈومین/TLD موجود،
ڈیو نیٹ کلید سے دستخط شدہ بلاک مسترد (`InvalidProducer`)۔

### اینکر لوپ (فائنلٹی، M5)

`--anchor-key` کے ساتھ (`.sconekey` کلیدی فائل، پاس فریز
`--anchor-passphrase-env` کے ذریعے، ڈیفالٹ `SCONE_ANCHOR_PASS` —
`scone-network` لائبریری ڈیفالٹ `SCONE_ANCHOR_PASSPHRASE` تک
بائنری کے ذریعے کبھی نہیں پہنچتا، clap ہمیشہ اسے override کرتا
ہے):

- ہر قبول/پیدا شدہ بلاک کے بعد، اگر یہ نوڈ موجودہ کمیٹی کا رکن
   ہو **اور** کمیٹی
   `MIN_FINALITY_COMMITTEE_SIZE` تک پہنچے، ریلے اپنے
   `SignerGuard` کے ذریعے تجویز شدہ
   چیک پوائنٹ پر دستخط کرتا ہے (ڈیٹا ڈائر میں `signer-state.dat`
   — ایک کلید = ایک ووٹ/epoch، crash-محفوظ fail-closed) اور
   اسے گوسپ کرتا ہے؛
- موصول دستخط (`Message::Checkpoint`) `CheckpointData` ہیش کے
   ذریعے جمع ہوتے ہیں (256 اندراجات تک محدود)؛ اسی
   ڈیٹا پر `quorum_for(committee size)` ممبر دستخطوں پر →
   `accept_checkpoint` + فائنل شدہ
   چیک پوائنٹ کی نشریات؛
- اینکر کلید کے بغیر ریلے **غیر فعال** رہتا ہے: جمع کرتا،
   فائنل کرتا، ریلے کرتا ہے، مگر کبھی دستخط نہیں؛
- `GetCheckpoints` → `checkpoint_window()` ونڈو دی جاتی ہے؛
- کوئی بھی لوپ خرابی لاگ اور نگل لی جاتی ہے — کبھی مہلک نہیں؛
- اسٹیٹس (`GetStatus`) `checkpoints` اور `finalized_epoch` ظاہر
   کرتا ہے۔

### فورک پارکنگ اور ری آرگس (sticky-minority درستگی)

اسی اونچائی پر بہن بلاک، یا جس بلاک کا والد موجودہ
ٹِپ نہیں (`ParentNotTip`/`UnknownParent`)، کبھی کھویا نہیں
جاتا: یہ **پارک** کر دیا جاتا ہے (محدود میپ، `PARKED_CAP = 2048`
بلاکس، ہر ایک ~KiB — محدود بدترین RAM؛ مکمل پارکنگ نئے آنے
والوں کو خاموشی سے نظر انداز کرتی ہے)۔ `accept_block` کو پہلے
ہی پیش کی گئی ہیشز ڈی ڈپلیکیٹ ہوتی ہیں (`seen_blocks`): دوبارہ
گوسپ شدہ ہارنے والا بلاک دوبارہ جانچا نہیں جاتا۔

ہر `Produce` ٹک پر، `reconsider_parked`:

1. پارک شدہ بلاکس کی لکیری نکاسی جن کا والد ٹِپ بن گیا؛
2. اگر کوئی پارک شدہ برانچ موجودہ ٹِپ سے مضبوط ہو (فورک چوائس
   قواعد بے تبدیل: فائنلٹی فرش، طویل ترین چین، سب سے کم ہیش)،
   اپنانا — بے دخل شدہ سفکس خود پارک ہوتا ہے (فورک کی
   دونوں طرفیں جانچی جاتی رہتی ہیں)۔

یہ اُس نوڈ کو غیر چسپاں کرتا ہے جس نے برابر اونچائی
فورک کا ہارنے والا طرف اپنایا: جیتنے والا بلاک، ایک بار پیش پھر
مسترد، دورهانجامی طور پر دوبارہ جانچا جاتا ہے بجائے ہمیشہ کے
لیے بھول جانے کے
(کیاوس-30 کی دریافت: دو بہن بلاکس 15 ms کے فاصلے پر)۔

**ری آرگ استقامت**: دوسری برانچ اپنانا یک طرفہ اپینڈ سے نہیں
گزر سکتا (`NonMonotonicHeight`)۔ ریلے
`rewind_to_height(فورک نقطہ)` پھر `persist_state_snapshot`
(چین کی ایکسپورٹ سے زندہ اسٹیٹ کی دوبارہ لکھائی) پھر جیتنے
والے سفکس کا یک طرفہ دوبارہ اپینڈ لگاتا ہے (دیکھیں `storage.md`)۔
استقامت ناکامی لاگ اور کم درجہ (بوٹ پر ری پلے کے ذریعے شفا) —
کبھی مہلک نہیں۔

## سنک (پکڑ)

ہر پیر سے کنکشن پر، ریلے
`GetBlocks(start = مقامی اونچائی + 1)` مانگتا ہے۔ ہر موصول
`Block` جو متوقع اونچائی بالکل مکمل کرے اگلی
اونچائی کی درخواست متحرک کرتا ہے، تھکاؤ (`Pong` = کچھ نہیں) یا
`MAX_SYNC_ROUNDS` (10,000) بیچز تک — جھوٹے پیر کے خلاف بھی
مطلق حد۔ موصول بلاکس مکمل تصدیق سے گزرتے ہیں: معاندار
پیر کچھ بھی غلط قبول نہیں کروا سکتا۔

### ریکارڈ DHT

- **put** (API/web فلو — CLI ہیکس چینل ہٹا دیا گیا): سخت محدود ڈی کوڈنگ
  (`MAX_DHT_CACHE_ENTRY`)، آن چین اسٹیٹ کے خلاف تصدیق
  (مالک، sequence، دوبارہ حساب شدہ `record_hash` — دیکھیں "ریکارڈ
  تصدیق")، پھر `kad.put_record` (مقامی اسٹوریج +
  قریب ترین پیرز تک نقل، نقل فیکٹر کا `Quorum::Majority`) اور
  پائیدار redb کیش۔
- **get** (`domain resolve`): `kad.get_record`؛ منتظر اپنے
  `QueryId` اور مانگی `DomainId` سے بندھا ہے — ایک جواب صرف
  میچنگ سوال حل کرتا ہے، اور ریکارڈ کلید بالکل
  مانگی گئی ڈومین ہونی چاہیے (آن چین تصدیق سے **پہلے** چیک)۔
  نتیجہ پھر واپس کرنے سے پہلے چین کے خلاف تصدیق ہوتا ہے۔ بیک وقت
  درخواستوں کی کیپ: `MAX_DHT_WAITERS` (256)؛
  اس سے آگے، فوری خرابی۔ کامیاب تصدیق شدہ ریزولوشن
  پائیدار کیش میں لکھا جاتا ہے (M5): مقامی پڑھائی
  (`domain_info`) پھر نئے DHT سوال کے بغیر خدمت دیتی ہے۔
- Kademlia سرور موڈ میں چلتا ہے، کوئی ریکارڈ TTL نہیں (چین
  درستگی کی حاکم ہے، وقت نہیں)۔

### ریکارڈ تصدیق ("چین ہی اختیار ہے" قاعدہ)

حل شدہ یا موصول `SignedDnsRecord` صرف اُس صورت قبول/واپس ہوتا
ہے:

1. ڈومین آن چین رجسٹرڈ ہو؛
2. `record.owner` = موجودہ آن چین مالک؛
3. `record.sequence` = موجودہ آن چین sequence؛
4. `record_hash(record.record)` (دوبارہ حساب شدہ BLAKE3) =
   آن چین commit شدہ `record_hash`۔

ورنہ: P2P طرف خاموش انکار، CLI طرف واضح خرابی۔ ریکارڈ کا Ed25519
دستخط ریلے کی جانب سے **وصولی پر تصدیق** ہوتا ہے
(`ResolveLocal`: مالک کی عوامی کلید آن چین معلوم، دستخط کھلنا
چاہیے — دوسری کلید سے دستخط شدہ ریکارڈ مسترد، `record rejected`)؛
یہ مستقبل کے تصدیق کاروں کے لیے بھی لے جایا جاتا ہے — آن چین
commitment بنیادی
سالمیت کنٹرول رہتا ہے۔

## Prometheus میٹرکس

ایک HTTP اینڈ پوائنٹ (Prometheus متن فارمیٹ 0.0.4، ہاتھ سے بنی
exposition — کوئی نیا انحصار نہیں) ایک مخصوص کام سے خدمت
پاتا ہے:

- **بذریعہ ڈیفالٹ بند**: `--metrics-addr` کے بغیر کوئی HTTP سرور نہیں چلتا (میٹرکس آپٹ ان ہیں)۔
- `--metrics-addr ADDR:PORT`: اُس پتے پر اینڈپوائنٹ باندھتا ہے (مثلاً مقامی `127.0.0.1:9101`، بیرونی `0.0.0.0:9101`)۔
- `--metrics-token TOKEN`: **نجی** موڈ پر سویچ —
  `Authorization: Bearer *** required (مستقل وقت
  موازنہ، ورنہ `401`؛ ٹوکن کبھی لاگز میں یا exposition میں
  ظاہر نہیں)۔
- بائنڈ ناکامی **اینڈ پوائنٹ بند** کر دیتی ہے (غیر مہلک تنبیہ) —
  کبھی نوڈ نہیں۔

مؤثر بائنڈ stdout پر اعلان ہوتا ہے (مشین پڑھنے کے قابل
معاہدہ، `p2p:` کی طرح): سنتے ہی ایک `metrics: <addr>` لائن۔

**19 کاؤنٹرز** (`counter`، یک طرفہ بڑھتے — ہاٹ پاتھز:
مشترکہ `Arc<Metrics>` پر `fetch_add(Relaxed)`، کبھی
کنسنسس ان پٹ نہیں):

| گروہ | سیریز |
|---|---|
| چین | `scone_blocks_applied_total`، `scone_blocks_rejected_total`، `scone_checkpoints_signed_total`، `scone_checkpoint_sigs_received_total` |
| Mempool | `scone_txs_admitted_total`، `scone_txs_rejected_total`، `scone_txs_evicted_grace_total`، `scone_txs_included_total` |
| DNS | `scone_dns_queries_total`، `scone_dns_cache_hits_total`، `scone_dns_cache_misses_total`، `scone_dns_local_chain_total`، `scone_dns_dht_answers_total`، `scone_dns_rejected_unverified_total` |
| DHT | `scone_dht_pulls_issued_total`، `scone_dht_negative_hits_total`، `scone_dht_negative_expired_total`، `scone_dht_negative_capped_total`، `scone_dht_cache_evictions_total` |
| پیر نیٹ ورک | `scone_peer_connections_established_total`، `scone_peer_connections_closed_total`، `scone_peer_connections_incoming_total`، `scone_peer_dial_failures_total`، `scone_peer_blocks_received_total`، `scone_peer_transactions_received_total` |

**6 گیجز** (`scone_height`، `scone_mempool`، `scone_peers`،
`scone_domains`، `scone_finalized_epoch`، `scone_addr_book_entries`)
— پہلے پندرہ `RelayCommand` چینل کے ذریعے ہر 15 s تازہ
(CLI `status` جیسا پاتھ — سچائی کا اکلوتی ذریعہ)؛
`scone_addr_book_entries` رجسٹری براہِ راست دیکھتی ہے
(ہر ایڈریس بک داخلے پر اپ ڈیٹ)۔

E2E ٹیسٹ: `metrics_endpoint_public_and_private` (200 +
exposition، غلط ٹوکن کے بغیر/ساتھ 401، Bearer کے ساتھ 200)۔

## CLI کنٹرول (RPC→p2p یکساں کاری)

JSON TCP RPC سرور **ہٹا دیا گیا** ہے: CLI (اور رجسٹرار کا
axum پل) p2p پروٹوکول **براہِ راست** بولتی ہے —
وہی وائر (`/scone/reqres/1`)، ریلے کی طرف وہی ہینڈلرز،
صفر متوازی چینل۔ ہر کمانڈ نوڈ کے multiaddr (`--peer`) پر ایک QUIC
کنکشن کھولتی ہے، ایک `Message` کا تبادلہ، بند۔

ریلے کی خدمت کردہ کنٹرول پیغامات:

- `GetStatus` → `NodeStatus { network, nat_reachable, tip,
  height, domain_count, mempool, peers, finalized_epoch,
  checkpoints, fresh_operators }` (`scone status` کا دکھایا —
  `fresh_operators` = تازہ ہارٹ بیٹ والے آپریٹرز، RFC
  proof-of-service)؛
- `LookupName { name }` → `NameState` (آن چین اسٹیٹ، جیسے
  `lookup`)؛
- `GetOwnedNames { owner }` → `OwnedNames` (ایک `OwnerId` کی
  زندہ ڈومینز + TLDs)؛
- `Transaction (tx)` → مفت گوسپ کے ساتھ جمع کروانا (ریلے
  پیرز کو دوبارہ نشریات کرتا ہے)؛
- `GetRecord { domain_id }` / `Record (r)` — DHT ریزولوشن اور
  اشاعت (CLI طرف `scone domain resolve` جیسا)؛
- ایپلیکیشن انکار → `Message::Error(msg)` (کلائنٹ
  تک پڑھنے قابل پیغام پہنچتا ہے، EOF نہیں)۔

کلائنٹ ایک کم سے کم libp2p سوارم لاتی ہے (request-response +
identify)، 30 s کال ٹائم آؤٹ (20 s راؤنڈ ٹرپ)۔ ڈیفالٹ `--peer`:
`/ip4/127.0.0.1/udp/4001/quic-v1/p2p/12D3KooW…` (مقامی dev نوڈ؛
حقیقی پیر id کے ساتھ مکمل multiaddr ریلے
stdout پر `p2p:` لائن کے ذریعے اعلان کرتا ہے)۔

اندرونی `RelayCommand` چینل ایمبیڈڈ DNS
سطح کے لیے زندہ رہتا ہے (`ResolveLocal`، ایک ان-پروسیس راؤنڈ
ٹرپ، کبھی DHT منتظر نہیں — دیکھیں `dns.md`)۔

### ماحول کنفیگریشن (`.env`)

اسٹارٹ اپ پر، `scone` (dotenvy کے ذریعے، clap پارسنگ سے پہلے)
موجودہ ڈائریکٹری سے ایک
`.env` فائل لوڈ کرتا ہے: غائب فائل = خاموش no-op، کبھی خرابی
نہیں۔ لوڈ شدہ قیمتیں ان آپشنز کی **ماحولی بنیاد** بنتی ہیں جو
متغیر کا اعلان کرتے ہیں (`cli.rs` میں `env = "…"`)؛ **واضح CLI
فلیگ ہمیشہ `.env` پر جیتتا ہے**، اور `.env` بلٹ اِن ڈیفالٹس پر:

```text
explicit CLI flag  >  .env variable  >  built-in default
```

ریپوزٹوری روٹ پر `.env.example` فائل ہر
متغیر دستاویز کرتی ہے (`.env` میں کاپی کر کے ایڈجسٹ کریں؛ `.env`
**gitignored** ہے — حقیقی `.env` کبھی commit نہ کریں)۔ متغیرات:

| متغیر | عکس فلیگ | معنی |
|---|---|---|
| `SCONE_NETWORK` | `--network` | `testnet` (ڈیفالٹ)، `mainnet`، `devnet` |
| `SCONE_DATA_DIR` | `--data-dir` | ڈیٹا ڈائریکٹری (ڈیفالٹ `~/.scone/<network>/`) |
| `SCONE_LISTEN` | `--listen` | P2P سننے کا multiaddr (ڈیفالٹ: تمام انٹرفیس، عارضی پورٹ) |
| `SCONE_BOOTSTRAP` | `--bootstrap` | bootstrap seeds، **دہرایا جانے والا** (فی قیمت ایک لائن — dotenvy جمع کرتا ہے)؛ builtin seeds کی جگہ لیتا ہے |
| `SCONE_GENESIS` | `--genesis` | جنسیس فائل (بانی نوڈز) |
| `SCONE_MDNS` | `--mdns` | LAN mDNS دریافت (`true` = فعال، `false` = آف؛ ڈیفالٹ: ڈیو نیٹ پر آن، باقی جگہ آف) |
| `SCONE_UPNP` | `--upnp` | UPnP پورٹ میپنگ (`true` = فعال) |
| `SCONE_DNS_ADDR` | `--dns` | UDP DNS سرور بائنڈ پتہ |
| `SCONE_DNS_UPSTREAM` | `--dns-upstream` | ریکرسو فال بیکس، **دہرایا جانے والا** |
| `SCONE_DNS_CACHE_LIMIT` | `--dns-cache-limit` | DNS کیش اندراج کیپ |
| `SCONE_DNS_CACHE_MAX_MEM` | `--dns-cache-max-mem` | DNS کیش میموری کیپ (مثلاً `64MB`) |
| `SCONE_DNS_MAX_INFLIGHT` | `--dns-max-inflight` | بیک وقت DNS سوال کیپ |
| `SCONE_METRICS_ADDR` | `--metrics-addr` | metrics endpoint address (`ADDR:PORT`)|
| `SCONE_METRICS_TOKEN` | `--metrics-token` | میٹرکس اینڈ پوائنٹ bearer ٹوکن |
| `SCONE_TOPOLOGY_PROFILE` | `--topology-profile` | ٹوپولوجی پروفائل (`tiny`/`small`/`default`/`high`/`very-high`/`devtest`؛ ڈیفالٹ `default`) |
| `SCONE_ANCHOR_KEY` | `--anchor-key` | اینکر کلیدی فائل (چیک پوائنٹ + پیداوار) |

`SCONE_ANCHOR_PASS` کسی متغیر کا آپشن نہیں: یہ **اینکر پاس فریز
رکھنے والے متغیر** کا ڈیفالٹ
نام ہے (`--anchor-passphrase-env`، CLI سطح پر ڈیفالٹ
`SCONE_ANCHOR_PASS`) — ریلے پاس فریز اُس متغیر سے پڑھتا ہے جس کا
یہ فلیگ نام بتاتا ہے۔

**اینکر آٹو (ڈیفالٹ آن)**: `--anchor-key` کے بغیر، ایک اینکر
کلیدی فائل ڈیٹا ڈائر میں خودکار طور پر بنی/محفوظ ہوتی ہے
(`anchor.sconekey`، پاس فریز `SCONE_ANCHOR_PASS` اگر تعریف شدہ،
ورنہ بے ترتیب پیدا اور `anchor.pass` میں لکھی) — ریلے جیسے ہی
اس کی کلید کے پاس زندہ
ڈومینز/TLDs ہوں پیدا کار بن جاتا ہے (PoS اہلیت کبھی مفت نہیں)۔
`--no-anchor-auto`
ریلے کو سخت غیر فعال رکھتا ہے۔ `--anchor-passphrase-env` کا
ڈیفالٹ env متغیر `SCONE_ANCHOR_PASS` ہے۔

`--network`: ڈیفالٹ BUILD کی پیروی کرتا ہے (mainnet-کندہ
بائنریز پر mainnet، ورنہ testnet)؛ `devnet` وہ
ری سیٹ قابل مقامی نیٹ ورک ہے (اپنی
`scone-devnet` جنسیس، تقریباً صفر 0..=2 بٹ PoW — `~/.scone/devnet/`
مٹا کر دوبارہ چلانا چین ری سیٹ کرتا ہے)۔ جنسیس، PoW مشکلیں، اور ڈیفالٹ
ڈیٹا ڈائر (`~/.scone/<network>/`) سیٹ کرتا ہے؛ دوسرے نیٹ ورک کی tx
ٹائپ شدہ طور پر مسترد (`WrongNetwork`)۔

آف لائن ہیکس سطح (`tx` اور `submit` ذیلی کمانڈز) ختم
(remove-tx-surface-v2)۔ CLI صارف پاتھز (`domain register`،
`domain renew`، `domains`) اور M8b
خاندان پہلے درجے کی کمانڈز کے طور پر ڈھانکتی ہے: `tld open`،
`tld transfer`،
`tld revoke`، `domain assign`، `domain transfer`۔
`register` دعوے اپنی PoW نیٹ ورک مشکل پر مائن کرتے ہیں
(ڈیو نیٹ پر ملی سیکنڈ)۔

`--geo-*`/`--health-*` آپشنز ایمبیڈڈ DNS ریزالور کی GeoDNS اور
health جانچ کنفیگر کرتے ہیں: مکمل معنی،
ترجیح ترتیب، اور مقامی GeoIP ٹیبل [`dns.md`](dns.md#geodns-geographic-routing)
میں دستاویز شدہ — جغرافیائی روٹنگ **ہمیشہ آن** ہے (ایمبیڈڈ
GeoIP ٹیبل، کوئی آپشن ضروری نہیں)؛
`--health-check` بطور ڈیفالٹ آف، کلاسک پاتھ بے تبدیل۔

### `domain register|update` (M5) — ایک کمانڈ میں دستخط شدہ ٹرانزیکشنز

یہ کمانڈز ایک ہی طلب میں زنجیر بن → دستخط (keystore) → جمع کروانا →
(تصدیق) چلاتی ہیں۔

- **register**: ایک دستخط شدہ `RegisterDomain` بناتی ہے (timestamp
  = اب، ڈیو نیٹ میں خالی ثبوت)، جمع کراتی ہے، آن چین
  تصدیق کا انتظار (sequence ≥ 0، 30 s ٹائم آؤٹ)۔ پہلے سے رجسٹرڈ
  نام کلائنٹ اور ریلے دونوں طرف مسترد۔
- **update**: ریکارڈز فائل اکلوتا سچائی کا ذریعہ ہے۔ sequence
  (آن چین + 1) اور `record_hash` (فائل کے ریکارڈز کی کیننیکل
  BLAKE3) **اخذ** ہوتے ہیں، کبھی دستی داخل نہیں: دستخط کنندہ اور
  تصدیق کاروں کا اختلاف ناممکن۔ UpdateDomain تصدیق کے بعد،
  `SignedDnsRecord` (فائل کے ریکارڈز + مالک + کیننیکل انکوڈنگ
  پر Ed25519 دستخط) `put_record` کے ذریعے DHT میں شائع ہوتا ہے
  (جو چین کے خلاف دوبارہ تصدیق کرتا ہے)۔ غیر رجسٹرڈ ڈومین، غیر
  مالک شناخت، یا فائل خرابی صاف ناکام، چین چھوئے بغیر۔

#### ریکارڈز فائل

متن، فی لائن ایک ریکارڈ، `#` = تبصرہ، خالی لائنیں نظر انداز؛
ترتیب شدہ کیننیکل انکوڈنگ فائل کی ترتیب کا commit شدہ ہیش پر
کوئی اثر نہیں رکھتی۔ فائل مکمل سیٹ ہے (اپ ڈیٹ بدلتی ہے، ملاتی
نہیں)۔ اقسام:

```text
A 192.0.2.1
AAAA 2001:db8::1
CNAME www.example.uip
NS ns1.example.uip
MX 10 mail.example.uip
TXT free text (spaces normalized)
```

ٹائپ شدہ خرابیاں: نامعلوم قسم، غلط IP/نام (لائن نمبر کے ساتھ)،
خالی سیٹ، ڈپلیکیٹ، > `MAX_RECORDS_PER_SET`۔

## `--genesis` (بانی)

`scone relay --genesis genesis.bin` — **صرف بانی نوڈز**
(kickstarter مہم؛ فائل `scone-genesis`
بائنری بناتی ہے)۔ نافذہ قواعد:

1. فائل پڑھنے سے **پہلے** مسترد ہے اگر 1 MiB سے بڑی،
   پھر سخت ڈی کوڈ (`decode_complete`: کوئی آخری بائٹس نہیں)۔
   بلاک 0 کا ہیش **دوبارہ حساب** ہوتا ہے، فائل سے کبھی نہیں پڑھا۔
2. معنوی تصدیق: اونچائی 0، `consensus` مانگے گئے نیٹ ورک کے
   network id (`--network`) سے شروع، کوئی ٹرانزیکشن نہیں،
   کیننیکل الاٹمنٹ مینی فیسٹ۔ کوئی بھی خلاف ورزی = اسٹارٹ اپ پر
   ٹائپ شدہ خرابی (کبھی panic نہیں، ڈیمن شروع نہیں ہوتا)۔
3. **کنواری** ڈیٹا ڈائر: چین الاٹ شدہ جنسیس پر پیدا ہوتی ہے —
   الاٹمنٹس کسی بھی ڈسک لکھائی سے **پہلے** RAM میں لاگو ہوتے
   ہیں، پھر محفوظ (سیڈ شدہ اسٹیٹس + میٹا کلید تلے جنسیس بلاک)۔
   پہلا پیدا شدہ بلاک اس لیے صرف الاٹ شدہ
   جنسیس کو بڑھا سکتا ہے۔
4. **پہلے سے پیداواری** ڈیٹا ڈائر: اسٹور کی پیدائشی جنسیس
   بلاک 1 کا `prev_hash` ہے (خود تصدیق)۔ برابر فائل ہیش = خاموش
   OK (آپشن پہلے اسٹارٹ اپ کے بعد **زائد** ہے)؛
   مختلف = ٹائپ شدہ انکار — کوئی نوڈ sync کے ذریعے نیٹ ورک میں
   شامل ہوتا ہے، کبھی `--genesis` سے نہیں۔
5. آپشن کے **بغیر** دوبارہ شروع: بانی پیدا شدہ ڈیٹا ڈائر میٹا
   کلید کے ذریعے اپنی الاٹ شدہ جنسیس بحال کرتا ہے (ہر
   بوٹ پر RAM دوبارہ بندھتا ہے)۔

مستقل جنسیس ہیش پن (نیٹ ورک اختلاف کے خلاف) ایک
الگ ورک اسٹریم ہے۔

### `scone-genesis` بائنری مینی فیسٹ (kickstarter)

`scone-genesis` بائنری (crate `scone-genesis`)
`genesis-manifest.json` مینی فیسٹ (`ALLOC-V1` فارمیٹ) تیار کرتی
ہے پھر `genesis.bin` بناتی ہے۔ نافذہ قواعد:

- `scone-genesis new --network <network>` خالی
  مینی فیسٹ بناتی ہے؛ `add`/`remove`/`list` الاٹمنٹس سنبھالتے
  ہیں، `build`
  `genesis.bin` بناتی ہے (+ ہیش)، `verify` اسے دوبارہ تصدیق کرتی
  ہے۔
- `add domain <name>` کے لیے ڈومین کی **TLD پہلے سے مینی فیسٹ
  میں الاٹ شدہ** ہونا ضروری (ورنہ فوری انکار — چین اسے جنسیس
  اطلاق پر مسترد کرتی)؛ اس کی `valid_until` **خودکار** ہے:
  `born_at + 1 سال` (مینی فیسٹ کی default_validity)، کبھی ہاتھ
  سے داخل نہیں۔
- `add tld <name>`: **بطور ڈیفالٹ کھلی** (کسی کی نہیں، خود سروس،
  1 سالہ فرور، وائر پر مالک = صفر — kind `0x03`)؛
  `--private` = ذاتی (مالک، جنسیس مدت `born_at +
  TLD_TERM_SECS` — 3 سال، معیاری زندگی: `RenewTld`،
  60 دن مہلت)۔
- نام کے مطابق کیننیکل ترتیب (برابر مواد → وہی بلاک → وہی ہیش،
  داخلے کی ترتیب جو بھی ہو)؛ ڈپلیکیٹس مسترد۔

## حدود اور میموری گارنٹیاں

| وسیلہ | حد |
|---|---|
| P2P فریم | پارسنگ سے پہلے `MAX_MESSAGE_LEN` (1 MiB) |
| Mempool | 4096 tx (اس سے آگے ٹائپ شدہ انکار)؛ فی ڈومین `MAX_PENDING_PER_DOMAIN = 4` زیر التوا txs |
| Mempool مہلت | `MAX_GRACE_ATTEMPTS = 10` کسی غیر حتمی وجہ سے flush شدہ tx کی دوبارہ داخلے (40 s/سائیکل پر ≈ 7 منٹ)، پھر بے دخلی |
| فورک پارکنگ | `PARKED_CAP = 2048` مقابل بلاکس |
| جمع شدہ چیک پوائنٹس | `MAX_PENDING_CHECKPOINTS = 256` (بے دخلی: سب سے چھوٹی ڈیٹا ہیش) |
| بیک وقت DHT منتظر | `MAX_DHT_WAITERS` (256)؛ DHT تلاش 30 s تک محدود (`DHT_LOOKUP_TIMEOUT`) |
| فی سنک جواب بلاکس | فی راؤنڈ ٹرپ 1؛ فی پیر ≤ 10,000 بیچز (`MAX_SYNC_ROUNDS`)؛ درخواست پر پروٹوکول حد `MAX_BLOCKS_PER_REQUEST = 128` |
| DHT ریکارڈ | `MAX_DHT_CACHE_ENTRY` (64 KiB) |
| پائیدار DHT کیش (ڈسک) | دوہری LRU حد: `DHT_CACHE_MAX_ENTRIES` (100,000 اندراجات) اور `DHT_CACHE_MAX_BYTES` (2 GiB) — جو پہلے لگے وہ کلید ترتیب سے بے دخل؛ GC بے دخلی بلاک کی اسی ٹرانزیکشن میں (چین GC کے مارے ہوئے ڈومین کبھی یتیم اندراج نہیں چھوڑتی) |
| DHT منفی کیش | `DHT_NEGATIVE_TTL_SECS` (30 s)، FIFO کیپ `DHT_NEGATIVE_CAP` (4,096) |
| RAM میں چین | جنسیس + ٹِپ ونڈو (تاریخ اسٹور سے دی جاتی ہے) |

اینٹی لوپ قاعدہ (H2): کوئی ٹرانزیکشن صرف اُس صورت دوبارہ
نشریات ہوتی ہے جب وہ واقعی mempool میں **داخل ہوئی** ہو (پہلی
نظر)؛ ڈپلیکیٹ
(پہلے سے پول میں یا چین میں) کبھی دوبارہ ریلے نہیں ہوتی۔
پہلے سے کیننیکل بلاک `push_block` سے پہلے پکڑا اور نظر انداز
ہوتا ہے (کوئی دوبارہ اسٹور نہیں، کوئی دوبارہ نشریات نہیں)۔

کھلے فیصلے: ریلے کی پائیدار نیٹ ورک شناخت، نشریات
گوسپ (فی الحال: ہر معروف پیر کو unicast درخواست-جواب)۔
ابتدائی تحریر سے حل شدہ: حقیقی فورک چوائس (پارکنگ +
reconsider_parked، اوپر دیکھیں)، PoW کنسنسس (دستخط شدہ پیدا کار +
اینکر کمیٹی)، DNS ریزالور (`--dns` سطح، دیکھیں
dns.md)، کنٹرول چینل (RPC→p2p یکساں کاری: اب کوئی JSON
TCP نہیں)۔

## شائستہ بند ہونا (SIGTERM / SIGINT)

`scone relay` ڈیمن (فور گراؤنڈ) `tokio::signal` کے ذریعے SIGTERM
اور SIGINT پکڑتا ہے: سگنل پر، `Relay::run` future منسوخ ہوتی
ہے (بائنری میں `tokio::select!`)، جو libp2p
Swarm گراتی اور QUIC ساکٹس بند کرتی ہے۔ پھر tokio رن ٹائم ایک
محدود بند ہونے (≤ 2 s) کے ساتھ رکتا ہے جو الگ
DNS کامز (UDP/TCP) گراتا اور ان کی ساکٹس بند کرتا ہے — ہدف یہ
ہے کہ ایک `kill` کوئی یتیم UDP ساکٹ نہ چھوڑے (ٹیسٹ نیٹ 60 پر
مشاہدہ)۔ سگنل سے چلنے والا بند ہونا `relay shutting down (signal)`
لاگ کرتا ہے (INFO،
stderr) اور ایگزیٹ کوڈ **0** سے نکلتا ہے: مانگی گئی بندش
ناکامی نہیں۔ اگر ہینڈلر نصب ناکام ہوا، سگنل کا ڈیفالٹ
روایہ لاگو ہوتا ہے (گراڈیشن، کبھی panic نہیں)۔


## Tor ٹرانسپورٹ (کھلا مسئلہ)

QUIC/UDP سادہ SOCKS پراکسیز پار نہیں کرتا، اس لیے ریلے آج
Tor پر آسانی سے نہیں چل سکتے۔ مقامی libp2p Tor ٹرانسپورٹ
(onion پتے والا ریلے) آگے کا ٹریک شدہ پاتھ ہے — موجودہ حالت اور
`.tor` CNAME پل (چھپی خدمات کے لیے پڑھنے قابل نام،
آج معاون) کے لیے ویب سائٹ کی سینسر شپ مزاحمت گائیڈ دیکھیں۔
