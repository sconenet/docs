# RFC — عمل کا ثبوت اور فائنلٹی کمیٹی (proof-of-service)

> حیثیت: نافذہ — سر تا سر نافذ (مرحلے 1 سے 5:
> core/protocol/blockchain/network/CLI؛ یہ دستاویز
> مرتب شدہ شکل ہے)۔ نیچے کا ہر قاعدہ کوڈ کے خلاف تصدیق شدہ ہے؛
> حوالے دی گئی مستقل مقداریں کوڈ شدہ قیمتیں ہیں۔
> تاریخ: اکتوبر 2026 (نافذہ تحریر)۔ متعلقہ:
> `scone-core`، `scone-protocol`، `scone-blockchain`،
> `scone-network`، `scone` (CLI)۔

## 1. وجہ

فائنلٹی پول مالکان کا پول ہے (زندہ ڈومینز/TLDs کے مالکان)۔
ملکیت سیٹ دیتی ہے — **آپریٹنگ** کچھ نہیں دیتی۔ یہ RFC چیک
پوائنٹس پر دستخط کے حق کو کسی آن لائن ریلے کے عمل کے ثبوت سے
جورتا ہے، بغیر کبھی ملکیت کو شرط بندے:

- **محفوظ آزادی**: ایک ذاتی TLD اپنی مدت تجدید (renew) رہنے تک
  بغیر کسی سرگرمی کی شرط کے قابلِ تخصیص رہتا ہے
  (`RenewTld`، 3 سالہ مدت)۔ صرف *چیک پوائنٹ دستخط* موجودگی سے
  کمایا جاتا ہے۔
- **آپریشن کی ترغیب**: ذاتی TLD (یا کوئی سیٹ) چلانا = کمیٹی
  میں بیٹھنا۔ آپریٹر نیٹ ورک کو زندہ رکھنے میں حصہ لیتا ہے
  اور پروٹوکول اسے تسلیم کرتا ہے۔
- **قابلِ پیمائش غیر مرکزیت**: کمیٹی اُن آپریٹرز کا مجموعہ بن
  جاتی ہے جو *واقعی آن لائن* ہیں، سوئے ہوئے کلیدیں نہیں۔

## 2. جائزہ

ایک ہلکی `Heartbeat` ٹرانزیکشن (ڈسکریمیننٹ `0x71`)،
ایک **آپریٹر** کلید کے دستخط شدہ، فی epoch ایک بار جاری۔ اسٹیٹ
حالیہ ہارٹ بیٹس کی پھسلتی کھڑکی رکھتی ہے۔ کسی epoch کی کمیٹی
پول کے اُس ذیلی سیٹ سے منتخب ہوتی ہے **جس کے مؤثر آپریٹر کے
پاس تازہ ہارٹ بیٹ ہو**۔ ہارٹ بیٹ کے بغیر: کوئی دستخط نہیں، مگر
ملکیتی حقوق کا نقصان بھی نہیں۔

## 3. Heartbeat ٹرانزیکشن

```
Heartbeat {
    operator: PublicKey,     // Ed25519 key of the operator (the signer)
    owner: OwnerId,          // identity RE-DERIVED from operator (never trusted)
    tip_seen: [u8; 32],      // last tip seen by the node
    height_seen: u64,        // corresponding height
    timestamp: u64,          // Unix seconds
} + Ed25519 signature over the canonical payload (network injected)
```

دستخط شدہ جسم (وائر، `scone-protocol`):
`operator[32] ‖ owner[32] ‖ tip_seen[32] ‖ height_seen.v ‖
timestamp.v ‖ operator[32]` (دستخط کنندہ کی کلید جسم کے دمے
میں آتی ہے، ہر tx کی طرح) `‖ signature[64]`، یعنی انکوڈ شدہ
تقریباً 230 بائٹس — **کوئی PoW نہیں**: لاگت مسلسل موجودگی ہے
(فی epoch ایک ہارٹ بیٹ، مہینوں تک)۔

دستخط کنندہ وہی آپریٹر ہے: `owner` ہمیشہ `operator` سے دوبارہ
اخذ ہوتا ہے (کبھی ان پٹ سے نہیں لیا جاتا)، اور ڈی کوڈنگ قسم
شدہ خرابی (`InvalidOwner`) کے ساتھ مسترد کرتی ہے وہ دستخطی کلید
جو سر (`head`) کے `operator` فیلڈ سے مختلف ہو۔

- `tip_seen`/`height_seen` مشاہدے کی خدمت کرتے ہیں (خراب یا
  پیچھے رہنے والے آپریٹرز کی دریافت)؛ یہ درستگی کو متاثر نہیں
  کرتے (ہلکی پیچھے رہنے والا نوڈ اب بھی زندہ نوڈ ہے)۔

### 3.1 خالص تصدیق (scone-core)

1. نیٹ ورک کے کیننیکل پے لوڈ پر درست Ed25519 دستخط۔
2. `owner` == `operator` سے اخذ شدہ شناخت (ورنہ
   `InvalidOwner`) — انکوڈ، ڈی کوڈ اور `validate()` تینوں پر
   چیک۔

### 3.2 اسٹیٹ قواعد (اطلاق، scone-blockchain)

`block_height` اونچائی کے لے جانے والے بلاک میں ہارٹ بیٹ کے
اطلاق پر (ہر انکار کسی تبدیلی سے پہلے):

1. **کراس epoch اینٹی ری پلے**: فی آپریٹر `timestamp` سخت بڑھتا
   ہے — ٹائپ شدہ انکار `StaleHeartbeat` اگر
   `timestamp <= operator_last_hb[operator]`۔
2. **فی epoch یکتائی**: فی (`operator`، لے جانے والے بلاک کا
   epoch) صرف ایک ہارٹ بیٹ قبول — ڈپلیکیٹ ٹائپ شدہ خرابی سے
   مسترد (`HeartbeatDuplicate`)۔ epoch ہے
   `block_height / epoch_min_blocks` (فائنلٹی جیسی ہی تعریف،
   کبھی کوئی نیا مستقل نہیں)۔
3. کھڑکی میں journaled داخلہ + `operator_last_hb` کی تازہ کاری
   (ری آرگ میں قابلِ واپسی، بٹ درست undo)۔

### 3.3 اینٹی سپیم

- فی آپریٹر فی epoch 1 قبول شدہ tx — زیادہ سے زیادہ بہاؤ
  `pool_size / epoch_secs`، نظر انداز۔
- کوئی فیس نہیں (پری اکانومی): شرح ساختی طور پر محدود ہے۔

## 4. عمل کا انتقال (delegation)

سیٹ → آپریٹر ربط دو مخصوص ٹرانزیکشنز سے ہوتا ہے:

- `SetTldOperator { tld_id, operator }` (ڈسکریمیننٹ `0xA9`)،
  **ذاتی** TLD کے **موجودہ** مالک کے دستخط شدہ (کھلی
  TLD کا کوئی جائز دستخط کنندہ نہیں — ٹائپ شدہ انکار
  `TldIsOpen`)۔ `operator: None` = منسوخی، مالک کی کلید سے
  خود آپریشن پر واپس؛ فوری طور پر منسوخ قابل۔
- `SetDomainOperator { domain_id, operator }` (ڈسکریمیننٹ
  `0x5E`)، ڈومین کے موجودہ مالک کے دستخط شدہ۔ وہی
  مفہوم۔
- `RegisterTld` / `RegisterDomain` / `AssignDomain` کوئی
  `operator` فیلڈ نہیں رکھتے: سیٹ → آپریٹر ربط ہمیشہ ایک حالیہ
  آن چین حقیقت ہے، ٹِپ پر حل ہوتی ہے۔

وائر پر آپریٹر آپشن کیننیکل ہے: `0x00` = `None`
(خود آپریشن)، `0x01` = خام 32 بائٹ کلید؛ کوئی اور قیمت ڈی کوڈ
پر مسترد۔

اسٹیٹ رکھتی ہے:

```
seat_operators: HashMap<OwnerId, OperatorKey>   // per seat
operator_seats: HashMap<OperatorKey, u64>       // bounded counter
operator_last_hb: HashMap<OperatorKey, u64>     // last accepted ts
```

اطلاق کے قواعد (`apply_seat_operator`، journaled):

- **غیر فعالی کے باوجود یکساں نتائج (idempotence)**: اُسی
  آپریٹر کو دوبارہ delegate کرنا (یا غیر موجود delegation
  منسوخ کرنا) غیر journaled no-op ہے (بٹ درست undo اس کا
  تقاضا کرتا ہے)۔
- **کرایہ روکی حد**: ایک آپریٹر کو ایک وقت میں صرف **ایک سیٹ**
  delegate کر سکتی ہے (`MAX_SEATS_PER_OPERATOR = 1`)۔ دوسری
  سیٹ کا پہلے سے لیے گئے آپریٹر پر delegate کرنا → ٹائپ شدہ
  انکار `OperatorAlreadyDelegated`۔ وجہ: حد کے بغیر کوئی بڑا
  آپریٹر دستخط بنکوں پر بیچ کر مرکزیت دوبارہ بناتا ہے — بالکل
  وہی جس سے منتخب کمیٹی بچنے کے لیے ہے۔

## 5. تازگی کی کھڑکی

### 5.1 پھسلتی کھڑکی

```
recent_heartbeats: BTreeMap<(epoch, OperatorKey), ()>
```

- اندراج درست ہارٹ بیٹ کے اطلاق پر داخل ہوتا ہے (§3.2)۔
- ہر بلاک اطلاق پر متعین صفائی
  (`gc_heartbeats_journaled`): epoch `e` کا کوئی بھی اندراج جس
  کا `e + HEARTBEAT_WINDOW_EPOCHS <= epoch` ہٹا دیا جاتا ہے
  (journaled — ری آرگ میں قابلِ واپسی، میعاد قطاروں کی طرح)۔
- `HEARTBEAT_WINDOW_EPOCHS = 2`: موجودہ epoch + پچھلا — ایک
  آپریٹر ایک epoch چھوڑ سکتا ہے بغیر تازگی کھوئے، دوسرا اسے
  ختم کر دیتا ہے۔
- **ساختی میموری کپ**: کھڑکی زیادہ سے زیادہ
  `HEARTBEAT_WINDOW_EPOCHS × operator_count` اندراج رکھتی ہے
  (فی آپریٹر فی epoch ایک، tuple کلید)؛ `operator_last_hb`
  آپریٹرز کی تعداد سے محدود ہے اور کبھی صاف نہیں ہوتا (اینٹی
  ری پلے قاعدہ یک طرفہ بڑھتا ہے)۔

### 5.2 تازگی

"تازہ" = `e` کے لیے `(e, operator)` اندراج کی موجودگی جہاں
`e` در `[epoch − HEARTBEAT_WINDOW_EPOCHS + 1, epoch]` میں ہو۔
چونکہ اسٹیٹ ہر بلاک پر صاف کرتی ہے، `recent_heartbeats` میں
موجودگی ہی تازگی ہے (`operator_is_fresh`)۔

### 5.3 مؤثر آپریٹر

کسی سیٹ کا **مؤثر آپریٹر** `seat_operators[seat]` ہے اگر زندہ
delegation موجود ہو، ورنہ مالک کی کلید
(`effective_operator`)۔ سیٹ اُسی مؤثر کلید کے تحت دستخط کرتی
ہے — delegation دستخط کا حق منتقل کرتی ہے، ملکیت کبھی نہیں۔

## 6. کمیٹی کا انتخاب

```
eligible = { effective operators of the frozen pool's seats
             (banned key excluded) having a fresh heartbeat }

if |eligible| >= MIN_FINALITY_COMMITTEE_SIZE (= 4) :
    committee = select_committee(seed, eligible)   // existing draw
else :
    committee = select_committee(seed, pool)       // safe degradation
```

نافذہ تفصیلات (`finality.rs` میں تصدیق شدہ،
`/docs/en/technical/blockchain.md` § "Seats and the finality
committee" میں متعین):

- `pool` وہ پول ہے جو **آخری فائنل شدہ چیک پوائنٹ پر منجمد
  ہوا** (`FinalizedBase.pool` — کبھی زندہ اسٹیٹ نہیں): مقامی
  منظر نوڈز کے درمیان الگ ہو جاتا اور قورم کبھی نہ بنتا؛
- `seed` پچھلے چیک پوائنٹ کے مواد کے ہیش سے اخذ ہوتا ہے
  (`signing_hash`)؛
- منجمد پول کی ہر سیٹ ٹِپ کی اسٹیٹ کے ذریعے اپنے مؤثر
  آپریٹر پر حل ہوتی ہے (delegation اور ہارٹ بیٹس حالیہ
  آن چین حقائق ہیں: ایک ہی ٹِپ پر دو نوڈ وہی مجموعہ بنتے ہیں)؛
  جلاوط کلیدیں باہر رہتی ہیں؛
- قرعہ کشی مؤثر کلیدوں کی ترتیب/غیر مکرر سیٹ پر چلتی ہے
  (`select_committee` بے تبدیل)۔

**واضح اور محفوظ گراڈ**: بوٹ اسٹریپنگ نیٹ ورک (کوئی ہارٹ
بیٹ نہیں)، یا آپریٹرز کی عمومی بندش، پورے پول پر گر جاتا ہے —
فائنلٹی تعمیر ہی سے کبھی نہیں کھوتی۔ یہ پروجیکٹ کا "کبھی ڈیڈ
لاک نہیں" قاعدہ یہاں لاگو ہے۔

### 6.1 سرد بوٹ اسٹریپ

Epoch 0 (اور جب تک `MIN_FINALITY_COMMITTEE_SIZE` سے کم
آپریٹر تازہ ہوں): پورا پول۔ آپریٹرز کے جاری کرنے کے ساتھ یہ
پابندی فطری طور پر سخت ہوتی جاتی ہے۔ کوئی خاص عبوری دور
کنفیگر نہیں۔

## 7. خودکار اخراج (scone-network)

ہر پیداواری سائیکل پر (`Wake::Produce` — کوئی نیا ٹائمر نہیں)،
ریلے چیک کرتا ہے کہ آیا EPOCH کی سرحد پار ہوئی
(`height / epoch_min_blocks`، فائنلٹی جیسی تعریف)۔ نئے epoch
کے پہلے سائیکل پر، وہ ہارٹ بیٹ جاری کرتا ہے اگر:

1. کوئی اینکر کلید مسلح ہو (`--anchor-key` یا آٹو)، اور
2. وہ کلید خود زندہ سیٹ رکھتی ہو (مقامی چیک: کلید آن چین
   اہلیت پول میں ہے — زندہ ڈومینز/TLDs کے مالکان،
   جلاوط کلیدیں باہر)۔

مقامی اینٹی سپیم: فی نوڈ فی epoch زیادہ سے زیادہ ایک اخراج
(`last_emitted_epoch` میمو، مقامی میموری، کبھی چین اسٹیٹ نہیں)؛
میمو کامیاب mempool انجیکشن کے بعد ہی لیا جاتا ہے — ناکامی
اگلے سائیکل میں دوبارہ کوشش کرتی ہے۔ یہاں کچھ بھی مہلک نہیں:
بدترین صورت ہارٹ بیٹ اگلے سائیکل کا انتظار کرتا ہے۔

ایک **delegated آپریٹر** (جو خود مالک نہیں) خودکار اخراج میں
شامل نہیں: وہ §8 کے CLI بلڈر کے ذریعے جاری کرتا ہے (دستی یا
ایئر گیپڈ آپریشن)۔ ہارٹ بیٹ لازمی نہیں کہ جاری کرنے والا خود
بلاک میں پیدا کرے: یہ ہر دوسری tx کی طرح ہے (mempool، کسی کا
بھی پیدا کردہ)۔

## 8. CLI (`scone`)

آف لائن ہارٹ بیٹ بلڈر (`tx` سطح کے ساتھ) ہٹا دیا گیا
آف لائن tx سطح کے ساتھ (cli-simplify-v1)۔ ریلے
اپنا ہارٹ بیٹ خودکار جاری کرتے ہیں (§7)؛ دستی/ایئر گیپڈ
اخراج، اگر دوبارہ کبھی درکار ہو، ایک مخصوص کمانڈ کے طور پر
لوٹے گا۔ ڈیفالٹس تھے: `tip_seen` = 32 صفر بائٹس
(صرف مشاہدہ)، `height_seen` = 0، `timestamp` = اب۔
- ہر tx کی طرح، `tx sign` آپریٹر اور مالک کو اصل
  دستخطی کلید سے دوبارہ باندھتا ہے (ان پٹ قیمتیں کبھی بھروسہ
  نہیں)؛ `tx verify` مقامی طور پر تصدیق کرتا ہے۔

## 9. مشاہدہ

- `NodeStatus` (وائر p2p پیغام `0x0d`) میں
  `fresh_operators: u32` (varint) ہے: تازہ ہارٹ بیٹ والے
  آپریٹرز کی تعداد — پول کا وہ زندہ ذیلی سیٹ جو کمیٹی کے لیے
  اہل ہے (پول کی سیٹوں کے مؤثر آپریٹر، جلاوط کلیدیں باہر،
  ترتیب/غیر مکرر)۔ ریلے اسے `state().fresh_operators(height)` سے
  بھرتا ہے؛ `scone status` اسے `fresh operators: N` کے طور پر
  دکھاتا ہے۔
- مہم کا دلیل: "ذاتی TLD چلانا = غیر مرکزی DNS کی فائنلٹی
  کمیٹی میں بیٹھنا" — آن چین قابلِ تصدیق۔
- مستقبل کی سطح (غیر متعین): `operator_status` — فی سیٹ،
  delegated آپریٹر، تازگی (تازہ / ختم / کبھی نہیں دیکھا)،
  آخری `tip_seen`۔ مقامی کنٹرول RPC ہٹا دیا گیا (صرف p2p
  نوڈ)؛ سطح ابھی متعین ہونی ہے۔

## 10. یہ RFC کیا نہیں کرتا

- غیر سرگرمی پر **ملکیت کا نقصان نہیں** (آپشن A — بغیر آپریٹر
  TLD کا زوال — واضح طور پر مسترد)۔
- **کوئی انعام نہیں** (آپشن C اکانومی پرت کا انتظار میں)۔
- ہارٹ بیٹ خدمت کی *کوالٹی* کا ثبوت نہیں (پیدا شدہ بلاکس،
  DHT ریکارڈز) — صرف موجودگی۔ حقیقی حصہ داری گننا ممکن
  توسیع ہے، مگر زیادہ کھیل قابل۔

## 11. محفوظ مستقل حقائق

- بٹ درست تعینیت: کھڑکی اور انتخاب لاگو اسٹیٹ کے خالص
  فنکشنز ہیں (journaled، بٹ درست undo)۔
- نیٹ ورک ڈیٹا پر کبھی panic نہیں: بگڑا ہوا ہارٹ بیٹ یا
  delegation → ٹائپ شدہ انکاری (`InvalidOwner`،
  `StaleHeartbeat`، `HeartbeatDuplicate`،
  `OperatorAlreadyDelegated`، `TldIsOpen`،
  `NotTldOwner`، `NotOwner`)۔
- ملکیت غیر مشروط ہے؛ صرف چیک پوائنٹ دستخط مشروط ہے۔
