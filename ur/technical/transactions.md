# دستخط شدہ ٹرانزیکشنز (فارمیٹ v1)

دستخط شدہ ٹرانزیکشن فارمیٹ کے لیے **نافذہ** حوالہ دستاویز۔
یہ فیلڈز، درست وائر ترتیب، سائز، دستخط شدہ پے لوڈ اور تصدیق کے
قواعد متعین کرتی ہے تاکہ Rust پڑھے بغیر آزاد نفاذ ممکن ہو۔ حوالہ
نفاذ [`scone-protocol`](../../../crates/scone-protocol) (انکوڈنگ)
اور [`scone-blockchain`](../../../crates/scone-blockchain) (تصدیق)
ہے۔

`PROTOCOL_VERSION` = **1**۔ فارمیٹس کا صرف ایک سیٹ ہے: `0x01` کے
سوا کوئی ورژن بائٹ (ٹرانزیکشن میں) یا مقامی ورژن سے مختلف (بلاک
میں) `UnsupportedVersion` کے ساتھ مسترد ہے۔

## جائزہ

```text
Transaction = disc u8 || version u8 || payload
```

| فیلڈ | سائز | کردار |
|---|---|---|
| `disc` | 1 B | ٹرانزیکشن کی قسم (نیچے جدول) |
| `version` | 1 B | **بالکل `0x01`** (tx فارمیٹ ورژن) |

**ٹرانزیکشنز وائر پر اب کوئی `network` فیلڈ نہیں رکھتیں**
(2026-09 تبدیلی): `network_id` (`str` ≤ 16، ASCII `[a-z0-9-]` —
مثلاً `scone-testnet`، 13 بائٹس) صرف **دستخطی پے لوڈ** میں رہتی
ہے — دستخط کنندہ اسے وہاں پہلے فیلڈ کے طور پر ڈالتا ہے (دیکھیں
[دستخط شدہ پے لوڈ](#دستخط-شدہ-پے-لوڈ)) — اور PoW ڈائجسٹ میں فی
نیٹ ورک رہتی ہے۔ ایک نیٹ ورک کے لیے **دستخط شدہ** ٹرانزیکشن اس
لیے کبھی دوسرے پر تصدیق نہیں ہوتی: اس کا دستخط ناکام ہو جاتا ہے
(`InvalidSignature`) چین کے دوبارہ حساب شدہ پے لوڈ کے خلاف، جو
اپنا نیٹ ورک ڈالتا ہے (دیکھیں
`/docs/en/technical/blockchain.md` — نیٹ ورکس اور جنسیس)۔

### ڈسکریمیننٹس (نافذہ جدول)

ہر ڈسکریمیننٹ ایک **مقررہ، غیر متعین اپاہج مستقل** ہے: قیمتیں
جان بوجھ کر الگ چنی گئی ہیں، تاکہ وائر کبھی اقسام کے درمیان
منطقی ترتیب کی تجویز نہ کرے (کوئی 0x01/0x02/0x03… تسلسل نہیں)۔
`0x00` کبھی بھی درست قسم نہیں (عام خرابی بائٹ)۔ مستقبل کی اقسام
کوئی بھی غیر استعمال شدہ آزاد قیمت لیں گی، ایک بار اس جدول میں
دستاویز شدہ۔

| ڈسکریمیننٹ | قسم | کردار |
|---|---|---|
| `0x21` | `RegisterDomain` | کسی ڈومین کا دعوی |
| `0x52` | `UpdateDomain` | ڈومین کے DNS ڈیٹا کا نیا ورژن |
| `0x93` | `RegisterTld` | اعلیٰ سطحی ڈومین کا دعوی (M7) |
| `0x47` | `TransferTld` | TLD کا نئے مالک کو منتقل (M8a) |
| `0x6B` | `RevokeTld` | TLD کا ترک (M8a) |
| `0xB8` | `SetTldOpen` | TLD کی خود رجسٹریشن کے لیے **ناقابلِ واپسی** کھلنا (یک رخہ، مالک آپشن؛ `open=false` ٹائپ شدہ انکار ہے) |
| `0xD4` | `AssignDomain` | TLD کے مالک کی جانب سے ڈومین کی براہِ راست تخصیص (M8a) |
| `0x3C` | `RenewDomain` | ڈومین رجسٹریشن کی توسیع (M8a؛ مالک آپشن سے کیننیکل نام رکھتا ہے — کھلی TLD میعاد کی پیروی کرتی ہے) |
| `0x8F` | `RenewTld` | ذاتی TLD کی 3 سالہ مدت کی تجدید (پیدائش کے برابر PoW) |
| `0x15` | `SlashTx` | اینکر غلط بیانی کا ثبوت + جلاوطی (M9) |
| `0xE2` | `TransferDomain` | ڈومین کا نئے مالک کو منتقل (M8c) |
| `0x71` | `Heartbeat` | آپریٹر کے زندہ رہنے کا ثبوت (proof-of-service RFC) |
| `0xA9` | `SetTldOperator` | ذاتی TLD کے آپریشن کی delegation (proof-of-service RFC) |
| `0x5E` | `SetDomainOperator` | ڈومین کے آپریشن کی delegation (proof-of-service RFC) |

`0x01` کے سوا کوئی ورژن بائٹ واضح طور پر مسترد ہے
(`UnsupportedVersion(موصول قیمت)`): نامعلوم یا متروک فارمیٹ کبھی
اتفاقی طور پر پارس نہیں ہوتا۔

## SLASH_TX (0x15, M9)

آن چین ثبوت کہ کسی اینکر نے اسی epoch پر دو **متضاد چیک
پوائنٹس** پر دستخط کیے (غلط بیانی)۔ کوئی بھی جمع کرا سکتا ہے —
ثبوت خفیہ نگاری کا ہے اور خود مختار:

```text
offender[32] | evidence_a (CheckpointData 116 B)
  | sig_a[64] | evidence_b (CheckpointData) | sig_b[64]
  | reporter_pk[32] | reporter_signature[64]
```

- `validate()` ڈھانچہ چیک کرتا ہے: وہی epoch، الگ
  `signing_hash`es، دو الگ دستخط، رپورٹر کے دستخط کیننیکل
  پے لوڈ پر؛
- اسٹیٹ قواعد (journaled، ری آرگ پر قابلِ واپسی): ملزم کے دونوں
  دستخط اسی epoch پر دو الگ دستخطی ہیشز کے خلاف تصدیق ہونے
  چاہئیں؛ ملزم اہل پول میں ہونا چاہیے (ورنہ
  `SlashOffenderNotInPool`)؛ پھر **جلاوطی** — کلید PoS پول سے
  مستقل طور پر ہٹا دی جاتی ہے (اسٹیٹ میں بلیک لسٹ)؛
- کم سے کم سزا: ملزم کی ڈومینز/TLDs ضبط نہیں ہوتیں
  (دستاویز شدہ M9 فیصلہ)؛
- ایک ہی چیک پوائنٹ دو بار = غلط بیانی نہیں (مسترد)؛ الگ
  epochs = مسترد؛ جعلی دستخط = مسترد۔

## REGISTER_DOMAIN (0x21)

```text
name(str ≤ 253) domain_id[32] owner[32] timestamp.v proof(bytes ≤ 256) public_key[32] signature[64]
```

| فیلڈ | قسم | پابندیاں |
|---|---|---|
| `name` | `str` ≤ 253 | دعوے شدہ ڈومین کا کیننیکل نام، **صاف الفاظ میں** (نیچے دیکھیں) |
| `domain_id` | 32 خام بائٹس | **لازم** `DomainId(name)` کے برابر (دوبارہ حساب، کبھی بھروسہ نہیں) |
| `owner` | 32 خام بائٹس | **لازم** `public_key` کا حصول ہو (نیچے دیکھیں) |
| `timestamp` | varint | ترتیب کی معلومات (Unix، سیکنڈ) |
| `proof` | `bytes` ≤ 256 | رجسٹریشن PoW پے لوڈ (نیچے دیکھیں [#رجسٹریشن-کا-کام-کا-ثبوت-pow](#رجسٹریشن-کا-کام-کا-ثبوت-pow)) |
| `public_key` | 32 خام بائٹس | دستخط کنندہ کی Ed25519 عوامی کلید (RFC 8032) |
| `signature` | **بالکل 64 بائٹس** | دستخط شدہ پے لوڈ کا Ed25519 دستخط |

### نام ٹرانزیکشن کے ذریعے لے جایا جاتا ہے

`RegisterDomain` کیننیکل نام صاف الفاظ میں لے جاتا ہے، اس کے
بعد اس کی `DomainId`۔ مطابقت `domain_id == DomainId(name)` انکوڈنگ،
ڈی کوڈنگ اور تصدیق پر دوبارہ چیک ہوتی ہے (گہری دفاع): جس
`RegisterDomain` کی id لائے گئے نام سے نہ ملے وہ غلط ہے۔
`DomainId` کنسنسس شناخت رہتی ہے (چین اور DHT کلیدیں)؛ لایا گیا
نام چین کو خود بیان کرتا بناتا ہے اور پورے دعوے کو دستخط میں
ڈھانکتا ہے۔

## REGISTER_TLD (0x93)

اعلیٰ سطحی ڈومین کا دعوی (TLD رجسٹری، M7):

```text
tld(str ≤ 63) tld_id[32] owner[32] timestamp.v proof(bytes ≤ 256) open(0x00|0x01) public_key[32] signature[64]
```

| فیلڈ | قسم | پابندیاں |
|---|---|---|
| `tld` | `str` ≤ 63 | TLD کا کیننیکل نام **صاف الفاظ میں** (M8b: PoW چیلنج نام سے اخذ ہوتا ہے، جیسے `RegisterDomain` اپنا رکھتا ہے) |
| `tld_id` | 32 خام بائٹس | TLD کی شناخت: `BLAKE3-256("SCONE-TLD-V1" || tld)` — **لازم** `tld` کا حصول ہو (دوبارہ حساب) |
| `owner` | 32 خام بائٹس | `public_key` کا حصول |
| `timestamp` | varint | ترتیب کی معلومات (Unix، سیکنڈ) |
| `proof` | `bytes` ≤ 256 | رجسٹریشن PoW پے لوڈ (نیچے دیکھیں) |
| `open` | `0x00\|0x01` | **کھلی** پیدائش: TLD براہِ راست `TldState::Open` میں اترتی ہے (کوئی نہیں، خود سروس + PoW، `open_tld_pow_difficulty` شرح پر ایک PoW — ذاتی سے سستا: مشترکہ وسائل، نہ PoS سیٹ نہ اختیارِ انفرادیت)؛ **ذاتی** پیدائش: تاریخی رویہ (مالک، PoS سیٹ، `tld_pow_difficulty`) |
| `public_key` | 32 خام بائٹس | دستخط کنندہ کی Ed25519 عوامی کلید |
| `signature` | **بالکل 64 بائٹس** | دستخط شدہ پے لوڈ کا Ed25519 دستخط |

`TldId` اسپیس `DomainId` اسپیس سے **الگ** ہے (الگ حصول سابقے —
دیکھیں `/docs/en/general/naming.md`): TLD `uip` رجسٹر کرنا
(`*.uip` نیم اسپیس پر دعوی) کبھی کسی ڈومین کی شناخت پر قبضہ نہیں
کر سکتا، نہ اس کا الٹ۔ اطلاق پر اسٹیٹ قاعدہ: TLD آزاد ہونی
چاہیے (رجسٹری، ڈومین رجسٹری سے الگ)۔

## M8a خاندان — وائر فارمیٹس

پانچ اقسام TLD رجسٹری اور ڈومین زندگی کو مکمل کرتی ہیں۔ M8a سے
نافذہ وائر فارمیٹس؛ **مکمل اسٹیٹ قواعد M8b سے** (دیکھیں
`/docs/en/technical/blockchain.md`): TLD مالک لازم، جہاں دعوی
خود سروس ہو وہاں PoW، ڈومین کی جانب میعادیں اور مہلتیں۔ کوئی
پے لوڈ وائر پر `network` فیلڈ نہیں رکھتا (وہ صرف دستخطی پے لوڈ
میں رہتا ہے)۔

### TRANSFER_TLD (0x47)

```text
tld_id[32] owner[32] new_owner[32] proof.v public_key[32] signature[64]
```

| فیلڈ | قسم | پابندیاں |
|---|---|---|
| `tld_id` | 32 خام بائٹس | منتقل شدہ TLD |
| `owner` | 32 خام بائٹس | `public_key` کا حصول (موجودہ مالک / دستخط کنندہ) |
| `new_owner` | 32 خام بائٹس | وصول کنندہ کی شناخت (اپاہج: نحوی طور پر کوئی بھی قیمت درست؛ خرچ کرنے والی کلیدوں سے بندھنا M8b اسٹیٹ قاعدہ ہے) |
| `proof` | محدود (varint ‖ بائٹس) | اینٹی چرن دستاویزی منتقلی ثبوت، چیلنج `SCONE-TLD-XFER-V1 ‖ tld_id`، فلیٹ مشکل `transfer_pow_difficulty`، ایپوک نمک |
| `public_key` | 32 خام بائٹس | دستخط کنندہ کی Ed25519 عوامی کلید |
| `signature` | **بالکل 64 بائٹس** | دستخط شدہ پے لوڈ کا Ed25519 دستخط |

کوئی timestamp یا sequence نہیں: ایک TLD کا ایک وقت میں بالکل
ایک مالک ہوتا ہے؛ پہلا لاگو شدہ منتقلی جیتتا ہے (صرف چین کی
ترتیب)۔

### REVOKE_TLD (0x6B)

```text
tld_id[32] owner[32] public_key[32] signature[64]
```

TLD کا رضاکارانہ ترک (بعد میں تازہ `RegisterTld` سے دوبارہ دعوی
قابل)۔ موجودہ مالک کے دستخط شدہ؛ جان بوجھ کر بغیر timestamp یا
sequence — revoke موجودہ اسٹیٹ کے خلاف ایک بار ہے۔

### SET_TLD_OPEN (0xB8)

```text
tld_id[32] owner[32] open u8 open_proof(proof) public_key[32] signature[64]
```

| فیلڈ | قسم | پابندیاں |
|---|---|---|
| `open` | 1 بائٹ | **سخت طور پر `0x00` یا `0x01`** (کیننیکل شکل؛ کوئی اور قیمت → ڈی کوڈنگ خرابی، کبھی زبردستی نہیں) |
| `open_proof` | `proof` (لمبائی-varint + بائٹس) | **دستخط شدہ** فیلڈ؛ `open = 0x01` پر لازم اور تصدیق شدہ (کھلنے کا PoW، نیٹ ورک کی `open_tld_pow_difficulty`، چیلنج `SCONE-TLD-OPEN-V1 ‖ tld_id`)؛ `open = 0x00` پر خالی (بند کرنا مفت ہے) |

**بند** TLD = صرف assign (ڈومینز صرف TLD کے مالک کے `AssignDomain`
سے بنتی ہیں)؛ **کھلی** TLD = کوئی بھی رجسٹریشن PoW کر کے آزاد
ڈومین کا دعوی کر سکتا ہے (`RegisterDomain`)۔ **کھلنا** ایک اضافی
کام کے ثبوت کی لاگت ہے (TLD دعوے سے ہلکا: مین نیٹ پر ~3 دن بمقابلہ
~1 ہفتہ)، مالک کی جانب سے `SetTldOpen` میں ایک بار ادا — ثبوت
دستخط شدہ `open_proof` فیلڈ میں سفر کرتا ہے اور دستخط کے بعد
بدلا نہیں جا سکتا۔

### ASSIGN_DOMAIN (0xD4)

```text
name(str ≤ 253) domain_id[32] owner[32] assignee[32] proof.v public_key[32] signature[64]
```

`RegisterDomain` کا عکس: کیننیکل نام صاف الفاظ میں لے جایا جاتا
ہے اور `domain_id` لازماً `DomainId(name)` کے برابر ہو (ڈی کوڈنگ،
انکوڈنگ اور تصدیق پر دوبارہ حساب)۔ **نام کی TLD کے مالک** کے
دستخط شدہ (اطلاق پر چیک، M8b)؛ `assignee` ڈومین کا پہلا مالک
بن جاتا ہے (اپاہج، `new_owner` کی طرح)۔ اپنا فلیٹ اینٹی اسپیم
ثبوت رکھتا ہے (`assign_pow_difficulty`، چیلنج
`SCONE-DOMAIN-ASSIGN-V1 ‖ name` — فیصلے سے فلیٹ: namespace کی
انفرادیت TLD کی پیدائش پر ادا ہو چکی تھی)۔

### RENEW_DOMAIN (0x3C)

```text
name(str ≤ 253) domain_id[32] owner[32] valid_until.v proof(bounded) public_key[32] signature[64]
```

| فیلڈ | قسم | پابندیاں |
|---|---|---|
| `name` | `str` ≤ 253 | کیننیکل نام **صاف الفاظ میں** (مالک آپشن: تجدید تلے کھلی TLD کی موت کو ملتوی کرتی ہے، چین کو نام جاننا چاہیے)؛ `domain_id` لازماً `DomainId(name)` کے برابر (دوبارہ حساب) |
| `valid_until` | varint | نئی رجسٹریشن میعاد (Unix، سیکنڈ) |
| `proof` | محدود | **تجدید کی اجازت** (نیچے دیکھیں) |

ڈومین کے موجودہ مالک کے دستخط شدہ؛ کیا `valid_until` واقعی میعاد
بڑھاتا ہے (اور زیادہ سے زیادہ ایک تجدید کی مدت تک) یہ اسٹیٹ
قاعدہ ہے (M8b)۔

#### تجدید کی اجازت — TLD کے مطابق PoW یا PoS

تجدید کی لاگت تلے کی TLD کی نوعیت پر منحصر ہے (اطلاق کے وقت،
بلاک اسٹیٹ پر جانچی جاتی ہے):

- **کھلی TLD**: تجدید کی لاگت **پیدائش جیسا ہی PoW** ہے — وہی
  چیلنج (`SCONE-DOMAIN-V1 ‖ canonical name`)، وہی فی لیبل لمبائی
  اور فی نیٹ ورک مشکل، وہی epoch درستگی ونڈو۔ کوئی ڈومین کبھی مفت
  "جمع" نہیں کی جاتی: زندگی کی ہر مدت کام میں ادا ہوتی ہے۔
- **ذاتی TLD**: نیم اسپیس TLD مالک کا داؤ (PoS) ہے۔ ٹرانزیکشن
  **TLD مالک کے دستخط شدہ** (یا اس کے delegated آپریٹر) ہونی
  چاہیے — دستخط ہی اجازت ہے، `proof` فیلڈ خالی ہونی چاہیے (20
  صفر بائٹس)۔ TLD مالک اپنے نیم اسپیس کی ڈومینز اپنے قواعد سے
  تجدید کرتا ہے۔

### RENEW_TLD (0x8F)

```text
tld(str ≤ 63) tld_id[32] owner[32] valid_until.v proof(bounded) public_key[32] signature[64]
```

| فیلڈ | قسم | پابندیاں |
|---|---|---|
| `tld` | `str` ≤ 63 | کیننیکل TLD نام؛ `tld_id` لازماً `TldId(tld)` کے برابر (دوبارہ حساب) |
| `valid_until` | varint | لازم بالکل `اب + 3 سال` ہو (مقررہ مدت — اطلاق پر دوبارہ اخذ، کوئی اور قیمت مسترد) |
| `proof` | محدود | تجدید کا PoW (نیچے دیکھیں) |

TLD کے موجودہ **ذاتی** مالک کے دستخط شدہ۔ اطلاق کے قواعد:

- صرف ذاتی TLD پر لاگو (کھلی TLD اپنی ڈومینز سے جیتی ہے —
  ٹائپ شدہ انکار `TldIsOpen`)؛
- مدت کے دوران اور میعاد کے بعد آنے والی **60 دن کی مہلت** تک
  درست؛ اس سے آگے TLD مر چکی ہے (GC) اور انکار
  `TldExpiredFrozen` ہے؛
- **پیدائش کے برابر PoW**: چیلنج
  `SCONE-TLD-V1 ‖ name ‖ current_expiry(BE64)` (اینٹی ری یوز
  سابقہ ہر PoW کو ایک مدت سے باندھتا ہے)، ابتدائی دعوے جیسی ہی
  فی لمبائی مشکل؛
- تجدید مہلت کے دوران منجمد نہیں — یہ میعاد گزرے مالک کی واحد
  دستیاب انتظامی عمل ہے۔

## UPDATE_DOMAIN (0x52)

```text
domain_id[32] owner[32] sequence.v record_hash[32] public_key[32] signature[64]
```

| فیلڈ | قسم | پابندیاں |
|---|---|---|
| `domain_id` | 32 خام بائٹس | ہدف ڈومین |
| `owner` | 32 خام بائٹس | `public_key` کا حصول |
| `sequence` | varint | **> 0**، اطلاق پر `موجودہ + 1` کے برابر ہونا چاہیے |
| `record_hash` | 32 خام بائٹس | DHT ریکارڈ سیٹ پر commitment |
| `public_key` | 32 خام بائٹس | دستخط کنندہ کی Ed25519 عوامی کلید |
| `signature` | **بالکل 64 بائٹس** | دستخط شدہ پے لوڈ کا Ed25519 دستخط |

نوٹ: `UpdateDomain` کوئی `timestamp` نہیں رکھتا — ترتیب
`sequence` سے ہوتی ہے۔ یہ نام بھی نہیں رکھتا: ڈومین پہلے سے
رجسٹرڈ ہے، id کافی ہے۔

### سخت حدود

- `public_key`: **بالکل 32 خام بائٹس**، کوئی لمبائی سابقہ نہیں۔
  جو pk curve نقطے کے طور پر ڈی کوڈ نہ ہو → ڈی کوڈنگ پر
  `InvalidTransactionKey` خرابی۔
- `signature`: **بالکل 64 خام بائٹس**، کوئی لمبائی سابقہ نہیں،
  کوئی مارجن نہیں۔ کوئی اور سائز سخت ڈی کوڈنگ خرابی ہے (کتراؤ
  مسترد)۔
- `proof`: لمبائی-varint + بائٹس، 256 پر capped
  (`MAX_PROOF_LEN`)، مختص سے پہلے چیک۔
- `name`: لمبائی-varint + UTF-8 بائٹس، 253 پر capped
  (`MAX_NAME_LEN`)، `scone-core` نام کے قواعد سے دوبارہ تصدیق۔

## POW-TO-OWNER — چار بغیر دستخط شکلیں (0x2A، 0x57، 0x84، 0xC3)

دستخط شدہ شکلوں کے ساتھ چار ADDITIVE variants (کبھی متبادل
نہیں — D1): `REGISTER_TLD_POW` (0x2A)، `RENEW_TLD_POW` (0x57)،
`REGISTER_DOMAIN_POW` (0x84)، `RENEW_DOMAIN_POW` (0xC3)۔ ان
میں سے کوئی بھی نہ signer کلید رکھتا ہے نہ دستخط: **مائن کیا
گیا کام کا ثبوت پوری اجازت ہے**۔

### چیلنج مستفید اور نیٹ ورک کو باندھتا ہے (D2)

```
challenge = kind_tag ‖ name ‖ pubkey_dest[32] ‖ len(network_id) ‖ network_id
```

- `kind_tag`: خاندان کا ٹیگ (TLDs کے لیے SCONE-TLD-V1،
  ڈومینز کے لیے SCONE-DOMAIN-V1) — اقسام کے درمیان کوئی
  کراس-kind ری پلے نہیں؛
- `pubkey_dest`: **مستفید** کی کلید — حوالے میں دیا گیا ثبوت
  صرف اسی کلید استعمال کر سکتی ہے (ثبوت چوری ناممکن، محفوظ
  وفاق شدہ مائننگ)؛
- `network_id`: devnet ثبوت کبھی testnet یا مین نیٹ پر ری پلے
  نہیں ہوتا۔

تجدید کی شکلیں دستخط شدہ خاندان کا اینٹی ری یوز لاحقہ جوڑتی
ہیں: `‖ current_valid_until` (BE، 8 بائٹس) — ایک مائن شدہ
ثبوت بالکل ایک مدت ادا کرتا ہے۔

### باڈی کی ساخت

دستخط شدہ باڈیز کے بالکل عکس، signer کلید کی جگہ
`pubkey_dest`، کوئی آخری دستخط نہیں:

- `REGISTER_TLD_POW`: name ‖ tld_id ‖ owner ‖ timestamp.v ‖
  proof ‖ open(0x00|0x01) ‖ pubkey_dest — `owner` =
  hash(pubkey_dest)، دوبارہ حساب، کبھی قابلِ اعتماد نہیں
  (D4)؛ open = کھلی پیدائش (ہلکی شرح)؛ ذاتی = سخت 3 سالہ
  مدت، مستفید PoS سیٹ بن جاتا ہے؛
- `REGISTER_DOMAIN_POW`: name ‖ domain_id ‖ owner ‖
  timestamp.v ‖ proof ‖ pubkey_dest — صرف کھلی TLD (ذاتی →
  TldClosed: ذاتی namespace مالک کے دستخطی راستہ رکھتا ہے)؛
- `RENEW_TLD_POW` / `RENEW_DOMAIN_POW`: name ‖ id ‖ owner ‖
  valid_until.v ‖ proof ‖ pubkey_dest۔

### اطلاق کے محافظ (D3)

- آن چین مالک چیلنج کا مستفید بھی ہونا چاہیے: تجدید کبھی
  ہاتھ نہیں بدل سکتی — صرف register نئی ملکیت بناتا ہے؛
- مشکلیں، ایپوک کھڑکی، رعایت اور مدتیں دستخط شدہ شکلوں کی
  اپنی ہیں (D5: داخلے کی لاگت نہیں بدلتی)؛
- مستفید کی کلید بالکل signer کی کلید جیسی سیکھی جاتی ہے
  (PoS پول ریزولوشن)۔

### txid اور بقائ باہم

txid مواد کا کیننیکل ہیش رہتا ہے؛ discriminants
0x2A/0x57/0x84/0xC3 فورک مارکر ہیں — پرانا نوڈ انہیں
UnknownDiscriminant کے طور پر مسترد کرتا ہے، نیا نوڈ v1
شکلیں بغیر تبدیلی ڈی کوڈ کرتا ہے۔ چاروں کے لیے
`signing_payload` N/A ہے (ٹائپڈ `PowNotSignable` خرابی):
ان پر کبھی دستخط نہیں ہوتے۔

CLI: `scone domain register <name> --to <pubkey-hex>`،
`scone domain mine <name> --mine-for <pubkey>`،
`scone domain renew <name> --to`، `scone tld register/renew
--to`۔

## مالک کا حصول

سخت قاعدہ: **مالک ہمیشہ دوبارہ حساب ہوتا ہے، کبھی بھروسہ نہیں**۔

```text
PublicKeyRef = BLAKE3-256("SCONE-PUBKEY-V1" || public_key)
OwnerId      = BLAKE3-256("SCONE-OWNER-V1" || PublicKeyRef)
```

جس ٹرانزیکشن کا `owner` اپنی `public_key` کے حصول سے نہ ملے وہ
غلط ہے (`InvalidOwner` core کی جانب،
`OwnerKeyMismatch` چین کی جانب)، انکوڈنگ، ڈی کوڈنگ **اور** چین
تصدیق پر مسترد (گہری دفاع)۔

## دستخط شدہ پے لوڈ

دستخط شدہ پے لوڈ ٹرانزیکشن کی کیننیکل انکوڈنگ ہے **دستخط فیلڈ
کے بغیر**، ایک ڈومین علیحدگی ٹیگ کے ساتھ سابق — **ہدف چین کی
`network_id` سر پر ڈالی ہوئی**:

```text
signing_payload(tx, network) = "SCONE-TX-SIG-V1"
                              || canonical_encode(tx_without_signature, network)
```

جہاں `canonical_encode(tx_without_signature, network)` اوپر کی
وائر ساخت کی پیروی کرتا ہے، ڈسکریمیننٹ اور ورژن بائٹ سمیت،
`signature` سے پہلے رک کر، **`network` پہلے فیلڈ کے طور پر** —
یہ اکلوتی جگہ ہے جہاں نیٹ ورک ظاہر ہوتا ہے۔ چین پے لوڈ اپنے
نیٹ ورک کے ساتھ دوبارہ حساب کرتی ہے: دوسرے نیٹ ورک کے لیے
دستخط شدہ ٹرانزیکشن کی دستخط تصدیق ناکام (`InvalidSignature`)؛
یہی اینٹی کراس چین ری پلے میکانزم ہے۔

```text
REGISTER_DOMAIN_no_sig = disc(0x21) version(0x01) network name domain_id[32] owner[32]
                            timestamp.v proof public_key[32]
REGISTER_TLD_no_sig    = disc(0x93) version(0x01) network tld tld_id[32] owner[32]
                            timestamp.v proof public_key[32]
UPDATE_DOMAIN_no_sig   = disc(0x52) version(0x01) network domain_id[32] owner[32]
                            sequence.v record_hash[32] public_key[32]
TRANSFER_TLD_no_sig    = disc(0x47) version(0x01) network tld_id[32] owner[32]
                            new_owner[32] proof public_key[32]
REVOKE_TLD_no_sig      = disc(0x6B) version(0x01) network tld_id[32] owner[32]
                            public_key[32]
SET_TLD_OPEN_no_sig    = disc(0xB8) version(0x01) network tld_id[32] owner[32]
                            open(0x00|0x01) open_proof(proof) public_key[32]
ASSIGN_DOMAIN_no_sig   = disc(0xD4) version(0x01) network name domain_id[32] owner[32]
                            assignee[32] proof public_key[32]
RENEW_DOMAIN_no_sig    = disc(0x3C) version(0x01) network name domain_id[32] owner[32]
                            valid_until.v proof public_key[32]
TRANSFER_DOMAIN_no_sig = disc(0xE2) version(0x01) network domain_id[32] owner[32]
                            new_owner[32] proof public_key[32]
```

خصوصیات:

- متعین اور خالص: وہی ٹرانزیکشن ⇒ ہر جگہ وہی پے لوڈ؛
- ASCII سابقہ `SCONE-TX-SIG-V1` (15 بائٹس،
  ہیکس `53434f4e452d54582d5349472d5631`) دستخط کے پروٹوکول کے کسی
  دوسرے ہیش ڈومین میں دوبارہ استعمال کو روکتا ہے؛
- `signature` کے سوا تمام فیلڈز ڈھانکے گئے — **بشمول
  `RegisterDomain` کا لایا گیا نام**: ان میں سے کسی ایک کی ترمیم
  دستخط کو غلط کر دیتی ہے؛
- ڈالی گئی `network_id` ڈھانکی گئی ہے: ایک ہی غیر دستخط شدہ tx
  دو نیٹ ورکس کے لیے دستخط ہو کر دو الگ پے لوڈز بناتی ہے (اس
  لیے دو الگ دستخط)۔

## رجسٹریشن کا کام کا ثبوت (PoW)

`RegisterDomain` اور `RegisterTld` کا `proof` فیلڈ رجسٹریشن کا
کام کا ثبوت رکھتا ہے (`scone-core::pow` ماڈیول)۔

### ڈائجسٹ (epoch نمک، اینٹی پری مائننگ)

```text
epoch  = block_height / POW_WINDOW        (POW_WINDOW = 144 blocks)
salt   = BLAKE3-256("SCONE-POW-V1-ARGON2" || network || challenge || epoch_le64)
digest = Argon2id(m, t, p = 1; password = nonce_le64, salt = salt[0..16])
```

`network` کیننیکل `network_id` ہے (M8b): ایک نیٹ ورک کے لیے مائن
شدہ ثبوت دوسرے پر ثبوت نہیں۔

`SCONE-POW-V1-ARGON2` نیز فی نیٹ ورک Argon2id پیرامیٹرز پن کرتا
ہے (`pow_params`: مین نیٹ m = 64 MiB، t = 2، p = 1؛ ٹیسٹ نیٹ/ڈیو
نیٹ m = 8 KiB، t = 1، p = 1): Argon2id کور (RFC 9106) فی ہیش
لاگت کو میموری غالب بناتا ہے (GPU/ASIC مزاحمت)، اور ایک
پیرامیٹر سیٹ کے تحت مائن شدہ ثبوت دوسرے کے تحت کبھی تصدیق نہیں
ہوتا۔

`challenge` دعوے شدہ شے کا حصول ان پٹ ہے — TLD کے لیے
`"SCONE-TLD-V1" || tld`، ڈومین کے لیے `"SCONE-DOMAIN-V1" || name`:
بالکل وہی بائٹس جو `TldId` / `DomainId` کے لیے ہیش ہوتی ہیں،
تاکہ کوئی ثبوت نیم اسپیسز یا شے کی اقسام کے درمیان دوبارہ
چلایا جانے والا نہ ہو۔ `epoch_le64` اور `nonce_le64` epoch اور
nonce کی لٹل-endian 8 بائٹ انکوڈنگز ہیں۔

ثبوت درست ہے جب `digest` میں کم از کم `difficulty` نمایاں صفر
بٹس ہوں۔

#### Epoch نمک — اینٹی پری مائننگ

بے نمک ڈائجسٹ نہ وقت سے بندھتا ہے نہ اونچائی سے: کوئی آج ہزاروں
ناموں کے ثبوت پہلے مائن کر سکتا تھا، پھر مین نیٹ لانچ پر جھنڈ
میں رجسٹر (قبضہ) — ثبوت خود مختار تھا اور جو بلاک پہلے آیا
درست تھا۔ ڈائجسٹ اُس **epoch سے نمکین ہے جو ٹرانزیکشن لاگو
کرتا ہے**:

- `epoch = block_height / POW_WINDOW`، `POW_WINDOW = 144` بلاکس
  (65 s/بلاک پر ~2.6 h): ایماندار صارف کے لیے مہلت کھڑکی (مائن،
  پھر کھڑکی میں جمع کروائیں)، اس سے آگے لازمی دوبارہ مائننگ؛
- ثبوت اپنا epoch وائر پر اعلان کرتا ہے؛ اطلاق پر، اعلان شدہ
  epoch لاگو بلاک کی **درستگی ونڈو** میں ہونا چاہیے — صرف
  **پیچھے کی رواداری** (دیر سے جمع کروانا جذب ہوتا ہے،
  "مستقبل کے لیے" مائننگ ناممکن)، ونڈو کا سائز
  `epoch_validity_window(difficulty)` = `1 << max(0, difficulty −
  16)` epochs (چوڑی ونڈو: اعلیٰ مین نیٹ مشکلیں دنوں سے ہفتوں
  میں مائن ہوتی ہیں، ایک epoch سے زیادہ؛ ذخیرہ سازی کچھ حاصل
  نہیں کرتی کیونکہ ونڈو ≈ مائننگ لاگت — جھنڈ کا ہر ثبوت اپنی
  مکمل `2^difficulty` ہیشز ونڈو کے اندر ادا کرتا ہے)۔ مشکل ≤ 16
  بٹس پر (ٹیسٹ نیٹ، لمبے نام) سخت مساوات کا قاعدہ بے تبدیل؛
- mempool داخلہ (best effort): مستقبل کی بلاک اونچائی نامعلوم
  ہے — ریلے `موجودہ اونچائی + 1` کے epoch کے خلاف تصدیق کرتا
  ہے؛ سخت اطلاق وقت کی تصدیق اختیار رہتی ہے؛
- متعین ری پلے: ثبوت اپنا epoch رکھتا ہے اور ونڈو (مشکل، بلاک
  epoch) کا خالص فنکشن ہے — تاریخی بلاک کسی بھی نوڈ پر ویسے
  ہی دوبارہ تصدیق ہوتا ہے۔

پری مین نیٹ توڑ تبدیلی: پرانا کمپیکٹ فارمیٹ (12 بائٹس) کوئی
پیچھے کی ہم آہنگی کے بغیر مسترد ہے۔

### وائر پے لوڈ (20 مقررہ بائٹس)

```text
nonce_le64 || epoch_le64 || difficulty_le32
```

مشکل اور epoch ثبوت کے ساتھ سفر کرتے ہیں، مگر وہ **پیدا کار کے
اعلان شدہ اور اس لیے کبھی بھروسہ نہیں**: تصدیق کنندہ مشکل کو
رجسٹریشن قسم کی **پروٹوکول مستقل** کے خلاف موازنہ کرتا ہے (جس
پے لوڈ کی اعلان شدہ مشکل مستقل سے مختلف ہو — کم *یا* زیادہ — وہ
مسترد، `InvalidProof`)، اور epoch کو لاگو بلاک کے epoch کے خلاف
(بے میلانی پر `ProofEpochMismatch`)۔ پھر nonce مستقل مشکل پر
دوبارہ تصدیق ہوتا ہے، ڈائجسٹ شروع سے دوبارہ حساب۔

### مشکلیں (**لمبائی پر مبنی** منحنی، M8b + ناپی گئی کیلیبریشن)

مشکل کوئی فلیٹ پیرامیٹر نہیں: یہ **بنائے گئے لیبل کی لمبائی**
کا متعین فنکشن ہے (`scone-core::pow_length` — `RegisterTld` کے
لیے TLD، `RegisterDomain` کے لیے بائیں ترین لیبل)، فی نیٹ ورک:

```text
difficulty(len) = apex − round(0.415 × (len − 1)), clamped at the floor
```

| نیٹ ورک | ذاتی TLD (apex/floor) | کھل کر پیدا شدہ TLD / ڈومین (apex/floor) |
|---|---|---|
| ٹیسٹ نیٹ | 8 بٹس / 2 بٹس | 6 بٹس / 2 بٹس |
| مین نیٹ | 42 بٹس / 30 بٹس | 40 بٹس / 30 بٹس |
| ڈیو نیٹ | 2 بٹس / 1 بٹ | 1 بٹ / 1 بٹ |

**کھل کر پیدا ہونے والی** TLD (`RegisterTld` بمع `open = 0x01`)
"کھلنے" والی منحنی ادا کرتی ہے (apex − 2، `domain_difficulty`
کی طرح)؛ **موجودہ ذاتی TLD کھلنا** (`SetTldOpen`) فلیٹ مشکل پر
رہتا ہے (`open_tld_pow_difficulty`: ٹیسٹ نیٹ 6 بٹس / مین نیٹ 22
بٹس / ڈیو نیٹ 2 بٹس — tx صرف `tld_id` رکھتا ہے، نام نے پیدائش
میں اپنی لمبائی کی قیمت ادا کی تھی)۔ مین نیٹ بینچ مارکس (ذاتی
TLD، ~6 M ہیش/s): 1 حرف = 42 بٹس (≥ 7 دن)، 5 حروف = 40 بٹس (~2
دن)، 19 حروف = 35 بٹس (~1.6 h)، 29+ حروف = 30 بٹ فرور (~3 منٹ)۔
منحنیاں `scone-core::pow_length` میں ہیں (مستقل `MAINNET_APEX =
42`، `MAINNET_FLOOR = 30`، `TESTNET_APEX = 8`،
`TESTNET_FLOOR = 2`، `DEVNET_APEX = 2`، `DEVNET_FLOOR = 1`)؛ فلیٹ
پیرامیٹرز (`tld_pow_difficulty`، وغیرہ)
`scone-core::network::NetworkParams` میں رہتے ہیں۔ کسی قیمت کی
تبدیلی = **اُس نیٹ ورک** کے لیے کنسنسس تبدیلی۔ مستقل حقیقت: ڈیو
نیٹ ایک مکمل تیسری `NetworkParams` ہے اور ٹیسٹ نیٹ اپنے پری
ڈیو نیٹ مستقلات (Argon2id پیرامیٹرز، منحنیاں، ونڈوز) کے بالکل
مشابہ رہتا ہے — ڈیو نیٹ کوڈ سے آگے دوسرے نیٹ ورکس کے ساتھ کوئی
مستقل شیئر نہیں کرتا۔

فلیٹ چوٹیوں کی ناپی گئی کیلیبریشن (2026-10، `cargo run
--release -p scone-core --example pow_bench` — حوالہ x86-64 پر
سنگل تھریڈ تھروپٹ ~7.7 M H/s):

| قسم (مین نیٹ) | مشکل | اوسط حقیقی وقت |
|---|---|---|
| `RegisterTld` | 24 بٹس | ~7 s |
| `RegisterDomain` | 20 بٹس | ~54 ms |

~65 s/بلاک پر: TLD دعوی ~0.1 بلاک سنگل کور CPU کی لاگت، ڈومین
~1 ms بلاک کا — صارف کے لیے علامتی، پیمانے پر صنعتی بنانا مہنگا
(اینٹی قبضہ)۔ اگر ہارڈویئر اہداف گر جائیں تو دوبارہ کیلیبریٹ
کریں (موبائل ARM: ~4–8× سست)۔

اسٹیٹ برانچز (M8b، شپ شدہ): `RegisterTld` ہمیشہ اپنا PoW مانگتا
ہے؛ `RegisterDomain` **کھلی** TLD پر مانگتا ہے (بند پاتھ صرف
assign ہے — `AssignDomain`، TLD کے مالک کے دستخط شدہ، اپنے
فلیٹ اینٹی اسپیم ثبوت کے ساتھ)۔

**دستاویزی منتقلی اور assign ثبوتیں (کنسنسس سطح اینٹی اسپیم)**:
`TransferTld`، `TransferDomain` اور `AssignDomain` ہر ایک
**فلیٹ** کام کا ثبوت رکھتا ہے — دو دستاویزی منتقلیوں کے لیے
`transfer_pow_difficulty` (چیلنجز `SCONE-TLD-XFER-V1 ‖ tld_id` /
`SCONE-DOMAIN-XFER-V1 ‖ domain_id`)، assign کے لیے
`assign_pow_difficulty` (چیلنج `SCONE-DOMAIN-ASSIGN-V1 ‖ name`)۔
رجسٹریشنز جیسا ہی ایپوک نمک اور اینٹی پری مائننگ ونڈو؛ mempool
داخلے پر (اندازہ شدہ ایپوک، best-effort) پھر اطلاق پر (سخت)
تصدیق۔ مقصد: منتقلی کی آمدورفت اور ذاتی TLD تلے بڑے پیمانے پر
تخلیق پر کنسنسس سطح کا کام لگے، پالیسی نہیں۔ کوئی فی لمبائی
ٹیکس نہیں: assign کے لیے namespace کی انفرادیت ذاتی TLD کی
پیدائش پر ادا ہو چکی تھی۔

**غیر فعال دستاویزی منتقلی**: یہ حصول کے راستے (`TransferTld`،
`TransferDomain`، `AssignDomain`) صرف منتقل کرنے والے کے دستخط
شدہ ہیں — وصول کنندہ سے کبھی مشورہ نہیں مانگا جاتا۔ منظور
شدہ انتخاب (تحائف، dead drops، وصیتیں)، کوئی عائد کیا جانے
والا PoS قرض نہیں: دیکھیں `security-model.md` (غیر فعال حصول
اور اہلیت)۔

## تصدیق کے قواعد

ایک ٹرانزیکشن درست ہے اگر اور صرف اگر:

1. **سخت ڈی کوڈنگ**: اوپر کی ساخت اور حدود ملتی ہوں (معروف
   ڈسکریمیننٹ، ورژن `0x01`، pk 32 B، دستخط 64 B، core کے مستقل
   حقائق ڈی کوڈنگ پر دوبارہ چیک)؛
2. **مالک/pk بندھن**: `owner == OwnerId::from(public_key)`
   (دوبارہ حساب)؛
3. **نام/id مطابقت** (RegisterDomain): `domain_id ==
   DomainId(name)` (دوبارہ حساب)؛
4. **دستخط**: `signature` کی Ed25519 `verify_strict` اس پے لوڈ
   کے خلاف جو چین کے نیٹ ورک کے ساتھ **شروع سے دوبارہ حساب** ہوا
   (کبھی کسی پیر یا ٹرانزیکشن سے جوں کی توں نہیں لیا) — دوسرے
   نیٹ ورک کے لیے دستخط شدہ tx یہاں ناکام (`InvalidSignature`،
   اینٹی کراس چین ری پلے)؛
5. **اسٹیٹ قواعد** (بلاک میں اطلاق پر — M8b، دیکھیں
   `/docs/en/technical/blockchain.md`):
   RegisterTld → TLD آزاد + ICANN نہیں + PoW (لمبائی پر مبنی
   مشکل)؛ RegisterDomain → TLD رجسٹرڈ **اور کھلی** + آزاد
   ڈومین (مہلت سمیت) + PoW (لمبائی پر مبنی)؛
   UpdateDomain → موجودہ ڈومین، موجودہ `owner`،
   `sequence == موجودہ + 1`؛
   TransferTld / RevokeTld / SetTldOpen / AssignDomain → موجودہ
   **اور ذاتی** TLD، دستخط کنندہ = TLD کا مالک؛
   TransferDomain → موجودہ ڈومین، مالک؛
   RenewDomain → موجودہ ڈومین، سخت توسیع ≤ 3 سال،
   PoW اجازت (کھلی TLD: پیدائش جیسا PoW،
   **موجودہ میعاد سے بندھا** — رجسٹریشن اور ہر پہلے تجدید سے الگ
   چیلنج) یا PoS (ذاتی TLD: TLD مالک کے — یا اس کے مؤثر آپریٹر
   کے — دستخط، خالی `proof`)۔

تصدیق `verify_strict` استعمال کرتی ہے (لچکدار دستخطوں اور کمزور/
غیر کیننیکل کلیدوں کا انکار)، جیسا غیر بھروسہ مند ڈیٹا کے لیے
ضروری ہے۔

## `push_block` میں عمل کی ترتیب

خفیہ نگاری کی تصدیق (2 سے 4) ہر ٹرانزیکشن کے لیے اسٹیٹ اطلاق
سے **پہلے** ہوتی ہے، فی بلاک ایٹمی کام کرنے والی اسٹیٹ پر؛
کوئی بھی خرابی چین کو بالکل بے تبدیل چھوڑ دیتی ہے۔

## بلاک اسمبلی

`BlockBuilder` (`scone-blockchain`) ٹرانزیکشن قطار سے بلاک بناتا
ہے: ترتیب شدہ فہرست پر `tx_root` دوبارہ حساب، ہیڈر والد ہیش سے
جڑا (`prev_hash`)، `version` = `PROTOCOL_VERSION`۔ کنسنسس پے لوڈ
(دستخط شدہ پیدا کار پے لوڈ) اور timestamp کالر فراہم کرتا ہے؛
موجودہ `Consensus` trait تصدیق کے متوازی استعمال ہوتا ہے۔

## ہیکس اب کہاں رہتا ہے

آف لائن `tx build|sign|verify` کمانڈز ہٹا دی گئیں
(cli-simplify-v1)۔ دستخط شدہ-ہیکس فارمیٹ خود بے تبدیل ہے اور
**ویب/API فلو** کا وائر فارمیٹ رہتا ہے: رجسٹرار ویب ایپ
ٹرانزیکشنز کو API پر کیننیکل ہیکس کے طور پر بناتی، دستخط
(براؤزر میں keystore) اور جمع کرواتی ہے۔ CLI کی جانب، صارف
پاتھز ایک کمانڈ شکلیں ہیں:

```bash
scone domain register example.uip        # mines, signs, submits
scone domain renew example.uip                      # renewal proof, signs, submits
scone domains                            # what you own
```

تمام کوڈ پاتھز میں مالک اور کلید دستخطی شناخت سے **دوبارہ حساب**
ہوتے ہیں، کبھی کسی ان پٹ سے نہیں لیے جاتے۔
