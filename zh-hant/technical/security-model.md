# 安全模型 — 委員會選取與反研磨

> 規範性文件。任何文件／程式碼分歧 = bug。

## 總覽

Epoch N+1 的委員會由種子
`next_seed(signing_hash(checkpoint N)) =
blake3("SCONE-SEED-V1" || signing_hash(checkpoint N))`
在被檢查點 N 最終化的區塊所**凍結的資格
池**上抽取。`signing_hash` 是檢查點**內容**
（epoch、高度、區塊、前一個、狀態根 —
簽章集合除外）的雜湊：種子是被最終化
之**什麼**的純函數，而非**哪個**法定子集
簽署了它 — 對同一檢查點持有不同（兩者
皆有效）子集的兩個視圖選出相同的委員會。

## 威脅：研磨委員會種子

攻擊者想影響委員會的組成。存在三個
攻擊窗口；三者都在結構上被封閉：

### 1. 種子之前 — 無法研磨自己的位置

Epoch N+1 的種子由**檢查點 N 的雜湊**
衍生，該檢查點經法定簽署（委員會 N 的
floor(2n/3)+1 — `quorum_for`）。檢查點 N
承諾一個**固定池**之狀態的 `state_root`
（PoS 基礎 = 已最終化區塊的精確狀態、
`FinalizedBase.pool`）。產生不同的種子需要
不同的法定簽署檢查點 — 也就是腐化 ≥
1/3 的委員會 N，這是 BFT 模型排除的
故障假設。

### 2. 種子之後 — 加入已太遲

任何註冊（網域/TLD 聲明、新擁有者金鑰
的出現）只對隨後的 epoch 有效，而其
種子尚未可知。池在任何人（包括檢查點
N 的簽署者）能計算 N+1 的種子**之前**
凍結於 `FinalizedBase`。

### 3. 無優勢的「m 中選最佳」

一把金鑰在抽取中的位置 =
`blake3("SCONE-COMMITTEE-V1" || seed || pk)`
（均勻），其唯一的自由度是 `pk`。生成
m 把金鑰而只註冊位置最佳的那把的研磨
者必須先**知道種子** — 但那時池已經
凍結。「以防萬一」註冊 m 個候選花費 m
個工作量證明（每網域/TLD 一個）而恰好
得到 m/|池| 的期望在場率：**相較 m 次
直接註冊沒有優勢**。適應性策略（見
種子、再選擇註冊什麼）在時間上不可能。

### 4. 末位生產者偏誤（扣留攻擊）

檢查點前最後一個區塊的生產者可以扣留
其區塊以影響 `signing_hash(checkpoint N)`
乃至種子。兩道防護：

- 檢查點簽署高度 H 的狀態，而**池在
  區塊 H 的時間戳評估** — 扣留區塊延遲
  檢查點、但不改變已被檢查點 N−1 凍結
  之 epoch 的池（池在 epoch 間重疊
  很少）；
- 扣留使攻擊者損失自己的生產獎勵，且
  只影響活躍性（延遲的檢查點）、絕不
  影響安全性：兩個不相容的最終檢查點
  需要 ≥ 1/3 的雙重簽章、可由 `SlashTx`
  證明並以禁權懲罰。

結論：VRF 或 commit-reveal 在此毫無
增益 — 種子已是一個法定簽署事件的
函數，該事件可延遲但不可偽造，而池
凍結移除了唯一的適應性槓桿。不要把
協定複雜化（約束 P1.7：「若有必要」—
分析：不必要）。

## Equivocation 與罰沒

在同一 epoch 簽署兩個衝突檢查點的錨點
可由任何持有兩個簽章的人證明
（`SlashTx`、判別碼 `0x15`）：自 PoS 池
禁權（有日誌、reorg 時可逆）。被指控者的
網域/TLD 不被沒收（最小制裁 — M9
決策）。

## 被動取得與 PoS 資格

**問題**：第三方能否未經我同意、把一項持有
— 以及隨之而來的 PoS 義務 — 強加給我？

**持有可以、債務不行。** 名稱可以被被動
取得：讓與交易（`TransferTld`、
`TransferDomain`）僅由**讓與方**簽署（受讓方
只是一個不透明的 `OwnerId`、絕不被徵詢），
`AssignDomain` 由 TLD 擁有者簽署，創世配置
落在清單的金鑰上。這是有意接受的特性：
贈與、死投、遺贈。反女巫性質不依賴於此：
每個**存活名稱的相異擁有者**一個席位
（`owner_refcounts`）、且每一項持有都讓
某個人付出工作。

**無可強加的債務**：罰沒只懲罰**被證明的
Equivocation**（兩個衝突簽章、`SlashTx`、
禁權）；一把被動的金鑰什麼都不簽署、因此
絕不會被罰沒。被抽中成員的缺席進入
**復原**（重抽）、不受制裁。不想要而收到的
席位仍可處置：到期 + GC、`SetTldOpen`
（開放時席位被釋放）、`RevokeTld`、或再次
轉移。

**已記錄的決策 — 無取得同意**：曾考慮並
否決了兩階段申領（待定轉移、由受讓方
簽署的接受）— 它破壞死投與「先套用者勝」、
在名稱上增加一台狀態機、且防備的是一個
可證明不存在的風險（無可強加的債務、
見上）。

## 經測試驗證的性質

- `checkpoint_hash_engages_signatures`：
  檢查點雜湊涵蓋簽章（無事後竄改）；
- `seed_chain_and_recovery`：種子鏈精確
  衍生、含復原 k；
- `small_committee_never_finalizes`：BFT
  防護 — 低於 `MIN_FINALITY_COMMITTEE_SIZE`
  的委員會絕不最終化；
- e2e 4 中繼站：一個檢查點最終化並
  傳播、所有節點上相同 epoch。

## 委派授權上的重播攻擊（計數器綁定）

五筆交易變更**誰**能對一個命名空間行事：
`TransferTld`、`TransferDomain`（所有權）、
`SetRecordDelegates`（記錄委派金鑰）、
`SetTldOperator`／`SetDomainOperator`（營運
委派）。這些形式的已記錄交易永遠保持
密碼學有效（簽章涵蓋靜態欄位；讓與 PoW 解
的是從命名空間自身衍生的挑戰）。唯一會
老去的是有界的重播窗口（最後 256 個
區塊）。超出它、重新武裝分析：

- **讓與 A→B→A**：A 轉移給 B、B 轉移回
  A — 狀態回到先前的組態。重播**原始**的
  A→B 交易在未經同意下重新執行轉移（擁有
  者檢查再次通過；靜態挑戰的證明仍然解得
  開）。
- **委派集循環**：委派設為 `{9,10}`、清空
  為 `∅`、然後**任何**恢復 `{9,10}` 的
  交易 — 第一筆 `SetRecordDelegates` 的
  重播復活被撤銷的金鑰。

以**當前**狀態（擁有者、集合內容、…）的
純函數計算的綁定、恰在狀態回到舊值時也
回到舊值 — 它會重新武裝它必須殺死的那場
重播。防禦是**單調**的世代：每個命名空間
攜帶 `mutations: u64`、被五筆受防護交易的
每一筆遞增；交易綁定到它構建所在世代的
計數器
（`BLAKE3-256("SCONE-BINDING-MUTATIONS-V1" ‖ id ‖ generation ‖ counter)`）、
套用時以**當前**計數器驗證該綁定。計數器
絕不回頭；因此沒有任何重播能重新武裝。
世代標記（網域為 `registered_at`、TLD 為
`valid_until`）使重新註冊命名空間的先前
**生命**互不相交。

殘餘邊緣（已載明）：綁定不依賴簽署者的
**金鑰**。五筆受防護交易全部由命名空間
**當前**的擁有者簽署、因此跨生命重播還
需要同一擁有者在兩個世代中都持有該命名
空間、且計數器重新達到被記錄的值 — 對
委派者／營運者這是自我掌控的情境、對讓與
則是擁有者受害者案例、要求受害者多年後
重新申領自己已死的命名空間。主網前接受；
若轉移量或命名空間回收使其變得實質、
重新審視。

## 已知限制（已載明、未修正）

- 資格池包含活躍 TLD 的擁有者（聲明 =
  已花費的 PoW）— 女巫表面受每金鑰的
  PoW 成本約束；
- 檢查點的 `state_root` 只在檢查點指向
  尖端時於 RAM 驗證；回溯重播是
  儲存／中繼路徑（見
  `docs/technical/blockchain.md`）。
